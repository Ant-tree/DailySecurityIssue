# Your Camera Can Hear You: Side-Channel Acoustic Eavesdropping via Android Camera2 Metadata
> arXiv 프리프린트 (심사 전). 저장 대학교(Zhejiang University) 블록체인·데이터 보안 국가 중점 실험실, 광둥 전력망 전력연구원
> 2026

안드로이드는 모션 센서가 몰래 마이크 역할을 하지 못하도록 SensorManager에 여러 겹의 방어를 두고 있습니다. 안드로이드 12부터 자이로스코프와 가속도계는 기본적으로 200Hz로 제한되고, 더 높은 속도를 쓰려면 HIGH_SAMPLING_RATE_SENSORS 권한이 필요하며, 시스템 전체 마이크 차단 스위치를 끄면 그 권한이 있어도 다시 200Hz로 묶입니다. 저자들은 Camera2 하위 시스템이 이 방어를 모두 우회한다는 사실을 보였습니다. 카메라 세션이 열려 있으면 Camera HAL의 광학식·전자식 손떨림 보정(OIS/EIS) 파이프라인이 고속 자이로스코프 값을 기록해 제조사 정의 CaptureResult 메타데이터로 앱에 넘겨 주는데, 스피커로 음성이 재생되면 본체 진동이 이 값에 그대로 실립니다. 2020~2026년 출시된 10개 제조사 스마트폰 50대 가운데 37대가 이 메타데이터를 노출했고, 26대가 200Hz 제한을 넘었으며, 최신 플래그십 6대는 800~1000Hz로 흘려보냈습니다. 이 경로에는 RECORD_AUDIO도 HIGH_SAMPLING_RATE_SENSORS도 필요 없고 CAMERA 권한만 있으면 됩니다. 저자들은 여기에 더해, 실제 기기 측정 데이터 없이 물리 모델로 만든 가상 누설 신호만으로 학습해 처음 보는 기종에도 통하는 음성 인식기 CamEar를 만들었습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.27964
- arXiv HTML 본문: https://arxiv.org/html/2611.27964
- arXiv PDF: https://arxiv.org/pdf/2611.27964

### Contribution
- 마이크 차단 스위치를 꺼도 Camera2 메타데이터는 속도가 줄지 않고, 카메라 차단 스위치를 끄면 영상 프레임만 빈 화면으로 바뀔 뿐 800~1000Hz 메타데이터는 계속 흐른다는 점을 실측으로 확인했습니다. Camera2 메타데이터와 SensorManager가 같은 MEMS 자이로스코프 값을 읽는다는 점도 상관 분석(R² 0.9993 이상)으로 보였습니다.
- 센서 허브가 클라이언트별로 속도를 분리하지 않아, 카메라 세션을 열면 같은 기기의 다른 SensorManager 리스너까지 권한 없이 400~500Hz로 올라가는 "속도 전이" 현상도 보고했습니다.
- 기존 학습 기반 공격은 대상 기기에서 수십 시간 분량의 데이터를 모아야 했는데, 음성 내용과 기기 고유의 진동 특성을 분리해 물리 기반 순방향 시뮬레이터로 학습 데이터를 합성하는 S2L(Source-to-Leakage Learning)을 제안해 대상 기기 데이터 없이 공격을 일반화했습니다.
- 메타데이터 속도를 낮추면 정확도가 크게 떨어진다는 완화 방향을 제시하고 해당 제조사에 알렸다고 밝혔습니다.

### Evaluation
- 대상: 800~1000Hz 메타데이터를 내보내는 6대(vivo X300s, X300 Pro, X200 Ultra, Xiaomi 17T Pro, HONOR Magic8 Pro Air, Redmi K90 Max, 모두 안드로이드 16). 학습은 LibriSpeech train-960을 시뮬레이터에 통과시킨 데이터만 썼고, 평가는 처음 보는 화자 16명의 발화 816개를 각 기기 스피커로 재생해 얻은 실측 4,896건으로 했습니다.
- 결과: 대상 기기 데이터 없이 평균 단어 정확도 52.1%(최대 61.8%), 문자 정확도 74.3%(최대 80.7%)였고, 텍스트 전용 LLM 보정을 더하면 평균 단어 정확도 60.1%였습니다. 기존 방법 ISpyU를 한 기기에서 24시간 분량으로 미세 조정한 모델은 다른 기기에서 평균 25.9%에 그쳤고, 같은 기기에서도 평균 36.6%라 CamEar가 모든 기기에서 앞섰습니다.
- 완화: 메타데이터를 400~499Hz로 제한하면 단어 정확도가 32.4%로, 200Hz로 제한하면 2.3%로 떨어졌습니다.
- 신빙성: 시험 기기를 휴대폰 스피커 최대 음량으로 단단한 탁자 위에 둔 조건이 기본이라 실제 통화 환경보다 유리한 설정입니다. 비교 대상 ISpyU는 코드가 공개되지 않아 저자들이 직접 재현했으므로 기준선 성능이 원 논문보다 낮게 나왔을 가능성을 배제할 수 없습니다. 다만 평가 화자가 학습과 겹치지 않고 수치도 50%대라 지나치게 좋은 결과로 보이지는 않습니다.

#### Comment
- 모바일 권한 모델의 "API 간 중재 불일치"를 정면으로 보여 주는 사례입니다. 영상 통화, AR, 비전 SDK처럼 카메라를 정상적으로 쓰는 앱에 포함된 서드파티 라이브러리가 공격 주체가 될 수 있어, 앱 심사나 SDK 공급망 관점에서도 의미가 큽니다.
- 중국 기관(저장 대학교) 논문이라 검증을 더 했습니다. 교신 저자 Bingsheng Zhang은 저장 대학교 소속으로 실재하는 연구자이며, 실험에 쓴 기기와 측정 조건, 평가 분할이 구체적으로 적혀 있습니다. 코드나 데이터 공개 주소는 본문에서 찾지 못해 재현성은 제한적입니다. 게재처가 정해지지 않은 심사 전 원고입니다.

# Correct Precedents Induce Policy Violations in On-Device LLM Agents
> arXiv 프리프린트 (심사 전). 모하메드 빈 자이드 인공지능 대학교(MBZUAI)
> 2026

클라우드 모델이 계획을 세우고 기기 안의 작은 모델이 개인 데이터에 실제 동작을 수행하는 로컬-클라우드 에이전트 구조에서, 기기 쪽 에이전트(저자들은 "가드"라고 부릅니다)는 파일 삭제나 환불처럼 되돌릴 수 없는 동작 앞의 마지막 관문입니다. 저자들은 이 가드가 같은 세션 안에서 내린 "올바른 결정" 때문에 이후 위반을 저지르는 현상을 처음 보고했습니다. 예를 들어 법적 보존 조치가 풀린 파일을 정상적으로 삭제하고 나면, 몇 항목 뒤에 아직 보존 조치가 걸린 비슷한 파일까지 삭제할 가능성이 높아집니다. 앞선 결정이 모두 옳았으므로 감사로 원인을 짚어 낼 단계가 없습니다. 저자들은 이를 "올바른 선례의 일반화"라고 이름 붙이고, 영향이 적은 교사 모델의 결정을 LoRA 어댑터로 증류하는 PDD(Paired Decision Distillation)로 고쳤습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.27216
- arXiv HTML 본문: https://arxiv.org/html/2611.27216
- arXiv PDF: https://arxiv.org/pdf/2611.27216

### Contribution
- 잘못된 단계나 주입된 지시가 없는 이력만으로도 에이전트가 제한을 어길 수 있다는 새 실패 유형을 정의했습니다. 기존 연구는 이력에 무언가 잘못된 요소가 있는 경우만 다뤘습니다.
- 앞선 항목 하나만 다른 두 대기열(보존 해제된 유사 항목과 평범한 항목)을 비교하는 실험 설계로 효과를 분리해 측정했고, 거절된 요청을 새 세션에서 다시 보내기만 해도 위험이 누적된다는 점을 보였습니다.
- 이력 개입 실험으로, 가드가 제한 항목의 상태를 확인하지 않고 앞선 유사 항목에 대한 행동을 그대로 옮긴다는 원인을 짚었습니다. 각 항목 옆에 상태를 적어 주면 효과 대부분이 사라졌습니다.
- PDD는 추론 시 추가 프롬프트, 도구 호출, 모델 호출 없이 안전율을 거의 100%로 되돌렸습니다.

### Evaluation
- 대상: 9개 개발사의 공개 가중치 모델 13종(GPU 한 장에서 돌아가는 크기, 큰 7종은 4비트). 파일 정리, 환불, 패키지 정리의 세 가지 생성 작업군을 쓰고, 각 대기열은 10개 항목으로 제한 항목을 7번째, 비교 항목을 3번째에 두었습니다. 위반 여부는 LLM 판정 없이 JSON 도구 호출을 직접 파싱해 판정했습니다.
- 결과: 13종 모두에서 선례 하나로 안전율이 떨어졌고, 가장 영향이 큰 모델(Nemotron-3.5)은 약 절반으로 떨어졌습니다. 같은 요청을 10번 반복하면 위반이 한 번이라도 일어날 확률이 선례가 없을 때보다 4배 이상 높았습니다(그림 사례 기준 48% 대 6%). τ²-bench와 Minions 구조를 옮긴 환경, 사고 과정 출력을 켠 경우에도 일부 모델에서 효과가 재현됐습니다.
- 완화: PDD는 증류한 모든 모델에서 안전율을 거의 100%로 회복했고, MMLU-Pro와 XSTest에서 원 모델보다 나쁘지 않았습니다. 상태 조회 도구, 깨끗한 문맥으로 재판정하는 관문 등 다섯 가지 추론 시점 대책과 비교했는데, 이들도 효과는 있었지만 모두 배포 시 추가 비용이 들었습니다.
- 신빙성: 확인 실험의 설계와 분석을 데이터 수집 전에 타임스탬프 커밋으로 고정했고, 작업군과 인스턴스 단위로 묶은 부트스트랩 신뢰구간과 순열 검정을 썼습니다. 다만 주 실험은 사고 기능을 끄고 JSON 텍스트로 행동을 내게 한 생성 대기열과 각본화된 클라우드 쪽에서 이루어져, 실제 배포 환경의 효과 크기와는 다를 수 있습니다.

#### Comment
- 온디바이스 모델을 "마지막 안전장치"로 두는 하이브리드 에이전트 설계에서, 단일 요청 단위 점검만으로는 부족하고 세션 전체를 놓고 평가해야 한다는 메시지가 분명합니다. 모바일 비서처럼 로컬 소형 모델이 개인 데이터를 다루는 환경에 직접 적용됩니다.
- 실험 통계가 꼼꼼한 편이지만 코드 공개 주소는 본문에서 확인하지 못했습니다. 게재처가 정해지지 않은 심사 전 원고입니다.
