# The Provenance-Privacy Paradox: Can Private Cloud Compute (PCC) Prove That Apple Reference Images Are Not Used for Learning?
> arXiv 프리프린트 (심사 전). 캘리포니아 주립 폴리테크닉 대학교 포모나
> 2026

아이폰의 사진 진위 증명 기능인 Apple Reference Image(ARI)가 원본 센서 데이터를 Private Cloud Compute(PCC)에서 현상하는 구조 때문에 생기는 개인정보 문제를 다룬 입장 논문입니다. ARI는 카메라 센서 서명, Secure Enclave 증명, 시간 범위 증명, PCC 현상, 양자 내성 서명을 묶어 "이 사진이 실제 아이폰 센서가 찍은 것에서 나왔다"는 것을 보증합니다. 그런데 디모자이킹, 색 보정, 톤 매핑, 압축 같은 현상 과정을 PCC가 맡으므로, 전송 중에는 암호화되더라도 승인된 PCC 작업은 원본 픽셀을 평문으로 다룰 수밖에 없습니다. 저자들은 원격 증명과 투명성 로그가 "어떤 소프트웨어가 실행되었는지"는 증명하지만 "그 소프트웨어가 사진에서 학습하거나 정보를 남기지 않았는지"는 증명하지 못한다고 주장하고, 이를 보이는 반례를 실험 환경에서 구현했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.21590
- arXiv HTML 본문: https://arxiv.org/html/2611.21590
- arXiv PDF: https://arxiv.org/pdf/2611.21590

### Contribution
- ARI의 출처 증명 장치(센서 서명, Secure Enclave)와 PCC의 기밀성, 증명 장치를 구분해, 센서 서명은 픽셀을 인증할 뿐 암호화하거나 사용 방식을 제한하지 않는다는 점을 정리했습니다.
- 작업의 신원을 검증하는 것과 작업의 행동을 검증하는 것의 차이를 형식화해, 증명과 투명성 로그 등재만으로는 "학습하지 않음"과 "보관하지 않음"이 따라 나오지 않음을 보였습니다.
- Python과 Docker로 ARI와 PCC의 관련 기능(현상, 작업 증명, 투명성 로그 검증, 클라이언트 수락)을 모델링한 실험 환경을 만들고, 두 작업이 같은 검증을 통과하면서 한쪽만 이미지 정보를 남기는 반례를 구현했습니다.
- 학습 금지 정책 명시, 영구 저장과 외부 통신 제한, 보관 데이터 공개, 작업 행동과 권한의 독립 검증을 권고했습니다.

### Evaluation
- 데이터: 공개 도메인 사진 27장.
- 결과: 기본 작업과 학습 기능이 있는 작업 모두 같은 증명과 투명성 로그 검사를 통과했고, 바이트 단위로 같은 JPEG를 돌려줬습니다. 그러나 학습 작업은 약 48KB 크기의 첫 층 기울기를 남겼고, 여기서 64×64 입력을 픽셀당 최대 절대 오차 6×10^-8로 복원할 수 있었습니다. 추가 처리 부담은 이미지 해독과 현상에 비해 작았습니다.
- 신빙성: 실제 PCC가 아니라 공개 문서를 바탕으로 만든 모델 환경이고, 입력도 64×64로 작아 실제 원본 센서 이미지에 대한 정량 결과는 아닙니다. 논문의 핵심은 수치보다 "신원 증명과 출력 동일성이 숨은 보관과 양립한다"는 반례 자체입니다.

#### Comment
- 저자들은 Apple이 실제로 ARI 사진으로 학습한다고 주장하지 않으며, 실제 PCC를 재현한 것도 아니라고 분명히 밝힙니다. "Apple도 데이터를 볼 수 없다"는 공식 설명을 어디까지 믿을 수 있는지에 대한 위협 모델 정리로 읽는 것이 맞습니다.
- 모바일 기기 기능이 클라우드 처리에 기대는 경우가 늘면서, 원격 증명이 보장하는 범위를 정확히 이해해야 한다는 점에서 의미가 있습니다. 다만 실험 규모가 작고, 학습 금지 같은 의미적 성질을 실제로 검증하는 방법은 제안하지 않았습니다.

# Post-Quantum Migration of Wi-Fi Key Establishment: A Hybrid ML-KEM Design for OWE and FILS, Validated on OWE with hostapd
> arXiv 프리프린트 (심사 전). 칸타브리아 대학교, 레이 후안 카를로스 대학교
> 2026

Wi-Fi 연결의 키 합의를 양자 내성 방식으로 옮기는 설계와 구현을 다룬 논문입니다. Wi-Fi의 데이터 암호화(AES)는 키 길이만 늘리면 양자 컴퓨터에도 비교적 안전하지만, 키 합의에 쓰는 Diffie-Hellman은 그렇지 않아 지금 기록한 연결을 나중에 해독하는 공격이 가능합니다. 저자들은 관리 프레임 안에서 키를 합의하는 두 프로토콜, 즉 개방형 네트워크에 암호화를 더하는 OWE와 이동이 잦은 밀집 환경을 위한 빠른 접속 방식 FILS를 대상으로, 기존 타원곡선 합의와 NIST 표준 ML-KEM(FIPS 203)을 함께 돌리고 두 비밀로 마스터 키를 만드는 하이브리드 방식을 제안했습니다. 기존 프레임을 그대로 쓰므로 왕복 횟수가 늘지 않고, 전환 기간에는 기존 OWE와 함께 공존할 수 있습니다. 설계는 오픈소스 Wi-Fi 구현인 hostapd와 wpa_supplicant에 OWE 기준으로 실제로 구현해 검증했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.21528
- arXiv HTML 본문: https://arxiv.org/html/2611.21528
- arXiv PDF: https://arxiv.org/pdf/2611.21528

### Contribution
- OWE와 FILS의 Diffie-Hellman 교환을 ECDH와 ML-KEM의 하이브리드 교환으로 바꾸는 설계를 제시했습니다. 두 구성 요소 중 하나만 안전해도 연결이 보호되며, 추가 왕복이 없습니다.
- 접속점이 하이브리드 모드를 기존 OWE와 함께 알릴 수 있게 하고, 하이브리드를 요구하도록 설정한 단말은 양자 내성 교환이 끝나지 않으면 접속을 거부하도록 했습니다. 광고한 기능을 유도 키에 묶어 변조를 탐지하는 확장은 설계로만 제시했습니다.
- hostapd와 wpa_supplicant에 OWE 하이브리드 모드를 구현하고, ML-KEM 세 매개변수 집합의 프레임 크기, 분할, 연산 시간을 실측했습니다.

### Evaluation
- 정확성: 모드마다 30번의 연결 모두에서 단말과 접속점이 같은 마스터 키를 유도했습니다.
- 프레임 크기: ML-KEM-768 기준 연결 요청 1,419바이트, 응답 1,306바이트로, 보수적으로 잡은 1,500바이트 분할 기준에서도 한 프레임에 들어갑니다. 핸드셰이크당 추가량은 2,296바이트였습니다. 더 작은 두 매개변수 집합은 한 프레임에 들어가고, 저자들은 ML-KEM-768이 보안 수준과 크기의 균형이 가장 좋다고 결론지었습니다.
- 지연: 블록 순서로 측정한 연결 교환 시간 중앙값이 1.17ms에서 1.41ms로 0.23ms 늘었습니다(Mann-Whitney U, p = 1.8×10^-7, N = 30). ML-KEM-768의 키 생성, 캡슐화, 복호화, 결합기 연산 합은 약 0.19ms였습니다. 6Mbps 전송률에서 추가 바이트의 전파 시간은 약 3.1ms로 계산했습니다.
- 신빙성: 시뮬레이션 드라이버를 쓰는 사용자 공간 시험 환경과 2vCPU 가상 머신 한 대에서 측정해, 실제 무선 칩과 드라이버(Broadcom, Qualcomm, Intel)에서의 지연과 분할 동작은 확인하지 않았습니다. FILS는 설계만 하고 측정하지 않았습니다.

#### Comment
- 표준화(IEEE P802.11bt)가 진행 중인 주제에 대해 실제로 동작하는 구현과 측정치를 내놓았다는 점이 장점입니다. 모바일 단말과 IoT 기기의 접속 경로를 양자 내성으로 바꿀 때 프레임 크기 부담이 감당할 만하다는 근거가 됩니다.
- 첫 접속 전 다운그레이드 공격은 열린 문제로 남아 있고, 기본 정책에서는 공격자 없이도 다운그레이드가 일어날 수 있다고 저자들이 직접 적었습니다. WPA3 전환 모드 공격과 비슷한 문제라 실제 배치 전에 인증 범위를 형식적으로 정해야 합니다.
