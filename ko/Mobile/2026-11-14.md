# MobileProbe: Adaptive Security Evaluation of Mobile Agents via Trajectory-Aware Injection
> NDSS 2027 채택 논문 (심사 완료, DOI 10.14722/ndss.2027.230546). arXiv 공개판. 홍콩 폴리테크닉 대학교, 저장대학교, Huawei
> 2026 (학회 발표 2027)

모바일 GUI 에이전트는 휴대폰 화면을 읽고 사람 대신 앱을 조작하므로, 이메일이나 메시지, 앱 안 대화상자처럼 화면에 보이는 내용에 지시문을 숨겨 행동을 바꾸는 환경 주입 공격에 노출됩니다. 기존 벤치마크는 전문가가 직접 만든 공격 문구를 정해진 작업의 정해진 단계에 고정해 두는 방식이라, 문구를 다른 앱으로 옮기기 어렵고, 에이전트가 다른 경로로 작업을 진행해 주입된 화면을 아예 지나치면 "안전"으로 기록되는 문제가 있습니다. MobileProbe는 에이전트가 실제로 지나간 경로를 보고 주입 지점과 공격 문구를 그때그때 정하는 레드팀 도구입니다. 자동 침투 테스트로 공격자가 통제할 수 있는 화면 요소를 미리 찾아 템플릿으로 만들어 두고, 에이전트가 해당 화면에 도달할 때만 주입하며, 대리 모델로 걸러 낸 후보 문구를 진화 방식으로 다듬습니다. 공격 경로는 권한 없는 제3자가 쓸 수 있는 두 가지(평범한 콘텐츠에 섞은 악성 텍스트, 재패키징 앱이 자기 화면에 띄우는 가짜 대화상자)로 한정했습니다.

### Contribution
- 고정 지점 벤치마크의 두 가지 한계(공격 사례가 특정 앱과 작업에 묶이는 문제, 경로가 달라지면 공격에 노출되지 않는 문제)를 짚고, 주입 지점 선택과 문구 생성을 에이전트의 실제 실행 경로에 맞춰 함께 찾는 문제로 정식화했습니다.
- MobileWorld 기반 작업 위에 12개 앱, 83개 공격 사례(악성 텍스트 44개, 가짜 대화상자 39개, 여러 앱에 걸친 작업 47개)를 만들고, 각 사례를 기밀성, 무결성, 가용성 가운데 하나의 공격 목표로 분류하고 성공 여부를 판정하는 검증 프로그램을 붙였습니다.
- 오버레이 창(SYSTEM_ALERT_WINDOW 권한 필요), 시스템 알림, 앱 아이콘 위장 등 다른 후보 경로를 왜 제외했는지 정리해 위협 모델을 권한 없는 공격자로 좁혔습니다.

### Evaluation
- 대상 에이전트: Gemini-3.1-Pro(화면을 직접 입력받는 상용 모델), Gemini에 UI 인식 모듈을 붙인 에이전트 구조, 온디바이스용 공개 모델 GUI-Owl-1.5-8B.
- 주입 지점 누락률(공격 문구를 아예 만나지 않은 비율): 전문가가 고정한 지점 13.3%, 12.0%, 22.9%에서 MobileProbe 4.8%, 3.6%, 6.0%로 낮아졌습니다.
- 공격 성공률: MobileProbe 85.1%, 86.3%, 85.1%. 같은 주입 지점을 쓴 비교 대상은 기존 벤치마크 템플릿 6.8~34.5%, 단발 LLM 생성 8.0~15.7%, 모바일용으로 옮긴 PAIR 54.6~77.5%, Genesis 39.0~61.4%였습니다. 가짜 대화상자(88.9~95.7%)가 악성 텍스트(78.0~81.8%)보다 잘 통했고, 가용성 공격(75.0~81.0%)이 가장 낮았습니다.
- 원래 작업을 마치면서 공격도 성공한 비율(들키지 않는 정도)은 Gemini 68.1%, GUI-Owl 46.4%였고, 구성 요소를 빼는 실험에서 진화적 다듬기를 빼면 성공률이 28.5%로 떨어졌습니다. 10명이 공격 문구 20개를 눈으로 평가한 결과도 실었습니다(진짜처럼 보이는 정도 4.3~4.7점, 행동의 그럴듯함 3.2~3.4점, 5점 만점).
- 신빙성: 비교 대상 PAIR와 Genesis는 원래 웹이나 텍스트용이라 저자들이 모바일용으로 옮겨 구현했으므로, 차이의 일부는 이식 과정의 손실일 수 있습니다. 성공 판정은 사례별 검증 프로그램으로 해서 LLM 판정보다 객관적입니다.

- 금융, 의료 앱은 벤치마크에 포함되지 않았습니다.
