# Ultrasound Watermark: Real-time Acoustic Watermarking against Voice Scams on Smartphones
> arXiv 프리프린트 (심사 전). 메릴랜드 대학교 볼티모어 카운티(UMBC), 인디애나 대학교 블루밍턴, 매사추세츠 대학교 애머스트, Bloomberg L.P., Amazon
> 2026

TTS와 음성 변환 기술이 좋아지면서 전화로 지인이나 기관을 사칭하는 보이스피싱이 훨씬 그럴듯해졌습니다. 기존 방어는 녹음을 사후에 분석하거나, 통화 코덱을 거치면 성능이 떨어지거나, 적응형 공격에 약했습니다. 저자들은 통화하는 동안 스마트폰 스피커로 초음파를 내보내고 마이크로 얼굴 조음 기관(입술, 턱)의 움직임에서 돌아오는 반사파를 받아, 이 움직임 특징을 송신 음성과 섞어 워터마크를 만드는 Ultrasound Watermark를 제안했습니다. 워터마크가 실제 발화 동작과 시간적으로 묶여 있으므로, 조음 동작 없이 합성하거나 재생한 음성으로는 맞는 워터마크를 만들기 어렵다는 것이 핵심 논리입니다. 생성기는 발신 측, 검출기는 수신 측 휴대폰에서 동작하며 별도 장비가 필요 없습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.30106
- arXiv HTML 본문: https://arxiv.org/html/2611.30106
- arXiv PDF: https://arxiv.org/pdf/2611.30106

### Contribution
- 음성 워터마크를 "누가 말했는가"가 아니라 "지금 이 사람이 실제로 입을 움직여 말하고 있는가"에 묶었습니다. 스마트폰 내장 스피커와 마이크만으로 초음파 조음 센싱과 워터마크 삽입을 동시에 수행합니다.
- 생성기와 검출기를 함께 학습하면서 음성과 초음파 움직임의 교차 정합성을 강제해, 재생 공격, 합성 음성, 조음 동작을 흉내 내는 공격을 구분하도록 설계했습니다.
- 통화 왜곡(대역 필터, 리샘플링, MP3/AAC, 잡음, 에코, Encodec 압축 등)을 학습과 평가 양쪽에 넣었습니다.
- iOS와 안드로이드 앱으로 구현해 200ms 단위 구간을 실시간으로 처리했습니다.

### Evaluation
- 데이터: 화자 22명, 스마트폰 8종, 실제 환경 4곳에서 모은 2.5시간 이상의 음성-초음파 동기 녹음입니다. 지표는 정확도, TPR, FPR, 공격 성공률, AUC를 썼습니다.
- 결과: 음성만 쓰는 공격과 무작위 초음파를 덧붙인 공격(재생, 합성 모두)은 AUC 1.00, FPR 0.01 이하로 걸러냈습니다. 가장 어려운 경우는 다른 사람의 실제 발화에서 얻은 동기화된 초음파를 붙이는 공격으로, AUC가 0.84(재생)와 0.88(합성)로 떨어졌고 FPR이 0.30~0.37까지 올라갔습니다.
- 여러 날, 통화 모드(스피커, 수화부), 휴대폰 위치를 바꾼 사용자 실험에서 모두 검출에 성공했다고 보고했습니다. 최신 기종에서 생성기는 15~24ms, 검출기는 8ms 미만이었고, 오래된 기종도 구간당 200ms 안에 들어왔습니다.
- 신빙성: 저자들 스스로 밝힌 대로 대역 통과·고역 통과 필터, AAC와 저비트레이트 Opus 압축에서는 워터마크가 크게 약해집니다. 실제 이동통신망의 음성 코덱(AMR, EVS 등)을 그대로 거친 종단 간 시험은 본문에서 확인하지 못했습니다. 화자 22명은 개인 간 조음 패턴 차이를 일반화하기에는 작은 규모입니다.

#### Comment
- 휴대폰 하드웨어만으로 "살아 있는 발화" 증명을 붙인다는 점에서 보이스피싱 대응 연구로 실용성이 있습니다. 다만 발신자와 수신자 양쪽에 앱이 깔려 있어야 하므로, 사칭 공격자가 워터마크 없이 전화를 거는 경우 "워터마크 없음"을 어떻게 사용자에게 알릴지가 실제 배포의 관건입니다.
- 동기화된 초음파 공격에서 FPR이 0.3을 넘는 것은 화자 구분 정보가 부족하다는 뜻이고, 저자들도 화자 조건 검출을 향후 과제로 남겼습니다.
- 코드나 데이터 공개 주소는 본문에서 찾지 못했습니다. 게재처가 정해지지 않은 심사 전 원고입니다.

# MobileGrail: Learning Compact Guardrails for On-Device deployable Mobile GUI Agent Safety
> arXiv 프리프린트 (심사 전). UC 데이비스, CodeDroid
> 2026

모바일 GUI 에이전트의 동작을 실행 전에 검사하는 런타임 가드레일은 지금까지 클라우드의 대형 멀티모달 모델에 의존해 왔고, 그러면 결제, 메시지, 진료 기록처럼 민감한 화면이 모두 외부 서버로 넘어갑니다. 저자들은 기기에서 돌아가는 2B 규모의 가드레일 MobileGrail을 제안했습니다. 짧은 문맥 안에서도 오래전 단계의 근거(사용자가 무엇을 허락했는지, 작업이 어디까지 진행됐는지)를 잃지 않도록 필요한 정보만 담은 순환 작업 상태를 유지하고, 위반을 확정하는 동작(unsafe)과 개입해야 하는 구간 안의 모든 동작(block)을 별도 라벨로 학습해 너무 이르거나 늦은 개입을 줄였습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.29847
- arXiv HTML 본문: https://arxiv.org/html/2611.29847
- arXiv PDF: https://arxiv.org/pdf/2611.29847

### Contribution
- 기존 데이터셋이 "위험해 보임", "위반 발생", "개입 필요"를 하나의 unsafe 라벨로 뭉뚱그려 안전 경계가 모호했던 문제를 짚고, 개입 구간(사용자 허락으로 더 이상 설명되지 않는 첫 동작부터 위반을 확정하는 동작까지)이라는 개념으로 라벨을 나눴습니다.
- 앱 32개로 이루어진 학습 환경을 만들고, 앱 백엔드가 각 동작의 실제 효과를 검증해 지도 학습 라벨과 강화 학습 보상을 제공하도록 했습니다.
- 학습에 쓰지 않은 앱 위주로 구성한 오프라인 벤치마크 MobileVeto(위험 궤적 210개, 각각 짝이 되는 정상 궤적 포함)를 공개했습니다.
- 4비트 양자화로 스냅드래곤 8 Elite에서 실제로 돌려 지연 시간을 측정했습니다.

### Evaluation
- 오프라인(MobileVeto): Qwen3.5-2B 기반 MobileGrail(SFT와 GRPO)은 위반 차단율 76.2%(프롬프트만 쓴 같은 모델 64.5%), 너무 이른 개입 비율 5.2%(같은 모델 58.6%), 정상 작업 오탐 15.7%(같은 모델 75.7%)였습니다. 클라우드 기반 OS-Sentinel(Kimi-K2.6)은 차단율 39.3%, 정상 작업 오탐 57.1%로 다섯 지표 모두에서 MobileGrail보다 나빴습니다. 반면 라벨링 교사로 쓴 Gemini 3.8 Flash는 차단율 95.5%로 여전히 가장 강했습니다.
- 온라인(GhostEI-Bench 110개 작업): Qwen3.8-27B 에이전트를 지켰을 때 완전히 성공한 공격이 13건에서 3건으로 줄고, 작업 완료는 48건에서 58건으로 늘었습니다.
- 성능: Q4_0 양자화 시 지연 중앙값 4.70초, 상주 메모리 3.67GiB로 클라우드 Gemini 3.8 Flash(5.11초)와 비슷했습니다.
- 신빙성: 학습 라벨과 근거 문장을 Gemini 3.8 Flash가 만들었고 비교 기준도 같은 모델이라, 교사 모델의 판단 기준이 결과에 녹아 있습니다. 벤치마크 210개 궤적은 저자들이 만든 환경과 같은 방식으로 생성됐으므로 실제 상용 앱 전반으로의 일반화는 아직 확인되지 않았습니다.

#### Comment
- 화면 내용을 외부로 보내지 않는 가드레일이라는 문제 설정이 모바일 프라이버시 관점에서 의미가 큽니다. 다만 동작 하나를 검사하는 데 4~5초가 걸려, 실시간 에이전트 체감 속도에는 여전히 부담이 됩니다.
- 코드와 모델 공개 주소는 본문에서 찾지 못했습니다. 게재처가 정해지지 않은 심사 전 원고입니다.

# NRSnooper: Enabling Real-Time Bidirectional Traffic Decoding in Commercial 5G NR Networks
> arXiv 프리프린트 (심사 전). KAIST, 밀라노 공과대학교
> 2026

5G NR의 하위 계층 트래픽을 상·하향 모두 해독하면 스케줄링 메타데이터만으로는 보이지 않던 프로토콜 동작, 보호되지 않은 시그널링, 암호화된 상위 계층 패킷의 크기와 시점까지 드러납니다. 그러나 상용망에서는 단말별 설정이 암호화된 RRC 메시지 안에 숨어 있고, 이미 연결된 단말의 식별자를 모르며, 광대역 신호를 실시간으로 처리하기도 어렵습니다. NRSnooper는 공격자가 정상 SIM으로 오픈소스 단말(OAI UE)을 직접 접속시켜 상용 단말의 능력 정보를 재현하고, 그때 기지국이 내려 주는 물리 계층 설정을 학습해 재사용합니다. 이어 진행 중인 전송에서 연결별 식별자(C-RNTI)를 복구하고, CRC 검증으로 맞는 설정을 골라 상·하향 데이터를 실시간으로 해독합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.29439
- arXiv HTML 본문: https://arxiv.org/html/2611.29439
- arXiv PDF: https://arxiv.org/pdf/2611.29439

### Contribution
- 암호화된 설정 갱신 이후의 트래픽과 이미 연결된 단말의 트래픽까지 해독할 수 있는 수동형 5G NR 스니퍼를 처음으로 상용망에서 시연했습니다.
- 증후군 기반 C-RNTI 복구, 제어 채널 후보 축소, 폴라 복호, 세션별 DMRS 식별자 복구를 결합했고, CPU와 GPU를 함께 쓰는 처리 구조로 100MHz 대역을 실시간 처리했습니다.
- 단말 능력 정보 21종과 변형 83종을 재현해 망별 설정 프로파일을 수집했습니다. 스니퍼는 오픈소스로 구현했다고 밝혔지만, 공개 주소는 본문에서 확인하지 못했습니다.
- 6G에서는 하위 계층 기밀성을 명시적 요구 사항으로 둬야 한다는 대응 방향을 제시했습니다.

### Evaluation
- 테스트베드(srsRAN 기지국): 기지국 로그를 정답으로 썼고, CRC를 통과한 모든 전송 블록이 기지국 페이로드와 바이트 단위로 일치했습니다. 하향 74.98~98.61%, 상향 87.87~97.16%의 전송 블록을 복구했습니다.
- 상용망 두 곳(K국 n78, U국 n41, 모두 100MHz SA): 비암호화 시그널링의 설정만 쓴 경우와 비교해 제어 메시지를 1.3배와 6.3배, 하향 데이터 블록을 9.0배와 17.7배 더 해독했습니다. 통화 중인 단말의 트래픽도 해독했습니다.
- 장비: 4안테나 USRP N310, i7-14700K, RTX 3080 Ti.
- 신빙성: 상용망에는 정답이 없어 "기법 적용 전후의 CRC 통과 블록 수"를 비교한 상대 지표이며, 전체 전송량 대비 커버리지는 측정하지 못했습니다. 표적 단말 실험은 저자들 자신의 단말로 한정했습니다.

#### Comment
- 한국 연구진(KAIST 김용대 교수 연구실) 논문으로, LTESniffer 계열 연구를 5G SA 상용망으로 확장한 결과입니다. 암호화된 RRC 재설정만 보호해서는 부족하다는 지적은 망 사업자와 표준화 측면에서 의미가 있습니다.
- 단말 기종을 좁히는 지문 채취 가능성도 언급했지만 실제 식별 성능은 평가하지 않았습니다. 윤리 고려 사항 절을 따로 두었습니다.
- 게재처가 정해지지 않은 심사 전 원고입니다.
