# Comparing WeChat and Telegram MiniApp Security Architectures: Toward Cross-Platform Analysis
> arXiv 프리프린트 (심사 전). IMT School for Advanced Studies Lucca, 제노바 대학교(이탈리아)
> 2026

미니앱은 슈퍼앱 안에서 돌아가는 경량 앱으로, WeChat은 전용 패키지(.wxapkg)를 자체 런타임에서 실행하는 반면 Telegram은 봇과 연결된 일반 웹 앱을 Android WebView에서 실행합니다. 기존 WeChat 미니앱 분석 도구(MiniCAT, WEMINT 등)는 패키지 구조와 WeChat 전용 API에 의존하므로 Telegram 미니앱에는 그대로 쓸 수 없습니다. 이 논문은 두 생태계를 실행 환경, 통신 경로, 신뢰 경계 기준으로 비교합니다. WeChat은 공식 문서와 기존 심사 논문을, Telegram은 공식 문서에 더해 Telegram Android 클라이언트 특정 커밋의 소스 코드를 직접 읽어 구조를 재구성했고, 보안 통제, 자산, 위협 출처라는 공통 분류로 정리했습니다. 끝으로 두 가지 사례를 통해 플랫폼을 가로지르는 자동 분석 도구가 갖춰야 할 요구 사항을 도출했습니다.

### Contribution
- WeChat의 앱 속 앱(App-in-App) 모델과 Telegram의 봇 중심 웹 미니앱 모델을 같은 기준으로 구조 비교했습니다.
- Telegram Android 클라이언트의 BotWebViewContainer 등 실제 코드 위치(줄 번호까지)를 근거로, 브리지 등록과 이벤트 전달, 권한이 필요한 요청 처리, 새 창 탐색 경로를 정리했습니다. 예를 들어 같은 JavaScript 인터페이스 이름(TelegramWebviewProxy)이 봇 여부에 따라 서로 다른 브리지 구현으로 연결되고, 새 창 탐색은 별도 경로로 처리되므로 원래 미니앱의 권한을 물려받는다고 단정할 수 없다는 점을 보였습니다.
- 자격 증명별 역할(WeChat의 AppSecret, access token, session key와 Telegram의 BOT TOKEN, initData)과 검증 지점을 구분해야 하고, 호스트 기능은 구체적인 실행 문맥과 권한 처리기에 연결해 모델링해야 한다는 두 가지 분석 요구 사항을 제시했습니다.
- 플랫폼 인증(Telegram 로그인, 봇 API 인증)이 미니앱 백엔드의 자원 권한 검사를 대신하지 않는다는 점을 양쪽 모두에서 명확히 했습니다.

### Evaluation
- 정량 평가는 없는 정성적 구조 비교 연구입니다. 저자들도 두 생태계의 보안 순위를 매기거나 취약점 탐지 성능을 검증했다고 주장하지 않는다고 밝혔습니다.
- 근거의 비대칭: WeChat 클라이언트는 비공개라 문서와 기존 논문에만 기대고, Telegram은 특정 커밋(62b56a07)의 소스 코드까지 확인했습니다. 따라서 코드 기반 주장은 그 판에만 해당합니다. 주요 주장과 근거 위치를 대응시킨 표를 제공해 추적은 가능합니다.
- 가장 가까운 선행 연구(Mohammadi 외, 2025)와 다룬 범위를 표로 비교했습니다.

#### Comment
- 실제 취약점 발견이나 자동 분석 도구 구현은 없고, 앞으로 만들 도구의 설계 요구 사항을 정리한 단계입니다. 미니앱 분석 도구를 만들려는 사람에게 참고 자료로 쓸모가 있습니다.
- 같은 연구진이 Telegram 미니앱의 개인정보 처리 실태를 동적 분석한 TeleGapper(arXiv 2608.13390)를 앞서 발표했으며, 이번 논문은 그 후속 성격입니다.
