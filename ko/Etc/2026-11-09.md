# E-UDE: A Scientific Machine Learning Model for Malware Propagation Dynamics
> arXiv cs.CR 2611.00971 (프리프린트, 심사 전). 라지브 간디 공과대학교(RGPV), 인도 과학산업연구위원회 국립데이터과학AI연구소(CSIR, 인도)
> 2026

인터넷에서 악성코드가 퍼지는 양상을 예측하는 모델은 크게 두 갈래입니다. 미분방정식 기반의 전염병형 모델은 해석은 쉽지만 실제 데이터와 잘 맞지 않고, 신경망 기반 모델은 잘 맞추지만 왜 그런지 설명하기 어렵습니다. 범용 미분방정식(Universal Differential Equation) 방식은 두 접근을 섞어, 알려진 메커니즘은 방정식으로 쓰고 설명되지 않는 부분은 신경망 잔차로 학습합니다. 이 논문은 기존 UDE 악성코드 모델을 확장해 감염 가능, 감염, 대응, 혼잡의 네 상태를 별도 구획으로 두고 전파율, 네트워크 구조, 혼잡 효과, 외부 공격 유입, 방어 대응, 보안 수준 저하를 명시적으로 넣은 E-UDE(Enhanced UDE)를 제안합니다. 구획이 명시되어 있어, 방어 대응 속도를 바꾸면 확산이 어떻게 달라지는지 같은 시나리오 분석을 할 수 있다는 점을 장점으로 내세웁니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.00971
- arXiv HTML 본문: https://arxiv.org/html/2611.00971
- arXiv PDF: https://arxiv.org/pdf/2611.00971

### Contribution
- 기존 UDE 모델의 일반적인 성장 항 대신 네 가지 상태 구획과 방어, 혼잡 요인을 넣어 해석 가능성을 높였습니다.
- 학습된 매개변수로 방어 대응 강화, 외부 유입 차단 같은 개입 시나리오의 효과와 비용 효율을 비교하는 분석 틀을 보였습니다.
- 데이터에 잡음을 섞었을 때 예측 성능이 덜 떨어진다는 견고성 결과를 함께 제시했습니다.

### Evaluation
- 데이터: CAIDA가 공개한 Code Red 웜(2001년)과 Witty 웜(2004년) 감염 호스트 관측 자료.
- 비교 대상: 고전적인 미분방정식 모델, 신경망 미분방정식(Neural ODE), 기존 UDE.
- 결과(Code Red 전체 구간 적합): E-UDE의 RMSE 783.70, MAE 421.65, MAPE 13.36%, 상관계수 0.961로, 고전 모델(RMSE 2325.87), Neural ODE(2094.76), UDE(1281.84)보다 낮은 오차를 보였습니다. 앞쪽 25%로 학습하고 뒤쪽 75%를 예측한 시간순 분할에서도 시험 RMSE 634.6, 상관계수 0.964를 보고합니다.
- 지표의 신빙성: 비교 대상이 모두 같은 계열의 단순한 모델이고, ARIMA나 LSTM 같은 시계열 예측 기준선은 표에 없습니다. 무엇보다 20년 넘은 단일 웜 확산 곡선 두 개로만 평가했기 때문에, 오늘날의 랜섬웨어나 봇넷처럼 표적이 좁고 사람이 개입하는 확산에 그대로 적용된다고 보기는 어렵습니다.

#### Comment
- 보안 쪽보다는 과학적 기계학습(물리 법칙과 신경망 결합)의 응용 사례로 읽는 편이 적절합니다. 대응 속도나 혼잡 같은 요인을 구획으로 드러낸 점은 교육용이나 정책 시뮬레이션에 쓸모가 있습니다.
- 한계: 구획 수가 늘면 매개변수도 늘어 과적합 위험이 있는데, 관측 자료가 감염 호스트 수 하나뿐이라 숨은 상태(대응, 혼잡)가 실제로 식별되는지는 따로 검증하지 않았습니다. 코드 공개 여부는 본문에서 확인하지 못했습니다.
- 신뢰도: 인도 국책 연구소와 대학 연구진의 심사 전 원고입니다. 공개 데이터셋을 쓰고 설정 표를 제시해 재현은 비교적 쉬운 편입니다.

# AutoPYara: Next-Gen YARA Rule Generator for Malware Family Clustering
> IEEE ACSAC 2026 채택 논문(arXiv comment와 본문 표기), arXiv cs.CR 2611.08608 공개본. 텍사스 A&M 대학교(미국)
> 2026

매일 쏟아지는 악성코드 대부분은 같은 패밀리의 변종이므로, 샘플을 패밀리 단위로 묶어 하나의 YARA 규칙으로 잡는 것이 대응 속도를 좌우합니다. 현재 최고 수준으로 꼽히는 AutoYara는 정상 파일에는 드물고 악성 파일에는 자주 나오는 바이트 N-gram을 찾아 규칙을 자동 생성하지만, 정답 패밀리 라벨이 있는 경우와 큰 클러스터에서만 평가되었습니다. 실제 현장처럼 패밀리 내부가 다양하고 클러스터링이 부정확하면 규칙 품질이 떨어집니다. AutoPYara는 유사도 해시로 클러스터 중심 샘플을 정밀하게 고르고, VirusTotal의 과거 패밀리 데이터로 패밀리 하나를 몇 개의 하위 클러스터로 나눌지 추정하는 방법을 더해 이 문제를 개선합니다.

원문 링크:

- arXiv HTML 본문: https://arxiv.org/html/2611.08608

- 저자 저장소(PyPI 패키지 소스): https://github.com/Botacin-s-Lab/AutoPYaraPyPI

### Contribution
- AutoYara의 VBGMM 기반 하위 클러스터 추정을 Fuzzy C-Means와 DBSCAN식 밀도 기반 k 결정, VirusTotal 이력 기반 휴리스틱으로 바꾸고, 유사도 해시로 중심 샘플을 고르는 단계를 추가했습니다.
- 라벨링 전략(SSdeep, J-SDhash 유사도 클러스터링 대 VirusTotal 라벨 기반 AVClass2 정규화)에 따라 규칙 생성 성능이 얼마나 흔들리는지 처음으로 체계적으로 측정했습니다.
- 같은 Java 백엔드를 쓰는 Python 패키지로 배포해 실무에서 바로 쓸 수 있게 했습니다.

### Evaluation
- 데이터: 한 백신 회사가 미국, 브라질, 일본 고객에게서 8년간 수집한 Windows PE 파일로, 악성 71,000개와 정상 22,000개입니다. 중복 샘플은 실제 환경을 반영하려고 일부러 지우지 않았습니다.
- 지표: 클러스터별 탐지율(규칙의 적용 범위), 정상 파일을 악성으로 잡는 오탐과 다른 패밀리를 잡는 오탐을 나눠 측정하고, 오탐 최소화를 우선하는 "탐지" 시나리오와 탐지율을 우선하는 "위협 헌팅" 시나리오를 따로 평가했습니다. 확률적 요소를 줄이려고 수렴 알고리즘으로 정한 횟수만큼 반복해 평균을 냈습니다.
- 결과: AutoYara 대비 규칙 적용 범위가 14%포인트 늘고, 분산이 7.1%포인트 줄고, 위협 헌팅 정확도가 10% 높아졌습니다. 결론에서는 최적 설정에서 80% 개선을 달성했다고 적었습니다.
- 지표의 신빙성: 실제 수집 샘플을 썼고 라벨링 방식에 따른 차이를 함께 보고해 설득력이 있습니다. 다만 "80% 개선"이 어떤 지표의 상대 개선인지는 요약 수준에서는 분명하지 않아, 초록의 세 수치를 기준으로 보는 편이 안전합니다. 데이터셋 자체는 공개되지 않았고 규칙과 벤치마크 결과가 공개되었습니다.

#### Comment
- 학계 연구가 현장 도구(YARA)와 맞닿은 드문 사례이고, 아티팩트 평가를 거친 패키지가 공개되어 있어 보안 관제나 위협 헌팅 팀이 바로 시험해 볼 수 있습니다.

# PhotoFinish: Portable Timerless Probing of Microarchitectural Latencies
> arXiv cs.CR 2611.09879 (프리프린트, 심사 전). CISPA 헬름홀츠 정보보안센터(독일)
> 2026

캐시 공격 같은 마이크로아키텍처 공격은 대개 고해상도 타이머로 "빠르다/느리다"를 구분합니다. 그래서 브라우저는 타이머 해상도를 낮추거나 잡음을 넣는 방식으로 방어해 왔습니다. 타이머 없이 상태를 관찰하는 기존 기법도 있지만 특정 명령어나 특정 캐시 구현에 기대어 이식성이 떨어졌습니다. PhotoFinish는 두 스레드의 경주로 지연 시간 차이를 곧바로 값으로 바꿉니다. 한 스레드가 측정할 연산(예: 메모리 접근)을, 다른 스레드가 기준 연산을 실행한 뒤 두 스레드가 같은 공유 메모리 위치에 서로 다른 값을 씁니다. 나중에 쓴 값이 남으므로, 남은 값만 읽으면 측정 대상이 기준보다 빨랐는지 느렸는지 알 수 있습니다. 필요한 것은 병렬 실행과 공유 메모리뿐입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.09879
- arXiv HTML 본문: https://arxiv.org/html/2611.09879
- arXiv PDF: https://arxiv.org/pdf/2611.09879

### Contribution
- 특정 ISA나 하드웨어 기능에 기대지 않는 이식 가능한 타이머 없는 측정 기법을 제시했습니다. 타임스탬프, 성능 카운터, 특권 명령어가 모두 필요 없습니다.
- 브라우저에서 WebWorker와 SharedArrayBuffer만으로 WebAssembly 구현을 돌려도 네이티브와 비슷한 정밀도를 보여, 타이머 제한만으로는 브라우저 기반 마이크로아키텍처 공격을 막을 수 없다는 점을 보였습니다.
- 캐시를 넘어 TLB, 실행 엔진 지연, LLC 슬라이스 식별까지 적용 범위를 넓혔습니다.

### Evaluation
- 범위: x86_64, AArch64, RISC-V, LoongArch 4개 ISA에 걸친 CPU 38종(하이브리드 구조를 나눠 45개 플랫폼 구성)에서 동기화 지연과 흔들림을 측정하고, 캐시 상태를 안정적으로 구분할 수 있음을 보였습니다.
- AES T-table 공격: OpenSSL 3.5.0의 T-table AES를 대상으로 한 첫 라운드 선택 평문 공격에서, 캐시 라인 크기가 맞지 않는 Apple M1, M2를 뺀 41개 플랫폼에 적용했습니다. 이 공격은 캐시 공격 연구의 표준 비교 과제라 기존 연구와 직접 비교할 수 있습니다.
- Evict+Reload: Apple M1에서 정밀 타이머 없이 축출 집합을 찾아 코어 간 은닉 채널을 구현했습니다.
- 지표의 신빙성: 표준 공격 과제와 매우 넓은 하드웨어 범위로 주장(이식성)을 직접 뒷받침합니다. 실험이 공격자가 스레드를 특정 코어에 고정할 수 있다는 가정에 기대며, 고정이 안 되면 반복 측정이 더 필요하다고 저자들이 밝혔습니다.

#### Comment
- 브라우저와 샌드박스 방어의 전제("타이머를 막으면 된다")를 흔드는 결과입니다. 공유 메모리와 진짜 병렬성이 있는 환경이면 어디서나 쓸 수 있으므로, 모바일 브라우저를 포함한 다양한 플랫폼에 영향이 있습니다.
- 대응: 공유 메모리 대신 메시지 전달을 쓰고 전달에 임의 지연을 넣기, 공유 메모리 쓰기 권한을 한 번에 한 스레드로 제한하기, 진짜 병렬 실행을 막기 등을 제시합니다. 브라우저의 SharedArrayBuffer 정책과 직결되는 논의입니다.
- 신뢰도: Michael Schwarz 연구실은 마이크로아키텍처 공격 분야 최고 수준의 그룹입니다. 심사 전 원고이며 본문에서 코드 공개 주소는 확인하지 못했습니다.

# Robust & Scalable Website Fingerprinting via Minimal DRAM Traffic
> arXiv cs.CR 2611.09422 (프리프린트, 심사 전). 인도공과대학교 봄베이(인도)
> 2026

같은 컴퓨터에서 실행되는 악성 자바스크립트가 공유 자원을 관찰해 사용자가 어떤 웹사이트를 방문하는지 알아내는 공격을 웹사이트 핑거프린팅이라고 합니다. 기존의 대표 공격인 sweep-counting과 loop-counting은 코어가 적은 시스템에서 90% 넘는 정확도를 보였지만, 코어가 많거나 칩렛(CCD) 구조인 최신 프로세서에서는 크게 떨어집니다. 예를 들어 loop-counting은 8코어에서 93%이던 정확도가 24코어에서 50%로, sweep-counting은 여러 CCD에 걸치면 84%에서 45%로 떨어집니다. 저자들은 포인터 추적 순회로 DRAM 접근을 일정 시간마다 세는 "memory-chasing" 공격을 제안합니다. DRAM 트래픽은 코어 수가 늘어도 모든 코어가 공유하므로 확장성이 좋습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.09422
- arXiv HTML 본문: https://arxiv.org/html/2611.09422
- arXiv PDF: https://arxiv.org/pdf/2611.09422

### Contribution
- 기존 공동 거주형 핑거프린팅 공격이 다코어, 칩렛, 다중 소켓 시스템에서 무너지는 원인을 분석했습니다(인터럽트 분산, CCD별 LLC 분할).
- 간섭을 최소화한 DRAM 접근 계수로 이 한계를 넘는 공격을 설계했습니다.

### Evaluation
- 시스템: Intel Xeon Gold 6342(코어 수 확장 실험), AMD EPYC 9754(CCD 영향 실험), 이중 소켓 Intel 시스템. 기본 환경은 Ubuntu와 Chrome 142이고, Firefox 136, Tor 브라우저 등으로 확장했습니다.
- 결과: 상위 50개 웹사이트 기준 24코어 시스템 96%, 여러 CCD에 걸친 경우 86%, 다중 소켓 80%, 개방형 설정(목록에 없는 사이트 포함) 97%입니다. 본문에서는 Tor 브라우저에서 91%를 보고합니다.
- 강건성: 브라우저, 운영체제, 격리 메커니즘, 시스템 잡음, 기존 연구(Cook 등)가 제안한 대응책 아래에서도 평가했습니다.
- 지표의 신빙성: 같은 하드웨어에서 기존 공격 두 종을 재현해 나란히 비교한 점이 좋습니다. 대상 사이트가 50개로 적은 편이고, 모바일 프로세서는 16코어 이상 제품이 없다는 이유로 평가에서 제외했습니다.

#### Comment
- 서버와 워크스테이션급 다코어 시스템에서도 브라우저 기반 사이드 채널이 통한다는 점을 보여, "코어가 많으면 잡음 때문에 안전하다"는 기대를 뒤집습니다.
- 한계: 공격 자바스크립트가 피해자 브라우저에서 실행되어야 하고, 사이트 수가 적은 닫힌 세계 평가가 중심입니다. 본문에서 코드 공개 주소는 확인하지 못했습니다.
- 신뢰도: 인도공과대학교 봄베이의 컴퓨터 구조 보안 연구실 원고로, 심사 전입니다.
