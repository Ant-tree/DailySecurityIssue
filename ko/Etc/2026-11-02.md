# OrionLink: Single Sign-On with Oblivious Identity Brokers
> NDSS Symposium 2027 게재(논문 PDF 표기: 2027년 3월 22~26일, 서울, DOI 10.14722/ndss.2027.231871), arXiv cs.CR 2610.41323 공개본. 베이항대학교, 중국과학기술대학교, 홍콩과학기술대학교, 베이징우전대학교
> 2026 (학회 발표는 2027)

싱글 사인온(SSO)에서 서비스(relying party, 이하 서비스)는 Google이나 Apple 같은 신원 제공자(identity provider, 이하 신원 제공자)에 로그인을 맡깁니다. 최근에는 여러 신원 제공자를 하나의 인터페이스로 묶어 주는 신원 중개자(identity broker, 이하 중개자)를 쓰는 경우가 늘었는데, 저자들은 SSO를 쓰는 웹사이트의 약 25%가 중개자를 거친다는 2025년 측정 연구를 인용합니다. 문제는 중개자가 모든 로그인을 중계하면서 사용자 식별자, 액세스 토큰, 세션 쿠키, 이메일과 전화번호 같은 개인정보를 평문으로 보게 된다는 점입니다. 2023년 Okta 고객지원 시스템 침해로 여러 서비스의 토큰과 쿠키가 유출된 사례처럼, 중개자는 한 번 뚫리면 피해가 연쇄적으로 번지는 단일 장애 지점이 됩니다.

OrionLink는 중개자가 로그인을 계속 중계하되 사용자의 실제 신원, 어떤 서비스를 쓰는지, 토큰과 개인정보는 전혀 알지 못하도록 SSO 흐름을 다시 설계한 시스템입니다. 중개자는 "정직하지만 호기심 많은" 존재로 가정하며, 프로토콜은 지키되 관찰 가능한 모든 정보로 추론을 시도한다고 봅니다.

원문: https://arxiv.org/abs/2610.41323 (본문은 저자가 공개한 저장소 https://github.com/Ooo0ption/Orionlink 의 논문 전체본 PDF로 읽었습니다)

### Contribution
- 서비스별 익명 가명 생성: Pointcheval-Sanders 서명 기반 익명 자격증명과 망각 의사난수 함수(OPRF)를 결합해, 신원 제공자가 사용자 식별자를 직접 노출하지 않고 서비스마다 다른 가명을 만들어 주도록 했습니다. 중개자와 여러 서비스가 정보를 모아도 같은 사용자를 연결할 수 없습니다.
- 익명 인증 키 합의: Signal의 X3DH를 변형한 프로토콜로 서비스와 신원 제공자 사이에 종단간 암호화 채널을 만들어, 토큰과 개인정보가 중개자를 지나가도 암호문으로만 보이게 했습니다. 신원 제공자는 매 로그인마다 새로 무작위화된 자격증명만 보므로 사용자가 어떤 서비스에 권한을 줬는지도 추적할 수 없습니다.
- 실사용 기능 두 가지를 추가했습니다. 사용자가 신원 제공자에게 관계를 노출하지 않고 서비스 권한을 확인하고 철회하는 기능, 그리고 더블 래칫 방식에서 착안해 갱신할 때마다 새 세션 키를 쓰는 전방 안전성 토큰 갱신입니다.
- 위 성질들을 UC 프레임워크에서 형식적으로 정의하고 증명했으며, 9,000줄 이상의 프로토타입(Go 서버와 브라우저 측 암호 연산 모듈)을 공개했습니다. 브라우저 측 암호 연산은 신원 제공자와 다른 출처에서 동작하는 별도 iframe(Trusted Computation Agent)이 맡습니다.

### Evaluation
- 환경: 서비스, 중개자, 신원 제공자를 Docker 컨테이너로 한 대의 서버(16코어 4.3GHz, 96GB 메모리)에 올렸고, 비교 대상은 같은 구조로 직접 구현한 OIDC 인가 코드 흐름 기반 표준 중개 SSO입니다. 사용자 클릭은 Playwright로 자동화했습니다.
- 로컬 연산 비용: 1,000회 평균으로 키 생성 46.59ms, 가명 생성 2.58ms, 익명 키 합의 11.39ms 등 전체 67.50ms였습니다.
- 종단간 지연: 왕복 지연 40ms 조건에서 로그인 전체가 OrionLink 2,080ms, 표준 방식 500ms였습니다(각 100회 평균). 0ms, 100ms, 200ms 조건에서도 지연은 네트워크 지연에 거의 비례해 늘었습니다.
- 부하: 익명 키 합의 인터페이스에 초당 1,000건 요청을 걸었을 때 95백분위 지연이 약 10ms였습니다.
- 모바일: 브라우저 측 암호 연산이 iPhone 15(Safari)에서 32.4ms, 노트북에서 32.2ms로 차이가 없었습니다(100회 중앙값).
- 지표 신빙성: 성능 수치는 기준선 대비 오버헤드를 숨기지 않고 그대로 보여 주며(로그인 시간이 약 4배), 과장된 지표는 보이지 않습니다. 다만 기준선을 저자가 직접 구현했고, 실제 상용 중개자 환경이나 사용자 연구로 사용성을 평가하지는 않았습니다.

#### Comment
- 중개자가 끼어 있는 SSO 구조 자체를 개인정보 위험으로 정면에서 다룬 첫 작업이라고 주장하며, 기존 연구(UP-SSO, BISON, ARPSSO, MISO 등)와 비교해 종단간 기밀성과 중개자 호환성을 함께 갖춘 점이 차별점입니다. MCP처럼 서버가 신원 제공자이자 서비스 역할을 동시에 하는 구조에서 중개 SSO 수요가 커지고 있다는 문제의식도 시의적절합니다.
- 한계: 중개자가 평문을 보지 못하므로 속성 값 정규화, 중개자 측 속성 기반 접근 제어, 콘텐츠 기반 위협 분석 같은 기능은 포기해야 한다고 저자들이 밝힙니다. 중개자가 완전히 악의적인 경우, 브라우저나 확장 프로그램이 침해된 경우, 전역 수동 공격자에 의한 상관 분석은 범위 밖입니다.
- 게재처: NDSS는 보안 분야 최상위 학회 중 하나입니다. 게재 정보는 논문 PDF 첫 페이지의 NDSS 2027 표기와 DOI로 확인했으며, NDSS 공식 채택 목록에서 직접 대조하지는 못했습니다.
- 본문 출처: 저자 저장소에 올라온 논문 전체본 PDF와 아티팩트 부록(Artifact-Appendix.pdf).
- 중국 기관 논문 검증: 저자 소속은 베이항대학교 사이버과학기술대학, 중국과학기술대학교, 홍콩과학기술대학교, 베이징우전대학교로 모두 실재하는 주요 연구 기관이며 기관 이메일 주소가 명시되어 있습니다. 게재처는 심사가 엄격한 NDSS이고, 코드 저장소에는 실험(E1~E3)을 그대로 재현하는 스크립트와 Docker 구성, 아티팩트 평가용 부록이 함께 공개되어 재현 가능성이 높습니다. 평가 수치가 기준선보다 불리한 결과(지연 증가)를 그대로 보고하고 있어 지표가 부풀려졌다고 볼 근거는 찾지 못했습니다.
