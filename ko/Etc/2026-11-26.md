# PORTA: Systematic Discovery of Vulnerabilities in Identity Brokers
> ACM CCS 2026 게재(프로시딩 논문, CC BY 4.0 오픈 액세스), arXiv 등록. 토론토 대학교
> 2026

Keycloak, Vault, Dex 같은 아이덴티티 브로커는 상위 IdP가 발급한 인증 증명(SAML 어설션, OIDC 토큰)을 검증하고 그 안의 신원과 권한 정보를 하위 서비스용 세션으로 바꿔 줍니다. 브로커 하나에 버그가 있으면 그 뒤의 모든 하위 서비스가 함께 뚫리고, 하위 서비스는 이미 원래 증명이 바뀐 뒤라 이를 알아챌 수 없습니다. 저자들은 브로커가 상위에 대해서는 신뢰 당사자(RP), 하위에 대해서는 IdP라는 이중 역할을 한다는 점이 기존 인증 명세의 "한 주체는 한 역할" 가정과 어긋난다는 데 주목했습니다. 예를 들어 SAML의 NotOnOrAfter 필드가 없을 때 이를 받아들이는 것은 일반 RP에게는 맞지만, 브로커에서는 공격자가 필드를 지워 만료 검사를 끄는 통로가 됩니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.33015
- arXiv HTML 본문: https://arxiv.org/html/2611.33015
- arXiv PDF: https://arxiv.org/pdf/2611.33015
- ACM 디지털 라이브러리(공식 논문 페이지, DOI): https://doi.org/10.1145/3830454.3846557
- 연구 산출물(Zenodo): https://zenodo.org/records/22820164

### Contribution
- 8개 SSO 명세의 규범 요구 40개와 브로커 플랫폼 10개의 과거 CVE 60개를 함께 분석해 브로커가 지켜야 할 보안 불변식 5개를 정의했습니다. 60개 CVE 모두 이 중 하나 이상을 위반합니다.
- 브로커 작업 흐름을 상위 수준 동작 범주로 나누고, LLM이 이 범주에 맞는 API 호출 순서를 만든 뒤 플랫폼별 HTTP 요청으로 구체화하는 2단계 구조(모델 기반 테스트 방식)를 설계했습니다. 판정은 불변식에 맞춘 결정적 오라클로 합니다.
- 새로 찾은 취약점을 8가지 반복 패턴으로 정리했습니다.

### Evaluation
- 대상: 오픈소스 브로커 7종(Keycloak, Casdoor, Dex, Authentik, Vault, Zitadel, Logto)의 OIDC와 SAML 조합 13가지. 고정 버전 도커 이미지에서 독립 실험 3회를 돌렸습니다.
- 새 취약점: 33개를 찾았고, 모두 책임 있게 공개해 29개 확인, 14개 패치, 19개 CVE 발급(그중 10개는 치명적 등급)을 받았습니다.
- 정밀도: 실험당 평균 약 500개 시퀀스, 실행 완료율 72.6%, 정밀도 88.5%(±6.1%)였습니다.
- 재현율: 지원 범위 안의 알려진 CVE 11개 중 10개(90.9%)를 잡았고, OIDC와 SAML 관련 CVE 18개 전체 기준으로는 10개(55.6%)였습니다.
- 절제 실험: 불변식과 예시를 모두 뺀 "일반 보안 버그 찾기" 프롬프트는 33개 중 0개를 찾았고, 예시만 뺀 경우 26개, 결정적 오라클 대신 LLM 판정을 쓰면 12개(정밀도 8.4%)였습니다. 불변식 정의와 결정적 판정이 성능의 핵심이라는 뜻입니다.
- 신빙성: 재현율 실험은 일부 CVE만 대상으로 한 하한값이고, 모든 결과가 최소 설정 배포 기준이라 기업 환경의 사용자 정의 매퍼나 플러그인은 반영되지 않았다고 저자들이 밝혔습니다. 근본 원인 분석, 분류, 보고서 작성은 사람이 했습니다.

#### Comment
- "LLM에게 버그를 찾으라고만 하면 0개, 명세에서 뽑은 불변식을 주면 33개"라는 절제 결과는 LLM 기반 보안 테스트 설계에 바로 참고할 만한 교훈입니다.
- 사내에서 Keycloak 같은 브로커를 쓰는 조직이라면 저자들이 정리한 8가지 패턴(어설션 필드 제거, 이메일 대소문자 정규화 불일치로 인한 계정 충돌 등)을 점검 목록으로 쓸 수 있습니다.
- ACM CCS는 최상위 보안 학회입니다. 연구 산출물이 Zenodo에 공개되어 있습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음). PDF 안에 CCS '26 프로시딩 표기와 DOI가 있어 게재본과 같은 판으로 판단했습니다.

# MALET & Katalina: A Large-Scale Dataset and Static Analysis of macOS Malware
> arXiv 프리프린트 (심사 전). 독립 연구자 2인(뉴욕)
> 2026

윈도와 안드로이드 악성코드는 많이 연구됐지만 macOS는 상대적으로 연구가 적고, 동적 분석이 어렵다는 점(애플 실리콘 전환, 애플 하드웨어가 필요한 가상화 제약)과 공개 데이터셋 부족이 원인으로 꼽힙니다. 저자들은 악성 Mach-O 바이너리 44,804개와 VirusTotal 탐지 0건인 샘플 44,457개로 이루어진 공개 데이터셋 MALET를 만들고, 보수적인 휴리스틱으로 후자에서 신뢰도 높은 정상 샘플 25,835개를 골랐습니다. 함께 공개한 정적 분석 도구 Katalina는 엔타이틀먼트, 서명 메타데이터, 내장 스크립트, 링크된 라이브러리 같은 macOS 고유 특징을 대량으로 추출합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.31949
- arXiv HTML 본문: https://arxiv.org/html/2611.31949
- arXiv PDF: https://arxiv.org/pdf/2611.31949
- 저자 저장소(Katalina): https://github.com/appsworld/katalina
- 데이터셋(Zenodo): https://zenodo.org/records/17877273

### Contribution
- 공개된 macOS Mach-O 데이터셋 가운데 가장 크다고 밝힌 MALET와, 오픈소스 정적 분석 도구 Katalina를 함께 공개했습니다.
- macOS 악성코드에 대한 첫 대규모 정적 특성 분석을 수행했습니다. 보안 엔타이틀먼트 오용, 네이티브 스크립트 인터페이스 악용, 코드 서명 기반의 이상 징후를 정리했습니다.

### Evaluation
- 서명: 악성 샘플의 93.0%가 서명되지 않았는데, 이는 사용자 승인 절차를 통해 서명 없는 코드가 실제로 실행되고 있음을 보여 준다고 해석했습니다. 인증 기관 서명이 있는 악성 샘플 중 28.4%(816개)는 나중에 폐기된 인증서와 연결되어 있었고, 북한 연계 공격자로 알려진 샘플도 포함됐습니다.
- 폐기 지연: 일부 인증서는 공개 탐지 후 700일 넘게 유효했습니다.
- 탐지 불안정성: 구조가 똑같은 악성 샘플 185개 중 77.2%(143개)에서 백신 엔진들의 탐지 결과가 일관되지 않았습니다.
- 신빙성: 라벨은 AVClass2로 뽑았는데, macOS 분류 체계가 덜 성숙해 55.27%는 패밀리 라벨이 없었고 17.88%는 어떤 태그도 없었습니다. 정적 특징만 썼으므로 실행 중 언패킹이나 C2 통신은 보지 못했습니다. 샘플이 VirusTotal과 VirusShare에서 왔기 때문에 이미 탐지되기 쉬운 위협 쪽으로 치우쳤고, 정상 샘플은 주로 macOS 시스템 파일이라 실제 앱의 다양성을 담지 못한다고 저자들이 밝혔습니다.

#### Comment
- macOS 악성코드 연구의 가장 큰 걸림돌인 공개 데이터셋 문제를 해결하려는 기여로, 탐지 모델 학습이나 비교 연구의 기준 데이터로 쓰일 가능성이 있습니다. 다만 이 논문 자체에는 분류기 성능 평가가 없고 특성 분석에 집중합니다.
- 제목 검색에서 1저자와 이름이 같은 발표자의 Black Hat Europe 2025 자료("macOS 악성코드 최대 공개 데이터셋에서 얻은 통찰")가 나왔지만, 이 논문과의 관계는 본문에서 확인하지 못했습니다. 학술 심사는 아직 거치지 않은 원고입니다.

# Agentic Discovery of Soundness Bugs in Safe Rust Bindings
> arXiv 프리프린트 (심사 전). UC 버클리
> 2026

러스트 크레이트는 C/C++ 라이브러리 호출이나 시스템 호출 같은 unsafe 코드를 안전한 인터페이스 뒤에 감춥니다. 인터페이스가 하위 라이브러리의 규칙(어떤 호출이 객체를 해제하는지, 어떤 포인터가 다음 호출에서 무효가 되는지 등)을 타입에 너무 약하게 담으면, unsafe 블록이 하나도 없는 순수 안전 러스트 프로그램도 정의되지 않은 동작을 일으킬 수 있습니다. 예를 들어 ssh2 크레이트의 auth_methods는 libssh2가 다음 호출에서 해제하는 버퍼를 가리키는 문자열을 돌려주는데, 대여 검사기가 다음 호출을 허용해 해제 후 사용이 생깁니다. 저자들은 이런 결함을 정적 분석기나 퍼저가 잘 찾지 못한다는 점에서 LLM 에이전트를 감사자로 쓰는 방법을 연구했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.31813
- arXiv HTML 본문: https://arxiv.org/html/2611.31813
- arXiv PDF: https://arxiv.org/pdf/2611.31813

### Contribution
- 바인딩 결함을 정의되지 않은 동작, 감싼 라이브러리와의 동작 차이, 불완전한 unsafe 계약의 세 갈래로 나눈 분류 체계를 만들었습니다.
- 실제 크레이트(git2) 하나를 폐쇄형 모델(Claude Opus 5.5)과 공개 모델(DeepSeek V4.1 Flash)로 반복 감사해, 에이전트가 어떤 결함을 찾는지, 분류를 얼마나 잘하는지, 무엇이 더 많이 찾게 하는지 측정했습니다.
- 이 결과를 C-to-Rust 작업 자동화 시스템 CRUSTIFY에 넣어 대규모로 실행했습니다.

### Evaluation
- 감사 행동: 에이전트는 앞의 두 종류는 지시 없이도 찾았지만, 불완전한 계약은 요청해도 거의 찾지 못했습니다. 독립 검토자 없이도 발견은 거의 항상 실제 결함이었지만, 새니타이저로 확인하는 일이 드물고 일찍 멈추는 등 분류 규율이 부족했습니다. 같은 지침을 주면 공개 모델이 폐쇄형 모델과 같은 수의 결함을 4분의 1 비용으로 찾았습니다.
- 대규모 실행: OpenSSL, SQLite, libgit2, libcurl 바인딩과 V8 엔진 바인딩을 포함한 널리 쓰이는 크레이트 16개에서 정의되지 않은 동작 버그 225개, 동작 차이 23개, 불완전한 계약 36개를 찾았습니다(크레이트당 3~61개, 감사당 비용 중앙값 50달러 미만). 리눅스 커널의 러스트 추상화에서도 정의되지 않은 동작 버그 11개와 불완전한 계약 4개를 더 찾았습니다.
- 보고한 83개 중 26개를 관리자들이 고쳤습니다.
- 신빙성: 행동 분석은 한 크레이트의 한 리비전만 대상으로 했고 프롬프트도 그 크레이트에서 다듬었습니다. 정답 데이터가 없어 재현율은 보고하지 못하고 발견 수와 일치도만 보고했습니다. 해당 크레이트의 일부 결함은 이미 공개되어 있었고 모델이 학습 중에 봤을 가능성을 완전히 배제하지 못한다고 저자들이 밝혔습니다.

#### Comment
- "안전한 러스트로 다시 쓰면 메모리 안전성이 확보된다"는 기대가 FFI 바인딩의 타입 설계 오류로 쉽게 무너질 수 있다는 점을 대규모 실측으로 보여 준 논문입니다. 커널 러스트 추상화에서도 결함이 나온 점이 눈에 띕니다.
- 패치 반영률(83개 중 26개)이 아직 낮아, 보고된 결함 상당수가 열려 있는 상태로 보입니다.
- 게재처가 정해지지 않은 심사 전 원고입니다. 코드 공개 주소는 본문에서 찾지 못했습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).
