# Revealing Semantic Gaps in Zero-Knowledge Virtual Machines via Obligation-Targeted Semantic Fuzzing
> NDSS Symposium 2027 채택(본문에 NDSS 2027 DOI 표기), arXiv 등록. UC 샌타바버라, 상하이 교통대학교, UC 샌디에이고
> 2026

영지식 가상 머신(zkVM)은 RISC-V 같은 명령어 집합으로 작성한 프로그램이 올바르게 실행됐음을 증명하며, 블록체인 롤업 등에서 막대한 자산을 지킵니다. 보안은 명령어 집합 명세와 제약 시스템(증명자가 기록한 중간값, 즉 witness를 검사하는 다항식)이 정확히 맞물리는지에 달려 있습니다. 둘이 어긋나는 "의미 격차"에는 두 종류가 있습니다. 제약이 너무 느슨해 악의적 증명자가 명세상 불가능한 실행의 증명을 위조할 수 있는 과소 제약 버그(건전성 위반)와, zkVM 자체가 명세와 다르게 동작하거나 멈춰 정직한 증명자가 정상 실행을 증명하지 못하는 발산 버그(완전성 위반)입니다. 둘 다 0으로 나누기 같은 경계 사례에 몰려 있고, 과소 제약 버그는 프로그램 출력이 바뀌지 않아 일반 퍼징으로는 보이지 않습니다. 저자들은 명령어 집합 명세와 증명 시스템의 대수 구조에서 "제약 의무" 60개를 도출하고, 이를 강화 학습 퍼저의 세 가지 무작위 결정(초기 입력, 보상, witness 변조 위치)에 대신 넣은 Beak을 만들었습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.29260
- arXiv HTML 본문: https://arxiv.org/html/2611.29260
- arXiv PDF: https://arxiv.org/pdf/2611.29260
- NDSS 2027 DOI: https://dx.doi.org/10.14722/ndss.2027.232037
- 저자 저장소(코드): https://github.com/whbjzzwjxq/beak-fuzz

### Contribution
- 각 의무를 (입력 생성 템플릿, 활성화 조건, witness 주입 템플릿) 세 쌍으로 정의해, 한 번 도출하면 여섯 개 zkVM에 공통으로 재사용할 수 있게 했습니다.
- 보상을 실행기 코드 커버리지 대신 "새로운 의무 조합을 건드렸는가"로 바꿨고, witness 변조를 의무가 활성화된 단계에 고정해 수백만 개 값 가운데 무작위로 바꾸던 기존 방식의 낮은 적중률 문제를 풀었습니다.
- 발산 버그는 기준 RISC-V 에뮬레이터와 레지스터를 비교해, 과소 제약 버그는 변조한 witness를 제약이 받아들이는지로 판정했습니다. 과소 제약은 변조된 witness로 증명을 끝까지 생성하고 zkVM 자체 검증기가 받아들일 때만 탐지로 셌습니다.

### Evaluation
- 대상: 증명 구조 네 가지에 걸친 상용 RISC-V zkVM 6종(SP1, Pico, OpenVM, Risc0, Jolt, Nexus)을 고정 커밋으로 시험했습니다.
- 알려진 버그 벤치마크: ArguZZ 보고, 전문 보안 감사 보고서, 공개 이슈에서 모은 37건(과소 제약 28건, 발산 9건)입니다. Beak은 25건(67.6%)을 찾았고, 기존 최고 도구 ArguZZ는 5건(13.5%), 일반 무작위 퍼저는 3건(8.1%)이었습니다. ArguZZ는 공개 아티팩트를 같은 하드웨어와 같은 시간·코어 예산으로 다시 돌렸습니다.
- 다섯 번 반복 실행에서 각각 22, 23, 23, 18, 24건을 찾았고, 버그별 탐지 시간 중앙값은 0.7초~0.64시간(전체 중앙값 약 2분)이었습니다.
- 제거 실험: 세 장치를 모두 빼면 발산 버그 9건만 찾았고, 입력 생성 템플릿을 빼면 16건, 보상을 코드 커버리지로 바꾸면 19건으로 줄었습니다.
- 신규 버그: 최신 개발 브랜치에서 알려지지 않은 버그 14건을 찾아 모두 알리고 패치됐습니다.
- 신빙성: 정답 벤치마크를 외부 출처에서 독립적으로 모았고, 반복 실행 결과도 보고해 비교가 공정한 편입니다. 다만 의무 60개는 RV32IM에 맞춰 도출한 것이라 다른 명령어 집합이나 새 구성 요소에는 새 훅이 필요하고, 놓친 12건은 여러 구성 요소를 함께 바꿔야 하는 버그였다고 저자들이 밝혔습니다.

#### Comment
- 명세에서 체계적으로 뽑은 "의무"를 퍼저의 안내 신호로 쓰는 접근은 zkVM 밖의 다른 검증 대상(예: 하드웨어 명세 대 구현)에도 적용할 여지가 있습니다.
- NDSS는 최상위 보안 학회입니다. 공저자 한 명이 상하이 교통대학교 소속이지만 1저자와 교신 저자가 UC 샌타바버라 소속이고, 코드 저장소가 실제로 공개되어 있음을 확인했습니다.

# Verifying Declared AI Workloads from GPU Supply Current
> arXiv 프리프린트 (심사 전). 멜버른 대학교 수학통계학부, MATS(Machine Alignment, Transparency & Security) 프로그램
> 2026

AI 컴퓨팅 관련 국제 합의가 실효성을 가지려면, 외부 검증자가 하드웨어 운영자가 금지된 작업(예: 숨겨진 대규모 학습)을 돌리지 않는다는 것을 확인할 수 있어야 합니다. 기존 연구는 검증자가 허용·금지 작업의 예시를 직접 만들어 분류기를 학습시키는 방식이었는데, 이 방식은 다른 칩으로 옮겨야 하고 예상한 회피 전략에만 통합니다. 저자는 검증자가 운영자 하드웨어에서 "신고된 허용 작업"(유휴, 추론)의 전류 서명만 기록하고, 이후 그 서명에서 벗어나는 신호를 표시하는 방식(서명 검사)을 제안했습니다. 금지 작업이나 회피 전략의 예시가 필요 없습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.29982
- arXiv HTML 본문: https://arxiv.org/html/2611.29982
- arXiv PDF: https://arxiv.org/pdf/2611.29982
- 저자 저장소(코드, 결과, 논문 PDF와 TeX 원고): https://github.com/tomkimpson/verifying-declared-ai-workloads

### Contribution
- GPU 공급 전류를 로고스키 코일로 칩 밖에서 측정해, 운영자 협조 없이 얻을 수 있는 아날로그 신호로 작업을 검증할 수 있음을 실측으로 보였습니다.
- 금지 학습을 숨기는 회피 전략 다섯 가지(추론과 시분할하는 방식 포함)를 고려하고, 허용 작업만으로 맞춘 단일 클래스 모델로 이를 잡아냈습니다.
- 신고 기록이 불완전하거나 오염됐을 때의 실패 양상을 분석했습니다. 불완전한 기록은 경보가 계속 울려 드러나지만, 운영자가 기록 중에 학습을 섞어 넣은 오염 기록은 조용히 실패할 수 있다는 점을 보였습니다.

### Evaluation
- 데이터: NVIDIA H200 NVL 한 장에서 유휴, 학습, 추론 작업의 전류를 23.4시간 기록했습니다. 학습 대상은 1억 6,800만 파라미터 모델 하나입니다.
- 결과: 다섯 가지 회피 전략을 포함해 금지 학습 구간의 99.9% 이상을 표시했습니다. 연속 감시기로 쓰면 추론과 시분할로 숨긴 금지 학습 188건을 모두 잡았고(지연 중앙값 3.0초), 신고된 작업 8.8시간 동안 오경보는 1번이었습니다. 유휴 기록이 빠지면 신고된 유휴 시간의 99.97% 동안 경보 상태가 됐습니다.
- 신빙성: 저자 스스로 밝힌 대로 숨긴 학습 탐지는 시험일 데이터를 채점하기 전에 개발 데이터로 측정했으므로, 완전히 미리 떼어 둔 데이터에서 나온 수치는 오경보율과 감시기 결과뿐입니다. GPU 한 장, 모델 하나라는 규모 제약이 있어 여러 GPU에 걸친 대규모 학습에 그대로 적용된다고 보기 어렵습니다.

#### Comment
- AI 거버넌스용 컴퓨팅 검증이라는 새 보안 응용 분야의 실측 연구입니다. 결과는 매우 좋지만 단일 GPU 실험이며, 저자 본인도 확장성을 주요 한계로 꼽았습니다.
- 저자 저장소에 논문 PDF와 TeX 원고가 함께 있어 그 PDF로 본문을 읽었고, 제목, 저자, 초록 핵심 수치가 arXiv 후보 목록의 초록과 일치함을 확인했습니다.
- 본문 출처: 저자 저장소의 논문 PDF.

# LaTSEC: Lattice-Based Threshold Signatures with Native Non-Interactive Identifiable Abort and Compact Per-Party Storage
> arXiv 프리프린트 (심사 전), IACR ePrint 2026/2948에도 등록. 모나시 대학교, 탐페레 대학교
> 2026

임계 서명은 서명 키를 n명에게 나눠, 충분히 많은 참여자가 모여야 서명할 수 있게 하는 방식입니다. 양자 내성 격자 기반 임계 서명에서 부정 행위자를 가려내는 "식별 가능한 중단(identifiable abort)"을 지원하려면, 기존에는 영지식 증명, 추가 대화형 프로토콜, 또는 참여자마다 여러 개의 짧은 부분 키와 그만큼의 공개 검증 키를 두는 방식 중 하나를 써야 했습니다. 세 번째 방식은 참여자당 저장량이 크게 늘어납니다. 저자들은 무손실 확장 그래프 기반의 최근 비밀 분산 방식 SEC를 써서 참여자마다 짧은 서명 키 하나와 공개 중단 키 하나만 두는 3라운드 격자 임계 서명 LaTSEC를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.30063
- arXiv HTML 본문: https://arxiv.org/html/2611.30063
- arXiv PDF: https://arxiv.org/pdf/2611.30063
- IACR ePrint: https://eprint.iacr.org/2026/2948
- 저자 저장소(구현과 논문 PDF): https://github.com/latsec-ts/latsec

### Contribution
- 부분 서명을 해당 참여자의 공개 중단 키로 바로 검증할 수 있어, 영지식 증명이나 추가 프로토콜 없이 부정 행위자를 식별합니다.
- 표준 MLWE와 MSIS 가정에서 정확성, 식별 가능한 중단 안전성, 임계 위조 불가능성을 증명했습니다. 위조 불가능성 증명을 위해 공개 중단 키들 사이의 상관관계를 담은 새 문제(Repeated-A Matrix Hint-MLWE)를 정의하고 표준 MLWE에서 환원됨을 보였습니다.
- Rust 구현(성능 측정용)과 논문 알고리즘을 줄 단위로 따른 Python 구현(테스트 벡터 생성용)을 공개했습니다.

### Evaluation
- 파라미터: 참여자 60명, 128비트 보안에서 최대 6명의 부정 참여자를 견디고, 무작위로 고른 46명 이상이 모이면 0.99 이상의 확률로 서명할 수 있었습니다(실험 추정치). 참여자당 서명 키는 약 14.3KiB, 공개 중단 키는 24.0KiB입니다.
- 비교: 같은 방식 계열인 sDKG(복제형, 램프형)와 Hermine과 저장량을 비교했습니다. 다만 이들 논문은 n=40, 60의 파라미터를 제시하지 않아 공유 구조로부터 외삽한 값이며, 저자들도 보안 검증된 파라미터가 아니라고 밝혔습니다.
- 성능: AMD Ryzen AI 9 HX 370 단일 코어에서 n=60일 때 서명자당 세 라운드 합계 7.6ms, 결합 33ms, 검증 0.76ms였습니다. 변조한 커밋, 공개값, 부분 응답 시험에서 일탈한 서명자만 지목됨을 확인했습니다.
- 신빙성: 구현은 연구용 시제품으로 완전한 상수 시간 구현이 아니고, 키 생성에 신뢰할 수 있는 배포자를 쓰며, 모든 참여자를 한 프로세스에서 돌렸습니다. 실제 네트워크 환경의 통신 지연은 반영되지 않았습니다.

#### Comment
- NIST의 다자간 임계 서명 공모를 겨냥한 연구로, 저장 공간이 제한된 장비에서 격자 임계 서명을 쓰려는 경우 참고할 만합니다. 공저자 Markku-Juhani O. Saarinen은 양자 내성 암호 구현 분야에서 잘 알려진 연구자입니다.
- 서명에 참여하지 않는 일부 참여자도 세 라운드 내내 온라인으로 남아야 한다는 운영상 제약이 있습니다.

# SecretSifter: A Runtime Secret-Detection Engine for Live Web Traffic
> SoftwareX 36 (2026) 103087 게재(오픈 액세스, 게재판 원고), arXiv 등록. 독립 보안 연구자(단독 저자)
> 2026

API 키, 접근 토큰 같은 비밀 정보 탐지는 지금까지 주로 소스 저장소와 CI 파이프라인을 훑는 스캐너(TruffleHog, git-secrets 등)가 맡아 왔습니다. 그런데 webpack, Vite 같은 번들러가 빌드 시점에 환경 변수 값을 결과물에 그대로 박아 넣거나, 설정 API와 서버 렌더링 상태 객체가 실행 중에 자격 증명을 브라우저로 내려보내면, 그 값은 저장소에 한 번도 나타나지 않습니다. SecretSifter는 이 틈을 겨냥해 실제 웹 트래픽을 가로채 분할된 자바스크립트 청크, 인라인 스크립트, `__NEXT_DATA__` 같은 서버 렌더링 상태, JSON·XML 응답, 요청·응답 헤더까지 한 번에 훑는 도구입니다. 하나의 탐지 엔진을 Burp Suite 확장, 크롬 확장, 윈도·macOS 데스크톱 앱 세 가지 형태로 배포하고, 외부 LLM 에이전트가 결과를 분류할 수 있도록 루프백 REST·MCP 서버를 둡니다.

### Evaluation
- 데이터셋: 단일 기관의 승인된 점검에서 56개 애플리케이션의 운영 자바스크립트로부터 모은 값 198개(GT-198)입니다. 정적 값 161개(APIM 구독 키 51, Azure AD client_secret 33, OAuth 식별자 40 등)와 CryptoJS-AES 암호화 설정 37개로 이뤄집니다. 정답은 Claude Opus 4.7로 추출하고 GPT-5.5로 교차 확인(고신뢰 확인율 89.9%)한 뒤 분석가가 직접 보강했습니다.
- 비교 대상: TruffleHog, SecretFinder, JSluice, Titus, JS-Miner, Nuclei, Sensitive Discoverer, Cariddi를 모두 기본 설정으로 돌렸습니다.
- 결과: SecretSifter는 198개 중 158개를 찾아 재현율 79.8%, 오탐 24건으로 정밀도 86.8%, F1 83.2%였습니다. 정적 스캐너 중 최고인 TruffleHog의 재현율은 35.9%였습니다.
- 신빙성: 저자 스스로 한계를 꽤 솔직하게 적었습니다. 벤치마크가 한 기관에서 나왔고, 우위의 대부분을 차지하는 Azure APIM과 CryptoJS 부류 규칙이 그 환경을 알고 만든 것이라 일반화 성능이 아니라 "같은 환경 안의 탐지 성능"으로 읽어야 합니다. 경쟁 도구에 규칙 6개를 공통으로 추가하면 정적 텍스트에서는 통계적으로 차이가 없어진다고 함께 보고했습니다. 실제 비밀이 담긴 GT-198은 공개할 수 없어 수치는 제3자가 재현할 수 없고, OAuth 식별자 40개를 빼고 다시 계산한 비교 지표는 제시하지 않았습니다.

# Anti OS Fingerprinting, Revisited: A Loadable Kernel Module for FreeBSD and What Twenty-Five Years Changed
> arXiv 기술 보고서 (심사 전). 일본 정책연구대학원대학(GRIPS), 단독 저자
> 2026

원격 OS 지문 채취는 TCP/IP 스택이 명세상 자유롭게 채울 수 있는 필드(TTL, 창 크기, TCP 옵션 순서 등)를 보고 상대 운영체제를 알아내는 기법입니다. 저자는 2001년에 FreeBSD 4.3 커널 소스를 고쳐 Nmap 탐침에 다른 OS처럼 답하게 하는 Anti OS Detection(AoD)을 발표했는데, 이 보고서는 같은 목표를 FreeBSD 15.1에서 다시 구현하고 그동안 무엇이 바뀌었는지 기록합니다. 저자는 새 방법을 주장하지 않는다고 분명히 밝히고, NIST SP 800-160 2권이 사이버 복원력 기법으로 꼽은 "기만(Deception)"의 작은 구체적 사례로 이 작업을 위치시킵니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.28651
- arXiv HTML 본문: https://arxiv.org/html/2611.28651
- arXiv PDF: https://arxiv.org/pdf/2611.28651
- 저자 저장소(코드와 측정 스크립트): https://github.com/daisu-mi/aod

### Contribution
- 커널 소스를 고치지 않고, pfil(9) 패킷 필터 훅 두 개(수신, 송신)와 커널 변수 하나만 쓰는 약 800줄짜리 적재형 모듈로 구현했습니다. 연결별 상태를 두지 않습니다. 창 크기와 초기 순서 번호는 모든 TCP 스택이 공유하는 SYN 캐시가 만들기 때문에 패킷 훅에서 고치는 편이 맞다는 설계 근거를 제시합니다.
- 송신 쪽에서는 TTL, DF, IP ID, SYN·SYN/ACK 창 크기, TCP 옵션 순서, 타임스탬프 옵션, 창 배율을 바꾸고, 수신 쪽에서는 흉내 내는 OS가 다르게 답하는 패킷(플래그 없음, SYN+FIN 등)에 대신 답하거나 버립니다. 리눅스(데이터베이스 기준, 실측 기준)와 윈도 11 위장 설정을 표 형태로 정리했습니다.
- 가장 가치 있는 부분은 "Nmap 하나로만 확인하면 무엇을 놓치는가"를 단계별로 기록한 점입니다. Nmap에서 정확히 일치한 뒤에도 p0f(수동 탐지)는 호스트가 보내는 SYN의 IP ID와 타임스탬프 옵션 차이를 잡아냈고, FIN·Xmas 스캔은 열린 포트의 FreeBSD식 무응답을 드러냈으며, 실제 윈도 호스트와 비교해 보니 "나가는 연결에는 타임스탬프를 제안하지 않고 들어오는 연결에서는 받아들인다"는 동작을 두 위장 설정이 각각 절반씩만 흉내 내고 있었습니다.

### Evaluation
- 환경: QEMU/KVM 위의 FreeBSD 15.1(8 vCPU, 8GB)을 대상으로, 같은 호스트의 실제 Ubuntu 26.04.1(리눅스 7.0)과 윈도 11 Enterprise 게스트를 비교군으로 두었습니다.
- 결과: 최종 윈도 위장 설정과 실제 윈도 11은 Nmap 7.98, p0f 3.09b, JA4T 판정이 모두 같았고, Nmap 지문의 OPS~IE 줄이 모두 일치했습니다. 반면 Nmap 데이터베이스가 리눅스 6.0에서 멈춰 있어 실제 리눅스 7.0 호스트는 정확히 일치하지 않았는데, 데이터베이스로 만든 위장 설정은 정확히 일치했습니다. 저자는 이를 "리눅스보다 더 리눅스 같다"고 표현하며, 지나치게 잘 인식되는 호스트가 오히려 신호가 될 수 있다고 지적합니다.
- 비용: iperf3 처리량, 초당 연결 수, ping 지연의 차이가 측정 조건 내부 편차보다 작았고, 훅 한 번 실행 시간은 400~480ns(조기 반환 경로 378ns)였습니다.
- 신빙성: 가상 머신 한 쌍과 실제 OS 두 종으로 한정된 실험이고, 대규모 실망(實網) 시험은 없습니다. 다만 각 도구의 판정 문자열과 측정값을 그대로 공개하고 불일치까지 보고해 결과를 검증하기 쉬운 편입니다.
