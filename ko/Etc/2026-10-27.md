# The 3DS Oracle: BIN Attack via the Network
> arXiv cs.CR (확장판 프리프린트, 심사 전), 방글라데시 BRAC 대학교
> 2026

온라인 카드 결제에서 3-D Secure(3DS)는 원래 사기를 막는 인증 장치지만, 이 논문은 브라우저 경유 3DS 연동 방식에서 결제 승인 전에 클라이언트가 볼 수 있는 응답이 카드 발급사의 라우팅 정보와 계정 상태를 드러내는 분류 채널이 될 수 있다고 주장합니다. 공격자는 Luhn 검사를 통과하는 카드 번호(PAN) 후보를 만들어 3DS 조회 단계의 첫 응답만 보고 실제 발급된 카드인지 가려낼 수 있고, 실제로 이런 신호를 이용하는 카드 테스트 도구와 유료 서비스가 이미 존재한다고 정리합니다. 표준 분석, 구조 재구성, ProVerif 형식 모델링, 문서 감사, 제한된 실측을 결합한 연구입니다.

원문: https://arxiv.org/abs/2610.32206

### Contribution
- 3DS의 첫 조회 단계(AReq/ARes) 응답이 연구자 소유 카드와 인접 번호 사이에서 서로 다른 응답 유형으로 갈리는 현상을 실측으로 확인했습니다.
- EMVCo 규격의 트랜잭션 ID 동일성 규칙을 형식화해, 응답이 어느 구성 요소에서 생성됐는지 조건부로 귀속할 수 있음을 보였습니다.
- 카드 번호 공간을 접두어 트리로 보고, 디렉터리 서버 단계의 조기 차단 응답이 범위 경계 사유 코드와 함께 나오면 탐색량을 크게 줄일 수 있다는 범위 가지치기 모델을 제시했습니다.
- 문제의 원인을 개별 사업자의 결함이 아니라 승인 이전 인증의 분리, 요청자 경계에 대한 약한 가정, 책임 분산이라는 구조적 문제로 정리하고 컨소시엄 차원의 개선안을 제안했습니다.

### Evaluation
- 연구자가 통제하는 가맹점 배포에서 Braintree/Cardinal 브라우저 경로를 대상으로, 서로 다른 발급사 인증 서버와 카드 범위에 속하는 연구자 소유 카드 7장(Visa, Mastercard)과 각 카드에 인접한 Luhn 유효 번호 3개씩, 총 28개 입력을 5번씩 새 세션으로 조회했습니다(140회 관측). 7개 집단 중 6개에서 응답 유형이 분리됐습니다.
- 브라우저나 SDK를 실행하지 않는 독립 HTTP 클라이언트로 요청했고, 결제 승인과 정산은 시도하지 않았습니다. Stripe와 Adyen에 대한 점검은 범위를 더 좁혀 별도로 보고합니다.
- 지표 신빙성: 표본이 매우 작고 윤리적 이유로 의도적으로 제한된 실험이라, 네트워크 전체에서의 유병률이나 실제 공격 규모를 주장하지 않는다고 저자가 분명히 밝힙니다. 형식 모델은 실측을 보완할 뿐 예측하지 않는다고 범위를 스스로 한정합니다.

#### Comment
- 결제 생태계에서 "각자는 규격을 지켰는데 전체로는 정보가 샌다"는 구조적 문제를 짚은 점이 독특합니다. 서론에서 IEEE S&P 2017의 관련 연구를 잇는 위치를 명확히 합니다.
- 2018년부터 진행된 독립 연구를 바탕으로 한 확장판 원고로, 분량이 매우 길고 표현이 방어적일 만큼 조심스럽습니다. 학회나 저널 심사를 거치지 않았으며, 책임 있는 공개 절차를 시작했다고 적고 있습니다.
- 실험 세부 기록 일부는 공개하지 않아 독립적인 재현은 어렵습니다.

# Not an Accident: Exploiting Safety Filter Inadequacy in Humanoid Robots
> arXiv cs.CR (프리프린트, 심사 전), 애리조나 주립대학교, 카네기멜런대학교
> 2026

휴머노이드 로봇의 최적화 기반 안전 필터는 주변 사람이나 물체와 충돌하지 않도록 제어 명령을 수학적으로 보정합니다. 이 논문은 그 보장이 파라미터가 작업과 환경에 맞게 설정됐을 때만 성립하며, 설정이 맞지 않으면 일반 사용자 권한만으로도 충돌을 유도할 수 있다는 점을 보입니다. 공격자가 정상 작업 사이에 중간 목표 지점 하나를 끼워 넣으면(goal insertion attack), 로봇이 원래 목표로 돌아가는 과정에서 안전 필터가 회피에 실패해 충돌하거나 멈춥니다. 이런 공격 지점을 자동으로 찾는 도구 SIREN을 제안합니다.

원문: https://arxiv.org/abs/2610.31923

### Contribution
- 안전 필터의 회피 속도 부족, 제어 권한 부족, 선제적 실패 회피 부재라는 세 가지 실패 원인을 분석하고, 이를 보안 취약점으로 처음 정식화했습니다.
- 교차 엔트로피 기법(CEM)으로 공격용 중간 목표를 탐색하는 SIREN을 구현했습니다.
- SSA, CBF, SSS와 그 완화 변형, p-SSA까지 7가지 대표 안전 필터를 시뮬레이션과 실제 Unitree G1 휴머노이드에서 모두 공격했습니다.

### Evaluation
- SPARK 벤치마크에서 원래 작업은 성공하지만 중간 목표를 넣으면 실패하는 취약 시나리오를 필터당 5개, 총 35개 구성해 비교했습니다. SIREN은 3,277개, 무작위 탐색은 1,760개의 공격을 찾았고, 두 방법 모두 35개 시나리오 전부에서 최소 하나의 공격을 찾았습니다.
- 실제 로봇 실험은 상체 모델과 정적 장애물 조건에서 필터마다 시나리오 하나씩 무작위로 골라 재현했고, 시뮬레이션과 같은 실패가 실제 로봇에서도 나타났습니다.
- 지표 신빙성: 공격 없이도 실패하는 작업은 제외하는 판정 기준을 써서 공격 효과를 분리했습니다. 다만 초록에서는 기준선 대비 "세 배"라고 쓰고 본문과 기여 목록에서는 1.86배(3,277 대 1,760)로 적고 있어 수치가 서로 맞지 않습니다. 본문 수치를 기준으로 보는 것이 타당합니다.

#### Comment
- 안전 장치 자체가 공격 표면이 될 수 있다는 관점을 로봇 제어 영역에 적용한 연구로, 보안 연구자(Tiffany Bao, Ruoyu Wang, David Brumley)와 로봇 제어 연구자(Changliu Liu)의 협업이라는 점이 특징입니다.
- 공격자가 배포된 안전 필터의 알고리즘과 파라미터를 모두 안다고 가정하며, 임의의 작업과 환경에서 공격이 존재할 확률은 추정하지 못한다는 한계를 저자가 직접 밝힙니다. 실제 로봇 검증도 상체, 정적 장애물이라는 좁은 조건에 한정됩니다.

# SEMPRE: Semantic-Aware Protocol Reverse Engineering via Consistency-Driven Joint Optimization
> arXiv cs.CR (프리프린트, 심사 전), 일리노이 공대, 인디애나 대학교, 난양공대, 싱가포르경영대학교
> 2026

문서가 없는 독자 프로토콜이나 악성코드 명령 제어 통신을 분석하려면 메시지를 필드로 나누고 각 필드의 의미를 알아내는 프로토콜 역공학이 필요합니다. SEMPRE는 동적 프로그램 분석에서 얻은 오염 흐름과 반복문 실행 흔적을 근거로, LLM이 생각의 나무(tree-of-thought) 방식으로 메시지를 필드로 나누고 중첩된 하위 페이로드까지 찾아 계층 구조를 만듭니다. 이어 필드의 타입과 역할을 추론하고, 확신도가 높은 부분은 고정한 채 경계를 다시 다듬는 과정을 수렴할 때까지 반복합니다.

원문: https://arxiv.org/abs/2610.31844

### Contribution
- 손으로 짠 휴리스틱 대신, 동적 분석 근거에 묶인 LLM 재귀 추론으로 필드 분할과 의미 추론을 수행하는 완전 자동 프레임워크를 제안했습니다.
- 필드 경계와 의미를 번갈아 개선하는 EM 방식의 공동 최적화로, 단계를 거칠수록 결과가 단조롭게 좋아지도록 설계했습니다.
- 버퍼를 두 번 읽는 Mirai 변종처럼 기존 도구의 단일 패스 가정이 깨지는 경우에도 동작함을 보였습니다.

### Evaluation
- 비교 대상: PolyGlot, Tupni, AutoFormat, BinPRE, BinaryInferno, DynPRE의 6개 기법. 앞의 넷은 원저자 코드를 그대로 썼고, 코드가 없는 BinaryInferno와 DynPRE는 논문을 보고 다시 구현했습니다.
- 데이터: BinPRE 논문의 8개 프로토콜(Modbus, S7comm, Ethernet/IP, DNP3, DNS, FTP, TFTP, HTTP), 깃허브의 문서 없는 실제 프로토콜 3종(KTP, CCN, Xfer), 사례 연구로 Mirai 봇넷 프로토콜을 사용했습니다.
- 필드 탐지 평균 F1은 0.76으로 가장 강한 경쟁자인 BinPRE의 0.39를 크게 앞섰고, 의미 추론 F1은 0.72로 BinPRE의 0.13보다 높았습니다. Mirai 사례에서 BinPRE는 단일 패스 가정이 깨져 정확도가 거의 0이었고, 버퍼를 두 번 읽는다는 힌트를 줘도 필드 F1이 0.55에 그친 반면 SEMPRE는 힌트와 관계없이 0.83이었습니다. 백본 모델은 GPT-o3입니다.
- 지표 신빙성: 원 코드 재사용과 정답 표기 기준(Table I)을 공개한 점은 좋지만, BinPRE가 메시지 데이터를 공개하지 않아 저자들이 직접 수집한 메시지로 평가했고, 기준선 둘은 재구현이라 결과 차이를 그대로 받아들이기보다는 일부 감안할 필요가 있습니다.

#### Comment
- 의미 기능 라벨이 BinPRE와 맞추느라 6가지로 제한되고, 바이트 단위 오염 추적을 재사용해 CAN처럼 비트 단위로 의미가 담기는 프로토콜에는 약하다는 한계를 저자가 직접 밝힙니다.
- LLM 환각 문제를 동적 분석 근거로 억제하는 설계는 악성코드 C2 분석이나 IDS 시그니처 생성 같은 실무에 바로 연결될 수 있습니다. 익명화된 저장소로 코드를 공개했습니다.

# Embedding Large PQC KEMs in IKEv2
> arXiv cs.CR (프리프린트, 심사 전), 독일 genua GmbH 등 산학 공동 연구
> 2026

양자 내성 암호(PQC)의 키 캡슐화 메커니즘(KEM)은 공개키가 매우 커서, 초기 교환을 단편화할 수 없는 VPN 핸드셰이크 프로토콜 IKEv2와 잘 맞지 않습니다. IETF에서 여러 해결안이 논의되고 있지만 같은 조건에서 비교된 적은 없었습니다. 이 논문은 IETF 문서를 체계적으로 조사해 기존 제안 5가지를 추리고, 순방향 오류 정정을 쓰는 방식과 QUIC 위에서 IKEv2를 돌리는 QUIKE 및 복합 키 교환을 결합한 QUIKE-composite까지 자체 제안 3가지를 더해 8가지를 같은 오픈소스 코드베이스에 구현해 비교했습니다.

원문: https://arxiv.org/abs/2610.32356

### Contribution
- IETF 제안들을 같은 구현 기반, 같은 테스트베드에서 처음으로 성능과 안정성 측면에서 비교했습니다.
- 기존 확인 응답 관련 초안에서 명세 공백 두 곳을 찾아냈습니다.
- 순방향 오류 정정 기반 방식과 QUIC 기반 QUIKE, QUIKE-composite을 새로 제안했습니다.

### Evaluation
- openiked-portable 위에 8가지 방식을 구현하고, 직접 연결한 베어메탈 리눅스 두 대에서 ML-KEM-1024, FrodoKEM-1344, Classic McEliece 8192128(모두 NIST 보안 수준 5)을 대상으로 대역폭(1/10/100Mbit/s), 지연, 패킷 손실(0~10%)을 바꿔 가며 1,296개 구성, 총 126,500회의 핸드셰이크를 측정했습니다. 측정 항목은 완료율, 완료 시간, 방향별 패킷 수입니다.
- 어떤 방식도 키 크기에 따른 성능 저하를 완전히 상쇄하지 못했습니다. Classic McEliece는 열악한 조건에서 모든 방식이 링크를 혼잡하게 만들거나 핸드셰이크당 평균 2분 가까이 걸렸습니다. ML-KEM과 FrodoKEM에서는 표준화된 확장을 개선하는 길과 전송을 QUIC에 위임하는 길이 있으며, 전반적으로는 QUIKE-composite이 가장 좋았습니다.
- 지표 신빙성: 구성마다 결론이 분명해질 때까지 반복 측정했고(최소 80회 이상), 전체 원시 데이터를 재현 패키지로 공개했습니다. 다만 netem의 무작위 손실은 실제 인터넷의 몰아치는 손실과 다르고, 구현 튜닝에 따라 특정 초안이 불리했을 수 있다는 점을 저자가 위협 요인으로 정리합니다.

#### Comment
- VPN 장비 제조사 연구진이 실제 구현을 바탕으로 IETF 논의에 실측 데이터를 제공한다는 점에서 표준화와 제품 개발 양쪽에 쓸모가 큽니다.
- 인증은 범위에서 빠져 있어 정적 사전 공유 키를 썼습니다. 양자 내성 서명까지 포함하면 메시지 크기 문제는 더 커질 수 있습니다.
- 제안 문헌 조사는 한 명이 선별했으며, 사전에 정한 기준과 선별 기록 전체를 공개해 보완했다고 밝힙니다.

# WADE: An LSTM-Based Anomaly Detection Engine for WebAssembly Applications
> arXiv cs.CR (프리프린트, 심사 전), 밀라노 공대, 노스이스턴 대학교
> 2026

WebAssembly는 스택 카나리아나 주소 공간 무작위화 같은 런타임 보호가 부족해 전통적인 메모리 공격에 노출됩니다. WADE는 브라우저에서 실행되는 WebAssembly 애플리케이션의 함수 단위 실행 흔적을 정상 조건에서 수집해 애플리케이션별 LSTM 모델을 학습하고, 실행 중 학습된 패턴에서 벗어나는 흐름을 공격으로 표시합니다. 취약점별 시그니처 없이 알려지지 않은 공격도 잡을 수 있다는 것이 목표입니다.

원문: https://arxiv.org/abs/2610.31984

### Contribution
- 브라우저 내 함수 단위 실행 흔적에서 비정상 제어 흐름을 찾는 이상 탐지 시스템을 설계했습니다.
- 임계값이 다른 탐지기 네 개를 병렬로 두고 가중 투표로 판정하는 다중 임계값 탐지 방식을 제안했습니다.

### Evaluation
- 표준 벤치마크가 없어 직접 데이터셋을 만들었습니다. 기존 연구에 기록된 실제 취약 프로그램 7개를 바탕으로, 그중 6개에서 Claude Opus 4로 변형 프로그램을 10개씩 생성해 총 67개를 구성했고, 생성된 변형은 수작업으로 검증했다고 합니다. 10가지 취약점 유형을 포함합니다.
- 재현율 100%(미탐 0), 정밀도 96.90%, F1 98.42%, 오탐률 0.42%를 보고합니다. 1차 마르코프 체인 기준선의 재현율은 7.1%에 그쳤습니다.
- 지표 신빙성: 평가 프로그램의 대부분이 소수 시드에서 LLM으로 파생된 변형이라 서로 유사할 가능성이 크고, 비교 대상도 단순한 마르코프 체인 하나뿐이어서 수치를 일반화하기는 어렵습니다.

#### Comment
- 저자가 직접 기저율 오류 문제를 짚은 점이 인상적입니다. 실제 공격 빈도가 매우 낮은 환경에서는 0.42% 오탐률이라도 경보의 약 5분의 4가 오탐일 수 있다고 계산해 보여 줍니다.
- 데이터만 바꾸는 공격이나 사이드 채널은 탐지 대상이 아니며, 학습 중 보지 못한 정상 경로는 오탐이 됩니다. 정상 전이만 이어 붙이는 모방 공격 같은 적응형 공격자도 평가하지 않았습니다.
