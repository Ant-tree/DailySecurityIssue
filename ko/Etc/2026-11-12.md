# Stinging the Swarm: Extracting Attacker Intelligence from a Twin-Controller OT Honeypot
> arXiv 프리프린트 (심사 전). TRACTIAN(산업 설비 모니터링 기업)
> 2026

언어 모델 에이전트가 Modbus 같은 필드버스 프로토콜로 산업 제어기를 직접 조작하고, 여러 에이전트가 동시에 공장을 탐색하는 상황이 현실이 되고 있습니다. 이 논문은 제어기 앞에 놓인 인라인 게이트 Talos를 제안합니다. 게이트는 요청마다 소형 온디바이스 모델로 몇 밀리초 안에 판단해 설비를 망가뜨리는 쓰기 요청을 막고, 적대적이라고 판단한 에이전트는 연결을 끊는 대신 같은 장치 계열과 시드로 만든 복제 제어기(미러 트윈)로 몰래 넘깁니다. 트윈은 모든 쓰기를 받아들이므로 공격자는 공격이 성공한다고 믿고 계속 행동하며, 그 과정에서 사용하는 도구와 노리는 레지스터 목록을 스스로 드러냅니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.13406
- arXiv HTML 본문: https://arxiv.org/html/2611.13406
- arXiv PDF: https://arxiv.org/pdf/2611.13406

### Contribution
- 탐지, 격리, 미러링, 정보 추출을 한 흐름으로 묶어, 차단만 하는 대신 공격자를 관찰하는 OT 방어 구조를 제시했습니다.
- 공격 에이전트를 지속성(저항을 만나도 계속 공격하는 정도)과 노출성(스스로 정보를 드러내는 정도) 두 축으로 나누고, 네 영역 중 세 영역에 정보 수집 경로가 있음을 보였습니다.
- 에이전트가 밝히는 신원은 꾸며낸 이야기지만, 스스로 보고한 도구 체계와 목표 레지스터 목록 같은 무심코 드러나는 단서는 여러 에이전트에 걸쳐 쌓여 높은 신뢰도의 공격자 프로필이 된다는 점을 보였습니다.
- 게이트, 미러, 실험 하네스를 합성 장치 계열과 함께 Apache 2.0으로 공개한다고 밝혔습니다(본문에 저장소 주소는 없음).

### Evaluation
- 설정: 거부 성향을 제거한 공개 모델(Llama-3.3-70B 기반 abliterated 판) 하나로 공격 에이전트 2,400개를 만들고, 은닉 노력에 따라 네 단계(은닉 없음, 정보 비공개 규칙, 허니팟 경고, 위장 신분) 600개씩 나눴습니다. 대상은 실제 인버터(ABB ACS880, Yaskawa GA500)를 본뜬 합성 양수 설비 하나입니다.
- 결과: 2,400개 에이전트 중 실제 설비에 반영된 쓰기는 0건이었습니다. 게이트는 설비 손상 경로의 쓰기를 99.4~100% 막았고, 정의되지 않은 레지스터 쓰기는 예외 없이 거부했습니다. 게이트가 허용한 1,427건(명령어 쓰기 1,421건, 비상 정지 6건)도 장치의 범위 검사에서 모두 거부됐습니다. 판단의 32~40%를 모델이 직접 내렸고 추론 시간 초과는 없었습니다.
- 정보 수집: 정보 비공개 규칙을 받은 에이전트는 55%가 트윈으로 넘어갔고 38%에서 정보를 추출했습니다. 위장 신분과 은닉 없음 단계는 격리 전에 96%, 100%가 진단 양식에 스스로 정보를 남겼습니다. 허니팟 경고를 받은 에이전트는 자발적 노출 0%, 격리 12%로 가장 어려운 경우였습니다.
- 지표의 신빙성: 공격 모델이 하나뿐이라 모델 간 일반화를 주장할 수 없고, 합성 장치 계열과 시드도 하나뿐이라 공격자가 트윈을 알아채는 상황은 시험하지 않았습니다. 저자들도 이를 한계로 적었습니다. 결과는 해당 공격 모델과 시나리오에서의 동작 확인으로 보는 것이 적절합니다.

#### Comment
- 실제 공장이나 고객 데이터 없이 합성 장치에서만 실험했고, 공격자 도구는 공개하지 않았다고 밝혔습니다.
- 기업 연구진이 자사 기술을 소개하는 성격이 강한 심사 전 원고입니다. 본문 제목과 부제가 홍보 문구에 가깝지만, 한계 절은 비교적 솔직합니다.

# Domain-Invariant and Language-Model-Assisted Acoustic Side-Channel Attacks on Keyboards
> arXiv 프리프린트 (심사 전, 인도 IIIT 델리 석사 학위 논문)
> 2026

키보드 소리로 입력 내용을 알아내는 음향 사이드 채널 공격은 같은 키보드에서 학습하고 시험하는 실험실 조건에서는 잘 되지만, 처음 보는 키보드, 다른 사용자, 소음, 압축된 VoIP 통화 같은 실제 조건에서도 통하는지는 분명하지 않았습니다. 이 학위 논문은 모델이 키 대신 "어느 키보드인지"를 학습해 버리는 것이 일반화 실패의 원인이라고 보고, 키보드 고유 특성 정규화, 도메인 적대 학습, 키보드 간 지도 대조 정렬, 음향 스타일 무작위화를 결합한 Decker를 제안했습니다. 여기에 음향 모델의 상위 후보들을 언어 모델의 제약된 빔 탐색으로 고쳐 문장과 비밀번호를 복원하는 공격을 더했습니다. 참가자 53명, 노트북 키보드 37종을 외장 마이크, 내장 마이크, VoIP로 녹음한 데이터셋 Hear도 함께 만들었습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.13922
- arXiv HTML 본문: https://arxiv.org/html/2611.13922
- arXiv PDF: https://arxiv.org/pdf/2611.13922
- 저자 데이터셋 저장소(Hear): https://github.com/vikrant-vikram/Hear-Dataset

### Contribution
- 키보드가 바뀌면 정확도가 약 40%포인트 떨어지는 일반화 문제를 여러 기준 모델에서 정량적으로 보였습니다.
- 도메인 불변 표현 학습으로 그 격차를 18%포인트 아래로 줄이고, 구성 요소별 기여를 제거 실험으로 확인했습니다.
- 언어 모델 후처리가 사람이 쓰는 문장과 사람이 고른 비밀번호 복원을 크게 높이지만, 무작위 고엔트로피 문자열에는 거의 효과가 없다는 점을 정리했습니다.
- 여러 기기, 사용자, 성별, 소음, 비가시선 녹음, 연속 문장, VoIP를 함께 담은 데이터셋을 공개했습니다.

### Evaluation
- 일반화 문제: wav2vec2, ECAPA-TDNN, CoAtNet-S, ResNet-34 모두 처음 보는 키보드에서 37~41%포인트 떨어졌습니다(예: ECAPA 95.3%에서 58.1%). 오디오와 스펙트로그램을 결합한 방식 8종도 처음 보는 키보드에서 62.7~66.2%에 그쳤습니다.
- Decker: 같은 키보드 98.9%, 처음 보는 키보드 81.3%(격차 17.6%포인트). 키보드 특성 정규화를 빼면 63.7%까지 떨어져 가장 큰 기여를 했습니다.
- 문장 복원: Decker 단독 문장 일치율 42.6%에서 GPT-2 Small 58.7%, FLAN-T5 62.1%, LLaMA-2 7B 66.5%, GPT-4 72.8%로 높아졌습니다. 키 입력 시점 오차 ±30ms에서도 FLAN-T5를 쓰면 52.0%를 유지했습니다. Apple M1 노트북에서 키당 2.3ms로 동작했습니다.
- 지표의 신빙성: 모든 실험이 저자가 만든 Hear 데이터셋 하나에서 이뤄졌고, 외부 공개 데이터셋에서의 교차 검증은 없습니다. 문장 복원 시험 문장이 언어 모델이 쉽게 맞히는 자연 문장 위주라면 수치가 높게 나올 수 있으며, 무작위 문자열에서는 효과가 거의 없다고 저자도 밝혔습니다. 학위 논문이라 동료 심사를 거치지 않았습니다.

#### Comment
- 형식은 석사 학위 논문이며, 본문에 따르면 Decker와 VoIP 관련 결과는 공동 연구자들과의 별도 논문들에 바탕을 둡니다.
- 키보드 대상 공격이지만 데이터셋에 스마트폰 마이크와 VoIP 경로가 포함되어 있어, 화상 회의 중 노트북 입력이 새어 나가는 위험을 다시 확인해 줍니다. 저자들은 하드웨어, 시스템, 모델 단의 방어책도 논의했습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# A Case Study of a Phishing Cluster Targeting German Universities
> arXiv 프리프린트 (심사 전). 베스트팔렌 응용과학대학 인터넷 보안 연구소, aDvens(독일)
> 2026

이 논문은 독일어권 대학을 노린 사이버 공격을 두 단계로 살펴봅니다. 먼저 2022년 2월부터 2023년 2월까지 독일어권 대학에 실제 피해가 확인된 공격 25건을 정리해, 이 기간 독일 전체 대학의 약 5%가 피해를 입었음을 보였습니다. 이어서 3년 넘게 이어진 "헬프데스크" 주제의 피싱 활동 군집을 URLScan 공개 스캔 기록에서 시각적 유사성과 도메인 연결을 따라가며 추적하고, 피해 대상과 공격 기법(TTP)을 분석했습니다. 눈에 띄는 기법은 이미 탈취한 대학 구성원 계정과 대학 VPN을 이용해 다른 대학의 메일 서버로 피싱 메일을 보내는 방식으로, 대학 간 신뢰를 악용합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.10698
- arXiv HTML 본문: https://arxiv.org/html/2611.10698
- arXiv PDF: https://arxiv.org/pdf/2611.10698
- 저자 공개 데이터(PATU23, OSF): https://osf.io/7vbzs?view_only=481b15d000d54319aff0339de276234a

### Contribution
- 독일어권 대학 대상 공격 25건의 시간표와 영향(데이터 유출, 암호화, 예방적 차단, 비밀번호 재설정 등)을 정리한 데이터셋을 만들었습니다.
- 공개 스캔 서비스 기록만으로 장기간 피싱 군집을 재구성하는 방법을 보여 주고, 442건의 스캔으로 이뤄진 데이터셋 PATU23을 공개했습니다.
- 받은 메일 헤더 분석과 다른 대학 5곳의 확인으로 "대학 1의 VPN으로 접속, 대학 2의 메일 계정으로 발송, 대학 3의 구성원을 공격"하는 발송 경로를 밝혔습니다.

### Evaluation
- 2023년 10월까지 피싱 사이트 270개를 찾았고, 이 가운데 164개(60.7%)가 103개 기관을 특정해 노렸으며, 그중 93개(90%)가 대학이었습니다. 대학 93곳 중 58곳(62%)이 독일 대학으로, 독일 대학 423곳의 약 14%에 해당합니다. 표적은 2020년 3월 호주 대학에서 시작해 2020년 5월부터 유럽, 특히 독일로 옮겨 갔습니다.
- 피싱 메일 24통(독일 학술 기관 14곳 관련)의 헤더에서 모두 학술 VPN IP가 확인됐습니다. 한 사례에서는 14일 동안 구성원의 11%가 피싱 메일을 받았습니다.
- 탈취 계정의 발신 메일을 보면 낮에는 피싱, 밤 10시 이후에는 대량 스팸을 보내 금전 목적일 가능성이 높다고 판단했습니다. 다만 같은 행위자인지는 인프라와 시간대의 겹침으로 추정한 것입니다.
- 지표의 신빙성: URLScan에 누군가 제출한 사이트만 보이므로 수치는 하한값이며, 저자들도 한 가지 페이지 디자인만 추적해 다른 변형은 놓쳤을 수 있다고 밝혔습니다.

#### Comment
- 대상 기간이 2020~2023년이라 최신 위협 정보는 아니지만, 대학 간 신뢰와 VPN을 악용하는 수법은 지금도 참고할 만합니다.
- 독일 대학 연구소와 보안 기업 연구진의 사례 연구이며 심사 전 원고입니다.
- 2026-11-11 실행에서 이월 후보로 남았던 논문입니다.

# How Well Do SAST Tools Work Across Languages? An Empirical Study Using OCPP Implementations
> 2026 IEEE International Conference on Cyber Security and Resilience (CSR), pp. 250-255 (저자 수용 원고, arXiv 공개)
> 2026

전기차 충전소 관리 프로토콜 OCPP는 사양이 추상적이라 구현마다 보안 수준이 달라질 수 있습니다. 이 논문은 서로 다른 언어 12개로 작성된 오픈소스 OCPP 1.6 구현 12개에 범용 정적 분석 도구(SonarQube, Semgrep)와 언어 전용 도구(Python의 Bandit, Java의 SpotBugs, C#의 Roslyn 등)를 적용해, 언어 생태계에 따라 정적 분석 결과가 어떻게 달라지는지 비교했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14362
- arXiv HTML 본문: https://arxiv.org/html/2611.14362
- arXiv PDF: https://arxiv.org/pdf/2611.14362

### Contribution
- 같은 프로토콜을 구현한 다언어 코드 묶음을 이용해 정적 분석 도구의 언어별 차이를 비교한 첫 실증 연구라고 주장합니다.
- 보안 중요 시스템의 구현 언어를 고를 때 그 언어에서 쓸 수 있는 정적 분석 도구 생태계도 고려해야 한다는 실무 시사점을 제시했습니다.

### Evaluation
- 결과: 언어별 탐지 건수는 Rust 2건에서 Java 1,689건까지 크게 달랐습니다. SonarQube가 3,428건, Semgrep이 160건을 냈고, Java에서는 SonarQube가 1,678건(주로 코드 품질과 스타일 문제), Python에서는 Bandit이 641건을 내 SonarQube(34건)보다 훨씬 많았습니다. Semgrep은 C 구현에서 실행되지 않았고, 일부 언어 조합에서는 도구가 아무것도 찾지 못했습니다.
- 지표의 신빙성: 탐지 건수만 셌고 실제 취약점인지(참 양성인지) 수작업 검증을 하지 않았습니다. 저자들도 이를 한계로 적었습니다. 구현마다 규모와 성숙도가 달라 건수를 언어 간 코드 품질 차이로 해석할 수 없고, 저자들도 성숙한 언어일수록 도구가 많아 건수가 많을 가능성을 제시합니다. 구현이 언어당 하나뿐이라 언어 효과와 프로젝트 효과를 분리할 수 없습니다.

#### Comment
