# Memory Safety Isn't All You Need: Code Reuse Attacks in Memory Safe Languages
> ACM ASIACCS 2027 게재 예정 논문의 arXiv 판. KTH 왕립 공과대학교
> 2026

메모리 안전 언어에서도 코드 재사용 공격이 사라지지 않는다는 점을 하나의 틀로 정리한 논문입니다. 메모리 안전성은 임의 메모리 손상에 기대는 ROP 같은 고전적 코드 재사용을 막지만, 객체 주입, 프로토타입 오염, 클래스 오염, DOM 클로버링, DOM 스크립트 가젯 같은 공격은 메모리 안전 추상화를 깨지 않고도 일어납니다. 저자들은 이 공격들이 같은 구조를 가진다고 봅니다. 공격자가 제어하는 데이터가 런타임 타입 정보, 프로토타입이나 클래스 상태, DOM 같은 "공유 런타임 상태"에 대한 접근을 좌우하고, 거기서 읽어 온 값이 이후 보안에 민감한 연산으로 흘러간다는 것입니다. 이를 바탕으로 공격을 공유 상태에서 값을 읽는 데서 끝나는 "약점"과, 읽어 온 값을 민감한 지점까지 전달하는 기존 코드인 "가젯"으로 나누는 언어 중립적 틀을 만들었습니다.

### Contribution
- 약점과 가젯으로 나누는 언어 중립적 틀을 만들고, 기존 다섯 공격 유형이 모두 이 틀로 설명됨을 보였습니다.
- 틀을 이용해 약점을 상태 없는 것, 상태를 바꾸는 것, 기존 상태를 재활용하는 것으로, 가젯을 단순, 수직, 수평 구조로 나눠 알려진 공격 유형 밖의 패턴을 도출했습니다.
- Go를 사례로 틀을 적용해, 패키지 변수처럼 변경 가능한 공유 상태가 있어도 공격자 데이터가 그 접근 방식을 좌우할 언어 장치가 없으면 약점이 되지 않는다는 분석 절차를 보였습니다.
- 기존 방어를 중재(mediation), 최소화(minimization), 제약(constraint)의 세 전략으로 정리하고 새로운 방어 방향 후보를 도출했습니다.
- 공유 런타임 상태와 코드 재사용 약점을 형식적으로 정의하는 모델 언어 imp_sm과 그 실행 가능한 인터프리터를 공개했습니다.

### Evaluation
- 이 논문은 실측 실험이 아니라 체계화와 형식화 연구입니다. 다섯 공격 유형의 대표 사례를 모델 언어로 옮겨 틀이 이를 포착하는지 보였고, Go 사례 분석으로 틀의 쓰임을 시연했습니다.
- 정량 지표나 비교 대상은 없습니다. 형식 정의의 한계도 저자들이 밝혔는데, 관측에서 읽은 값을 빼고 접근을 다중집합으로만 비교하므로 값이나 순서만 바뀌는 차이는 일부러 무시하며, 가젯과 끝에서 끝까지의 취약점 정의는 실제 실행 가능성까지 강제하지 못합니다.

#### Comment
- 웹과 스크립트 언어의 여러 취약점을 "공유 런타임 상태 위의 코드 재사용"이라는 하나의 관점으로 묶어 준다는 점에서, 새 언어 기능이나 프레임워크의 공격 표면을 점검할 때 쓸 수 있는 사고 틀을 줍니다. Rust나 Go 같은 메모리 안전 언어로 옮기면 공격 표면이 사라진다는 기대에 대한 반론이기도 합니다.
- 같은 연구실(Balliu)은 프로토타입 오염 RCE, 객체 주입 탐지 등 이 주제의 선행 연구를 USENIX Security, NDSS에 꾸준히 발표해 왔습니다. ASIACCS는 이 분야의 주요 학회입니다.

# Inferring Sensitive Events in Multi-Mode Cyber-Physical Systems via Scheduling Side Channels
> arXiv 프리프린트 (심사 전). 펜실베이니아 대학교, 브리티시컬럼비아 대학교
> 2026

물리 사건에 따라 작업 구성과 주기를 바꾸는 다중 모드 사이버 물리 시스템에서, 모드 전환이 스케줄링 부채널이 되어 민감한 사건을 드러낸다는 것을 보인 논문입니다. 예를 들어 홈 보안 시스템은 집주인이 나가면 카메라 분석을 시작하고, 자율 주행 시스템은 주행 상황에 따라 인지와 계획 부하를 바꿉니다. 모드가 바뀌면 함께 도는 다른 작업이 받는 간섭이 달라지므로, 권한 없는 공존 작업이 자기 실행 시간과 (멀티코어라면) 배정된 코어만 보고도 집주인의 귀가나 차량의 이동 경로를 추론할 수 있습니다. 기존 스케줄 기반 공격과 방어는 단일 모드 시스템이나 알려진 특정 피해 작업만 가정해 이 통로를 놓쳤습니다. 저자들은 작업 매개변수나 스케줄링 정책을 몰라도 동작하는 가벼운 공격 Stamp를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.17761
- arXiv HTML 본문: https://arxiv.org/html/2611.17761
- arXiv PDF: https://arxiv.org/pdf/2611.17761

### Contribution
- 다중 모드 CPS의 모드 전환이 시스템 전체의 스케줄링 변화를 일으켜 정보를 흘린다는 새 부채널을 제시했습니다.
- Stamp는 공격자가 아는 정보에 따라 두 전략을 씁니다. 모드가 명시적이면 시간 백분위수의 변화로 모드 전환을 찾고 각 구간을 시간과 코어 배정 특징으로 분류하며, 모드가 숨어 있으면 관찰 창을 바로 사건으로 분류합니다. 대상 기기에서 라벨 없이 잠깐 측정한 값으로 특징을 정규화해, 공격자가 프로파일링한 기기와 다른 하드웨어로도 옮겨 갑니다.
- 기존 스케줄 무작위화 방어가 이 공격을 부분적으로만 막고, 대신 실시간 일정 준수를 크게 해치며 새 누출까지 만든다는 점을 보였습니다.

### Evaluation
- ZoneMinder 홈 보안 시스템(Raspberry Pi 4B와 카메라): 처음 보는 하드웨어에서 모드를 94.7% 정확도로 식별했고, CPU 한 코어의 0.5% 미만만 썼습니다.
- ROS 2 AMCL과 Oxford RobotCar 데이터셋: 처음 보는 플랫폼에서 일곱 개 경로 구간 중 어느 곳을 지났는지 86.0%(±0.8%) 정확도로 맞혔고, 관찰 주기 5ms에서 최고 88.6%였습니다. 명시적 모드 전략만 쓰면 73.0%, 미세 시간 규모를 보는 1차원 CNN을 빼면 75.7%로 떨어져 각 요소의 필요성을 보였습니다.
- 실제 로봇: Raspberry Pi 5 기반 Yahboom MicroROS 로봇의 TEB 경로 계획에서도 경로를 구분했습니다.
- 방어: 스케줄 무작위화는 탐지 재현율을 0.53으로 낮추지만, 그 설정에서 제시간에 끝나는 작업이 53.9%로 줄었습니다. 잡음을 더 키우면(ε = 10) 제시간 완료가 14.4%까지 떨어지고, 작업 집합의 14.1%에서 새로운 누출이 생겼습니다.
- 신빙성: 학습에 쓰지 않은 플랫폼과 트레이스로 시험하는 교차 기기 평가를 써서 과적합 위험을 줄였습니다. 시뮬레이션 부분은 작업 이동 비용과 출발 지터를 0으로 가정해 공격자에게 유리한 조건이라고 저자들이 밝혔습니다.

#### Comment
- 차량, 로봇, 스마트홈처럼 여러 소프트웨어가 한 칩을 나눠 쓰는 환경에서, 자원 사용량만으로 물리 세계의 사건이 새어 나간다는 점을 보여 줍니다. 단순 무작위화로는 막기 어렵고, 모드와 상관없이 고정된 자원을 예약하면 막을 수 있지만 그러려면 모든 모드의 최대 수요만큼 자원을 잡아야 한다는 비용 문제를 짚었습니다.
- 한계: 서로 다른 모드가 관찰 가능한 패턴에서 비슷하면 구분할 수 없고, 오프라인 프로파일링이 실제 환경을 충분히 대표해야 하며, 부하나 스케줄러 설정이 크게 바뀌면 정확도가 떨어질 수 있습니다. 코드 공개 주소는 본문에서 찾지 못했습니다.

# Deterministic ECDSA on secp256k1: the RFC 6979 assumption, a counterexample, and the state of deployed implementations
> arXiv 프리프린트 (심사 전). 모스크바 고등경제대학교(HSE)
> 2026

비트코인과 이더리움 생태계의 사실상 표준인 결정적 ECDSA(RFC 6979)의 안전성이 정확히 어떤 가정에 기대는지를 따지고, 실제 구현 31개를 점검한 논문입니다. RFC 6979는 서명 키 x와 메시지 해시 h로 HMAC_DRBG를 돌려 논스를 만들어, 실행 중 난수 생성기에 대한 의존을 없앱니다. RFC 본문은 "HMAC이 PRF처럼 동작하면 안전하다"고 적고 있지만, 저자는 실제로 필요한 가정이 그것이 아니라 "공개키를 아는 상태에서 결정적 논스로 만든 서명 기록이 균일 난수 논스로 만든 기록과 구별되지 않는다"는 별도 가정 A*라는 점을 정식화했습니다. 그리고 PRF 안전성만으로는 A*가 따라 나오지 않음을 반례로 보였습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.18449
- arXiv HTML 본문: https://arxiv.org/html/2611.18449
- arXiv PDF: https://arxiv.org/pdf/2611.18449

### Contribution
- 가정 A*를 정식화하고, A*가 성립하면 결정적 ECDSA가 무작위 ECDSA와 정확히 같은 수준으로 안전함을 보였습니다.
- 반례: 표준 가정 아래 PRF이지만 서명 하나로 키가 드러나는 논스 함수를 만들었고, 이를 압축 함수 수준까지 끌어올려 HMAC 증명에 쓰는 PRF, 이중 PRF 성질을 가진 압축 함수 위에서 RFC 6979 상태 기계를 그대로 써도 서명 하나로 깨지는 경우가 있음을 보였습니다(충돌 저항 전제 필요).
- A*와 보조 입력 PRF(AI-PRF) 가정이 양방향으로 다름을 보였습니다. 이상적인 압축 함수 모델에서는 A*가 이산 로그 문제의 어려움으로부터 손실 없이 따라 나오며, 논스 키를 서명 키와 분리하면 이 가정이 아예 필요 없어집니다.
- 곡선별로 비밀 HMAC 메시지 블록이 균일 분포에서 얼마나 떨어지는지 계산했습니다(secp256k1 2^-127.65, P-256 2^-32, brainpoolP256r1 0.336).
- 실제 구현 31개를 점검하고, 아무도 시험하지 않는 h ≥ n 분기의 시험 벡터를 공개했습니다.

### Evaluation
- 구현 점검: secp256k1 구현 31개 중 28개가 추가 엔트로피 없이 결정적으로 서명했고, libsecp256k1 0.2.0 이전의 원시 메시지 처리 편차(bits2octets 미준수)가 NBitcoin, dcrd, btcec v2에 남아 있음을 소스 코드로 확인했습니다. 31개 모두 논스 키를 서명 키와 분리하지 않았습니다.
- 낮은 R 값 그라인딩(Bitcoin Core)은 A* 외에 추가 가정이 필요 없음을 증명했고, 그 논스 집합의 0이 아닌 푸리에 계수가 모두 2^-116.9보다 작음을 무조건적으로 보였습니다.
- 1비트 논스 편향 공격의 필요 서명 수를 모델로 약 2^47개(불확실 범위 2^40~2^47)로 추정했습니다.
- 신빙성: 각 주장에 직접 증명, 문헌 인용, 소스 코드 확인, 추정과 해석을 구분하는 표시를 달아 근거 수준을 밝힌 점이 좋습니다. 다만 단일 저자의 이론 논문이고 심사 전이므로 증명은 전문가 검증이 필요합니다.

#### Comment
- 실용적인 의미는 "RFC 6979가 지금 깨졌다"가 아니라, 가장 널리 배포된 ECDSA 관행이 아직 증명되지 않은 가정 위에 있다는 것입니다. HMAC_DRBG에 대해 A*를 깨는 알려진 공격은 없습니다. 지갑과 서명 라이브러리 개발자에게는 bits2octets 준수 여부와 h ≥ n 분기 시험 벡터 점검이 바로 쓸 수 있는 결과입니다.
- 열린 문제로 HMAC_DRBG에 대한 표준 모델 증명이나 반증, 충돌 저항 전제 제거, 1비트 누출 비용의 실측 등을 남겼습니다.
