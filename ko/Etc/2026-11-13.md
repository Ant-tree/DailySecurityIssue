# Lessons Not Learned: Why Cross-Chain Bridges Keep Losing Billions the Same Way
> arXiv 프리프린트 (심사 전). Monad Foundation
> 2026

크로스체인 브리지 해킹은 수십억 달러의 손실을 냈지만, 상당수는 코드 버그가 아니라 보안 태세의 실패에서 나왔습니다. 저자들은 보안 태세를 브리지의 사람, 코드, 통제 장치, 오프체인 인프라가 어떻게 구성되어 있는지로 정의합니다. 2021년부터 2026년 7월까지 브리지 사고 72건(보고된 총손실 35.2억 달러)을 정리한 결과, 2023년 이후 손실의 88%가 보안 태세 실패에서 나왔고 거의 모두 이전 사고의 반복이었습니다. 2026년 4월 KelpDAO 사고처럼 여러 번 감사받은 코드를 쓰고도 단일 검증 네트워크만 믿도록 설정한 배포 하나 때문에 2.92억 달러를 잃은 사례가 대표적입니다. 코드 감사로는 이런 실패를 잡을 수 없으므로, 저자들은 온체인 증거로 각 배포를 채점하고 치명적 위험이 있으면 점수를 최저로 떨어뜨리는 평가 기준표를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12252
- arXiv HTML 본문: https://arxiv.org/html/2611.12252
- arXiv PDF: https://arxiv.org/pdf/2611.12252

### Contribution
- 72건의 브리지 사고를 원인별(보안 태세 대 코드 결함)로 분류한 목록을 만들었습니다.
- 토큰이 여러 체인에 배포되어 하나의 담보를 공유하면, 발행이나 담보 인출이 가능한 가장 약한 배포의 점수가 그 토큰 전체의 점수가 된다는 원칙을 기준표에 넣었습니다.
- 예상하지 못한 공격에도 전송량 제한과 긴급 정지가 손실 상한을 정한다는 점(공격자가 이를 해제할 수 없다는 전제)을 보였습니다.
- 기준표를 적용하고 변경을 감시하는 분석기와, 같은 검사를 임의의 브리지에 수행하는 LLM 기반 에이전트 분석기를 만들었습니다.

### Evaluation
- 기준표는 보안 태세 실패 29건을 모두 잡아냈다고 보고합니다.
- 각 해킹을 기준표의 통제가 있었다고 가정하고 다시 돌려 보는 반사실 모델로, 손실이 35.2억 달러에서 3,300만 달러로 105배 줄었을 것이라고 추정했습니다.
- 지표의 신빙성: 105배 감소는 실제 측정이 아니라 사후 재구성 모델의 추정치이며, 전송량 제한 기준(예: 48시간, 5%) 같은 문턱값은 저자들의 판단이라고 본문에 적혀 있습니다. 경제적 공격과 발행자 권한 남용은 기준표 범위 밖입니다.

#### Comment
- 블록체인 재단 소속 저자들의 산업계 원고로, 사고 목록과 기준표가 실무에 바로 쓰일 수 있다는 점이 장점입니다. 반면 저자 소속 재단의 이해관계가 있을 수 있어 특정 브리지 평가 결과는 독립 검증이 필요합니다.
- 보안 태세 실패(키 관리, 단일 검증자 설정, 업그레이드 권한 집중)가 코드 버그보다 큰 위험이라는 메시지는 다른 분야의 공급망 보안에도 그대로 통합니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# DeepChronos: Temporal Neuro-Symbolic Reasoning for Multi-Step Attack Detection
> arXiv 프리프린트 (심사 전). 델프트공과대학교(네덜란드), 투르쿠대학교(핀란드)
> 2026

현대 공격은 정찰, 초기 침투, 권한 상승, 내부 이동, 유출처럼 시간과 인과 관계로 이어진 여러 단계로 진행됩니다. 지금의 방어는 대체로 침입 탐지 시스템이 이벤트를 하나씩 분류한 뒤 나중에 경보를 엮어 공격 흐름을 재구성하는 "먼저 탐지하고 나중에 연관 짓는" 방식입니다. 학습 기반 탐지기는 단계 사이의 관계를 통계적으로만 배우므로, 예측이 실제 공격 순서를 지킨다는 보장이 없습니다. 이 논문은 신경망이 흐름 단위 증거를 내고, 확률 논리 프로그래밍으로 표현한 공격 단계 규칙, 시간상 선행 조건, 이미 추론된 단계 이력이 각 탐지 결정을 함께 제약하는 신경-기호 결합 네트워크 침입 탐지 시스템 DeepChronos를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12760
- arXiv HTML 본문: https://arxiv.org/html/2611.12760
- arXiv PDF: https://arxiv.org/pdf/2611.12760

### Contribution
- "논리적 진행을 통한 탐지"라는 방식으로, 공격 이력이 현재 흐름의 분류에 직접 반영되도록 했습니다.
- 예를 들어 유출 단계는 침투 단계가 관찰된 뒤에만 가능하도록 하는 시간 제약과, 포트와 프로토콜에 기반한 단계별 규칙을 신경망 출력과 함께 추론합니다.
- 인과 위반(앞 단계 없이 뒤 단계를 예측)과 역행 위반을 재는 시간 일관성 지표를 함께 보고했습니다.

### Evaluation
- 데이터셋: DARPA 2000, AIT-LDS V2. 패킷 캡처를 Zeek 흐름으로 바꾸고 계층화한 70/30 무작위 분할로 학습과 시험을 나눴습니다.
- 비교 대상: 다중 분류 LSTM, 앙상블 LSTM, 규칙만 쓰는 기호 기준선, Kitsune.
- AIT-LDS V2에서 시간 제약과 규칙을 모두 쓴 모델의 macro F1은 0.944로, LSTM 다중 분류(0.880)보다 높았고, 신경망 기준선에서 나타난 인과 위반을 0으로 만들었습니다.
- DARPA 2000에서는 Kitsune의 macro F1이 0.984로 가장 높았지만 오경보율이 0.037로, DeepChronos 종단 학습 모델(F1 0.940, 오경보율 0.00015)보다 훨씬 높았습니다.
- 지표의 신빙성: 데이터셋이 오래되었거나(DARPA 2000) 규모가 제한적이고, 시간 순서가 아닌 계층화 무작위 분할을 써서 같은 공격 흐름의 앞뒤 구간이 학습과 시험에 함께 들어갔을 가능성이 있습니다. 규칙이 정답 공격 흐름을 알고 작성되었다는 점에서 실제 환경의 미지 공격으로의 일반화는 별도 검증이 필요합니다.

#### Comment
- 탐지 결과가 공격 순서와 모순되지 않도록 보장하고 설명 가능한 탐지를 제공한다는 점은 보안 운영 센터 관점에서 쓸모가 큽니다.
- 공격자가 단계를 건너뛰거나 순서를 바꾸는 경우 엄격한 시간 제약이 오히려 탐지를 막을 수 있다는 점은 저자들도 한계로 다뤘습니다.
- 코드 공개 여부는 본문에서 확인하지 못했습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# MammothDP: Private Boosted Decision Trees Ready for Trusted Hardware and Leakage-free Hyperparameters
> arXiv 프리프린트 (심사 전). 뤼베크대학교(독일), 취리히 연방공대(스위스)
> 2026

유럽 건강 데이터 공간(EHDS) 규정은 민감 데이터를 보안 처리 환경 안에서 처리하고 결과는 익명화해 공개하도록 요구합니다. 신뢰 실행 환경(TEE)과 차등 프라이버시(DP)를 함께 쓰면 처리와 공개를 모두 보호할 수 있을 것 같지만, 저자들은 이 조합에서 예상하지 못한 문제가 생긴다고 지적합니다. DP 학습 알고리즘이라도 실행 시간이 데이터에 따라 달라지면 타이밍 사이드 채널로 DP 보장이 무너지고(실험에서 ε=0.1인데도 학습 데이터 한 점의 포함 여부를 실행 시간으로 구별), TEE의 롤백 공격으로 같은 질의를 여러 번 돌려 타이밍 정보를 모을 수 있으며, 기존 롤백 방어 ElephantDP는 이 위협 모델에서 취약하고, 일반적인 DP 하이퍼파라미터 탐색은 프라이버시 예산을 너무 많이 씁니다. 이 논문은 DP 경사 부스팅 결정 트리 S-BDT를 바탕으로 이 문제들을 함께 해결한 시스템 MammothDP를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14317
- arXiv HTML 본문: https://arxiv.org/html/2611.14317
- arXiv PDF: https://arxiv.org/pdf/2611.14317
- 저자 저장소(코드): https://github.com/kirschte/MammothDP
- 저자 저장소 TEE 실행 이미지: https://github.com/kirschte/MammothDP/tree/main/tee-ready-image

### Contribution
- S-BDT를 비트마스크와 전체 데이터 순회로 바꾸고, 고정 시간 고정소수점 라이브러리와 고정 시간 잡음 샘플러를 맞춰 넣어 상수 시간 구현을 만들었습니다. 데이터 크기 차이로 생기는 반복 횟수 차이도 다뤘습니다.
- ElephantDP의 설계 결함을 지적하고, 공개가 아니라 계산 자체를 제한하는 해시 체인 기반 롤백 방어를 제안했습니다.
- DP로 근사한 경사 합만 쓰는 후처리 방식의 조기 종료 기준을 만들어, 추가 프라이버시 비용 없이 트리 개수를 데이터에 맞게 고르도록 했습니다.

### Evaluation
- 상수 시간 검증: 동적 타이밍 사이드 채널 분석 도구 Microwalk로 데이터 의존 부분을 구성 요소별로 무작위 입력 100개씩 분석했고, 실행된 S-BDT 코드 전체에서 누출이 보고되지 않았습니다.
- 프라이버시와 정확도: 회귀 2종(Insurance, Abalone)과 분류 3종(Credit, Adult, Spambase) 데이터셋에서, 조기 종료 S-BDT는 고정 하이퍼파라미터 S-BDT보다 회귀에서 뚜렷이 좋았고 분류에서는 낮은 ε 구간에서만 좋았습니다. 프라이버시 비용을 무시하고 하이퍼파라미터를 조정한 S-BDT보다는 약간 낮지만 비슷한 수준이었습니다.
- 실행 환경: Intel TDX(Xeon Gold 6526Y)와 AMD SEV(EPYC 7763)에서 상수 시간 구현, TEE, 롤백 방어 각각의 실행 시간 비용을 측정했습니다.
- 지표의 신빙성: 고정 하이퍼파라미터를 정할 때 쓴 데이터셋과 별도로 시험용 데이터셋 2개를 두어 비교의 공정성을 챙겼습니다. 다만 동적 분석은 시험 입력이 닿는 경로만 검증하므로 완전한 증명은 아닙니다.

#### Comment
- 차등 프라이버시와 TEE를 "함께 쓰면 안전하다"는 통념에 실제 사이드 채널과 롤백 문제로 반례를 보이고 해결책까지 제시한 점이 좋습니다. 모바일 TEE 기반 데이터 처리에도 같은 문제가 적용될 수 있습니다.
- 코드와 TEE 실행 이미지를 공개해 재현 가능성이 높습니다. 같은 연구 과제(AnoMed)의 2025년 버전 자료가 있지만, 이번 요약은 arXiv 판을 기준으로 했습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# Hidden in Plain Sight: Privacy-Enhanced Computing Through Register Renaming
> arXiv 프리프린트 (심사 전, cs.AR 주 분류). 웁살라대학교(스웨덴)
> 2026

프라이버시 강화 컴퓨팅(PEC)은 완전 동형 암호의 큰 비용 없이 프로그램의 비밀 값을 외부에 숨기려는 하드웨어 기법입니다. 기존의 격리 암호화(Sequestered Encryption, SE)는 복호화, 연산, 재암호화를 하는 전용 장치를 따로 두어 연산 자원을 중복으로 갖춰야 했고, 보호된 명령이 프로세서의 여러 실행 장치나 벡터 장치를 쓰지 못했습니다. 이 논문은 레지스터 이름 변경(register renaming)과 명령 확장 장치라는 기존 CPU 구조를 활용해, 평문을 어떤 아키텍처 레지스터도 가리킬 수 없는 숨은 마이크로아키텍처 레지스터에만 두는 HPS-PEC를 제안했습니다. PEC 명령은 디코더에서 복호화, 일반 연산, 암호화 마이크로 연산으로 펼쳐지고, 레지스터와 메모리에는 암호문만 기록됩니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12570
- arXiv HTML 본문: https://arxiv.org/html/2611.12570
- arXiv PDF: https://arxiv.org/pdf/2611.12570

### Contribution
- 암호화와 복호화 장치만 추가하고 나머지는 기존 연산 장치를 공유해, 보호된 명령도 비순차 실행과 병렬 실행의 이점을 얻게 했습니다.
- 평문이 레지스터 파일 안에 있더라도 아키텍처 레지스터가 매핑될 수 없게 해, 엔클레이브처럼 모든 일반 명령의 접근을 막습니다. 레지스터 이름 변경기의 정확성 외에 새로운 신뢰 요구는 없다고 주장합니다.
- 위협 모델: 운영체제를 포함한 모든 소프트웨어를 공격자가 통제하지만 물리 접근은 없고, 프로그램은 데이터 독립적(제어 흐름과 메모리 주소가 비밀 값에 의존하지 않음)이라고 가정합니다. 잘못된 경로의 일시적 실행도 범위에 포함합니다.

### Evaluation
- gem5 비순차 코어(8폭, 2.5GHz) 시뮬레이션과 VIP-Bench 25개 벤치마크, 7사이클 QARMA-64 암호를 사용했습니다. 암호 장치는 ASAP7 7nm 라이브러리로 배치 배선해 2.5GHz를 만족함을 확인했습니다.
- 암호화된 실행은 보호 없는 일반 코드의 3.41배(기하 평균) 시간이 걸렸고, 이 가운데 데이터 독립적 코드 자체의 비용은 1.03배였습니다.
- 같은 코드 생성 조건의 SE 장치보다 1.26배 빨랐고(16개 벤치마크에서 빠름, 5개에서 느림), 추가 면적은 SE의 30% 미만(5,097µm² 대 최소 17,199µm²)이었습니다.
- 지표의 신빙성: 시뮬레이션과 배치 배선 결과이며 실제 칩 구현은 없습니다. 저자들은 벤치마크의 일부 오류를 고쳤다고 밝혔고, 상수와 공개 값의 처리 방식 등 측정 조건을 자세히 적었습니다.
