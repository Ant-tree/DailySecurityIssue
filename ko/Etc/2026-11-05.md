# The Native Menace: Host-to-Browser Cross-Boundary Attacks via Native Messaging
> IEEE S&P 2027(IEEE Symposium on Security and Privacy) 게재 예정(저자 아티팩트 저장소 표기), arXiv cs.CR 2611.04291 공개본. 일리노이대학교 시카고(미국)
> 2026 (학회 발표는 2027)

브라우저 확장 프로그램은 NativeMessaging API로 사용자 컴퓨터에 설치된 데스크톱 앱(네이티브 호스트)과 통신할 수 있습니다. 비밀번호 관리자 앱이 확장 프로그램에 자격 증명을 넘겨 자동 입력하게 하거나, 전자신분증 앱이 웹사이트 로그인과 전자서명을 처리하는 식입니다. 지금까지 확장 프로그램 보안 연구는 악성 웹페이지나 악성 확장 프로그램을 주로 다뤘고, 이 통로 자체는 거의 분석되지 않았습니다. 이 논문은 NativeMessaging을 처음으로 체계적으로 분석해, 특별한 권한이 없는 사용자 수준의 악성 앱이 이 통로를 가로채거나 흉내 낼 수 있음을 보였습니다.

공격의 출발점은 통로에 신뢰의 기준점이 없다는 사실입니다. 브라우저는 확장 프로그램이 부를 네이티브 호스트를 매니페스트 파일로 찾는데, 사용자 수준 매니페스트는 사용자 권한 프로세스라면 누구나 고칠 수 있고(macOS의 사용자 프로필 폴더, Windows의 HKCU 레지스트리), Chromium 계열 브라우저는 사용자 수준 경로를 시스템 경로보다 먼저 찾습니다. 그래서 공격자는 매니페스트의 실행 파일 경로를 자기 프로그램으로 바꾸거나, 시스템 수준으로 설치된 호스트와 같은 이름의 매니페스트를 사용자 경로에 끼워 넣을 수 있습니다. 앱이 실행될 때마다 매니페스트를 덮어쓰는 경우에도, 변경을 감시하다 다시 바꿔 놓으면 됩니다. 이를 바탕으로 확장 프로그램과 호스트 사이에서 모든 메시지를 중계하며 엿보고 바꾸는 양방향 가로채기, 확장 프로그램이나 호스트 한쪽을 속여 명령을 내리는 단방향 가로채기(대리인 혼동 공격), 호스트가 설치되지 않은 경우에도 가능한 호스트 흉내 공격을 구성했습니다.

### Contribution
- NativeMessaging의 설계와 배포 방식에서 매니페스트 무결성 부재, 탐색 순서로 인한 가려 쓰기, 확장 프로그램과 호스트 간 상호 인증 부재 같은 근본 결함을 찾아냈습니다.
- 양방향, 단방향 두 가지 "호스트에서 브라우저로 경계를 넘는" 공격을 제시하고, 17개 주요 앱에 실제로 적용했습니다.
- 공격 결과가 심각합니다. 1Password, Bitwarden, KeePassXC, RoboForm 같은 비밀번호 관리자에서 금고 전체 유출, EU와 중남미, 인도의 전자정부 서비스(Web eID, Web PKI 등)에서 사용자 사칭과 법적 효력이 있는 문서 서명, 화상회의 세션 개입, 인증 토큰 탈취, 화면 캡처와 키 입력 주입 권한 오용을 시연했습니다. 취약한 확장 프로그램의 누적 설치 수는 약 5억 3,200만 회입니다.
- macOS처럼 앱 간 격리가 강한 운영체제에서는, 이 통로가 단순한 우회 경로가 아니라 격리를 넘는 유일한 수단이 된다는 점을 보였습니다. 1Password, Bitwarden, RoboForm, Web PKI, Web Signer, Web eID 공격은 NativeMessaging 없이 같은 사용자 권한만으로는 재현되지 않았습니다.
- 운영체제, 브라우저, 앱 각각에 대한 완화책을 제시했고, 앱 수준에서는 대역 외로 공유한 비밀로 메시지를 암호화하는 간단한 방법을 권했습니다.

### Evaluation
- 실태 측정: 2026년 8월 14일 Chrome 웹 스토어 스냅샷에서 확장 프로그램 250,735개의 매니페스트를 분석해, NativeMessaging 권한을 선언한 확장 프로그램 1,972개(누적 설치 약 10억 7천만 회)를 찾았습니다. 절반은 설치 수가 1,000회 안팎이지만 상위 5%가 수억 회를 차지합니다.
- 공격 검증: 설치 수, 분야, 민감도를 고려해 17개 확장 프로그램을 골라 macOS 26.3과 Windows 11에서 Chrome 151로 시험했습니다(Bitwarden은 생체 인증 장치가 있는 Windows 기기가 없어 macOS만). Firefox에서도 Web eID, Web PKI, 1Password, KeePassXC, Bitwarden, RoboForm으로 재현했습니다. Web eID는 공식 앱과 인증 토큰 검증 참조 구현을 직접 배포해 전체 인증 흐름에서 시연했습니다.
- 예외 사례: iCloud 비밀번호는 매니페스트가 시스템 무결성 보호(SIP) 영역으로 심볼릭 링크되어 있어 공격이 통하지 않았습니다. 이 사례가 그대로 완화책의 근거가 됩니다.
- 공개 대응: Google과 Mozilla는 사용자 수준 로컬 공격자를 위협 모델 밖으로 보고 보고를 닫았고, Edge, Opera, Vivaldi도 변경을 약속하지 않았습니다. Foxit은 HMAC-SHA256 메시지 무결성과 재전송 방지를 배포했고, Anthropic은 이미 보고된 문제로 수정 추적 중이라고 확인했으며, RoboForm은 변경을 검토 중입니다. 1Password, Bitwarden, KeePassXC는 위협 모델 관점에서 검토했으나 변경을 약속하지 않았습니다.
- 지표 신빙성: 실제 앱 최신 버전에 대한 개념 증명과 공급사 확인을 거쳐 결과의 신뢰도가 높습니다. 다만 17개 대상은 무작위 표본이 아니라 민감도 위주로 고른 것이라, 전체 1,972개 중 취약한 비율을 추정한 것은 아닙니다.

#### Comment
- 위협 모델이 핵심 논쟁점입니다. 공격자는 사용자 컴퓨터에서 사용자 권한으로 실행되는 악성 앱이어야 하고, 브라우저 공급사들은 이를 "이미 끝난 상황"으로 봅니다. 저자들은 macOS의 앱 격리와 개인정보 보호 장치가 강해진 지금은 그 전제가 낡았다고 반박하며, 17개 앱 중 4개만 Mac App Store로 배포되어 대부분의 앱이 샌드박스 밖에서 실행된다는 점을 근거로 듭니다.
- AI 에이전트 확장 프로그램도 대상에 들어 있습니다. Claude in Chrome은 호스트 흉내 공격과 양방향 공격에 모두 취약했고, 공격자가 로그인된 탭에서 자바스크립트를 실행해 토큰이나 쿠키를 가져갈 수 있다고 보고했습니다. 브라우저를 조작하는 에이전트 확장 프로그램이 늘어나는 만큼 이 통로의 인증 문제는 더 중요해질 것으로 보입니다.

# A Rowhammer attack on Fil-C's software capabilities
> arXiv cs.PL 2610.33748 v2 (cs.CR 교차 등록, 프리프린트, 심사 전). 독립 연구자 2인(영국 케임브리지), 서식스대학교와 Montanarius Ltd(영국)
> 2026

Fil-C는 기존 C/C++ 코드를 거의 고치지 않고 컴파일만 다시 해서 공간적, 시간적 메모리 안전성을 얻게 해 주는 시스템입니다. 모든 포인터에 하한과 상한을 담은 소프트웨어 권한 정보(InvisiCap)를 붙이고, 역참조할 때마다 범위를 검사합니다. 이 논문은 Fil-C의 보장이 "DRAM이 이 권한 정보를 그대로 보존한다"는 드러나지 않은 하드웨어 가정에 기대고 있으며, Rowhammer가 그 가정을 깬다는 것을 보였습니다.

Fil-C 0.679에서는 힙 포인터 권한 정보 일부가 객체 바로 앞 16바이트 헤더에 일반 DRAM으로 저장되고, 이를 보호하는 MAC이나 패리티, 별도 태그 메모리가 없습니다. 상한 값의 비트 하나가 0에서 1로 바뀌면 허용 범위가 2의 k제곱 바이트만큼 늘어나고, 런타임은 바뀐 값을 그대로 믿기 때문에 아무런 패닉이나 신호도 발생하지 않습니다. 저자들은 새로운 해머링 기법을 제안하는 것이 아니라, 이미 알려진 하드웨어 결함이 소프트웨어 메모리 안전 장치에 어떤 의미인지를 보여 주는 것이 목적이라고 분명히 합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2610.33748
- arXiv HTML 본문: https://arxiv.org/html/2610.33748
- arXiv PDF: https://arxiv.org/pdf/2610.33748

### Contribution
- Fil-C를 겨냥한 첫 Rowhammer 공격입니다. Fil-C 0.679의 권한 정보 배치를 분석해, 범위 검사가 일반 DRAM에 놓인 인라인 메타데이터의 무결성에 의존한다는 점을 밝혔습니다.
- 재현성을 위해 두 경로로 나눠 시연했습니다. 결정적 경로에서는 /proc/pid/mem으로 비트 하나를 대역 외에서 바꿔 하드웨어와 무관하게 결과만 분리해 보였고, 물리 경로에서는 실제 Rowhammer로 템플릿 작성, 메모리 배치 유도(grooming), 해머링까지 전 과정을 수행했습니다.
- 네 가지 사례를 보였습니다. 범위 밖 읽기/쓰기 창 확보, 비밀 정보 유출, 옆 필드 is_admin을 바꾸는 권한 상승, SQLite 기반 다중 사용자 자격 증명 서비스에서 다른 사용자의 API 키 유출입니다.
- Fil-C 전용 완화책으로 PT-Guard 방식의 MAC 보호를 권한 정보에 옮겨 적용하자고 제안했습니다. 새로운 방어 기법은 아니라고 저자들이 밝혔습니다.

### Evaluation
- 결정적 경로: DDR3 실험 기기(Intel Core i7-2630QM, 8GiB DDR3, Linux 5.15)에서 Fil-C 0.679로 빌드한 피해 프로그램에 비트 하나를 바꾸자 네 사례 모두에서 범위 밖 접근이 허용되었고, 객체 길이가 256바이트에서 384바이트로 보고되었습니다. 비트를 바꾸지 않은 대조군에서는 같은 접근이 런타임 패닉으로 종료되었습니다. 512바이트 할당에서도 같은 결과를 확인했습니다.
- 물리 경로: DDR3에서는 고전적인 양면 해머링으로 약 2분 만에, Target Row Refresh(TRR)가 있는 DDR4에서는 다면 해머링으로 10~35분 만에 공격이 성공했습니다. 두 기기 모두 ECC가 없는 메모리를 썼습니다.
- 지표 신빙성: 비트 하나가 바뀌면 보호가 사라진다는 결과 자체는 분명합니다. 다만 물리 경로는 공격자가 피해 프로세스를 직접 fork한 부모 프로세스이고, 피해 프로그램이 할당된 범위를 공유 영역으로 알려 주며, /proc/pid/pagemap으로 물리 주소를 얻는 등 실험에 유리한 조건을 둡니다. 실제 환경에서 공격자가 피해 객체의 위치를 알아내고 원하는 비트를 맞추는 난이도는 따로 평가하지 않았습니다. DDR4 기기의 제조사와 모델은 조율된 공개 정책에 따라 밝히지 않았습니다.

#### Comment
- CHERI나 Arm MTE처럼 하드웨어가 보호하는 방식과 달리, 소프트웨어 권한 정보는 하드웨어 결함에 그대로 노출된다는 점을 구체적으로 보여 줍니다. 메모리 안전 언어나 런타임의 보장도 하드웨어 무결성 위에 서 있다는 점을 상기시키는 연구입니다.
- 한계: 저자들 스스로 주장을 "쓸 만한 비트 반전을 메타데이터의 적절한 위치에 만들 수 있다면"이라는 조건부로 제시합니다. 대부분의 비트 반전은 위치, 방향, 현재 값, 포인터 유효성 조건 때문에 쓸 수 없고, ECC 메모리를 쓰는 서버에서는 결과가 달라질 수 있습니다. 시험한 Fil-C 버전도 0.679 하나입니다.
- 게재처: 심사 전 프리프린트이며, 주 분류는 cs.PL입니다. 저자 중 두 명은 소속이 없는 독립 연구자입니다.

# Janus Vehicles: Entity-Centric Threat Modelling of Protocol-Conformant Vehicles under a Malicious-Manufacturer Assumption
> IEEE PRDC 2026(31st IEEE Pacific Rim International Symposium on Dependable Computing) 채택 논문, arXiv cs.CR 2610.37059 v2 공개본. 고려대학교(한국 서울)
> 2026

자동차 보안 연구는 대개 제조사는 선량하다고 가정하고, 공급망 위협이나 외부 공격, 오작동으로 드러나는 침해 차량을 다룹니다. 이 논문은 그 가정을 뒤집어, 인증도 정상이고 통신 규약도 그대로 지키면서 신고하지 않은 감지, 통신, 특정 상황에서의 작동을 숨겨 둔 "설계 단계부터 악의적인" 차량을 위협 모델로 정리합니다. 폭스바겐 배출가스 조작처럼 시험 환경을 알아채고 행동을 바꾼 실제 사례와, 중국산 차량과 버스를 둘러싼 각국의 조사와 제한 조치를 문제의식의 배경으로 듭니다.

저자들은 프로토콜을 지키는 것(protocol conformance)과 목적을 지키는 것(purpose conformance)을 구분합니다. 앞의 것은 상호 운용에 필요하지만, 차량 전체가 믿을 만하다는 증거로는 부족하다는 것입니다. 이를 바탕으로 세 부분으로 된 개체 중심 위협 모델을 제안합니다.

### Contribution
- 악의적 개체 유형 네 가지를 정리했습니다. 주변 개체에는 선량해 보이지만 목적이 악의적인 차량(유형 I), 침해된 차량, 정품 부품을 다른 용도로 재활용한 경우, 차량이나 부품을 모방한 경우입니다. 유형 I은 진위 확인과 행동 감시 모두에 근거를 남기지 않는다는 점에서 다른 유형과 다릅니다.
- 두 가지 보증 공백을 짚었습니다. 진품임이 확인되어도 신고된 목적을 지킨다는 보장은 없고, 악의적 기능은 과거 행동 기록이나 주변 개체가 볼 수 있는 증거에 기반한 탐지를 피할 수 있습니다. 재활용된 정품 부품은 신호 지문 인식과 인증서 기반 인증의 효과도 떨어뜨립니다.
- 행동-위치 행렬(Behaviour-Locus Matrix)로 은밀한 행동, 드러난 행동, 은폐 행동을 하드웨어, 소프트웨어, 네트워크 위치에 걸쳐 배치해 조사 범위를 체계화했습니다.
- 행동 상호작용 모델로 숨겨진 기능이 어떤 조건(타이머, 외부 명령, 특정 위치나 대상 인식, 차량 상태)에서 활성화되어 행동으로 이어지고, 어떤 흔적을 남기며, 어떻게 은폐되는지를 연결했습니다.

### Evaluation
- 실험 평가는 없습니다. 저자들도 개념적 위협 모델이며, 숨겨진 기능을 심어 둔 차량이나 시험대로 검증하지 않았다고 한계에서 밝혔습니다.
- 행동-위치 행렬의 예시는 망라적이지 않고 설명용이며, 증거 수집 절차나 분석 도구, 판정 기준을 제시하지 않습니다.
- 지표 신빙성: 평가할 정량 지표가 없으므로, 기존 표준(ISO/SAE 21434 등)이나 MITRE 프레임워크와의 비교, 사례 분석의 타당성으로 판단해야 하는 논문입니다.

#### Comment
- 커넥티드카와 V2X가 확산되면서 "제조사 자체를 믿을 수 있는가"라는 질문이 정책 차원에서 커지고 있는데, 이를 보안 공학의 언어로 정리하려는 시도로 의미가 있습니다. 결론에서는 관찰되지 않았다고 해서 기능이 없다고 할 수 없고, 모델로 제조사의 의도나 법적 책임을 판정할 수는 없다는 점도 분명히 했습니다.
- 한계: 개념 정리에 그쳐 실무 적용에는 후속 연구가 필요합니다. 저자들은 정적 검사, 동적 관찰, 상황 자극을 결합한 조사 절차와, Malware Behavior Catalog를 사이버 물리 시스템에 맞게 확장하는 방향을 제시했습니다.
- 게재처: IEEE PRDC는 고신뢰 컴퓨팅 분야의 IEEE 학회로, 보안 최상위 학회급은 아니지만 정식 심사를 거치는 학회입니다. 채택 사실은 arXiv 원고 첫 쪽 각주에 적혀 있습니다.

# What Malware Actually Does: An Empirical Analysis of Post-Infection Behavior Across Malware Families
> arXiv cs.CR 2611.03774 (프리프린트, 심사 전, 원고에 IEEE 저작권 고지가 있으나 게재처는 밝히지 않음). 노스다코타대학교(미국)
> 2026

악성코드 탐지 연구는 대개 파일이 실행되기 전에 악성인지 가려내는 데 집중하고, 감염 이후 실제로 무엇을 하는지는 상대적으로 덜 다룹니다. 이 논문은 37개 악성코드 계열을 오픈소스 샌드박스 CAPEv2에서 실행해 감염 후 행동을 분석했습니다. 실행 기록을 프로세스, API, 파일, 레지스트리, 네트워크 다섯 종류의 노드와 일곱 종류의 관계로 된 이종 그래프로 만들어, 평평한 특징 벡터가 버리는 "어느 프로세스가 어느 레지스트리 키를 쓰면서 어디로 접속했는가" 같은 관계 구조를 보존하려 했습니다.

그래프에서 구조 특징 55개를 뽑아 랜덤 포레스트, 엑스트라 트리, XGBoost를 묶은 투표 앙상블로 악성 여부와 계열을 분류하고, 계열별 행동 지문을 레지스트리, 네트워크, 프로세스, API 관점에서 정리했습니다. 마지막으로 LLM(Claude Sonnet 4.6)이 관찰된 행동 근거를 바탕으로 MITRE ATT&CK 기법을 연결한 분석 보고서를 만들게 했고, 전체 파이프라인을 HeteroScan이라는 웹 도구로 공개했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.03774
- arXiv HTML 본문: https://arxiv.org/html/2611.03774
- arXiv PDF: https://arxiv.org/pdf/2611.03774
- 저자 프로젝트 페이지(HeteroScan): https://ama-andam.github.io/heteroscan

### Contribution
- 원격 접근 트로이목마(AsyncRAT, njRAT, NanoCore 등), 정보 탈취형(RedLine, AgentTesla, Vidar 등), 로더(GuLoader, Amadey 등)를 포함한 37개 계열의 감염 후 행동을 같은 샌드박스 환경에서 비교했습니다.
- 행동 기록을 이종 그래프로 표현하고 구조 특징만으로 분류하는 파이프라인을 만들었습니다.
- 샌드박스에서 의미 있는 행동을 보이지 않은 표본 비율을 계열별로 보고했습니다. Phorpiex처럼 몇 초 만에 종료해 그래프가 하나도 남지 않은 계열도 있었습니다.
- LLM 설명 계층을 행동 일관성 점검 다섯 가지로 평가하는 방법을 제시했습니다.

### Evaluation
- 데이터: MalwareBazaar의 악성 표본 6,835개와 DikeDataset, PortableApps, GitHub 릴리스, Windows 시스템 파일에서 모은 정상 표본 1,212개를 실행했고, 고유 API 노드가 두 개 미만인 표본을 빼니 그래프 2,516개(악성 1,793, 정상 723)가 남았습니다. 이를 70/15/15로 층화 무작위 분할했습니다.
- 악성 여부 분류: 시험 표본 378개에서 앙상블은 정확도 94.44%, F1 0.9617, MCC 0.8628, AUC 0.966을 냈고, 평평한 행동 특징 기준선보다 MCC가 7.4%포인트 높았습니다.
- 계열 분류: 그래프가 10개 이상인 24개 계열(1,774개)에서 정확도 68.91%, 매크로 F1 0.5818이었습니다. NanoCore(0.974), Vidar(0.900)는 잘 맞혔지만 IcedID, Netwire처럼 표본이 적은 계열은 0에 가까웠습니다.
- LLM 설명: 20개 계열의 20개 표본에 대한 보고서를 다섯 가지 일관성 점검으로 평가해 평균 5점 만점에 4.4점, 20개 중 12개가 모든 점검을 통과했습니다.
- 지표 신빙성: 저자들이 한계에서 직접 밝혔듯, 표본 단위 무작위 분할이라 같은 계열의 비슷한 변종이 학습과 시험에 함께 들어가 성능이 낙관적일 수 있습니다. 악성과 정상 표본의 출처가 완전히 달라, 분류기가 악성 행동이 아니라 수집 출처의 차이를 배웠을 가능성도 있습니다. 시험 표본이 378개로 작고, LLM 설명 평가도 20개 표본에 대한 저자들의 규칙 기반 점검이라 일반화하기 어렵습니다.

#### Comment
- 새 탐지 기법보다는 감염 후 행동을 계열별로 정리한 기술 보고서에 가깝습니다. 계열별 행동 지문과 샌드박스에서 행동이 사라지는 계열 목록은 샌드박스 기반 분석을 설계할 때 참고할 만합니다.
- 한계: 시간 기준 분할이 없고, 표본 대부분이 MalwareBazaar의 범용 악성코드라 표적 공격용 악성코드와 Windows 이외 플랫폼은 거의 빠져 있습니다. 샌드박스 관찰 시간이 짧아 지연 실행 행동을 놓칠 수 있습니다. 서론은 IoT 위협 통계로 시작하지만 실제 분석 대상은 Windows PE 파일입니다.
