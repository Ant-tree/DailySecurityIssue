# Reconfiguring System-Level Protection Through Bounded Delegation in RISC-V MCUs
> arXiv 프리프린트 (심사 전)
> 2026

마이크로컨트롤러(MCU) 기반 임베디드 시스템에서는 OTA 업데이트처럼 실행 중에 메모리 영역이나 가속기를 다른 도메인으로 넘겨야 하는 일이 늘고 있습니다. 그런데 상용 MCU의 보호 장치는 "누가 보호 규칙을 바꿀 수 있는지"만 제한할 뿐, 권한을 받은 도메인이 "어떤 규칙을 만들 수 있는지"는 제한하지 않습니다. 그래서 설정 권한을 위임받은 도메인이 자기 영역을 넘어 규칙을 넓히거나 다른 도메인의 경계와 겹치는 규칙을 만들 수 있습니다. 이 논문은 이를 "제한된 설정 권한"이라는 빠진 기본 요소로 정의하고, 규칙마다 소유자를 두고 위임된 규칙이 소유자 규칙 범위 안에 들어가는지를 반영 전에 검사하는 소유권 기반 모델을 제안했습니다. 이 모델을 오픈소스 RISC-V World Checker에 구현해 CVA6 기반 SoC에 통합했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12622
- arXiv HTML 본문: https://arxiv.org/html/2611.12622
- arXiv PDF: https://arxiv.org/pdf/2611.12622

### Contribution
- 기존 MCU 보호 장치를 조사해, 설정 접근 제어만으로는 정책 권한이 제한되지 않는다는 문제를 정리했습니다.
- 명시적 소유권과 규칙 포함 관계로 설정 권한과 재위임을 함께 제한하는 모델을 제안했습니다. 검사는 설정 경로에서만 이뤄지므로 평소의 메모리 접근 검사 경로는 늘어나지 않습니다.
- 펌웨어나 하이퍼바이저를 거치지 않고 위임받은 도메인이 직접 정책을 바꿀 수 있어, 정책 전환 지연을 크게 줄였습니다.

### Evaluation
- Xilinx Genesys2 FPGA 위의 단일 하트 CVA6 SoC에서 하드웨어 비용, 접근 지연, 재설정 지연, 보안 강제 여부를 평가했습니다.
- 규칙 8개 기준으로 LUT 7.1%, FF 1.2%가 늘었고(기존 6,157 LUT에서 6,595 LUT), 접근 지연과 동작 주파수는 떨어지지 않았습니다. 규칙 수는 1개부터 64개까지 바꿔 가며 측정했습니다.
- OTA 업데이트 사례에서 위임받은 도메인의 직접 재설정은 하이퍼바이저 중재 대비 89.5%, 신뢰 펌웨어(OpenSBI) 중재 대비 94.6% 정책 전환 지연을 줄였습니다.
- 정상적인 세분화는 허용하고, 범위를 넘거나 다른 도메인과 겹치는 규칙 변경은 반영 전에 거부되는지를 시나리오로 확인했습니다.
- 식별자 위조, 검사기 우회, 물리 공격, 서비스 거부는 위협 모델에서 제외했습니다.

#### Comment
- 포르투갈 미뉴대학교(Sandro Pinto 연구실)와 Infineon Technologies 공동 연구로, 산업 측 저자가 다수 참여해 실제 MCU 설계와의 연결성이 높습니다. 결과를 RISC-V 국제 표준화 논의에 반영하려는 목적을 밝히고 있습니다.
- 모든 결과물을 공개하겠다고 했지만 아직 공개 주소는 본문에 없습니다.
- 단일 하트 FPGA 프로토타입 평가라 실제 양산 MCU에서의 면적과 전력 비용은 더 확인이 필요합니다.

# Public, Identifiable, and Effectively Immutable: Ethical Lessons from Research on arXiv
> 19th Workshop on Cyber Security Experimentation and Test (CSET 26, ACSAC 26 동시 개최) 채택, arXiv 프리프린트. RWTH 아헨공대(독일), 남덴마크대학교(덴마크), 플로리다 국제대학교(미국)
> 2026

arXiv는 논문을 올릴 때 LaTeX 소스 파일도 함께 받아 그대로 공개 배포하는데, 많은 저자가 이를 모릅니다. 그래서 소스 파일 안에 남은 주석, 할 일 목록, 지운 줄 알았던 문장, 심지어 자격 증명이나 개인 키가 그대로 노출되는 경우가 있고, arXiv는 이렇게 실수로 공개된 내용을 고치는 것을 허용하지 않습니다. 이 소스 파일을 분석한 연구가 최근 세 편(그중 하나는 저자들의 연구) 나왔는데, 세 편 모두 윤리 성명을 실었으면서도 도구 공개 여부, 내장 링크를 따라가도 되는지 등에서 서로 다른 결론을 냈습니다. 이 경험 논문은 연구자, 피해 저자, 독자와의 논의를 바탕으로 arXiv라는 "공개되어 있고, 실명으로 식별되며, 사실상 지울 수 없는" 데이터셋의 윤리적 상황을 정리하고, 네 가지 딜레마와 네 가지 교훈을 제시했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12271
- arXiv HTML 본문: https://arxiv.org/html/2611.12271
- arXiv PDF: https://arxiv.org/pdf/2611.12271
- 저자 연구실(RWTH 아헨 COMSYS) 논문 페이지: https://www.comsys.rwth-aachen.de/publication/2026/2026_pennekamp_public-identifiable-effectively-immutable/
- 저자 연구실 논문 PDF: https://www.comsys.rwth-aachen.de/publication/2026/2026_pennekamp_public-identifiable-effectively-immutable/2026_pennekamp_public-identifiable-effectively-immutable.pdf

### Contribution
- 소스 파일 안에서 끝나는 자체 포함 데이터(주석, 욕설, 낡은 문장 등으로 사실상 고칠 수 없음)와 외부에서 악용할 수 있는 데이터(접근 토큰, 자격 증명, 개인 키 등으로 일부는 폐기나 교체로 고칠 수 있음)로 나누고, 유형별 수정 가능성과 민감도를 정리했습니다.
- 네 가지 딜레마를 도출했습니다. 민감 정보를 정량화하려면 읽어야 한다는 문제, 검증 시도와 과잉 보고 사이의 문제, 문제 규모와 가용 자원(사람의 주의력, LLM 사용에 따른 계산 자원) 사이의 문제, 알림이 주는 인식 개선 효과와 오히려 노출 정보에 주목을 끄는 부작용 사이의 문제입니다.
- 네 가지 교훈을 제시했습니다. 공개되어 있다는 사실은 윤리 판단의 출발점이지 결론이 아니며, 연구가 노출 정보를 더 찾기 쉽게 만드는 증폭을 최소화해야 하고, 공개와 알림은 피해 정도, 확신도, 수신자가 실제로 조치할 수 있는지에 맞춰 조정해야 하며, 사실상 지울 수 없다는 점을 수집, 검증, 공개 전 과정에서 고려해야 한다는 것입니다.

### Evaluation
- 정량 실험이 없는 경험 논문입니다. 기존 arXiv 소스 파일 연구 세 편(60만 건 분석, 전체 코퍼스 분석, 10만 건 LLM 분석)의 윤리 판단(자격 증명 시험 사용 금지, 분석 코드 비공개 결정, 책임 있는 공개 미실시 등)을 비교 분석하는 방식으로 논의를 전개했습니다.
- 지표의 신빙성: 근거가 저자들의 경험과 논의, 선행 연구의 윤리 성명에 기반하므로 일반화에는 한계가 있습니다. 저자 중 한 명이 비교 대상 연구의 저자라는 점도 감안해야 합니다.
