# When Shuffling Fails: Token Recovery from Obfuscated KV Caches
> arXiv 프리프린트 (심사 전). 화중 과학기술대학교, 매쿼리 대학교, 그리피스 대학교
> 2026

LLM 서빙 시스템은 효율을 위해 KV 캐시 블록을 저장하고, 다른 장치로 옮기고, 요청끼리 공유합니다. 그 과정에서 토큰 수준 표현이 인프라 운영자나 같은 장비를 쓰는 다른 사용자에게 노출됩니다. 최근 방어 기법(KV-Cloak, PermLLM 등)은 비밀 선형 변환과 매번 새로 뽑는 무작위 순열을 결합한 "셔플 난독화"로 이를 막으며, 가능한 순열 수 b!을 안전성의 근거로 내세웁니다. 저자들은 이 계산이 틀렸다고 지적합니다. 같은 토큰을 반복한 입력을 넣으면 캐시 블록의 첫 층 Value 행이 모두 같아져 어떤 행 순열도 데이터를 바꾸지 못하고, 위치가 바뀌는 것은 복구용 표지 한 줄뿐이라 구별 가능한 상태가 b!개에서 b개로 줄어듭니다. 이 성질을 이용한 Repeat-to-Reveal 공격은 공격자가 자기 탐침 입력으로 b개 상태를 모은 뒤, 상태 사이의 계수 1(rank-one) 차이로 비밀 변환과 같은 효과의 복호기를 복원합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.24276
- arXiv HTML 본문: https://arxiv.org/html/2611.24276
- arXiv PDF: https://arxiv.org/pdf/2611.24276

### Contribution
- 셔플 난독화의 안전성은 순열의 개수가 아니라 공격자가 고른 입력에서 "구별되는 출력"의 개수로 따져야 한다는 점을 보였습니다. 같은 원리가 KV-Cloak뿐 아니라 Thomas 등의 순열 구현과 PermLLM에도 적용됨을 확인했습니다.
- 한 번 보정하면 같은 비밀 주기(epoch) 안의 다른 요청에서 관찰한 캐시 블록까지 수동적으로 복원할 수 있어, 공격 비용이 요청 수에 비례해 늘지 않습니다.
- 대안으로 난독화 대신 바이트 단위 인증 암호화를 쓰는 VeilKV를 제안하고 vLLM에서 동작을 확인했습니다. 공개 접두사 공유와 요청별 비공개 부분의 범위 제한을 지원합니다.

### Evaluation
- 공식 KV-Cloak 구현(커밋 6b40f36)을 대상으로, Qwen, Llama, OLMo, TinyLlama 계열 공개 모델 11개와 블록 크기 변형을 포함한 13개 구성에서 WildChat 실제 사용자 프롬프트 3,000개로 평가했습니다(A100 GPU 1장).
- 결과: 비밀 매개변수를 거의 정확히 복원했고, GPU 환경에서 토큰 다중집합 복원율 100%를 달성했습니다. 언어 모델로 순서까지 복원하면 원문과의 의미 유사도가 0.947이었고, 후보 100개 가운데 사용자가 입력한 민감한 값을 맞히는 정확도(상위 1개)는 97.5%였습니다.
- 주기마다 행 단위 비밀을 새로 뽑으면 요청 간 전이가 끊겨, 비밀 재사용 범위가 실제 취약점임을 확인했습니다.
- 신빙성: 공격이 대수적이고 결정적이라 100% 수치가 부자연스럽지는 않습니다. 대상이 공식 구현의 특정 커밋으로 고정되어 있어 재현 조건이 명확합니다. 민감 값 실험은 합성 데이터라 실제 환경의 후보 집합 크기에 따라 결과가 달라질 수 있습니다.

#### Comment
- 난독화를 보안 장치로 쓸 때 "탐색 공간이 크다"는 논리만으로는 부족하고, 공격자가 입력을 고를 수 있으면 대칭성 때문에 공간이 무너질 수 있다는 점을 잘 보여 주는 사례입니다. 코드 난독화 평가에서도 참고할 만한 관점입니다.
- 중국 기관 논문이라 추가로 확인했습니다. 저자는 화중 과학기술대학교와 호주 두 대학 소속이고, 공격 대상은 공개된 공식 구현입니다. 책임 있는 공개 절차에 따라 2026년 11월 3일 보고서를 제출했고, KV-Cloak 개발자가 11월 17일 취약점을 인정했다고 본문에 적혀 있어 외부 확인이 있습니다. 다만 공격 코드 공개 주소는 본문에서 찾지 못했습니다.

# ElevatorII: High-Performance Fully-Static Cross-ISA Binary Translation
> arXiv 프리프린트 (심사 전). UC 어바인
> 2026

다른 명령어 집합(ISA)용 바이너리를 실행하는 일반적인 방법은 에뮬레이션과 JIT 컴파일이지만, 대상 장비에 신뢰해야 하는 런타임이 필요하고 동적 컴파일 결정을 예측하거나 재현하기 어렵습니다. 저자들은 x86-64 ELF 바이너리를 런타임 지원 없이 독립 실행 가능한 AArch64 ELF로 미리 바꾸는 완전 정적 번역기 ElevatorII를 제안했습니다. 핵심은 상위 집합 역어셈블(superset disassembly)입니다. 텍스트 영역의 모든 바이트 오프셋에서 명령어를 하나씩 해석해 번역한 블록 "격자"를 만들어, 정적으로 알 수 없는 간접 분기가 어디로 가든 미리 번역된 코드가 있게 합니다. 여기에 관찰 기반 경로 선택(OGPS)으로 최적화한 "확인된 경로"를 덧씌우고, 자주 쓰이는 코드는 주 영역에, 나머지는 .text.unlikely 영역에 둡니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.19577
- arXiv HTML 본문: https://arxiv.org/html/2611.19577
- arXiv PDF: https://arxiv.org/pdf/2611.19577

### Contribution
- 바이트 단위 격자와 최적화 경로를 결합한 최초의 완전 정적 교차 ISA 번역기라고 저자들은 밝힙니다. 실행될 바이너리 자체를 미리 시험할 수 있어 JIT가 들어간 에뮬레이터보다 배포 위험이 낮습니다.
- 코드와 데이터를 가르지 않고 모든 해석을 번역하므로, 정적 역어셈블러가 따라가지 못하는 가상화 난독화나 분기 함수 난독화가 적용된 바이너리도 번역할 수 있습니다.
- 코드 크기를 성능과 맞바꾸는 새로운 설계 선택을 제시했습니다.

### Evaluation
- 벤치마크: SPEC CPU 2026 정수 부문(C/C++ 14개 중 C++ 예외를 쓰는 3개 제외), 45개 기준 입력. 비교 대상은 네이티브 AArch64 빌드, Box64(가장 빠른 동적 번역기), QEMU 사용자 모드입니다.
- 결과: 전체 실행 시간 기준 OGPS를 쓴 ElevatorII가 Box64보다 2%, QEMU보다 80% 앞섰고, QEMU는 모든 벤치마크에서 3~15배 느렸습니다. 프로파일 없이는 Box64보다 34% 뒤졌습니다. 출력 코드는 소스에서 컴파일한 코드의 51배 크기지만 주 영역에 들어가는 자주 쓰는 코드는 2~3%뿐입니다.
- 난독화 실험: Tigress로 핫 함수에 세 가지 변환을 함께 적용한 프로그램도 번역했습니다. sqlite에서는 난독화된 프로그램이 네이티브로도 11배 오래 걸리고 Box64에서 12배, ElevatorII에서 16배였습니다. 난독화 함수 비중이 큰 경우에는 Box64가 앞섰습니다.
- 신빙성: 표준 벤치마크와 공개 도구를 비교 대상으로 써서 비교 조건은 공정해 보입니다. 다만 단일 스레드 프로그램만 지원하고, 프로파일 기반 최적화의 효과는 실행 입력에 따라 달라질 수 있습니다.

#### Comment
- 지난 실행에서 본문을 구하지 못해 이월했던 논문이며, 이번에는 난독화 바이너리 처리가 주요 기여에 포함되어 있어 난독화 분류에 실었습니다.
- 역난독화 관점에서는, 정적 분석이 실패하는 난독화 바이너리를 "해석하지 않고도" 다른 아키텍처에서 그대로 실행할 수 있다는 점이 흥미롭습니다. 반대로 보호 측면에서는 가상화 난독화가 플랫폼 이식을 막는 장벽이 되지 못함을 시사합니다.
- 한계: 실행 중 코드를 생성하거나 고치는 프로그램(JIT 등), C++ 예외, 다중 스레드는 지원하지 않습니다. 저자 Michael Franz는 바이너리 변환과 소프트웨어 다양화 분야의 오랜 연구자입니다.
