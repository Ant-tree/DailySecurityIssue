# Rethinking Neural Decompilation: Candidate Selection as the Hidden Bottleneck
> ICICS(International Conference on Information and Communications Security) 게재 논문, arXiv cs.CR 2611.02788 공개본. 뤼베크대학교 IT보안연구소(독일)
> 2026

LLM 기반 신경망 디컴파일러는 Ghidra나 IDA Pro 같은 규칙 기반 도구보다 읽기 좋고 기능적으로 정확한 코드를 복원하지만, 여러 번 생성해 그중 가장 좋은 결과를 고를 때의 성능과 실제로 한 번에 내놓는 결과의 정확도 사이에는 큰 차이가 있습니다. 이 차이는 제어 흐름 평탄화(FLA)나 가짜 제어 흐름(BCF) 같은 난독화가 걸리면 더 커져서, 원래 LLM4Decompile 논문은 공개 체크포인트가 난독화된 입력에 적합하지 않다고 결론 내렸습니다.

이 논문은 디컴파일을 "후보 생성"과 "후보 선택"의 두 단계로 나눠 봅니다. LLM4Decompile 구조를 분석해 보니 정답 토큰이 모델의 다음 토큰 상위 5개 예측 안에 평균 95.6% 위치에서 들어 있었고, 여러 번 샘플링하면 HumanEval-Decompile에서 pass@100이 93%에 이르렀습니다. 즉 정답은 이미 모델의 샘플 공간 안에 있고, 문제는 그것을 골라내는 데 있다는 것입니다. 저자들은 입력마다 후보 100개를 만들고 텍스트, 구문, 임베딩, 합의, 가능도, 실행 기반 선택기로 순위를 매기는 "생성 후 선택" 방식을 체계적으로 비교했습니다. 또한 OLLVM으로 난독화한 표본 362,647개로 이루어진 ExeBench-Obfuscated 데이터셋을 새로 만들어 공개했습니다.

### Contribution
- 토큰 수준 분석으로, 정답 복원 결과가 대부분 이미 모델의 샘플링 공간에 있다는 점을 보였습니다. 오류는 컴파일 과정에서 사라지는 식별자 이름과 const, static 같은 한정자에 몰려 있었습니다.
- 선택기를 체계적으로 비교해, 음의 퍼플렉서티(모델 자신의 가능도)가 HumanEval-Decompile에서 가장 강한 정적 선택기임을 확인했습니다.
- 난독화 표본 362,647개의 ExeBench-Obfuscated 데이터셋을 공개하고, 이 데이터로 한 에포크만 미세조정해도 선택 파이프라인과 결합하면 난독화된 바이너리의 pass@1이 88.8%에 이른다는 점을 보여, 공개 체크포인트가 난독화 입력에 쓸 수 없다는 기존 주장을 반박했습니다.

### Evaluation
- 설정: Ghidra 의사 코드 입력에는 LLM4Decompile-Ref-9B-v2, 어셈블리 입력에는 LLM4Decompile-End-6.7B-v1.5를 쓰고, HumanEval-Decompile과 ExeBench 두 벤치마크를 조합한 네 가지 설정에서 시험했습니다. 후보는 온도를 0.0~1.0으로 섞어 입력당 100개를 만들었고, 시드 다섯 개의 평균을 보고했습니다.
- 결과: 무작위 선택과 오라클(정답이 하나라도 있으면 성공) 사이의 차이는 16.3~33.4%포인트였습니다. 정적 선택기 중에서는 음의 퍼플렉서티가 네 설정 중 세 곳에서 가장 좋아 HumanEval-Decompile 의사 코드 입력에서 pass@1 73.3%를 냈습니다. 테스트를 실행해 고르는 실행 기반 선택은 ExeBench에서 86.3%, 75.4%로 오라클과 0.5%포인트 이내까지 좁혔습니다. 후보 생성에는 입력당 약 12.6초가 더 듭니다.
- 지표 신빙성: 같은 후보 풀을 고정한 뒤 선택기만 바꿔 비교했으므로 선택기 간 비교는 공정합니다. 다만 컴파일 가능한 후보가 하나도 없는 입력은 선택 분석에서 뺐고, 실행 기반 선택은 입력과 출력 테스트가 있어야 하므로 실제 리버스 엔지니어링 현장에서는 그대로 쓰기 어려울 수 있습니다. 88.8%는 OLLVM 난독화 데이터로 미세조정한 뒤의 수치라, 학습에 쓰지 않은 다른 난독화 도구에 대한 일반화는 별도로 봐야 합니다.

#### Comment
- 난독화 도구를 만드는 입장에서 주목할 결과입니다. OLLVM의 평탄화와 가짜 제어 흐름 같은 고전적 변환은 해당 변환으로 미세조정한 신경망 디컴파일러와 후보 선택을 결합하면 상당 부분 되돌려질 수 있다는 뜻이기 때문입니다. 난독화의 강도를 평가할 때 "디컴파일러 한 번 실행" 대신 "여러 후보 생성 후 선택"을 공격 모델로 삼아야 한다는 점을 보여 줍니다.
- 한계: 대상이 C 함수 단위이며, 함수 간 구조나 대형 프로그램 전체 복원은 다루지 않습니다.
