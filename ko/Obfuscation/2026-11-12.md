# RoCoMark: Robust Code Watermarking Against LLM-Based Functionality-Preserving Rewriting Attacks
> arXiv 프리프린트 (심사 전, v2). 쓰촨사범대학, 상하이대학, 지난대학(중국)
> 2026

소스 코드 워터마킹은 생성된 코드의 출처와 소유권을 확인하는 수단이지만, 최신 LLM은 기능은 그대로 두고 변수, 식, 제어 흐름, 반복문 구조까지 다시 써서 워터마크를 지울 수 있습니다. 이는 난독화와 같은 계열의 의미 보존 코드 변환 공격입니다. 저자들은 기존 방식(SrcMarker, RoSeMary 등)이 약한 이유를 공격 강도보다 "학습 때 본 변형과 LLM 재작성의 분포가 다르다"는 데서 찾습니다. 이에 따라 워터마크 삽입기와 LLM 재작성기 사이의 여러 라운드 미니맥스 게임으로 학습하는 RoCoMark를 제안했습니다. 각 라운드에서 LLM이 다시 쓴 코드로 인코더를 대조 학습과 지식 증류로 적응시키고(위협 프로파일링), 인코더와 추출기를 함께 최적화한 뒤, Reflexion과 단기, 장기 기억 풀을 이용해 재작성 공격을 점점 강하게 진화시킵니다.

### Contribution
- LLM 재작성 공격 아래 워터마크가 무너지는 원인을 학습 분포 불일치로 진단하고, 공격자를 학습 과정 안에 넣어 함께 진화시키는 적대적 학습 틀을 제시했습니다.
- 재작성 전후 코드의 임베딩 거리를 줄이도록 인코더를 적응시키면서, 대조 학습과 지식 증류로 기존 표현이 무너지는 문제(표현 표류)를 억제했습니다.
- 다중 비트 메시지를 넣는 사후 처리 방식이라 기능 보존율이 높고, 소유자 메시지 복원까지 가능합니다.

### Evaluation
- 데이터: CodeSearchNet Python 함수 25,000개로 학습하고, HumanEval(164), MBPP(974), EvalPlus(542), APPS(5,000개 부분집합)로 평가했습니다.
- 비교 대상: SWEET(추론 시점 워터마킹), SrcMarker, RoSeMary. 사후 처리 방식 세 가지는 같은 학습 데이터로 다시 학습해 비교했습니다.
- 공격: GPT-5.5, DeepSeek-V4-Flash, MiMo-V2.5-Pro, GLM-5, Claude Sonnet 4.5로 강도가 다른 프롬프트 4종을 써서 재작성하고, 문법, 인터페이스, 기능 시험을 통과한 재작성 코드만 평가에 넣었습니다.
- 결과: 다섯 공격 평균 AUROC 74.2%, 비트 정확도 75.3%, 기능 통과율 99.7% 이상. MiMo 공격에서 AUROC 0.7408, TPR 0.4638, FPR 0.0463으로 RoSeMary(0.7182, 0.4062), SrcMarker(0.6948, 0.3617)보다 조금 높았습니다. 변수 이름 바꾸기 비율을 50%까지 높인 공격에서도 가장 높은 AUROC를 유지했습니다.
- 지표의 신빙성: 비교 대상이 이 분야의 대표적인 공개 방법이고 같은 데이터로 다시 학습해 비교 조건은 공정한 편입니다. 다만 학습에 MiMo-V2.5-Pro 재작성 결과를 대량으로 썼는데 같은 모델이 시험 공격자에도 포함되어 있어, 이 공격에서의 결과는 처음 보는 공격에 대한 일반화로 보기 어렵습니다. 개선 폭도 2~3%포인트 수준이고, TPR이 0.46 정도라 재작성된 코드의 절반 이상은 여전히 워터마크가 검출되지 않습니다. Python만 평가했습니다.
