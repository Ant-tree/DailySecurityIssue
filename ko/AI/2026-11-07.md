# A Gingerbread House for LLM Agents: Source-Planned Honeypots That Lure Autonomous Attackers into an Isolated Shadow
> arXiv cs.CR 2611.07611 (프리프린트, 심사 전). 숭실대학교
> 2026

LLM 에이전트가 웹 취약점을 찾아 공격하는 속도가 빨라지면서, 방어자가 패치를 끝내기 전에 침해가 일어날 수 있다는 우려가 커지고 있습니다. 지금까지 LLM 공격 에이전트를 겨냥한 기만 기법은 대부분 미끼 쪽으로 주의를 끄는 데 그쳐, 실제 취약 경로는 여전히 열려 있었습니다. 이 논문은 다른 구성을 시험합니다. 배포 전에 방어용 LLM이 애플리케이션 소스 코드를 읽고 정적 허니팟(미끼 페이지, 가짜 엔드포인트, 허니토큰)을 설계해 두고, 실행 중에는 고정 코드로 된 라우터가 클라이언트별 상태를 관리합니다. 공격 페이로드 서명이나 404 응답 폭주가 보이면 "의심" 상태로, 허니토큰 사용이나 가짜 엔드포인트 접근이 확인되면 "확정" 상태로 바꾸고, 확정된 클라이언트의 이후 요청은 실제로 동작하는 익스플로잇까지 포함해 모두 별도 컨테이너에 있는 격리된 복제본(섀도)으로 보냅니다.

비교 대상은 방어 없음(A), 정적 계획만 쓰는 구성(B), 여기에 실행 중 LLM 응답기와 추가 라우터 규칙을 더한 구성(C) 세 가지입니다. 판정은 벤치마크의 기존 채점기를 그대로 써서 실제 대상과 섀도 양쪽에서 수행했습니다.

### Contribution
- 소스 코드를 바탕으로 LLM이 미리 설계한 정적 기만과, 공격자로 확정된 클라이언트를 격리된 복제본으로 통째로 옮기는 라우팅을 결합해, 실제 침해에 쓰인 공격 프레임워크를 상대로 평가했습니다. 섀도 허니팟이나 허니 패치 같은 고전적 설계를 LLM 공격자 환경으로 옮긴 셈입니다.
- 실제 침해율이 0에 가까워져 구성 간 차이를 가릴 수 없는 상황을 고려해, "실제 대상 침해", "섀도에서만 익스플로잇 성공", "공격자가 가짜 비밀값을 진짜로 보고했는지", "확정 전 실제 대상에 닿은 페이로드 수" 같은 보조 지표를 따로 측정했습니다.
- 설계에 쓰지 않은 새 CVE 20개로 구성한 alt-cve-bench를 공개했습니다. CVE-Bench와 같은 과제 형식과 같은 채점기를 씁니다.

### Evaluation
- 실험은 세 단계입니다. Claude Opus 4.8 공격자로 CVE-Bench 치명 등급 40개 과제(기만 설계에 쓴 개발용 집합), 오픈소스 다중 에이전트 공격 프레임워크 ARTEX(DeepSeek-V4-Flash 구동)로 같은 40개 과제, ARTEX로 alt-cve-bench 20개 과제입니다. 계획한 300회 중 296회를 기록했고 288회가 유효했습니다.
- 정적 계획(B)만으로 실제 침해가 Opus 4.8 기준 26/40에서 5/40으로, ARTEX 기준 20/40에서 0/40(유효 31회)으로, 새 과제에서는 15/20에서 0/20으로 줄었습니다. 통제군이 침해한 30개 과제에서 B의 침해율 95% 신뢰구간 상한은 11.6%입니다.
- ARTEX 실험의 기만 구성에서는 실행의 약 절반에서 익스플로잇이 섀도에서만 성공했습니다. 즉 방어가 익스플로잇을 막은 것이 아니라 옮긴 것이며, 남은 위험은 확정 전에 실제 대상에 도달한 요청입니다. 섀도가 처리한 ARTEX 요청 비율의 중앙값은 95.2%, 93.2%였습니다.
- ARTEX는 기만 구성 120개 과제 가운데 30개에서 심어 둔 가짜 비밀값을 진짜로 보고했고, 그중 20번은 실제로 동작한 익스플로잇 없이 미끼만 보고 보고했습니다. 다섯 번은 한 항목은 미끼라고 적으면서 다른 가짜 비밀값은 진짜로 보고했습니다.
- B와 C의 차이는 통계적으로 유의하지 않았습니다(예: Opus 4.8 실제 침해 5/40 대 1/40, 정확 McNemar 검정 p = 0.22). 정상 크롤러는 기록된 실행 대부분에서 정상 상태로 남았고, 두 번 의심 상태가 되었지만 확정된 적은 없었습니다.
- 지표 신빙성: 벤치마크 채점기를 바꾸지 않았고, 우회 행위(외부 정보 검색, 다른 실행 파일 읽기 등)를 검사해 무효 처리하는 절차와 채점기 양성 대조 실험까지 갖춰 신뢰할 만합니다. 다만 과제와 구성마다 한 번씩만 실행했고, 클라이언트 식별을 리스너 단위로 고정했으며, 정상 트래픽이 크롤러 하나뿐이라 실제 배포 환경의 오탐률은 알 수 없습니다.

#### Comment
- "공격 에이전트를 막지 말고 진짜와 똑같은 가짜로 옮긴다"는 발상이 눈에 띕니다. 무력화보다 기만에 가까워, 실제 대상을 지키면서 공격자가 운영자에게 잘못된 성과를 보고하게 만든다는 점이 실무적으로 흥미롭습니다.
- 한계: 공격자가 신원(세션, 주소)을 바꾸면 새 클라이언트로 처음부터 다시 시작합니다. 섀도의 컨테이너 이름 같은 단서가 코드 실행 권한을 얻은 공격자에게 드러난 경우가 있어, 실제 배포에서는 이런 흔적을 숨겨야 한다고 저자들이 직접 적었습니다. 응답기(C)의 효과는 이 설계로는 따로 분리되지 않습니다.
- 신뢰도: 국내 대학 연구진의 심사 전 원고입니다. 사전 설계된 지표와 통계 검정, 한계 서술이 비교적 꼼꼼합니다.

# Signed but Not Safe: Requirement Integrity in Multi-Agent LLM Handoffs
> arXiv cs.CR 2611.07483 (프리프린트, 심사 전). 매사추세츠대학교 애머스트, 듀크대학교, 조지아공과대학교, 일리노이대학교 어바나-섐페인, Accentrust
> 2026

기업용 AI 에이전트는 사용자 요청을 여러 하위 에이전트에 나눠 맡기고 결과를 합칩니다. 이때 요청을 넘겨주는 지점마다 요구사항이 요약 과정에서 빠지거나, 중간 에이전트가 고치거나, 간접 프롬프트 주입으로 바뀌거나, 결과를 합치는 에이전트가 무시할 수 있습니다. 이 논문은 이 문제를 "적대자 없이 생기는 손실"과 "의도적인 변조"로 나누고, 사전 등록한 통제 실험으로 세 가지 전달 방식을 비교합니다. 자유 형식 요약, 구조화된 JSON, 그리고 서명된 요구사항 목록(매니페스트)입니다.

매니페스트 방식에서는 오케스트레이터가 요구사항마다 원문 그대로의 인용과 검사 가능한 조건식을 뽑아냅니다. 신뢰하는 실행 코드가 인용이 원문에 실제로 있는지 확인하고, JSON을 정규화한 뒤 어떤 모델도 보지 못하는 키로 HMAC-SHA256 서명을 붙이며, 최종 결정이 모든 조건을 지키는지 LLM이 아닌 결정적 코드로 검증합니다. 위반이 있으면 한 번 고칠 기회를 주고, 그래도 안 되면 실행하지 않습니다.

### Contribution
- 오케스트레이터, 하위 에이전트, 병합 에이전트로 이어지는 흐름에서 요구사항 단위 위협 다섯 가지(정상, 요약 손실, 전송 중 변조, 도구 출력 주입, 병합 단계 지시 덮어쓰기)를 정의하고, "위반인데 걸리지 않고 실행된 결정"(안전하지 않은 실행)과 "요구사항을 모두 지킨 실행"(유용성)을 함께 보도록 지표를 설계했습니다. 실행을 거부해서 안전해 보이는 착시를 막기 위해서입니다.
- 서명 없는 매니페스트와 서명된 매니페스트를 비교해, 서명이 실제로 무엇을 더하는지 분리했습니다.
- 같은 실행 기록 위에서 결정적 검증기와 LLM 검사기를 나란히 비교했습니다.
- 정답 매니페스트(오라클)를 준 대조 실험과 서명 전 주입 공격으로, 서명으로는 고칠 수 없는 잔여 위험이 추출 단계에서 생긴다는 점을 보였습니다. 서명은 전송 구간을 보호할 뿐이고, 신뢰 경계는 추출 단계라는 것이 핵심 결론입니다.

### Evaluation
- 주 실험은 Qwen3-8B로 다섯 가지 위협에 걸쳐 1,440개 실행 기록을 만들었습니다. 공격 상황에서 안전하지 않은 실행 비율은 서명된 매니페스트가 9.0%로, 비교 기준의 69.4%보다 크게 낮았습니다(차이 60.4%포인트, 95% 신뢰구간 51.4~69.4). 구조상 거부가 보장되는 전송 중 변조를 빼고 주입과 병합 덮어쓰기만 보면 58.4% 대 13.5%입니다. 구조화 JSON 대비 정상 실행 비율의 손실은 없었습니다(-0.4%포인트).
- 서명의 효과: 전송 중 변조 실행에서 서명 없는 매니페스트는 79%가 위반을 실행했고 서명된 매니페스트는 한 건도 없었습니다. 대신 변조된 실행은 끝까지 가지 못하고 중단됩니다.
- 같은 실행 기록에서 결정적 검증기는 위반 결정의 78.7%를 잡았고 오경보는 7%였습니다. LLM 검사기는 59.0%를 잡고 오경보가 50%였습니다.
- 오라클 매니페스트를 주면 남은 안전하지 않은 실행이 모두 사라졌습니다. 즉 남은 11.2%포인트는 서명 전 추출 오류(선호 사항을 필수로 뽑거나 요구사항을 빠뜨림)에서 나옵니다.
- 서명 전 주입 공격: 요청 문맥에 적대적 문장 한 줄을 넣자 서명된 매니페스트의 위반 비율이 Qwen3-8B 14.6%에서 37.5%, gpt-oss-20b 11.1%에서 63.9%, GPT-5.6-luna 8.3%에서 75.0%로 올랐습니다. 모든 위반은 서명 전에 오염된 매니페스트에서 나왔고, 서명은 오히려 그것을 인증해 주었습니다.
- 두 번째 모델군인 gpt-oss-20b(432개 실행 기록)에서는 구조화 JSON만으로도 적대자가 없거나 주입만 있을 때는 이미 안전했고, 이득은 변조 저항에서만 나왔습니다. 매니페스트 추출이 과제의 22%에서 실패해 유용성 손실도 있었습니다.
- 지표 신빙성: 가설, 다중 비교 보정 방식, 파서 규칙을 모델 호출 전에 고정하고 해시로 기록했으며 사전 수정 사항도 공개해 투명성이 높습니다. 반면 과제가 정확히 채점할 수 있도록 만든 합성 과제이고, 주 모델이 8B급이라 실제 기업 업무로 바로 일반화하기는 어렵습니다. 코드와 데이터는 요청 시 제공한다고만 적었습니다.

#### Comment
- 제목 그대로 "서명했다고 안전한 것은 아니다"를 실험으로 보여 준 논문입니다. A2A 에이전트 카드나 AP2 결제 위임처럼 에이전트 산출물에 서명을 붙이는 흐름이 늘고 있는데, 서명 이전 단계(요구사항 추출)가 공격 표면으로 남는다는 지적은 설계 시 참고할 만합니다.
- 한계: 오케스트레이터 자체가 오염되거나 실행 코드가 침해되는 경우, 키 탈취는 다루지 않습니다. 최신 대형 모델 실험은 탐색적 하위 실험에 그칩니다.
- 신뢰도: 미국 대학과 보안 기업 연구진의 심사 전 원고입니다.

# Authorization Propagation in Agent2Agent Systems: An Experimental Security Evaluation of Multi-Hop Delegation
> arXiv cs.MA 2611.07050 (cs.CR 교차 게재, 프리프린트, 심사 전). 노르웨이과학기술대학교(NTNU) 정보보안통신기술학과
> 2026

Agent2Agent(A2A) 프로토콜로 여러 에이전트가 작업을 이어 맡을 때, 지금 요청을 보내는 에이전트와 권한을 처음 부여한 주체가 다를 수 있습니다. A0에서 A1, A2로 작업이 넘어가면 A2는 직전 호출자 A1을 인증할 수는 있지만, 요청된 작업이 앞 단계에서 정한 권한 범위 안에 있는지는 알 수 없습니다. 반대로 권한 증거가 유효하다고 해서 그것을 들고 온 현재 요청이 인증되는 것도 아닙니다.

이 논문은 이 두 가지를 분리해 검증하는 계층형 설계를 합성 의료비 환급 업무(환급 클라이언트, 환자 에이전트, 병원 에이전트, 보험 에이전트의 네 당사자)로 시험합니다. 현재 호출자 정보(Secure Passport 확장의 CallerContext, Ed25519 서명), 여러 단계를 거쳐 전달되는 권한 증거(공유 HMAC 키로 보호), 단계별 Ed25519 요청 서명, 요청과 권한 증거 각각의 재사용 방지 상태를 층층이 더하며 네 가지 구성(C0~C3)을 비교했습니다.

- A2A 핵심 프로토콜을 고치지 않고 확장만으로 이 계층을 구현했습니다.
- 공격 평가와 함께, 이 설계로도 남는 두 가지 한계(위임 경로를 따라 권한이 줄어드는지에 대한 의미 수준 검사 부재, 공유 키 보유자에 대한 원본 권한 보존 불가)를 실험으로 드러냈습니다.

### Evaluation
- 발신자 사칭, 요청 본문과 보호 메타데이터 변조, 금액이나 수혜자 등 권한 내용 변조, 허가되지 않은 경유나 목적지 바꿔치기, 범위 확대, 재전송과 만료 등 15가지 공격 조건 가운데 14가지가 의도한 검증 단계에서 거부되었습니다.
- 통과한 한 가지는 위임 경로 검사만 따로 시험한 경우입니다. 경로 검사는 참여자 순서와 최종 목적지만 확인하므로, 범위에 승인 권한을 덧붙여도 구조상 유효하게 통과합니다. 저자들은 이것을 종단 우회가 아니라 의미 수준 권한 축소 검사가 없다는 증거로 해석합니다.
- 별도 실험에서, 정당한 서명 키와 공유 HMAC 키를 모두 가진 병원 에이전트가 최대 금액을 120유로에서 9,000유로로 바꾸고 증거를 다시 계산하자 모든 검증을 통과했습니다. 공유 키 방식으로는 권한을 받은 중간 참여자의 악의적 변경을 막을 수 없음을 보인 것입니다.
- 반복 실험에서 정상 실행 400회는 모두 통과했고 공격 실행 500회는 모두 거부되었습니다. 전체 구성의 보안 처리 지연 중앙값은 5.11ms, 직렬화 크기는 3.87kB였습니다.
- 지표 신빙성: 반복 실행은 정해진 공격 입력에 대한 결정적 동작을 확인한 것이지, 임의 공격에 대한 탐지 확률이 아니라고 저자들이 명시합니다. 지연은 Windows 노트북 한 대에서 네트워크, TLS, 저장소를 뺀 로컬 처리 시간만 잰 값입니다.

#### Comment
- 분량이 짧은 실험 보고 성격의 논문이지만, A2A 다단계 위임에서 "현재 요청 인증"과 "상속 권한 검증"을 섞으면 안 된다는 점과 공유 HMAC 키의 한계를 구체적인 예로 보여 줍니다. 에이전트 간 위임 설계를 검토할 때 점검 목록으로 쓰기 좋습니다.
- 한계: 고정된 네 당사자 경로만 다루며 동적 에이전트 탐색, 키 배포와 폐기, 분산 환경의 재사용 방지 상태 동기화는 범위 밖입니다. 의미 수준 권한 축소와 원본 권한을 보존하는 위임(예: 단계별 서명 체인)은 향후 과제로 남겼습니다.
- 신뢰도: NTNU 연구진(석사 과정 학생 포함)의 심사 전 원고입니다.

# A Bag of Tricks for Defending Deep Learning-based Face Recognition Pipelines against Backdoor Attacks
> arXiv cs.CV 2611.06412 (cs.CR 교차 게재, 기술 보고서, 프리프린트, 심사 전). Thales Cyber & Digital 사이버보안 AI 팀(프랑스)
> 2026

실제 얼굴 인식 시스템은 하나의 모델이 아니라 얼굴 검출, 정렬, 위조 얼굴 판별(안티스푸핑), 얼굴 특징 추출로 이어지는 여러 모델의 연쇄입니다. 이 기술 보고서는 업계에서 가장 현실적인 위협 모델, 즉 모델 학습은 자체적으로 하지만 학습 데이터는 오염되었을 수 있는 외부에서 구하는 상황을 가정하고, 데이터 오염 기반 백도어 공격에 대한 실용적인 방어 기법 세 가지를 제시합니다.

백도어 공격은 두 단계로 이뤄집니다. 내부자가 트리거(예: 볼에 붙인 패치)를 달고 등록하면 악성 임베딩이 저장되고, 이후 같은 트리거를 단 공격자는 누구든 그 내부자로 인증됩니다. 기존 백도어 방어는 대부분 고정 클래스 분류 문제를 기준으로 만들어져, 각도 마진 손실로 학습한 개방형 임베딩 공간에서 동작하는 얼굴 인식에는 잘 맞지 않습니다. 저자들은 학습 시점 방어 하나와 추론 시점 방어 둘을 제안합니다.

- arXiv HTML 본문: https://arxiv.org/html/2611.06412
- arXiv PDF: https://arxiv.org/pdf/2611.06412

### Contribution
- 조기 오염 식별(학습 시점): 트리거는 얼굴보다 단순해서 오염된 신원이 정상 신원보다 훨씬 빨리 학습된다는 관찰을 이용합니다. 학습 초반 배치에서 신원별 분류 정확도를 추적해 비정상적으로 빨리 오르는 신원을 찾아내고, 원하면 학습 중에 그 신원의 샘플을 바로 제거합니다. 깨끗한 참조 데이터나 트리거에 대한 사전 지식이 필요 없습니다.
- 검출기 수준 모델 짝짓기(추론 시점): 주 얼굴 검출기 옆에 MTCNN 같은 단순한 기성 검출기를 붙여, 검출 개수, 박스 겹침 정도(IoU 0.5 이상), 랜드마크 차이가 일치하지 않으면 입력을 거부합니다. 가짜 얼굴을 만들어 내는 공격(FGA)과 랜드마크를 비트는 공격(LSA)을 겨냥합니다.
- 잘라 붙이기(추론 시점): 입력 얼굴을 미리 정한 마스크로 조각내 소수의 검증된 깨끗한 얼굴 이미지에 붙인 뒤, 원본과 지나치게 비슷해지는 경우가 많으면 트리거가 있다고 판단합니다. STRIP의 아이디어를 개방형 임베딩 공간에 맞게 옮긴 것입니다.
- 조기 오염 식별과 잘라 붙이기는 각각 유럽 특허 출원(EP4738203, EP4811192)의 내용이라고 밝혔습니다.

### Evaluation
- 모델: 검출기는 RetinaFace(MobileNetV1, ResNet50 백본)를 WIDER-Face로 학습했고, 특징 추출기는 GhostFaceNetV2, IR-SE-50, MobileFaceNet, RobFaceNet, ResNet50 다섯 가지를 MS1Mv2로 학습했습니다. 트리거는 BadNets, SIG, FauxIt, 마스크 기반을 썼습니다.
- 조기 오염 식별: 오염 라벨 방식 공격 12건은 모두 학습 초반에 백도어 신원을 찾아냈지만, 클린 라벨 방식 공격 3건은 하나도 찾지 못했습니다. 방어를 켜면 학습 초반 1~3 에폭 동안 학습이 약 1.5배 느려집니다.
- 모델 짝짓기: 평균 오탐률 0.81%, 미탐률 4.31%였고, FGA 미탐률 7.06%, LSA 미탐률 0.65%(잘 학습되지 않은 모델 하나 제외)였습니다. 가장 나쁜 경우(미탐률 15.5%)는 공격 성공률 자체가 57.0%로 백도어가 덜 학습된 모델이었습니다. 추가 지연은 얼굴당 약 0.09초입니다.
- 잘라 붙이기: 두 모델(SIG 트리거 클린 라벨 공격, 공격 성공률이 낮은 경우)을 빼고는 오탐률 0.5~1.1%에서 미탐률 1.0% 이하였습니다. 백도어와 비슷하게 동작하는 적대적 패턴 FIBA에 대해서도 예비 실험에서 오탐률 1% 미만, 미탐률 0%였습니다. 추가 지연은 이미지당 0.02~0.04초입니다.
- 추론 시점 방어 평가에는 CelebA-Spoof에서 뽑은 2,048장(진짜와 위조 반반)을 썼습니다.
- 지표 신빙성: 여러 구조와 트리거를 고르게 시험했지만, 실패 사례를 "백도어가 덜 학습된 경우"로 설명하는 부분은 그만큼 약한 공격에 방어가 취약하다는 뜻이기도 합니다. 단순한 패치와 확산형 트리거만 다뤘고 적응형 공격은 시험하지 않았습니다.

#### Comment
- 얼굴 인식을 여러 단계의 연쇄로 보고 각 단계에 맞는 방어를 고른 실무형 보고서입니다. 생체 인증이나 출입 통제 시스템을 운영하는 쪽에서 바로 적용을 검토해 볼 만한 수준의 구체성이 있습니다.
- 한계: 클린 라벨 공격에는 학습 시점 방어가 통하지 않고, 안티스푸핑 단계 방어는 다루지 않았습니다. 내부자만 패턴을 착용하는 충돌형 공격(UniID)은 막지 못한다고 저자들이 밝혔습니다. 코드 공개 언급은 없고 일부 기법은 특허 출원 중입니다.
- 신뢰도: 프랑스 방산·보안 기업 Thales의 기술 보고서로, 학회 심사를 거친 것은 아닙니다.
