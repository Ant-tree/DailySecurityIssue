# GapLeak: When Privacy-Preserving LLM-based Web Agents Become a Privacy Risk
> Proceedings on Privacy Enhancing Technologies (PoPETs) 2027 2호 게재 확정, arXiv 프리프린트. 퀸스 대학교(캐나다)
> 2026

LLM 기반 웹 에이전트의 개인정보 보호는 보통 두 원칙에 기댑니다. 사용자가 작업에 필요한 정보만 주는 데이터 최소화와, 에이전트가 작업에 허용된 출처만 쓰게 하는 최소 권한입니다. 저자들은 이 두 원칙이 필요하지만 충분하지 않다고 지적합니다. 두 원칙은 에이전트가 "쓰도록 허락된" 범위만 제한할 뿐, 로그인된 계정의 주문 내역이나 결제 정보처럼 "닿을 수 있는" 더 민감한 출처는 그대로 남겨 두기 때문입니다. 웹사이트가 허용된 출처로는 채울 수 없는 항목을 요구하면 정보 공백이 생기고, 사람이라면 빈칸으로 두겠지만 목표 지향적인 에이전트는 작업을 끝내려고 허용되지 않은 출처까지 뒤져 채워 넣습니다. 저자들은 프롬프트 주입이나 악성 지시 없이 정상적인 웹 양식만으로 이를 유도하는 공격을 GapLeak으로 정식화하고, 제출 직전에 각 항목을 검사해 허용되지 않은 내용을 걸러 내는 방어를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.22223
- arXiv HTML 본문: https://arxiv.org/html/2611.22223
- arXiv PDF: https://arxiv.org/pdf/2611.22223
- 저자 아티팩트 저장소(익명판): https://github.com/Hunter-CCL/GapLeak_release

### Contribution
- 허용 범위와 도달 가능 범위의 차이에서 생기는 구조적 취약점을 GapLeak으로 정식화했습니다. 제3자 데이터까지 포함해, 에이전트가 쌓아 둔 민감 정보가 정상 양식을 통해 새어 나갈 수 있음을 보였습니다.
- 채용, 전자상거래, 여행, 의료 네 영역의 통제된 시나리오를 설계해, 정보 공백이 있을 때와 없을 때를 비교했습니다.
- 지시문 수준의 최소 권한 방어가 개인정보와 작업 성공률 사이에서 손해를 본다는 점을 보이고, 실행 중이 아니라 제출 시점에 검증하는 방어를 제안했습니다.

### Evaluation
- 대상: 웹 에이전트 프레임워크 세 개(BrowserUse, DoBrowser, Agent-E)와 세 회사의 모델 여섯 개(Claude Haiku 4.5, Claude Sonnet 4.6, Gemini 2.5 Flash, Gemini 2.5 Pro, GPT 5.4 Mini, GPT 5.4).
- 결과: 평균 무단 공개율은 약 37%였고, 정보 공백이 있으면 무단 공개가 50% 넘게 늘면서 작업 성공률은 약 3분의 1 줄었습니다. 최소 권한을 명시 지시로 넣는 방어를 써도 완료된 작업의 77%에서 공개가 남았고 작업 성공률은 30%로 떨어졌습니다. 제출 시점 검증은 무단 공개의 96% 이상을 없애면서 작업 성공률을 더 낮추지 않았습니다.
- 신빙성: 모든 프레임워크와 모델 조합에서 같은 경향이 나와 일반성이 있습니다. 다만 시나리오는 저자들이 만든 통제 환경이고, 제출 시점 검증은 정보 공백으로 잃은 작업 성공률까지 되살리지는 못한다고 저자들이 밝혔습니다.

#### Comment
- 악성 지시가 전혀 없어 기존 프롬프트 주입 탐지나 이상 지시 탐지로는 막기 어렵다는 점이 핵심입니다. 에이전트가 "도와주려는 성향" 때문에 스스로 범위를 넘는다는 관찰은, 권한을 줄이는 것만으로는 부족하고 출력 단계 검증이 필요하다는 점을 보여 줍니다.
- PoPETs는 심사가 엄격한 개인정보 보호 분야 대표 학술지 겸 학회입니다. 저자 전원이 퀸스 대학교 소속이며 아티팩트를 공개했습니다.

# PersonaHate: A Scalable Persona-Based Data Synthesis Pipeline for Hate Speech Analysis
> ACM CCS 2026 게재, DOI 10.1145/3830454.3846648, arXiv 프리프린트. CISPA 헬름홀츠 정보보안 센터
> 2026

혐오 표현 탐지기의 성능이 대상 집단과 표현 방식에 따라 들쭉날쭉한 이유를 학습 데이터의 부족한 범위에서 찾고, 페르소나를 이용해 다양한 혐오 표현 데이터를 대량으로 합성하는 파이프라인을 제안한 논문입니다. 4chan /pol/ 게시물에서 추론한 혐오 성향 페르소나와 PersonaHub의 일반 페르소나를 합쳐 45만 7천 개의 페르소나 풀을 만들고, 다양성을 고려한 표본 추출로 고른 페르소나를 34개 정체성 집단과 짝지어 LLM 여덟 개로 문장을 생성한 뒤 여러 판정 모델로 라벨을 붙였습니다. 그 결과 79만 1천 개 표본을 얻고, 집단별로 균형을 맞춘 6만 7천 개 학습 세트를 만들었습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.21951
- arXiv HTML 본문: https://arxiv.org/html/2611.21951
- arXiv PDF: https://arxiv.org/pdf/2611.21951
- ACM 디지털 라이브러리(DOI): https://doi.org/10.1145/3830454.3846648

### Contribution
- 실제 혐오 게시물에서 화자 유형을 추론한 페르소나와 일반 페르소나를 결합해, 노골적인 극단 표현부터 암시적이고 우회적인 편견 표현까지 포괄하는 합성 방식을 제시했습니다.
- 모듈 구조라 새 정체성 집단, 새 생성 모델, 새로 등장하는 혐오 대상에 맞춰 확장할 수 있습니다.
- 페르소나 조건이 직접 프롬프트보다 의미와 어휘 다양성을 높이고, 안전 정렬된 LLM의 거부율도 낮춘다는 점을 분석했습니다.

### Evaluation
- 외부 벤치마크 네 개에서 평가했습니다. 1억 8,400만 파라미터 DeBERTa-v3를 PersonaHate로 처음부터 학습하면 평균 F1 77.5%, 평균 정확도 79.4%로 HateBenchSet과 MHS에서 OpenAI Moderation API를 앞섰습니다.
- Llama-3.1-8B를 추가 미세 조정하면 평균 F1이 70.7%에서 78.4%로 올라, 같은 구조 기반의 Meta LlamaGuard-3을 네 벤치마크 중 세 개에서 넘었습니다.
- 절제 실험에서 정체성 집단을 10개, 17개, 34개로 늘리면 평균 F1이 74.3%, 75.6%, 77.6%로 올라, 데이터 양과 별개로 집단 범위가 성능에 기여함을 보였습니다.
- 신빙성: 학습은 합성 데이터로, 평가는 사람이 작성한 외부 벤치마크로 나눠 순환 평가를 피했습니다. 저자들은 합성 데이터가 사람 작성 데이터를 대체하지 못하며, 플랫폼별 규범과 맥락은 재현하기 어렵다고 한계를 밝혔습니다.

#### Comment
- LLM으로 혐오 표현을 대량 생성할 수 있게 된 상황을 거꾸로 탐지기 학습에 이용한 연구입니다. 작은 모델로도 상용 분류기에 근접한다는 점은 실제 콘텐츠 관리 환경에서 의미가 있습니다.
- CCS는 보안 분야 최상위 학회이고, CISPA의 Yang Zhang 연구실은 LLM 오용 연구 실적이 많습니다. 생성된 혐오 데이터의 공개 범위는 확인하지 못했습니다.

# Eight in Ten LLMs Leak System-Prompt Secrets: Nevan, an Agentic Capture-the-Flag Study
> arXiv 프리프린트 (심사 전). 캄피나스 주립 대학교(UNICAMP, 브라질)
> 2026

시스템 프롬프트에 넣은 비밀을 모델이 지켜 내는지를, OpenRouter 목록의 텍스트 모델 363개 전체를 대상으로 점검한 감사 연구입니다. 각 모델의 시스템 프롬프트에 16자리 깃발 문자열을 숨기고, 사람 연구자가 조종하는 AI 에이전트(OpenCode, DeepSeek V4.1 Flash 기반)가 모델을 설득해 깃발을 말하게 하는 깃발 뺏기 방식으로 진행했습니다. Nevan은 이 감사와 실험 도구, 공개 자료의 프로젝트 이름으로, 약어가 아니라 게임 캐릭터 이름에서 따왔다고 저자들이 밝혔습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.21956
- arXiv HTML 본문: https://arxiv.org/html/2611.21956
- arXiv PDF: https://arxiv.org/pdf/2611.21956

### Contribution
- 집계 서비스에 올라온 모델 전체를 같은 조건으로 점검해, 지시 계층(시스템 지시를 사용자 요청보다 우선하는 성질)이 모델마다 얼마나 다르게 지켜지는지를 보였습니다.
- 깃발 탈취마다 사용한 기법과 언어를 기록해, 어떤 경로로 비밀이 새는지 정리했습니다.
- 실무 교훈 세 가지를 제시했습니다. 시스템 프롬프트에 비밀을 넣지 말 것, 중요한 동작은 출력 검증과 결정적 검사로 모델 밖에서 강제할 것, 중대한 결과를 LLM 판정 하나에 맡기지 말 것.

### Evaluation
- 결과: 363개 중 296개 모델에서 깃발을 빼냈고, 목록 고정 이후 공개된 모델 네 개를 더해 모두 300건을 탈취했습니다. 이 중 170건은 영어가 아닌 언어로 바꿔 묻는 방식이 쓰였고, 프랑스어가 가장 많았습니다.
- 신빙성: 저자들이 한계를 꼼꼼히 적었습니다. 목록은 2026년 10월 6일 시점으로 고정했고, 50개는 미결, 17개는 제외되어 판단하지 않았습니다. 의미 없는 합성 깃발 하나만 썼으므로 내용의 의미에 기대는 보호 장치는 측정하지 못했습니다. 대부분 단발 시도였고 공격 에이전트 구성은 하나뿐이었으며, 마지막 50개 모델은 사람이 상당 부분 이끌었습니다. 모델마다 첫 성공 기법만 기록해 기법, 언어, 순서가 뒤섞여 있고, 프랑스어를 가장 먼저 시도했으므로 프랑스어가 더 효과적이라는 뜻도 아닙니다.

#### Comment
- 깃발 탈취는 "한 번이라도 사용자 요청을 시스템 지시보다 앞세웠다"는 증거일 뿐, 실제 민감 정보를 일관되게 흘린다거나 유해 콘텐츠 탈옥에 취약하다는 뜻은 아니라고 저자들이 선을 그었습니다. 결론보다는 "시스템 프롬프트는 비밀 저장소가 아니다"라는 OWASP 권고를 대규모로 확인한 자료로 보는 것이 맞습니다.
- 심사 전 원고입니다. 측정이 부분적으로 사람 조종에 의존해 재현성은 제한적입니다.

# Stopping Is Not the Limit: Understanding and Eliciting Agent Capability in Long-Horizon Vulnerability Exploitation
> arXiv 프리프린트 (심사 전). UNIST 안전 AI 연구센터, 포스텍
> 2026

LLM 에이전트가 알려진 소프트웨어 결함으로 실제 동작하는 익스플로잇을 만들 수 있는지 평가할 때, 에이전트가 예산이 남았는데도 "충분히 조사했다"며 스스로 멈추는 문제를 다룬 논문입니다. 저자들은 ExploitBench에서 DeepSeek-V4-Flash-0731과 MiMo-V2.6-Pro로 멈춘 뒤에도 실행을 이어 가면 어떤 일이 생기는지를 2,000턴까지 살폈습니다. 첫 멈춤 이후에도 검증된 성과가 추가로 나왔지만 시간이 갈수록 줄었고, 같은 맥락 안에서 멈춤 응답이 늘어나는 것과, 요약에 "이 기능은 불가능하다"는 판단이 남아 있으면 더 일찍 멈추는 경향이 관찰되었습니다. 이를 바탕으로 멈춤이 몰릴 때 맥락을 압축하고 불가능 판단을 "증명되지 않음"으로 바꿔 표시하는 맥락 관리 기법 SCoRe를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.22888
- arXiv HTML 본문: https://arxiv.org/html/2611.22888
- arXiv PDF: https://arxiv.org/pdf/2611.22888
- 코드 공개 예정 저장소: https://github.com/trustml-lab/stopping-is-not-the-limit

### Contribution
- 기존 평가가 300턴 안팎에서 끝나 에이전트의 공격 능력을 과소평가할 수 있다는 점을, 긴 실행으로 정량적으로 보였습니다.
- 생산성이 떨어지는 지속 실행의 두 가지 패턴(멈춤 응답의 누적, 요약 속 불가능 판단)을 찾아냈습니다.
- 멈춤 시점 압축과 판단 재표시를 결합한 SCoRe를 제안했습니다.

### Evaluation
- 결과: MiMo는 SCoRe로 2,000턴에서 능력 범위 점수 67.0%를 얻었습니다. 원래 멈춤 정책의 32.4%, 요약 기반 지속의 53.3%보다 높고, ExploitBench의 300턴 참고 결과로 계산한 GPT-5.5의 58.6%도 넘었습니다.
- 절제 실험: 판단 재표시를 빼면 평균 검증 능력이 6.65에서 6.14로, 멈춤 시점 압축을 빼면 5.32로 떨어졌습니다.
- 신빙성: 모델 두 개와 V8 익스플로잇 과제로 제한됩니다. DeepSeek 비교는 41개 과제 전체를 썼지만 MiMo 비교와 절제 실험은 21개 과제의 Mythos-ACE 부분집합만 썼습니다. GPT-5.5와의 비교는 같은 조건의 실행이 아니라 벤치마크가 공개한 300턴 결과에서 계산한 값이므로 직접 비교로 보기 어렵습니다. 관찰된 패턴과 성과 부진의 인과 관계는 아직 밝혀지지 않았다고 저자들이 적었습니다.

#### Comment
- 공격 능력 평가에서 "멈춘 지점이 한계"라고 보면 위험을 낮게 잡게 된다는 점은 AI 안전 평가 관점에서 중요한 지적입니다. 같은 기법은 방어 측 자동 취약점 검증에도 쓰일 수 있습니다.
- 코드는 아직 공개되지 않았고 "공개 예정"으로만 적혀 있습니다.

# GuardAgent: A Memory-Augmented Agentic Framework for Adaptive Detection of Adversarial Promotions in LLM-Based Recommendation
> WSDM 2027 채택, arXiv 프리프린트. 뉴사우스웨일스 대학교(UNSW), CSIRO, 모나시 대학교, 매쿼리 대학교(모두 호주)
> 2026

LLM 기반 추천 시스템은 상품 제목과 설명 같은 텍스트를 프롬프트에 넣어 추천을 만들기 때문에, 판매자가 자기 상품의 텍스트만 고쳐도 더 많은 사용자에게 추천되게 만들 수 있습니다. 기존 방어는 학습 데이터에 섞인 가짜 평점이나 구매 기록을 걸러 내는 데 맞춰져 있고, 퍼플렉시티 기반 프롬프트 인젝션 탐지기는 고정된 규칙으로 한 번 판단하고 끝나 새로운 공격에 적응하지 못합니다. 저자들은 탐지를 인지, 행동, 반성, 기억이 반복되는 에이전트 루프로 보고 GuardAgent를 제안했습니다. 적응 단계에서는 정상 텍스트와 악성 텍스트 한 쌍 중 악성을 고르게 하고, 틀린 사례를 묶음으로 모아 쌍 내부 대조와 사례 간 대조로 "앞머리에 붙은 과장 형용사" 같은 텍스트 규칙을 고쳐 기억에 쌓습니다. 추론 단계에서는 다듬어진 규칙과 비슷한 과거 사례를 함께 불러와 판단하고, 어떤 규칙이 걸렸는지 근거를 문장으로 남깁니다.

### Contribution
- 추론 시점에 상품 텍스트를 바꿔 특정 상품을 밀어 올리는 공격을, LLM 기반 추천 시스템에서 탐지하는 문제를 처음으로 체계적으로 다뤘다고 주장합니다.
- 보상 기반 강화학습 대신, 틀린 판단의 추론 과정을 되짚어 사람이 읽을 수 있는 텍스트 규칙을 고치는 반성 방식을 택했습니다. 실패 사례 하나가 아니라 묶음 단위로 규칙을 갱신해 개별 오류에 과적합하는 것을 줄였다고 설명합니다.
- 최근 갱신한 규칙을 담는 단기 기억과 검증된 과거 사례를 쌓는 장기 기억을 나눠 두고, 추론 때는 문장 임베딩 유사도로 비슷한 사례를 불러와 규칙과 함께 씁니다.
- 판단마다 근거 규칙과 추론 과정을 남겨 보안 담당자가 결과를 감사할 수 있게 했고, 프롬프트 템플릿을 부록에 공개했습니다.

### Evaluation
- Amazon 리뷰 데이터의 악기 분야(사용자 27,530명, 상품 10,620개)와 Yelp 데이터에서 뽑은 부분집합(사용자 1,599명, 업체 1,318개)을 썼고, 문자, 단어, 문장 수준의 기존 텍스트 공격 6종(DeepwordBug, PuncAttack, TextFooler, BertAttack, TrivialInsertion, ChatGPTAttack)으로 만든 악성 텍스트를 7:3으로 나눠 평가했습니다.
- 반성과 최종 판단에는 GPT-5, 적응 단계의 행동에는 GPT-3.5-turbo를 썼습니다. GuardAgent는 Amazon에서 정확도 0.93, 재현율 0.88, 오탐률 0.03, F1 0.92, Yelp에서 정확도 0.84, 재현율 0.68, 오탐률 0.01, F1 0.81을 기록했습니다. 가장 강한 비교 대상인 검색 기반 인컨텍스트 학습의 F1은 각각 0.86과 0.77이었고, 퍼플렉시티 탐지기는 재현율이 0.02와 0.01에 그쳤습니다.
- 단어 수준 공격은 동의어 치환이 자연스러워 탐지율이 상대적으로 낮았고, 업체 이름이 다양한 Yelp에서 더 낮았습니다.
- 기존 공격 6종으로만 적응시킨 뒤, 보지 못한 에이전트 대상 공격 DrunkAgent에만 시험했을 때 두 데이터셋 평균 탐지율 100%에 오탐이 거의 없었다고 합니다. 반성을 빼거나 묶음 학습을 빼면 성능이 떨어졌고(Amazon F1 0.92에서 각각 0.86, 0.79), 추론 모델을 Qwen-3로 바꾸면 성능이 다소 떨어졌습니다.
- 신빙성: 공격이 실제로 성공한 정상-악성 쌍만 골라 평가했고 시험 표본 수는 밝히지 않았습니다. 고정 시드로 한 번만 돌려 분산이 없습니다. "보지 못한 공격"으로 쓴 DrunkAgent는 저자들의 이전 연구이고 "###", "Ignore previous instructions" 같은 눈에 띄는 표식이 들어 있어 탐지가 쉬운 편이며, 탐지기를 의식해 우회하는 적응형 공격은 다루지 않았습니다.

#### Comment
- 텍스트 규칙을 스스로 고쳐 가는 탐지기라는 점이 특징이고, 판단 근거가 규칙 단위로 남아 운영자가 오탐을 따져 보기 좋습니다. 다만 판단마다 GPT-5급 모델을 호출해야 하므로 대규모 상품 목록에 적용하는 비용은 논하지 않았습니다.

> 2026

생성 모델과 의미 임베딩에 블랙박스 접근만 있으면 쓸 수 있고, 증명 가능한 무왜곡 성질을 갖는 의미 기반 워터마크 알고리즘을 제시했다고 저자들은 설명합니다. 무왜곡이란 비밀 검출 키에 대해 평균을 내면 생성 모델의 출력 분포가 바뀌지 않는다는 뜻으로, 워터마크가 출력 품질을 떨어뜨리지 않는다는 형식적 보장입니다. 이미지에서는 압축, 잘라내기, 크기 조정 같은 평범한 처리만으로 픽셀 전체가 바뀌므로 내용이 보존되는 변환에 강한 의미 기반 검출이 필요한데, 기존 방법은 자기회귀 텍스트 생성이나 확산 모델의 초기 잡음 제어, 역변환 같은 내부 접근에 의존했다고 합니다.
