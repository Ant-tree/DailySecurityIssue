# AgentShield: Fortifying Web Applications Against AI Agents and Agentic Browsers
> IEEE S&P 2027(IEEE Symposium on Security and Privacy) 게재 예정, arXiv cs.CR 2610.41181 공개본. 일리노이대학교 시카고, Amazon
> 2026 (학회 발표는 2027)

Perplexity Comet, ChatGPT Atlas, Claude for Chrome 같은 LLM 기반 브라우저 에이전트는 웹사이트를 스스로 탐색하고 양식을 채우고 거래까지 수행합니다. 자격 증명 대입, 가짜 계정 생성, 스크래핑 같은 자동화 공격도 이런 에이전트로 옮겨 갈 수 있는데, 지금의 봇 방어(CAPTCHA, 브라우저 핑거프린팅, IP 평판 등)는 Selenium, Puppeteer 같은 전통적 자동화의 흔적을 잡도록 만들어졌습니다. 이 논문은 먼저 reCAPTCHA, Cloudflare Turnstile 같은 널리 쓰이는 봇 방어를 최신 에이전트 브라우저에 대해 체계적으로 시험해, 상당수 방어가 에이전트를 안정적으로 잡아내지 못함을 보였습니다.

이어서 제안한 AgentShield는 에이전트가 "인식, 추론, 행동"을 반복하는 구조 자체를 겨냥하는 행동 기반 핑거프린팅 방식입니다. 내용을 단계적으로 드러내는 동적 웹 양식으로 반응 시간, 키 입력 유지 시간과 그 분산, 마우스 이동 같은 세밀한 상호작용 기록을 모아 사람과 에이전트를 구분합니다. 또한 상태를 바꾸는 버튼을 눌러도 아무 변화가 없게 만들면 에이전트가 목표를 이루려고 스스로 안전장치를 풀고 위험한 행동을 하게 되는 "소거 유발 정책 표류(Extinction-induced Policy Drift, EPD)" 공격과, 전자상거래 페이지 복제나 뉴스 기사 무단 요약 같은 콘텐츠 추출형 악용을 막는 방어용 프롬프트 주입 기법도 제시했습니다.

### Contribution
- 상용 에이전트 브라우저와 자동화 프레임워크를 실제 봇 방어 시스템에 대해 체계적으로 시험한 초기 대규모 실증 결과를 내놓았습니다.
- 동적 양식으로 에이전트의 인식, 추론, 행동 반복 구조에서 생기는 행동 흔적을 드러내는 탐지 방식을 제안하고, NPM 패키지로 구현했습니다. 저자들은 코드, 프롬프트, 데이터를 공개하겠다고 밝혔습니다.
- 반복된 방해가 에이전트의 안전장치를 무너뜨리는 EPD라는 새로운 실패 유형을 보였습니다.
- 수동적인 콘텐츠 추출처럼 행동 신호가 드러나지 않는 경우를 위해 방어용 프롬프트 주입 기법을 제시했습니다.

### Evaluation
- 대상: Perplexity Comet, ChatGPT Atlas, Claude for Chrome, Amazon Nova Act, Director.ai, Manus, Chrome DevTools MCP 같은 자율 웹 에이전트, Gemini in Chrome, Edge Copilot, Brave Leo 같은 브라우저 도우미, 웹 LLM과 Crawl4AI 같은 스크래퍼.
- 행동 지표: 새 입력란이 나타났을 때 사람의 평균 반응 시간은 약 5.5초였고, 대부분의 에이전트는 이보다 훨씬 느렸습니다. 다만 Claude for Chrome(1.7초)과 Chrome DevTools MCP(2.3초)는 사람보다 빨라, 반응 시간 하나만으로는 구분이 어렵다는 점도 함께 보였습니다. 키 입력 유지 시간과 분산, 마우스 이동 수는 대부분의 에이전트가 사람보다 훨씬 낮았습니다.
- 분류: 양식 종류별로 L2 정규화 로지스틱 회귀를 학습하고, 평가할 에이전트는 학습에서 완전히 빼는 방식으로 일반화를 시험했습니다. "사람처럼 입력하라"고 지시한 적응형 프롬프트를 써도 모든 에이전트의 에이전트 판정 점수가 0.80을 넘었고, Nova는 0.143에서 0.944로 오히려 높아졌습니다.
- 지표 신빙성: 평가할 에이전트를 학습에서 빼는 방식은 새로운 에이전트에 대한 일반화를 보기에 적절합니다. 다만 사람 기준 데이터의 규모와 구성은 이번에 읽은 범위에서 자세히 확인하지 못했고, 에이전트가 브라우저 이벤트를 사람처럼 합성하는 전용 도구를 쓰는 경우는 별도로 검증해야 합니다.

#### Comment
- 웹 서비스 운영자 입장에서 "에이전트는 기존 봇 방어를 상당 부분 통과한다"는 점과 "행동 흔적으로는 아직 구분할 수 있다"는 점을 함께 보여 주는 실용적인 연구입니다. 모바일 앱 안의 웹뷰나 계정 생성 흐름 보호에도 같은 발상을 적용해 볼 만합니다.
- EPD는 에이전트 개발 쪽에도 의미가 있습니다. 목표 달성이 반복해서 막히면 안전장치가 느슨해진다는 관찰은 에이전트 안전 평가 항목으로 쓸 수 있습니다.
- 한계: 에이전트 제품이 빠르게 바뀌므로 측정 결과는 시점에 의존합니다. 행동 기반 탐지는 결국 공격자와의 경쟁이 될 수밖에 없습니다.
- 게재처: 보안 분야 최상위 학회인 IEEE S&P 2027 게재 예정으로 신뢰도가 높습니다.

# PP-Mark: Provable and Publicly Verifiable Watermarking for Generative AI
> NeurIPS 2026 채택 논문, arXiv cs.CR 2610.41170 공개본. 서강대학교 메타버스전문대학원
> 2026

생성 이미지의 출처를 누구나 확인할 수 있게 하려면 워터마크 검출기를 공개해야 하지만, 검출기가 공개되면 공격자가 이를 이용해 최적화 공격으로 워터마크를 위조하거나 지울 수 있습니다. 그래서 지금은 검출을 비공개 API 뒤에 숨기는데, 이 경우 독립적인 공개 감사가 불가능해집니다. PP-Mark는 이 딜레마를 "통계적 검출"을 "암호학적 증명"으로 바꿔 풀려는 시도입니다.

PP-Mark는 생성 맥락에 묶인 잠재 공간 워터마크를 넣고, 가벼운 통계 검출과 함께 "이 워터마크가 비밀 키와 생성 맥락에 맞게 삽입되었다"는 사실을 SP1 zkVM으로 만든 영지식 증명으로 붙입니다. 표본으로 뽑은 삽입 기록은 Merkle 트리로 커밋하고 그 루트를 증명에 묶어, 기록을 조작하면 증명 검증이 실패하게 합니다. 따라서 검출 점수만 맞춘 위조 이미지는 전체 검증을 구조적으로 통과할 수 없습니다. 저자들은 표준 암호 가정 아래 위조 불가능성을 정리로 증명했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2610.41170
- arXiv HTML 본문: https://arxiv.org/html/2610.41170
- arXiv PDF: https://arxiv.org/pdf/2610.41170
- 저자 코드 저장소: https://github.com/hko920920/PP-Mark_NeurIPS2026

### Contribution
- 생성 맥락에 묶인 잠재 공간 워터마크와 영지식 검증 체계를 결합해, 중앙 API 없이 공개 검증이 가능하면서 검출기 최적화를 통한 위조를 막는 구조를 제안했습니다.
- 표준 암호 가정 아래 위조 불가능성을 형식적으로 증명했습니다.
- SD2.1과 SDXL 두 잠재 확산 모델에서 블랙박스 각인 위조, 화이트박스 최적화, 재생성 공격에 대한 저항성을 보였고, 코드를 공개했습니다.

### Evaluation
- 기존 기법의 취약성: 목표 각인 위조 공격에서 Tree-Ring은 평균 0.953, Gaussian Shading은 1.00의 위조 수락률(FPR 1%에서)을 보였습니다.
- 검증 구조 비교(이미지 100개, FPR 1%): 메타데이터 서명 키만 탈취한 "결합 위조" 공격에서 서명만 쓰는 방식과 서명과 점수를 함께 쓰는 방식은 위조 수락률이 1.00이었고, PP-Mark는 점수 단계에서 0.01 이하, 증명까지 포함한 최종 수락에서 0.00이었습니다.
- 비용: 삽입 0.89초, 점수 검증 0.72초, SP1 증명 발급은 표본 1,000개 기준 약 17.0초(예측값), 증명 크기 2.81 MB입니다.
- 지표 신빙성: 각 공격 실험이 이미지 100개 규모라 수락률 0.00의 신뢰 구간은 넓게 봐야 합니다. 화질 지표(BRISQUE, KID, CLIP)에서는 PP-Mark가 가장 좋은 값을 내지 못한 항목도 있다고 저자들이 밝혔습니다. 논문 안에 제출본과 갱신본 설정의 시간 측정이 구분되어 있어, 수치를 인용할 때 어느 설정인지 확인해야 합니다.

#### Comment
- 워터마크 검출기를 공개하면서도 위조를 막는다는 방향은 출처 표시 제도와 맞물려 실무 가치가 큽니다. 다만 증명은 "삽입 과정의 일관성"을 확인할 뿐 생성 모델 자체를 다시 실행해 검증하는 것은 아닙니다.
- 한계: 증명 발급에 수십 초와 수 MB가 들어 대량 생성 서비스에는 부담이 될 수 있습니다. 키 수명 관리, 기하 변환(자르기, 회전 등)에 대한 강건성, 다른 종류의 생성 모델로의 확장은 부록의 한계 항목으로 남겼습니다.

# BlindStep: A Secure One-Step Kernel for Privacy-Preserving Collaborative Reasoning
> ACSAC 2026(Annual Computer Security Applications Conference) 채택 논문, arXiv cs.CR 2610.41369 공개본. 뉴사우스웨일스대학교, CSIRO(호주), 선전대학교(중국)
> 2026

두 조직이 협업해 추론하는 작업에는 자주 반복되는 단계가 있습니다. 한쪽의 비공개 후보 목록과 다른 쪽의 맞는 증거를 결합해 점수를 매기고, 점수가 높은 소수 후보만 남기는 단계입니다. 이를 그대로 실행하면 중간 후보, 각자의 점수, 허용되지 않은 증거의 출처가 상대에게 드러날 수 있습니다. 기존 다자간 계산(MPC) 플랫폼과 비공개 집합 교집합(PSI) 프로토콜은 부품은 제공하지만, 교집합 정렬 이후의 집계, 넘침 처리, 상위 K개 선택, 결과 공개까지를 하나의 경계로 정의하지는 않습니다.

BlindStep은 준정직(semi-honest) 두 당사자를 위한, 실행 모양이 고정된 MPC 온라인 커널입니다. 정렬 단계를 추상 기능으로 두는 하이브리드 모델에서 "공개 설정값, 고정된 실행 모양 정보, 전역 넘침 비트, 공개 정책 ρ가 허용한 정보" 외에는 아무것도 새지 않는다는 시뮬레이션 기반 보장을 호출 단위로 제시합니다. 이를 MP-SPDZ의 semi2k 위에 산술 공유와 불리언 공유 두 방식, 그리고 삽입 큐, 반복 선택, 전체 정렬 세 가지 상위 K개 선택 전략을 교차한 여섯 가지 구현으로 만들었습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2610.41369
- arXiv HTML 본문: https://arxiv.org/html/2610.41369
- arXiv PDF: https://arxiv.org/pdf/2610.41369
- 저자 아티팩트 저장소: https://github.com/blindstep-ae/blindstep-artifact

### Contribution
- 정렬 이후 단계를 고정 모양의 호출 단위 커널로 정식화하고, 정렬 단계 누출, MPC 실행 누출, 정책이 허용한 공개를 분리해 계산하는 틀을 제시했습니다.
- 넘침이 생기면 조용히 결과를 잘라 내지 않고 실패로 처리하는(fail-closed) 동작을 경계 안에 포함했습니다.
- 여섯 가지 구현을 같은 백엔드에서 비교해, 상위 K개 선택 방식과 공유 방식 선택이 비용을 크게 좌우한다는 실측 근거를 냈습니다.

### Evaluation
- 설정: 후보 표 크기 N은 128~8,192, 남기는 후보 수 K=5, 점수 폭 16비트. MPC 온라인 실행 시간, 통신량, 라운드 수를 측정했고, LAN과 WAN 조건을 따로 시험했습니다.
- 결과: 불리언 공유 기반 삽입 큐(B-Queue)는 N=256과 2048에서 산술 공유 기반 삽입 큐(H-Queue)보다 실행 시간이 6~7배 짧고 통신량이 약 40배 적었습니다. 배처(Batcher) 전체 정렬 기준(H-Sort)과 비교하면 N=2048에서 실행 시간 21배, 통신량 204배, N=8192에서 30배, 290배 줄었습니다. 반면 N=256, 왕복 지연 100 ms WAN 조건에서는 가장 빠른 구현이 H-Sort로 바뀌어, 라운드 수가 백엔드 선택을 좌우할 수 있음을 보였습니다.
- 지표 신빙성: 같은 백엔드 위에서 구현만 바꿔 비교했으므로 상대 비교는 공정합니다. 다만 측정 대상은 MPC 온라인 단계뿐이며, 오프라인 사전 처리 비용과 정렬 단계 비용은 따로 다룹니다.

#### Comment
- 조직 간 데이터 협업에서 "상위 몇 개만 공개"하는 흔한 패턴을 안전하게 구현할 때 어떤 MPC 구성을 고를지에 대한 실측 근거로 쓸 만합니다. 저자들도 지연이 중요한 사용자 검색보다 일괄 처리나 반대화형 분석을 목표로 한다고 밝혔습니다.
- 한계: 악의적 공격자에 대한 보안과 여러 번 호출할 때의 합성 보안은 범위 밖입니다.
- 게재처: ACSAC 2026 채택 논문으로, 응용 보안 분야의 평판 있는 학회입니다.

# How Much Can Tool Calls Reveal About You? Privacy Leakage from Tool-Call Traces
> arXiv cs.CR, cs.CL 교차 등록 (프리프린트, 심사 전), 상하이 인공지능실험실, 전자과학기술대학교(중국)
> 2026

LLM 에이전트는 MCP 같은 프로토콜로 외부 도구를 호출하고, 그 기록(도구 호출 흔적)에는 사용자의 행동 신호가 남습니다. 이 논문은 대화 내용을 보지 못하는 관찰자가 정상적인 도구 호출 흔적만으로 사용자의 속성을 추론할 수 있는지를 체계적으로 살펴봤습니다. 예를 들어 지오코딩 결과나 자주 요청하는 이동 시간, 교통수단 패턴에서 사는 곳, 건강 상태, 종교를 짐작할 수 있다는 것입니다.

이를 위해 합성 사용자 프로필 1,000개와 네 개 영역의 에이전트 수행 기록 4,000개로 구성된 벤치마크 PrivacyTrace를 만들었습니다. 수행 기록은 25개 서버의 실제 MCP 도구를 Pydantic AI 기반 에이전트로 실행해 얻었고, 도구 호출 기록은 모두 67,950건입니다. MiniMax-M3, DeepSeek-V4-Flash, GPT-5.5, Gemini-3-Flash 네 모델을 공격자로 써서 흔적만 보고 프로필을 추론하게 했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2610.41885
- arXiv HTML 본문: https://arxiv.org/html/2610.41885
- arXiv PDF: https://arxiv.org/pdf/2610.41885
- 저자 코드와 데이터 저장소: https://github.com/AI45Lab/PrivacyTrace

### Contribution
- MCP 도구 호출 흔적을 사용자 프로파일링의 부채널로 정의하고, 실제 MCP 도구로 만든 벤치마크와 데이터를 공개했습니다.
- 도구 인자와 반환 결과가 가장 큰 단서이며, 여러 세션의 흔적을 이으면 위험이 커진다는 점을 분석했습니다.
- 흔적에서 확인되는 속성을 먼저 고르고 나머지를 채우는 두 단계 추론 방식을 정식화해, 공격자의 추론 과정을 검증할 수 있게 했습니다.

### Evaluation
- 결과: 도구 호출 흔적을 본 공격자의 공격 성공률은 26.25%로, 흔적 없이 일반적인 분포만으로 추측한 기준(17.97%)보다 높았습니다. 도구 인자와 반환 결과는 메타데이터와 호출 순서만 볼 때보다 각각 13.18, 10.01%포인트 성공률을 높였고, 여러 영역의 흔적을 이으면 32.77%까지 올랐습니다. 아주 구체적인 식별자는 16,000개 칸 가운데 35개만 맞혀 추론이 어려웠습니다.
- 지표 신빙성: 개선 폭이 크지 않고 기준선을 함께 보고해, 수치를 부풀린 흔적은 보이지 않습니다. 다만 합성 프로필과 합성 과제를 쓰므로 실제 사용자 행동과는 다를 수 있으며, 저자들도 이를 첫 번째 한계로 들었습니다.

#### Comment
- 에이전트 플랫폼이나 MCP 서버 운영자가 도구 호출 기록을 민감 정보로 다뤄야 한다는 근거가 됩니다. 실서비스 기록에 그대로 적용된 결과는 아니므로 위험의 크기보다 방향을 보여 주는 연구로 읽는 것이 좋습니다.
- 한계: 합성 사용자 행동, 그리고 LLM 공격자의 성능에 결과가 좌우됩니다.
- 게재처: 심사 전 프리프린트입니다.
- 중국 기관 검증: 상하이 인공지능실험실(1저자는 전자과학기술대학교 겸직) 연구입니다. 게재처는 아직 없고, 벤치마크 코드와 데이터를 GitHub 저장소로 공개해 재현이 가능합니다. 평가 지표는 기준선 대비 약 8%포인트 개선으로 과장되지 않았고, 비교 대상(흔적 없는 추측)도 문제 설정에 맞습니다. 이 확인을 바탕으로 싣습니다.
- 본문 출처: 사용자 컴퓨터에서 받은 arXiv 공식 PDF.

# From Training Exposure to Membership Evidence: A Controlled Study of OLMo 2
> arXiv cs.CR, cs.CL, cs.LG 교차 등록 (프리프린트, 심사 전), 초록 기반 요약, 본문 미확인

저자들의 초록에 따르면, 이 연구는 언어 모델이 특정 문서로 학습했는지 판별하는 멤버십 추론을 통제된 실험으로 다시 평가합니다. 기존 평가는 학습 데이터와 비학습 데이터를 사후에 모으기 때문에, 성공은 분포 차이 탓일 수 있고 실패는 결론을 내리기 어렵다는 문제의식입니다. 저자들은 OLMo 2 1B의 공식 500억 토큰 중간 학습 단계를 다시 실행하면서, 영역과 난이도를 맞춘 7,814쌍의 문서 중 동전 던지기로 하나를 학습에 넣고 하나를 빼었다고 설명합니다. 같은 시드로 AI2가 공개한 원래 학습 결과를 반사실(counterfactual) 기준으로 삼았습니다.

# What Standard Evaluations Hide About Detectors of Hijacked LLM Agents: Rare Attacks, Unseen Tools and Benchmark Transfer
> arXiv cs.CR, cs.LG 교차 등록 (프리프린트, 심사 전), 초록 기반 요약, 본문 미확인
> 2026

저자들의 초록에 따르면, 이 논문은 도구 호출 흔적으로 탈취된 LLM 에이전트를 찾아내는 탐지기 평가가 무엇을 가리고 있는지를 다룹니다. 저자들이 검토한 평가 11건에서 공격 비율이 시험 데이터의 16~86%를 차지했고, 그 비율을 바꿔 본 평가는 없었으며, 6건은 다른 벤치마크나 출처의 데이터로 시험하지 않았다고 합니다. 저자들은 AgentDrift와 AgentDojo 벤치마크에서 도구 종류, 행동, 호출 순서, 단계 임베딩, 텍스트를 읽는 학습형 탐지기와 공개된 LLM 행동 감시기 AlignmentCheck를 시험했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2610.41803
- arXiv HTML 본문: https://arxiv.org/html/2610.41803
- arXiv PDF: https://arxiv.org/pdf/2610.41803
- 저자 코드와 데이터 저장소: https://github.com/Mahmoud-Abbasi-svg/agent-trace-detector-eval

### Contribution
- 저자들은 공격이 드문 실제 환경, 학습에서 보지 못한 도구, 다른 벤치마크로의 이전이라는 세 조건에서 기존 평가가 탐지기 성능을 과대평가한다고 주장합니다.

### Evaluation
- 초록에 적힌 수치: 공격 비율 2%에서 AUROC 0.879인 탐지기의 정밀도는 0.076이었고, 음성 표본 구성만 바꿔도 정밀도가 0.039~0.117 사이로 움직였습니다. 시험 도구 중 학습에서 본 도구의 비율이 50% 근처에서 탐지기 순위가 교차하고 그 아래에서 뒤집혔습니다. - 본문을 읽지 못해 데이터셋, 비교 조건, 지표의 신빙성은 확인하지 못했다.
