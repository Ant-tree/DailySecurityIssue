# LLM Agent Authorization Across Context Compaction
> arXiv 프리프린트 (심사 전). 시드니 공과대학교, 싱가포르 국립대학교, 뉴사우스웨일스 대학교
> 2026

Progent, DRIFT 같은 "요청 기반 권한 부여기"는 도구가 실행되기 전에 사용자 요청을 읽고 에이전트가 할 수 있는 행동(허용 도구와 인자 제약)을 정해, 간접 프롬프트 주입을 막습니다. 이 방어는 "요청 자리에 있는 글이 사용자가 한 말"이라는 귀속 가정에 기대고 있습니다. 그런데 대화가 길어져 컨텍스트 한도에 가까워지면 하네스는 이전 대화를 모델이 요약한 글로 바꾸는 압축(compaction)을 하고, 저자들이 관찰한 모든 자동 압축에서 Claude Code와 Codex는 이 요약을 사용자 메시지 자리에 넣었습니다. 그러면 요약이 인용한 사용자 발언, 문서 내용, 주입된 글이 모두 "사용자가 말한 것"으로 읽히고, 권한 부여기의 정책이 요약을 따라가게 됩니다.

### Contribution
- 압축이 권한 부여기를 독립적인 검사에서 "요약을 따라가는 정책"으로 바꾼다는 실패를 구체적으로 보였습니다. 예를 들어 은행 에이전트에서 압축 전에는 거부했던 송금이, 압축 후 요약이 그 송금을 "미완료 작업"으로 기록하자 공격자 계좌로의 송금 한 건을 정확히 허용하는 새 정책으로 바뀌었습니다.
- 글만 읽는 권한 부여기는 위조된 기록과 그것이 흉내 낸 정상 기록을 두 글 자체가 구별되는 정도 이상으로 구별할 수 없다는 한계를 증명하고, 그 한계가 빈틈없음(tight)도 보였습니다. 정상 기록과 비슷하게 쓰인 데이터라면 요약을 더 잘하거나 탐지기를 붙여도 해결되지 않는다는 뜻입니다.
- 해결책으로 "증인 붙은 요청 게이트"를 설계했습니다. 사용자 발화를 도착 시점에 인증하고 압축 경계를 넘어 원문 그대로 보관해, 에이전트는 요약을 읽되 권한 부여기는 사용자의 원래 발화만 받게 합니다. 게이트가 넘겨주는 것은 정확히 그 글이거나 아무것도 아님을 증명해, 공격자가 정책을 막을 수는 있어도 모양을 바꿀 수는 없게 했습니다.

### Evaluation
- 요약 위치: Claude Code와 Codex에서 기록한 자동 압축 1,108회 모두에서 요약이 요청 자리를 차지했습니다. Gemini CLI, OpenHands, Cline, Goose, Aider, Qwen Code 등 다른 하네스 여덟 개의 압축 코드도 같은 방식이었다고 합니다.
- 정책 오염: 압축 전 Progent가 막던 주입이 작은 압축 모델을 쓴 주 실험에서는 압축 후 방어가 없는 에이전트와 비슷한 비율로 성공했습니다. 사용자가 수취인을 직접 밝힌 경우에도, 공격자 공지문이 다른 계좌를 평범한 데이터로 적어 두면 최신 모델 요약에서 도출한 정책이 그 계좌를 91%(다른 정책 생성기에서는 59%) 허용했고, 사용자 원문에서 도출한 정책은 한 번도 허용하지 않았습니다.
- 원인 분석: 최신 압축 모델은 주입된 "지시"에는 표시를 붙였지만 "데이터"로 쓰인 계좌에는 거의 붙이지 않았습니다. 정당한 쌍둥이가 없는 지시와 달리 데이터는 정상 기록과 구별할 근거가 없기 때문이며, 증명한 한계와 맞아떨어집니다.
- 수정안: 게이트를 적용한 AgentDojo 공격 에피소드 40회에서 공격자 행동은 하나도 완료되지 않았고, 에이전트가 쓸 수 있는 파일을 통한 기록 재생을 포함한 적응형 공격 여덟 가지를 모두 버텼습니다. 정상 과제는 게이트를 거쳐 26건을 완료해 압축하지 않은 실행(27건)과 비슷했습니다. 요청마다 정책을 새로 도출하면 이후 과제 완료율이 12%에서 68%로 올라 실용성도 확인했습니다.
- 신빙성: AgentDojo 네 개 도구군, ASB 열 개 에이전트, 하네스 11개가 배포한 압축 프롬프트 18개, 실제 Claude Code·Codex 압축까지 범위를 넓혀 측정했습니다. 다만 게이트 평가는 재생한 AgentDojo 세션 위에서 했고, 실제 하네스에 통합하는 일은 다음 단계로 남겼습니다. 사용자가 문서에 맡긴 값은 문서 출처가 인증되지 않는 한 여전히 한계 정리의 영향을 받으며, 키와 카운터가 에이전트 손이 닿지 않는 곳에 있다는 가정이 필요합니다.

#### Comment
- 장기 실행 코딩 에이전트에서 압축은 흔한 기능인데, "무엇을 남기고 어떻게 표시하느냐"가 보안 매개변수라는 지적이 실무적으로 중요합니다. 압축 이후 권한 판단을 사용자 메시지 기준으로 하는 구성이라면 바로 점검해 볼 만합니다.
- 2026-11-26에 실린 "When Answering Is Administering"과 같은 연구 그룹(시드니 공과대학교, 뉴사우스웨일스 대학교 등)의 연속 작업으로 보입니다. 두 논문 모두 에이전트 권한 정책이 사용자 이외의 글에 휘둘리는 경로를 다룹니다.
