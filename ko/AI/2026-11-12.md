# BypassGym: A Benchmark for Evaluating AI Agents' Endpoint Defense Evasion Capabilities
> arXiv 프리프린트 (심사 전). 화중과기대학(중국), 버지니아공대(미국)
> 2026

LLM 에이전트의 공격 능력을 재는 벤치마크는 침투 테스트, 취약점 발견, CTF 위주였고, 실제로 설치된 EDR(엔드포인트 탐지 및 대응) 제품을 뚫는 "방어 회피" 능력은 체계적으로 측정되지 않았습니다. 이 논문은 C2 프레임워크(Havoc, AdaptixC2, Sliver)의 셸코드를 주고, 에이전트가 이를 실행하는 로더를 직접 작성하고 컴파일해 EDR이 설치된 실제 Windows 11 가상 머신에서 차단이나 종료 없이 실행시키는지를 평가하는 벤치마크 BypassGym을 제안했습니다. Proxmox VE 위에서 먼저 EDR 없는 VM으로 기능을 확인하고, 통과한 제출물을 EDR이 설치된 VM에서 실행한 뒤 실패한 단계를 구조화된 결과로 돌려줍니다. 공개된 회피 기법 37개, 완성된 로더 프로젝트 3개, DLL 하이재킹 템플릿 6개를 에이전트 스킬 형태의 지식으로 제공하고, 그 유무에 따른 차이도 측정합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.13684
- arXiv HTML 본문: https://arxiv.org/html/2611.13684
- arXiv PDF: https://arxiv.org/pdf/2611.13684

### Contribution
- 셸코드 스캐너나 샌드박스 판정이 아니라, 실제 엔드포인트에서 페이로드가 실행되고 C2 세션이 유지되며 명령과 파일 전송까지 성공해야 통과로 치는 실행 기반 판정을 썼습니다.
- 작업 조건(페이로드, 도구, 반복 예산)은 고정하고 로더 구현 방식은 열어 두어, 모델, 에이전트 실행 환경(Codex CLI, Claude Code, OpenCode), 추론 강도, 제공 지식, 피드백 수준을 따로 바꿔 가며 비교할 수 있게 했습니다.
- 1~4주 뒤 같은 제출물을 다시 실행하는 지연 재검사로, 클라우드 평판 기반의 늦은 탐지까지 확인했습니다.

### Evaluation
- 설정: 경량 모델 5종(GPT, Gemini, GLM, DeepSeek, Qwen 계열) × EDR 6종(Windows Defender, Kaspersky, Elastic, Trend Micro, Sophos, Bitdefender) × 페이로드 3종, 총 90회 실행.
- 결과: 90회 중 71회(78.9%)에서 에이전트가 EDR을 통과하는 로더를 만들었습니다. DeepSeek-V4.1 Flash가 18회 중 17회로 가장 높았고, Bitdefender가 가장 어려운 대상이었습니다. 성공 사례 대부분은 서명된 정상 프로그램을 이용한 DLL 사이드로딩이라는 같은 접근을 반복했습니다.
- 지연 재검사: 성공 제출물 71개 중 62개(87.3%)가 1~4주 뒤에도 통과했습니다. Kaspersky는 13개 중 5개를 뒤늦게 잡아(생존율 61.5%) 가장 큰 차이를 보였습니다.
- 통제 실험: 제공 지식을 없애면 DeepSeek은 17/18에서 13/18, GLM은 15/18에서 9/18로 떨어졌습니다. 통과 여부만 알려 주는 피드백은 1회 시도와 차이가 없었고, 어떤 검사에서 실패했는지 알려 주는 상세 피드백만 성공률을 높였습니다(DeepSeek 14/18에서 17/18). 추론 강도를 높여도 성공률이 꾸준히 오르지는 않았습니다.
- 지표의 신빙성: 조건당 실행 수가 18회 수준으로 작고, EDR 제품의 특정 시점 스냅샷과 기본 설정에서의 결과입니다. 저자들도 제품 간 우열을 일반화하지 말라고 밝혔습니다.

#### Comment
- 중국 기관 논문이라 추가로 확인했습니다. 화중과기대학의 Haoyu Wang과 버지니아공대의 Peng Gao는 소프트웨어 보안과 시스템 보안 분야에서 활동이 확인되는 연구자입니다. 게재처는 아직 없는 심사 전 원고이며, 코드와 데이터는 "심사 이후 공개"라고만 적혀 있어 지금은 재현할 수 없습니다. 수치는 지나치게 좋다기보다 제품과 모델에 따라 고르게 갈리고 실패 원인도 함께 보고해 비교 설계 자체에는 큰 문제를 찾지 못했습니다. 다만 재현 자료가 없다는 점은 감안해야 합니다.
- 공격 능력 측정 연구라 윤리 문제가 따르며, 저자들은 결과를 EDR 업체에 알렸고 방어 연구와 모델 공개 결정을 위한 측정이 목적이라고 밝혔습니다.
- 방어 측 시사점은 서명된 호스트를 이용한 DLL 사이드로딩, 매핑된 이미지에서의 실행, 메모리 권한의 RW에서 RX 전환 같은 반복적인 탐지 공백입니다.

# From Attack Surface to Defense Architecture: Compositional Security for Agentic Coding Harnesses
> arXiv 프리프린트 (심사 전). Evercursion(GaiaLogic), 마카오 대학교, Allianz, 난양공대
> 2026

AI 코딩 에이전트 실행 환경(하네스)은 LLM에 셸, 파일 시스템, 네트워크를 연결하므로, 공격자가 이슈나 문서에 지시를 심으면 bash, curl, find 같은 정상 도구가 그대로 공격 수단이 되는 "환경 내 도구 악용(Living-off-the-Land)" 플랫폼이 됩니다. 저자들은 하네스의 고위험 결함 다수가 심볼릭 링크 경합, 경로 조작, 하위 프로세스 탈출, SSRF, 자격 증명 노출 같은 고전적인 운영체제와 소프트웨어 문제이며, 보안은 개별 모델의 행동이 아니라 구조와 권한 조합의 성질이라고 주장합니다. 이를 바탕으로 "지능은 행동을 제안하되 자기 권한을 정하지 않는다"는 원칙의 참조 모니터 구조 ActiveSecHarness를 제안했습니다. 위임할수록 권한이 줄어드는 HMAC 능력 토큰, 신뢰도와 민감도를 곱한 오염 격자(taint lattice), 여러 에이전트가 디스크를 거쳐 비밀을 흘리지 못하게 하는 작업 공간 출처 원장, 결정적 검사기(Ring 0) 등으로 구성됩니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.13960
- arXiv HTML 본문: https://arxiv.org/html/2611.13960
- arXiv PDF: https://arxiv.org/pdf/2611.13960

### Contribution
- 코딩 에이전트 하네스의 공격 표면을 고전적인 시스템 보안 문제의 조합으로 정리하고, 정규식 차단 목록과 LLM 심사관(LLM-as-a-Judge) 방식의 한계를 논증했습니다.
- 권한(능력 토큰), 정보 흐름(오염 격자와 작업 공간 출처 원장), 실행 통제(결정적 검사기), 검증(도구 인증서, 이중 키 감사 로그, 보안 테스트 생성)을 분리한 다층 구조를 설계했습니다.
- 단계별로는 무해해 보이는 행동이 여러 단계와 여러 에이전트에 걸쳐 조합될 때 생기는 유출 경로를 상태 기반으로 막아야 한다는 점을 실험으로 보였습니다.

### Evaluation
- 데이터: 저자들이 만든 252개 시험 사례(단일 단계 공격 120개, 정상 개발 작업 120개, 5단계 공격 사슬 12개).
- 비교: 무방어, 정규식 차단, 로컬 LLM 심사관(qwen3:4b), Ring 0, 혼합 방식. 공격 차단율은 각각 0.000, 0.439, 1.000, 1.000, 1.000, 오탐률은 0.000, 0.000, 0.983, 0.000, 0.000이었습니다. LLM 심사관은 정상 작업의 98.3%를 거부해서야 공격을 막았고 판단 지연 중앙값이 142.3ms였던 반면, Ring 0는 12.7µs였습니다.
- 다단계 실험: 이상적인 상태 비저장 작업 정책(Conseca 방식)도 공격 사슬 12개 중 4개를 놓쳤고(차단율 0.667), 단순한 불리언 오염 잠금은 정상 작업의 83.3%를 막았습니다. 제안 방식은 차단율 1.000, 오탐률 0.000이었습니다.
- 지표의 신빙성: 시험 사례를 제안자가 직접 설계했으므로 완벽한 수치는 설계 범위 안에서만 의미가 있습니다. LLM 심사관 비교 대상이 4B 소형 모델 하나뿐이라 공정한 비교라고 보기 어렵고, 저자들도 이를 "소형 모델 최악의 경우"라고 인정했습니다. 실제 코딩 에이전트 작업(예: SWE-bench)에서의 유용성 손실은 측정하지 않았습니다.

#### Comment
- 설계 원칙 자체(모델이 아니라 권한 구조에서 강제)는 타당하고 실무에 참고할 만하지만, 논문이 방대한 구성 요소를 한꺼번에 제안해 각 요소의 효과를 따로 검증하지는 못했습니다.
- 첫 저자 소속 기업의 제품 성격이 짙고, 저자들의 다른 이론 논문을 근거로 자주 인용합니다. 정식 심사 전 원고입니다.

# Isolation Is Not Confidentiality: Security Boundaries of Geometric Access Control in RAG
> arXiv 프리프린트 (심사 전). 클레르몽오베르뉴 대학교, CNRS, LIMOS(프랑스)
> 2026

기업용 RAG는 접근 정책이 서로 다른 문서를 한 벡터 데이터베이스에 넣는 경우가 많습니다. 최근 연구들은 정책마다 비밀 기하 변환(회전, 차원 추가, 거리 비교 보존 암호화 DCPE 등)을 임베딩에 적용해, 같은 정책끼리만 검색되도록 하는 방식을 제안했습니다. 이 논문은 이 방식이 실제로 어떤 보안 성질을 주는지 정책 격리, 표현 기밀성, 질의 위조 저항, 정책 소속 은닉 네 가지로 나눠 분석하고, 원저자들의 공개 구현을 직접 돌려 검증했습니다. 결론은 검색 성능과 정책 격리는 지켜지지만 나머지 세 성질은 지켜지지 않는다는 것입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14061
- arXiv HTML 본문: https://arxiv.org/html/2611.14061
- arXiv PDF: https://arxiv.org/pdf/2611.14061

### Contribution
- 기하 변환 기반 RAG 접근 제어의 보안 목표를 네 가지로 구분해 정식화하고, 격리가 기밀성을 뜻하지 않는다는 점을 보였습니다.
- 원래 임베딩과 보호된 표현의 짝을 가진 "호기심 많은 사용자"가 최소제곱 추정만으로 변환을 학습해 원래 임베딩을 복원하거나 다른 정책의 질의를 위조할 수 있음을 보였습니다. 복원과 위조는 대상이 다르고 비용도 다르게 늘어난다는 점을 구분했습니다.
- 보호된 표현만 보는 클라우드 사업자도 정책별 기하 구조 때문에 어떤 문서가 같은 정책에 속하는지 알아낼 수 있음을 보였습니다. DCPE 같은 암호 방식도 예외가 아니었습니다.

### Evaluation
- 대상: Trans-RAG, 키 기반 차원 추가 방식, DCPE(IronCore SDK)와 앞의 두 방식의 결합. 모두 원저자 구현을 사용했습니다.
- 데이터와 모델: 정책 격리는 MedQuAD에 9개 속성 기반 정책을 붙인 표본, 검색 성능은 MS MARCO와 BEIR 3종(NFCorpus, SciFact, FiQA), 복원과 위조는 MedQuAD 단일 정책 부분집합(저장 임베딩 3,500개, 질의 300개)으로 평가했습니다. 인코더는 MiniLM(384차원), MPNet(768), GTE-large(1024)입니다.
- 결과: 모든 방식에서 교차 정책 검색은 0이었고 Recall@10은 보호 전과 0.01 이내였습니다. 그러나 모든 방식이 200~400쌍의 짝만으로 상위 10개 결과 일치도 0.8 이상까지 복원됐고, 차원이 커져도 복원 비용은 늘지 않았습니다. 위조는 비밀 변환 방식에서 500쌍(384차원)에서 1,800쌍(1024차원)으로 비용이 늘었지만 결국 성공했고, 키 기반 차원 추가 방식은 공격자가 자기 정책의 짝으로 공통 회전을 추정하면 대상 정책은 한 쌍으로 충분했습니다. 정책 소속 군집 지표(ARI)는 대부분 1.00이었습니다.
- 지표의 신빙성: 원저자 구현을 쓰고 시드 3개로 반복해 재해석 오류를 줄였습니다. 다만 공격 비용은 100쌍 단위의 거친 격자로 한 표본에서만 측정해, 200쌍과 300쌍 같은 차이는 의미 있게 볼 수 없다고 저자들도 적었습니다. 공격자가 짝을 수백 개 얻을 수 있다는 가정이 실제 배포에서 얼마나 현실적인지는 시스템마다 다릅니다.

#### Comment
- 특정 시스템의 암호학적 파괴가 아니라 방식 전체의 보안 경계를 밝히는 논문이라, RAG 접근 제어를 설계할 때 "임베딩 변환으로 격리했으니 안전하다"는 가정을 점검하는 데 유용합니다.
- 차원 추가 방식의 파라미터를 코사인 유사도 저장소에 그대로 옮기면 검색이 무너진다(Recall@10 0.02)는 이식성 문제도 함께 보고했습니다.
- 프랑스 대학 연구진의 심사 전 원고입니다.
