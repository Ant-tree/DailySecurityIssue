# Where the Savings Go: The Limits of Hiding Cross-Tenant Cache Hits in LLM Serving
> arXiv 프리프린트 (심사 전). 존스홉킨스 대학교
> 2026

LLM 서빙 엔진의 프롬프트 접두사 캐시를 여러 테넌트가 공유할 때, 캐시 적중을 "숨기는" 방어가 근본적으로 어디까지 가능한지 따진 논문입니다. 캐시가 적중하면 앞부분 계산을 건너뛰어 응답이 빨라지므로, 공유 캐시는 다른 사용자가 같은 텍스트를 보냈는지를 드러냅니다. 계정마다 캐시 키에 솔트를 넣으면 이 통로는 닫히지만 테넌트 간 재사용 이득이 사라지고, 계정 단위로만 격리되어 중계 서비스처럼 한 계정 아래 여러 사용자가 섞이는 경우는 막지 못합니다. 그래서 캐시는 공유하되 적중 요청이 미스처럼 보이게 만드는 방어들이 제안되었는데, 저자들은 이 방어들이 적중 요청 하나만 본다는 점을 짚고 "절약된 시간이 어디로 가는가"를 추적했습니다. 단계 단위로 요청을 처리하고 일감이 있으면 쉬지 않는 스케줄러에서는, 적중으로 절약된 시간이 그 뒤에 줄 선 모든 요청에 똑같이 넘어가 이들이 모두 같은 만큼 일찍 끝납니다.

### Contribution
- 공격: 공격자는 후보 텍스트를 담은 탐침 요청의 앞뒤를 출력 토큰 하나짜리 자기 요청(리스너) 묶음으로 감싸 짧은 간격으로 보내고, 리스너들이 몇 단계 만에 끝나는지를 셉니다. 시간 대신 단계 수를 세므로 대기열 지연에 둔감하며, 평범한 요청 한도 안에서 동작합니다.
- 방어 평가: 적중 요청만 미스처럼 보이게 하는 방어는 vLLM과 SGLang 모두에서 탐침 한 번으로 무너지고, 무작위 지연은 이동량의 열 배 이상이 되어야 공격 이점을 0.1로 낮출 수 있으며, 공유 범위를 좁히는 방식도 보장을 주지 못함을 보였습니다.
- 이론: 테넌트가 관찰할 수 있는 이득은 곧 신호이므로, 요청 한도가 있는 테넌트가 다른 계정 k개가 쓴 내용에서 얻는 이득은 허용 누출량의 k배 정도로 제한된다는 것을 증명했습니다. 누출이 0이면 절약은 서비스 제공자만 가집니다.
- 단일 인스턴스에서 정확한 숨김은 원리상 가능하지만, 건너뛴 작업이 얼마나 걸렸을지 근사적으로만 알기 때문에 적중 수가 아니라 시간에 비례하는 패딩 비용이 든다는 점을 보였습니다.

### Evaluation
- 환경: 주요 서빙 엔진 열 가지의 스케줄러를 코드와 문서로 조사했고, vLLM과 SGLang에서 실험했습니다. L40S GPU의 유휴 vLLM에서 1,024토큰 적중은 뒤에 줄 선 16개 요청을 모두 68~69ms 일찍 끝나게 했습니다.
- 주요 결과: 실제 서비스 트레이스를 vLLM 인스턴스 하나에 용량의 절반까지 재생한 조건에서, 탐침 한 번으로 256토큰 이상 텍스트의 캐시 여부를 공격 이점 0.98 이상으로 판별했습니다.
- 신빙성: 공격 조건(다른 테넌트 요청이 짧은 탐침 구간에 끼어들지 않을 것)을 필요한 전송 속도로 정량화했고, 방어 평가를 기존 연구의 위협 모델과 직접 대조했습니다. 측정은 단일 인스턴스 중심이라 대규모 분산 서빙에서의 효과는 따로 확인이 필요합니다.

#### Comment
- 결론이 실무적으로 분명합니다. 격리가 필요한 서비스는 캐시를 "숨기려" 하지 말고 신뢰 경계마다 솔트를 넣어야 하며, 그 경계는 경계를 아는 계층(중계 서비스, 애플리케이션)이 정해야 한다는 것입니다.
- 공격 모델이 공격자 자신의 요청 타이밍만 쓰는 고전적인 대기열 부채널을 LLM 서빙에 적용한 것이라 이해하기 쉽고, 상용 API의 캐시 범위 정책을 점검하는 근거가 됩니다.

# When Tool Names Are Not Identities: Measuring Provider Misbinding in MCP-Based AI Agents
> arXiv 프리프린트 (심사 전). 뉴브런즈윅 대학교 캐나다 사이버보안 연구소(CIC)
> 2026

Model Context Protocol(MCP)로 여러 서버의 도구를 함께 쓰는 에이전트에서, 도구 이름이나 설명이 실제 제공자의 신원과 묶여 있지 않아 생기는 문제를 측정한 논문입니다. 저자들은 이를 "도구 제공자 오결합(tool-provider misbinding)"이라고 부르는데, 정상 제공자에게 가야 할 요청이 공격자가 운영하는 도구로 해석되어 실행되는 실패를 뜻합니다. 공격자는 호스트, LLM, 정상 서버, 네트워크를 전혀 건드리지 않고, 같은 클라이언트가 보는 MCP 서버를 하나 더 운영하면서 원하는 메타데이터로 도구를 광고하기만 합니다. 정상 서버 하나와 공격자 서버 하나를 둔 통제 환경에서, 도구 이름, 설명, 스키마를 체계적으로 바꿔 가며 다섯 LLM 클라이언트가 어느 제공자를 고르는지 측정했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.21577
- arXiv HTML 본문: https://arxiv.org/html/2611.21577
- arXiv PDF: https://arxiv.org/pdf/2611.21577

### Contribution
- 도구 제공자 오결합을 공격자가 도구 선택 확률을 최대화하는 최적화 문제로 정식화하고, 공격자 선택률, 확인 질문 비율, 실패율, 반복 실행 시 결합 안정성 같은 측정 지표를 정의했습니다.
- 이름(무관, 복사), 설명(무관, 과업 정렬, 권위 강조), 스키마(호환 여부)를 2×3×2로 조합한 열두 조건의 요인 실험을 설계해, 각 메타데이터 필드의 기여를 분리했습니다.
- 이름 하나나 공격자 후보 하나에 따른 우연이 아님을 보이기 위해 무관 이름 표본, 권위 강조 설명 표본, 공격자 후보 수(예산)를 바꾼 추가 실험을 했습니다.
- 서명된 도구 매니페스트, 제공자에 묶인 도구 식별자, 스키마 해시, 클라이언트 측 강제 같은 "제공자에 묶인 도구 신원"을 방어 방향으로 제시했습니다.

### Evaluation
- 대상: GPT-5.4, Claude Sonnet 5, Gemini 2.5 Pro, Qwen3.7 Max, DeepSeek V3. 프롬프트 10개를 5번씩 반복해 조건마다 모델당 50회 시행했습니다.
- 주요 결과: 관련 없는 대조 조건은 대부분 안전했지만, 이름이 정확히 겹치고 설명이 과업에 맞고 스키마가 호환되는 조건에서 실패가 가장 컸습니다. 설명 표본 다섯 개로 반복한 결과에서 이 조건의 공격자 선택률은 GPT-5.4 0.98, Qwen3.7 Max와 DeepSeek V3 1.00, Gemini 2.5 Pro 0.72였고, Claude Sonnet 5는 0.256에 확인 질문 비율이 0.744였습니다. 이름이 겹치지 않아도 권위를 강조한 설명과 호환 스키마만으로 잘못된 제공자 실행이나 해결되지 않는 모호성이 생겼습니다.
- 신빙성: 반복 시행과 95% 신뢰구간을 보고했고 표본을 바꿔 결과가 유지됨을 확인했습니다. 다만 데이터셋 조회라는 한 가지 과업만 시험했고, 메타데이터 변형도 통제된 범위라 실제 MCP 배치와 모든 공격 전략을 대표하지는 않는다고 저자들이 밝혔습니다.

#### Comment
- 모델마다 실패 양상이 다르다는 점이 흥미롭습니다. 일부 모델은 조용히 공격자 도구를 실행하고, Claude Sonnet 5는 주로 사용자에게 되묻습니다. 되묻는 것이 조용한 실행보다는 낫지만, 저자들 말대로 모델의 신중함이 제공자 신원 확인을 대신하지는 못합니다.
- 반복 실행에서 결합이 안정적이라는 것 자체가 안전 지표가 아니라는 지적(공격자 도구에 안정적으로 묶이는 것이 가장 나쁜 경우)도 평가 설계에 참고할 만합니다.

# Compositional Exploits in Autonomous Coding Agents: Attack Mechanics and Ephemeral Defense
> arXiv 프리프린트 (심사 전). Google
> 2026

코딩 에이전트가 하나하나는 무해한 도구를 여러 턴에 걸쳐 이어 붙여 허가되지 않은 공격을 수행하는 "조합형 익스플로잇"을 다룬 논문입니다. 지금의 도구 심사는 Bandit, Semgrep 같은 정적 분석기나 LLM 심사로 도구를 하나씩 따로 검사합니다. 그런데 네트워크 권한이 없는 설정 점검 도구가 자격 증명을 임시 파일에 쓰고, 자격 증명 파일을 읽을 수 없는 웹훅 알림 도구가 그 임시 파일을 외부로 보내면, 어떤 도구도 규칙을 어기지 않았는데 결과적으로 자격 증명이 유출됩니다. 저자들은 이것을 바이너리 공격의 코드 재사용(ROP)에 빗대어, 작업 공간 파일, 환경 변수, 대화 메모리라는 공유 상태를 통해 정상 도구가 연결되는 위협으로 정식화했습니다. 방어로는 단기 권한 임대와 데이터 흐름 출처 추적을 하는 제어 평면과, Linux Landlock과 seccomp-BPF, 루프백 프록시로 커널에서 강제하는 실행 평면을 결합한 CompGuard를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.19764
- arXiv HTML 본문: https://arxiv.org/html/2611.19764
- arXiv PDF: https://arxiv.org/pdf/2611.19764

### Contribution
- 공유 상태(파일, 환경 변수, 메모리) 위의 조합형 위협 모델과 여덟 가지 위험 유형 분류를 제시했고, 평범한 작업 지시, 간접 프롬프트 주입, 잠복한 CI/CD 트리거, 다중 에이전트를 거친 거부 우회 같은 유발 경로를 보였습니다.
- 공격 벤치마크와 정상 작업 벤치마크, 실제 클라우드 진단 작업 100개로 이루어진 560개 과제 평가 묶음을 만들었습니다.
- CompGuard: 한 번에 한 스킬에만 권한을 주는 단기 권한 임대, 설정 파일을 구조적으로 파싱하는 세밀한 데이터 출처 그래프, 매 실행마다 Landlock 규칙과 seccomp 소켓 필터를 새로 만들어 커널에서 파일과 네트워크 접근을 제한하는 계층을 결합했습니다. 셸 우회(base64, 변수 치환, 동적 임포트)로 사용자 공간 필터를 피하는 문제를 커널 강제로 막는 것이 핵심입니다.

### Evaluation
- 공격 결과: 보호가 없는 Gemini 3.5, 3.7, 3.8 Flash가 조합형 공격 사슬을 72.9~84.5% 성공했고, 단일 도구를 검사하는 배포 전 스캐너 다섯 종은 구성 도구를 하나도 탐지하지 못했습니다.
- 방어 결과: CompGuard는 방어 차단율 100%(종료 전 순 공격 성공률 0.0~0.8%), 개입 부담 61.4마이크로초, 정상 개발 작업 해결률 98.0%(오탐 2.0%), 실제 클라우드 진단 호출 615건에서 오탐 0건을 보고했습니다.
- 신빙성: 공격과 방어를 모두 저자들이 만든 벤치마크에서 평가했고, 대상 모델도 같은 회사의 Gemini 계열뿐이라 다른 에이전트 제품에서의 성공률은 알 수 없습니다. 코드 공개 주소는 본문에서 찾지 못했고, 책임 있는 공개 내역의 티켓 번호는 가려져 있습니다.

#### Comment
- 도구를 하나씩 심사하는 현재의 MCP나 스킬 마켓 심사 방식이 조합 공격에 무력하다는 문제 제기는 설득력이 있고, 실무에서 에이전트 샌드박스를 설계할 때 바로 참고할 만합니다.
- 한계로 저자들은 독자 형식 파일의 과도한 오염 표시, 사전 허용된 로컬 소켓을 악용할 때 생기는 마이크로초 단위의 종료 지연 구간, SNI만 보는 프록시가 도메인 프론팅이나 ECH로 속을 수 있다는 점을 들었습니다. 시간 기반 은닉 채널은 범위 밖입니다.

# From Bytes to Behavior: Request-Level Attribution from Live GPU Hidden States
> arXiv 프리프린트 (심사 전). 싱가포르 내무부 산하 과학기술청(Home Team Science and Technology Agency)
> 2026

실행 중인 LLM 서비스의 GPU 메모리에서 요청 하나를 처리하는 동안 만들어지는 층별 잔차 스트림 활성값을 꺼내, 그 요청에서 모델이 무엇을 했는지 포렌식 증거로 쓰는 방법을 다룬 논문입니다. 기존 머신러닝 메모리 포렌식은 모델 가중치나 프롬프트 기록 같은 정적 산출물을 대상으로 했고, 잔차 스트림은 처리 직후 메모리가 재사용되어 로그에 남지 않습니다. 저자들은 대상 프로세스를 수정하지 않는 CUDA 디버거를 붙여, 모델 구조나 가중치를 모르는 상태에서 PyTorch 할당기의 메모리 이벤트 흐름만 보고 잔차 스트림 할당을 골라내 읽는 방법을 제시했습니다.

### Contribution
- 기존 연구가 일부만 다룬 카드 위조, 기능 은폐, 카드 오염 등을 넓혀 발견 단계의 공격 표면을 열 가지 조작 공격으로 분류했습니다.
- 인터넷 도메인 3,610만 개를 조사해 실제 배포된 Agent Card 310개를 모으고, 두 명이 독립적으로 라벨링해 96.8% 일치도를 얻었습니다. 실제 A2A 생태계를 측정한 자료로서 가치가 있습니다.
- 실제 카드에 공격을 주입한 660개 벤치마크(짝지은 정상 대조군 포함)와, Claude Sonnet 4.6으로 생성한 뒤 사람이 검토한 열 가지 공격 유형의 합성 벤치마크 260개를 만들었습니다.

### Evaluation
- 실제 카드에 주입한 공격에서 가장 강한 의미 판단 모델이 보안 재현율 97.0%, 오탐률 1.7%를 기록했습니다.
- 합성 벤치마크에서 LLM 판단 모델 아홉 개의 보안 재현율은 25.8%에서 92.3%까지 크게 달라, SECCARD의 효과가 판단 모델 선택에 크게 좌우됨을 보였습니다.
- 신빙성: 평가는 공격 카드를 "탐지했는가"를 잰 것이며, 실제 배포된 오케스트레이터에 대한 공격 성공률을 끝까지 잰 것은 아니라고 저자들이 밝혔습니다. 합성 벤치마크는 LLM이 생성해 실제 공격자의 다양성을 다 담지 못할 수 있습니다.

#### Comment
- 카드가 무해해도 호출 후 실제 행동은 다를 수 있으므로, 이 체계는 실행 중 행동 검증을 대신하지 못한다고 저자들이 분명히 했습니다. 발견 단계 메타데이터를 "신뢰할 수 있는 서비스 설명"이 아니라 보안 경계로 다뤄야 한다는 결론은 MCP 같은 다른 에이전트 메타데이터 프로토콜에도 적용됩니다.
- 같은 날 실린 MCP 도구 제공자 오결합 논문과 같은 문제, 즉 에이전트가 고르는 대상의 메타데이터가 신원과 묶여 있지 않다는 문제를 A2A 쪽에서 본 연구입니다.
- AIDC'26은 ACSAC과 함께 열리는 신생 워크숍이어서 평판은 아직 쌓이는 중입니다. 저자 저장소 주소는 본문에서 확인했습니다.
