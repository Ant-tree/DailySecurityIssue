# NameTrap: Steering AI Coding Agents Toward Security Vulnerabilities via Variable Names
> arXiv cs.CR (프리프린트, 심사 전), 국립양명교통대학(대만). 원고에 WWW '27 학회 양식이 적용돼 있으나 채택 여부는 원고와 arXiv 정보 어디에도 명시돼 있지 않습니다.
> 2026

AI 코딩 에이전트는 작업 중에 저장소를 복제하고 웹에서 받은 소스 코드를 읽기 때문에, 공개된 코드가 에이전트가 새로 쓰는 코드의 맥락이 됩니다. 이 논문은 지시문을 심는 프롬프트 인젝션 없이, 서드파티 Python 파일의 식별자 이름만 바꿔 에이전트가 특정 CWE 취약점을 작성하도록 유도하는 NameTrap 공격을 제시합니다. 예를 들어 명령 주입(CWE-78)을 노린다면 "이미 검증된 신뢰 명령"처럼 읽히는 변수명을 붙여, 에이전트가 빈 부분을 채울 때 검증을 생략하게 만듭니다. 배포되는 미끼 파일에는 지시문도 취약한 코드도 없고 이름만 바뀌어 있어서, 기존 정적 분석기와 AI 기반 분석기 일곱 종 모두 사전에 잡아내지 못했습니다.

원문: https://arxiv.org/abs/2610.34253

### Contribution
- 공격자 쪽 코딩 에이전트가 CWE별 명명 규칙에 맞춰 이름을 바꾸고, 별도 세션에서 실제로 코드를 채워 Bandit과 Semgrep으로 취약점이 생기는지 확인하는 과정을 반복해 미끼를 자동으로 만듭니다. 최종 미끼는 토큰 비교, Git 비교, 컴파일 검사, 수작업 확인을 거쳐 "식별자만 바뀌고 동작은 같다"는 조건을 만족해야 배포됩니다.
- 무작위 이름 변경, 중립적 이름 변경, 기존 식별자 오염 공격(XOXO)과 같은 조건에서 비교해, 효과가 이름을 바꾸는 행위 자체가 아니라 의도적으로 고른 이름에서 나온다는 점을 분리해 보였습니다.
- 번체 중국어 프롬프트, 모델 간 전이, 보안 주의 문구를 넣는 프롬프트 방어, 사전 탐지까지 여러 각도에서 공격의 지속성을 확인했습니다.

### Evaluation
- 대상: 별 수 상위 100개 GitHub 프로젝트 중 31개 프로젝트의 Python 파일. 깨끗한 원본으로 10번 채워도 목표 취약점이 한 번도 나오지 않은 파일만 남겨 출발점으로 삼았습니다.
- 에이전트 6종(OpenCode, Claude Code, Codex, mini-swe-agent, Aider, OpenHands)과 모델 10종(Qwen-3.5 계열, Gemma-4, Nemotron, GPT-5.4-mini, DeepSeek-V4-Flash, Claude Haiku 4.5), 취약점 4종(CWE-78, 79, 327, 502).
- Qwen-3.5-27B를 공통 모델로 쓴 6개 에이전트 실험에서 공격 성공률은 22.5~56.0%였고, 무작위 이름 변경 평균 11.8%, 중립 이름 변경 6.6%보다 높았습니다. XOXO는 같은 조건에서 2.1%에 그쳤습니다.
- 전이: CWE-78 미끼가 다른 모델에서도 한 번 이상 취약점을 유발한 비율은 81개 조합 중 42개(51.9%)였습니다. 보안 주의 문구 방어는 30개 설정 평균 성공률을 22.3%에서 19.2%로 낮추는 데 그쳤고, 오히려 높아진 설정도 15개 있었습니다.
- 탐지: CodeGemma, CodeAstra-7B, GPT-5.4-mini, Bandit, Semgrep, CodeShield, CodeQL 모두 미끼 파일에서 목표 취약점을 보고하지 않았습니다.
- 지표 신빙성: 공격 성공 판정을 Bandit과 Semgrep에만 의존하는데, 미끼 생성 과정에서도 같은 두 도구로 성공을 확인하므로 평가 도구에 맞춰 최적화됐을 가능성이 있습니다. 무작위 이름 변경만으로도 Claude Code의 CWE-327에서 60%가 나오는 등 기준선 자체가 불안정하고, 칸당 시도 횟수가 10~20회 수준이라 개별 수치의 편차가 큽니다. 주 실험이 4비트 양자화 오픈 모델 중심이고 최신 대형 상용 모델은 소형 모델(GPT-5.4-mini, Claude Haiku 4.5)만 포함됐습니다.

#### Comment
- 프롬프트 인젝션 방어가 "지시문처럼 보이는 텍스트"를 걸러 내는 데 집중하는 반면, 이 공격은 지시문이 전혀 없는 정상 코드의 이름만으로 작동한다는 점이 새롭습니다. 코딩 에이전트가 외부 코드를 맥락으로 쓸 때 신뢰 경계를 어디에 둘지에 대한 문제 제기로 의미가 큽니다.
- 탐지 실험은 "미끼 파일 자체에 취약한 코드가 없으니 코드 취약점 탐지기가 못 잡는다"는 당연한 결과에 가깝습니다. 미끼를 막으려면 이름과 코드 의미의 불일치를 보는 새로운 검사기가 필요하다는 것이 저자들의 결론입니다.
- 모든 실험은 격리 환경에서 진행됐고 오염 파일을 공개 저장소에 올리지 않았다고 밝혔습니다. 코드 공개 링크는 확인되지 않았습니다.

# Spoofing the Toolbox: Optimizing Tool Descriptions to Deceive LLM Agents
> arXiv cs.CR (프리프린트, 심사 중이라고 표기), 미국 유타대학교
> 2026

MCP처럼 에이전트가 외부 도구를 쓰는 구조에서는 에이전트가 도구 설명문을 보고 어떤 도구를 쓸지 고릅니다. 이 논문은 공격자가 정상 도구와 똑같이 동작하는 척하면서 뒤에서 악성 행위를 하는 도구를 배포하고, 그 설명문을 최적화해 에이전트가 정상 도구 대신 악성 도구를 고르게 만드는 "도구 사칭" 공격 TSA를 제안합니다. 기존 공격은 "반드시 이 도구를 쓰라" 같은 명령조 문구나 `<IMPORTANT>` 태그에 의존해 탐지기와 사람 눈에 쉽게 띄었는데, TSA는 정상 설명문의 변형에서 출발해 대리 에이전트의 선택 결과와 문장 자연스러움(퍼플렉시티)을 함께 피드백으로 받아 설명문을 다듬습니다.

원문: https://arxiv.org/abs/2610.33182

### Contribution
- 도구 사칭을 블랙박스 최적화 문제로 정식화하고, 대리 에이전트의 선택 결과와 GPT-2 퍼플렉시티를 결합한 피드백 함수, 성공과 실패 사례를 대비해 보여 주는 대조 예시 학습으로 LLM(Qwen3-8B)이 설명문을 고쳐 쓰게 하는 최적화 방법을 제시했습니다.
- 단일 도구와 다중 도구 사용 상황을 모두 다루는 평가용 벤치마크 TSABench를 함께 만들었습니다.
- 사람 대상 평가와 MCP 악성 도구 탐지기 네 종으로 은닉성을 따로 검증했습니다.

### Evaluation
- 데이터: MetaTool, MCP-Atlas, TSABench. 대리 선택 모델은 Llama-3.3-70B, 평가 모델은 Qwen-Coder2.5-32B, Qwen3-32B, Qwen3.8-27B, GPT-5 등 5종.
- 비교 대상: 프롬프트 인젝션 계열(`<IMPORTANT>` 태그, ToolHijacker)과 은닉성 중심 계열(GAPMA, AMA) 네 가지.
- 공격 성공률은 TSABench 88.65%, MetaTool 87.94%, 다중 도구 상황에서 MetaTool 82.5%, MCP-Atlas 80.1%였고, 최적화에 쓰지 않은 GPT-5로 옮겼을 때 최대 92.13%였습니다. 정상 설명문과 모든 공격 설명문을 한꺼번에 제시하면 에이전트가 TSA 설명문을 50.4% 비율로 골랐습니다.
- 탐지: MCP-Scanner, MCP-Shield, MCP-Guard, GAPMA-D, LLM 기반 탐지기에서 TSA 최대 탐지율은 4.25%였고, `<IMPORTANT>` 방식은 규칙 기반 탐지기에 100% 걸렸습니다. ToolHijacker는 기존 탐지기는 피했지만 LLM 탐지기에 85.3% 걸렸습니다.
- 사람 평가에서 의심스러운 순으로 순위를 매기게 했을 때 TSA의 평균 순위(4.00)가 정상 설명문(4.03)과 거의 같았습니다.
- 지표 신빙성: 비교 대상이 최근 공격을 고루 포함해 적절하고, 전이 평가를 따로 두어 대리 모델 과적합 문제를 점검했습니다. 다만 평가 질의 일부를 LLM으로 합성했다고 밝혔고, 사람 평가는 Prolific에서 모집한 20명 규모라 표본이 작습니다.

#### Comment
- 사용자가 도구 호출 전에 설명문을 확인하는 MCP 클라이언트의 승인 절차가 이 공격에는 거의 무력하다는 점을 보여 줍니다. 도구 신원은 설명문이 아니라 실제 동작이나 서명으로 확인해야 한다는 방향의 방어 연구(같은 날 공개된 ProbeID 등)와 함께 읽을 만합니다.
- 한계: 공격자가 악성 도구를 마켓플레이스에 올릴 수 있다는 전제를 두며, 실제 악성 행위의 탐지나 런타임 행위 감시는 다루지 않습니다. 저자들은 사용한 MCP 클라이언트 관리자에게 결과를 알렸고 방어 기법을 개발 중이라고 밝혔습니다. 코드 공개 링크는 확인되지 않았습니다.

# From Instructions to Exploits: Applying Program Analysis to Malicious Agent Skills Across Natural Language and Code
> arXiv cs.CR (프리프린트, 심사 전), 중국과학원 정보공정연구소, 앤트그룹 MYbank
> 2026

에이전트 스킬은 자연어 지시문(SKILL.md)과 함께 묶인 스크립트로 구성되기 때문에, 악성 행위가 지시문과 코드 사이의 상호작용에서 생길 수 있습니다. 예를 들어 지시문은 "발표 자료를 정리하라"고만 말하고, 함께 들어 있는 스크립트가 입력 파일을 외부로 보내는 식입니다. 이 논문은 지시문을 제한된 보안 API 집합을 쓰는 Python 형태의 중간 표현으로 컴파일하고, 지시문과 코드 각각의 프로그램 의존 그래프를 하나로 잇는 정적 분석기 SCS를 제안합니다. 그 위에서 신뢰도, 민감도, 권한(Trust-Sensitivity-Capability) 속성을 전파해 정보 유출이나 은닉 실행 같은 위험을 규칙으로 찾아냅니다.

원문: https://arxiv.org/abs/2610.33489

### Contribution
- 자연어 지시문을 `read_file`, `http_post` 같은 보안 관련 API 호출로 이루어진 중간 표현으로 바꾸고, 코드 쪽 그래프와 연결한 교차 영역 그래프(xPDG)를 만들어 지시문과 코드에 걸친 데이터 흐름을 추적할 수 있게 했습니다.
- LLM은 지시문을 중간 표현으로 바꾸는 단계에만 쓰고, 이후 판정은 그래프 위의 규칙으로 결정적으로 내려 LLM 판단에 대한 의존을 줄였습니다.
- 2026년 4월 20일 기준 ClawHub 스킬 66,157개를 전수 분석해 실제 악성 스킬 분포를 보고했습니다.

### Evaluation
- 벤치마크: 기존 데이터셋(MalSkills, MaliciousAgentSkillsBench)에서 모은 악성 스킬 117개와 정상 스킬 117개를 수작업으로 검증한 234개 균형 데이터.
- 비교 대상: GitHub 별 1,000개 이상인 오픈소스 스캐너(Cisco Skill-Scanner, A.I.G, NVIDIA SkillSpector 등)와 학술 기법 네 가지. LLM 다섯 종(GPT-5.4, Claude Sonnet 4.6, GPT-OSS-120B, Qwen3-235B, DeepSeek-R1)을 번갈아 적용했습니다.
- SCS는 다섯 LLM 평균 정확도 85.6%, 정밀도 80.2%, 재현율 95.2%, F1 86.9%로 가장 높은 정확도와 F1을 기록했습니다. A.I.G는 정밀도가 82.0%로 약간 높았지만 재현율이 낮았고, Skill-Scanner와 MalSkills는 재현율은 높지만 정밀도가 62% 안팎에 머물렀습니다.
- 지시문을 중간 표현으로 바꾸는 단계는 실제 스킬 400개로 만든 정답 세트에서 단계별 정확도 92.5~94.5%였습니다.
- 실사용 분석: 후보 2,473개 중 동적 검증과 수작업 검토로 627개를 악성으로 확인했고, 이 중 88%가 두 게시자에게 집중돼 있었으며 대부분 이후 레지스트리에서 사라졌습니다.
- 지표 신빙성: 비교 대상 선정 기준이 명확하고 수치가 지나치게 좋지 않아 해석이 자연스럽습니다. 토큰 소비량은 A.I.G가 SCS의 4배 이상(56.9M 대 13.7M)이었지만, Skill-Scanner와 MalSkills는 SCS보다 적게 썼습니다. 다만 벤치마크가 234개로 작고 저자들이 직접 선별, 검증했다는 점은 고려해야 합니다.

#### Comment
- 스킬 마켓플레이스가 새로운 공급망 공격 면이 됐다는 점을 정적 분석 관점에서 정면으로 다룬 연구입니다. 같은 날 공개된 CoSA(정상 스킬의 조합으로 생기는 위반)와 함께 보면, 단일 스킬 검사만으로는 부족하다는 문제의식이 공유되고 있습니다.
- 한계: 정의된 API 집합 밖의 동작이나 실행 시점에 결정되는 경로와 값은 놓칠 수 있고, 실사용 분석의 최종 판정은 수작업에 의존합니다.
- 중국 기관 검증: 중국과학원 정보공정연구소와 앤트그룹 산하 MYbank는 모두 실재하는 기관이며 저자 이메일 도메인(iie.ac.cn, mybank.cn)도 소속과 일치합니다. 게재처는 아직 없는 심사 전 원고입니다. 공개 데이터셋과 공개 스캐너를 비교 대상으로 썼고 비교 구성이 적절하며 성능 수치가 과장된 정황은 보이지 않습니다. 다만 논문이 아티팩트 링크로 제시한 anonymous.4open.science 저장소는 조사 시점에 만료 상태여서 코드와 실사용 분석 결과를 직접 확인하지 못했습니다. 이 점을 재현성의 공백으로 남겨 두고, 나머지 확인 항목을 충족해 포함했습니다.
