# One Fabrication Is Enough: A Fake News Article Changes the Forecasts of LLM Forecasting Systems
> arXiv 프리프린트 (심사 전). 노스웨스턴 대학교
> 2026

뉴스를 검색해 근거로 삼는 LLM 예측 시스템에, 가짜 기사 한 편을 공개하는 것만으로 예측 방향을 뒤집을 수 있음을 보인 논문입니다. 공격자는 예측 질문만 알고 모델, 검색기, 검색어에는 전혀 접근하지 못하며, 그럴듯한 뉴스 기사를 써서 검색 대상 아카이브에 올리는 것이 할 수 있는 전부입니다. 기사 안에는 모델에게 내리는 지시나 예측 문장도 넣지 않습니다. 저자들은 주식 수익률 질문 183개와 ForecastBench, Polymarket, Kalshi의 실제 예측시장 질문 308개를 대상으로, 단일 검색 예측기 다섯 종과 상위권 실서비스 예측 시스템 두 종(AIA Forecaster, xAI의 Grok ForecastBench 시스템)을 공개된 설명에 따라 재구현해 공격했습니다. 반대 방향 기사 두 편을 동시에 올려 예측을 흐리게 만드는 공격과, 현재 가장 강한 검색 단계 방어 두 가지도 함께 시험했습니다.

### Contribution
- 가짜 기사가 문맥에 들어가기만 하면, 시험한 모든 최신 모델(Gemini 3.7 Flash, GPT-5.6, GLM-5.3 Flash, Grok 4.20, Claude Sonnet 5)에서 기사와 반대였던 예측의 74~82%가 기사 쪽으로 뒤집힌다는 것을 보였습니다.
- 공격 성패를 가르는 것은 모델이 기사를 믿느냐가 아니라 검색되느냐라는 점을 밝혔습니다. 같은 위치에 진짜 기사를 넣으면 예측 변화가 3분의 1 수준에 그쳐, 효과가 문서 추가가 아니라 조작된 내용에서 온다는 것을 확인했습니다. 모델에게 기사가 조작인지 물으면 조작 기사와 진짜 기사의 절반 가까이를 모두 조작이라고 답해 검증 능력이 없었습니다.
- 검색을 넓게 하는 실서비스 구조일수록 더 취약하다는 점을 보였습니다. 두 시스템의 다중 에이전트 검색은 약 90%의 실행에서 가짜 기사를 가져왔습니다.
- 공격 이후에도 평균 정확도는 거의 변하지 않는다는 점을 짚었습니다. 공격자의 방향이 맞으면 더 맞고 틀리면 더 틀리기 때문에, 정확도 지표로는 피해가 드러나지 않습니다.
- 반대 방향 기사 두 편을 올리면 모델이 불확실성을 표현하지 않고, 기사 순서에 따라 오히려 더 큰 폭의 확신 있는 예측을 내놓는다는 점을 보였습니다.

### Evaluation
- 아카이브: 2026년 2~8월의 실제 뉴스로 만든 2주 단위 창(창마다 220단어 문단 2,867~4,521개)을 고정했고, 질문, 기사, 평가 규칙을 실험 전에 미리 정했습니다. 모델 지식 시점은 2026년 사건 20개에 대해 모두 "모른다"고 답하는지로 확인했습니다.
- 지표: 기사와 반대였던 예측이 뒤집히는 비율(reversal), 기사가 문맥에 들어간 비율(exposure), 결정 변화율, 실제 결과 대비 방향 정확도와 오차 변화.
- 방어 평가: 판정 모델이 조작 문단을 걸러내는 방식(passage filtering)과 아카이브를 나눠 따로 예측한 뒤 중앙값을 내는 방식(partitioned retrieval)은 각각 기사 한 편은 막았지만, 기사를 고쳐 쓴 복사본이나 진짜 기사의 숫자 하나만 바꾼 변형으로 쉽게 우회되었습니다. 두 방어를 합치면 기사 네 편까지는 막았지만 열여섯 편에서 뚫렸고, 공격이 없는 날에도 정상 결정의 29%를 바꾸고 진짜 뉴스의 39%를 버렸으며, 호출 수가 1회에서 48회로 늘었습니다.
- 신빙성: 사전에 고정한 절차, 대조군(진짜 기사, 무관 종목 질문), 사후 문제 질문 제거 전후 비교(74.0% 대 74.0%), 임계값 민감도 분석을 제시해 통계 처리는 꼼꼼한 편입니다. 다만 실서비스 두 종은 공개 설명을 바탕으로 재구현한 것이고, 실제 웹 검색 대신 고정 아카이브를 써서 실제 검색 엔진이 신뢰도 낮은 출처를 얼마나 상위에 올리는지는 반영되지 않았습니다. 코드와 결과는 게재 후 공개 예정이라고 밝혔습니다.

#### Comment
- 예측 시장에서 실제로 돈이 걸린 판단에 LLM이 쓰이기 시작한 상황에서, 공격 비용이 보도자료 배포 수준이라는 점이 실질적인 위협입니다. 보안 분야에서도 위협 인텔리전스나 취약점 뉴스를 검색해 판단하는 에이전트에 같은 구조가 그대로 적용됩니다.
- 열린 웹을 검색하는 시스템은 아카이브 분할 방어를 쓸 수 없어 필터 하나에 의존해야 한다는 지적이 중요합니다. 출처 평판과 교차 보도 여부를 결정 규칙에 넣지 않으면, 감독 에이전트가 "출처가 약하다"고 적어 놓고도 예측에는 반영하지 않는 현상이 계속될 것입니다.
- 소규모 공개 모델 기반 예측기를 다룬 동시 연구(Lu와 Zhang)와 결론이 일치한다고 저자들이 밝혔습니다.

# Poison-then-Hide: Finetuning-Activated Backdoor Attack on Pretrained Vision Encoders
> NeurIPS 2026 채택 논문 (본문에 "40th Conference on Neural Information Processing Systems (NeurIPS 2026)" 표기), arXiv 공개본. MIT, 우스터 공과대학교
> 2026

공개된 사전학습 비전 인코더 안에 평소에는 드러나지 않는 백도어를 숨겨 두었다가, 피해자가 깨끗한 데이터로 모델 전체를 파인튜닝하면 그때 백도어가 살아나게 만드는 공격입니다. 기존 파인튜닝 활성화 공격은 사전학습과 하위 작업이 비슷하거나 인코더 일부 층이 고정된다는 가정에 기대고 있어, 모든 층을 파인튜닝하는 현실적인 전이학습에서는 성공률이 1~3%까지 떨어졌습니다. Poison-then-Hide는 세 단계로 이 문제를 풉니다. 먼저 파인튜닝을 흉내 낸 모델 여러 개에서만 작동하고 원본 모델에서는 작동하지 않도록 트리거를 최적화하고, 다음으로 공격자가 가진 대리 데이터로 정상 작업과 백도어를 함께 학습시킨 뒤, 마지막으로 배포 직전에 표적 클래스 로짓을 억누르는 제어된 언러닝으로 백도어를 감춥니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14970
- arXiv HTML 본문: https://arxiv.org/html/2611.14970
- arXiv PDF: https://arxiv.org/pdf/2611.14970
- 저자 코드 저장소(논문에 표기): https://github.com/QixuanJin99/poison-then-hide

### Contribution
- 모델 전체를 파인튜닝하고 도메인이 바뀌는 조건에서도 작동하는 파인튜닝 활성화 백도어를 제시했습니다. 배포 시점에는 공격 성공률이 낮고 파인튜닝 뒤에는 높아지는 "숨었다가 살아나는" 동작을 일관되게 보인 방법은 비교 대상 가운데 이 방법뿐이었습니다.
- 공격 성공의 핵심 요인이 독살 단계에서 정상 하위 작업을 함께 학습하는 것임을 실험으로 보였습니다(기반 모델 정확도와 파인튜닝 후 성공률의 상관계수 0.541). 다만 정상 작업 학습만으로는 충분하지 않다는 점도 기존 공격(Hibernated)과 비교해 확인했습니다.
- 표준 방어와 최신 방어 일곱 종을 평가해, 대부분이 상당한 성능 손실 없이 백도어를 없애지 못하거나 정상 파인튜닝 뒤에 백도어가 다시 나타난다는 점을 보였습니다.

### Evaluation
- 데이터와 모델: CIFAR10에서 SVHN, ImageNet에서 RESISC, ImageNet에서 Camelyon17(병리 영상, 표적 "종양 없음")로 전이하는 세 설정과 UC Merced, 다른 병원 데이터를 쓰는 도메인 이동 설정. ResNet-18, ResNet-50, CLIP ViT-B/16, DINOv2. 공격자 대리 데이터와 피해자 파인튜닝 데이터는 표본이 겹치지 않습니다.
- 비교 대상: FAB, Hibernated Backdoor, Latent Backdoor, NeuBA. 지표는 일반 공격 성공률과, 원래 표적 클래스인 표본을 뺀 더 엄격한 Flip-ASR입니다.
- 결과: 파인튜닝 후 성공률에서 기존 방법보다 평균 64% 높았고(최고 97%), 도메인 이동 설정에서 Flip-ASR 격차는 8.55~69.52점이었습니다. 반대로 SVHN에서 MNIST처럼 표적 의미가 이어지지 않는 전이에서는 Flip-ASR이 1% 수준으로 떨어져, 저자들도 임의의 작업으로 전이된다고 주장하지 않습니다. LoRA 파인튜닝 한 번의 실험에서도 54.98%가 유지되었습니다.
- 방어: Neural Cleanse, DECREE, Fine-Pruning, MIMIC, DeDe, MARTINI는 백도어를 확실히 없애지 못했고, CLIP 전용 탐지기인 CLIP-Inspector는 공격받은 CLIP 모델을 탐지하고 복구했습니다.
- 신빙성: 다섯 시드의 95% 신뢰구간과 짝지은 부호 검정을 제시했고, 실패 사례와 경계 조건도 함께 보고해 결과가 과장되지 않았습니다. 공격자가 하위 작업의 종류와 표적 의미를 미리 알아야 한다는 가정은 강한 편입니다.

#### Comment
- 허깅페이스 같은 모델 허브에서 "ImageNet 사전학습"으로 보이는 인코더를 받아 의료 영상이나 원격 탐사 분류기로 파인튜닝하는 흐름이 그대로 공격 경로가 됩니다. 배포본을 검사해도 백도어가 보이지 않으므로, 출처를 확인할 수 있는 체크포인트만 쓰고 파인튜닝 이후 모델을 다시 검사해야 한다는 것이 실무적인 결론입니다.
- 숨김 단계가 표적 로짓만 누르는 방식이라, 파인튜닝 후 모델에 트리거 역추적 계열 탐지를 다시 돌리면 잡히는지는 별도로 확인할 필요가 있습니다.
- NeurIPS는 머신러닝 분야 최상위 학회입니다. 코드와 재현 절차가 공개되어 있습니다.

# Hijacking a Trusted LLM in Real-World Quantized Deployments Only Requires a Disguised Adapter
> arXiv 프리프린트 (심사 전), IEEE Transactions on Information Forensics and Security 투고. 시드니 공과대학교, 마카오 시티 대학교
> 2026

외부에서 받은 LoRA 어댑터를 전체 정밀도 기반 모델에 붙여 감사하면 정상으로 보이지만, 배포를 위해 같은 기반 모델을 4비트로 양자화하는 순간 특정 결정을 공격자 뜻대로 바꾸는 공격(QHijack-LoRA)입니다. 공격자는 어댑터만 만들 수 있고, 신뢰된 기반 모델이나 양자화 도구는 건드리지 못하며, 피해자가 어떤 양자화 설정을 쓸지도 모릅니다. 저자들은 양자화가 기반 가중치에 자연스럽게 남기는 오차(Q(W) - W)에 어댑터가 반응하도록, 전체 정밀도에서의 표적 입력, 전체 정밀도에서의 정상 입력, 양자화 상태의 표적 입력, 양자화 상태의 정상 입력을 각각 다루는 네 가지 목표로 학습시켰습니다. 여러 양자화 방식으로 동시에 학습하면서 방식별 가중치를 조정하고 오차 방향을 늘려, 학습 때 보지 못한 설정에도 전이되게 했습니다. 트리거 문자열은 필요 없고, "양자화 상태"와 "공격자가 고른 의미 범주"가 함께 갖춰질 때만 발동합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14978
- arXiv HTML 본문: https://arxiv.org/html/2611.14978
- arXiv PDF: https://arxiv.org/pdf/2611.14978

### Contribution
- 어댑터만으로, 기반 모델 수정이나 양자화 설정 지식 없이 양자화 배포 환경에서 결정을 가로챌 수 있음을 처음 보였습니다. 기존 양자화 조건부 백도어는 공격자가 전체 가중치를 배포하거나 양자화 방식을 안다는 가정이 필요했습니다.
- 콘텐츠 안전 판정(안전하지 않음을 안전함으로), 금융 감성 분류(부정을 중립으로), 함수 호출(정해진 함수를 다른 함수로)의 세 사례로 위협을 구체화했습니다. 바뀐 출력도 모두 작업의 출력 형식을 지키므로 하위 실행기가 형식으로는 알아챌 수 없습니다.
- 같은 어댑터를 배포할 양자화 설정에서 전체 정밀도 결과와 짝지어 비교하는 교차 정밀도 감사와 완화 방법 세 가지를 제시했습니다.

### Evaluation
- 대상: Llama-3.1-8B와 NeMoGuard 어댑터(Aegis 2.0), Mistral-7B와 공개 금융 감성 어댑터(FinGPT), Qwen3-4B와 xLAM 함수 호출 어댑터. 학습에 쓴 4비트 방식은 NF4, FP4, RTN, AWQ, GPTQ이고, 설정을 바꾼 미학습 조합 9개와 별도 도구(bitsandbytes LLM.int8(), GGUF Q4_K_M, HQQ, AutoRound)로 전이를 확인했습니다.
- 결과: 전체 정밀도 공격 성공률은 공개 정상 어댑터와 최대 1.33점 차이였고 정상 작업 F1은 유지되거나 올랐습니다. 양자화 후 성공률은 안전 판정 47.67~94.00%, 금융 94.33~100%, 함수 호출 88.00~97.60%였습니다. 학습하지 않은 4비트 도구에서도 40.33~77.80%였지만, 8비트 LLM.int8()에서는 12~16% 수준으로 낮았습니다. RTN과 GPTQ는 설정이 바뀌면 성공률이 크게 떨어졌습니다(예: 함수 호출 GPTQ 96.80%에서 32.80%).
- 비교 대상: 조건 없는 일반 LoRA 백도어는 전체 정밀도에서 이미 페이로드가 드러났고, NF4 하나로만 학습한 변형은 다른 방식에서 42.67% 이하, 기존 양자화 조건부 백도어를 어댑터용으로 옮긴 방식은 기반 모델만 양자화하는 경로에서 33.67% 이하였습니다.
- 방어: 교차 정밀도 감사는 15개 조합 중 14개에서 100%, 나머지 하나에서 99%를 탐지했고 정상 어댑터 오탐은 AWQ 두 조합(4%, 1%)을 빼고 0이었습니다. 어댑터 크기 줄이기와 크기 기반 가지치기는 효과가 제한적이었고, 신뢰 표본 최대 256개로 양자화 상태에서 다시 파인튜닝하면 성공률이 0~5.93%로 떨어졌습니다.
- 신빙성: 공개 정상 어댑터를 기준선으로 같은 데이터에서 비교했고, 불리한 결과(8비트에서의 낮은 성공률, 설정 변화에 따른 하락, RTN에서의 정상 성능 저하)도 그대로 보고했습니다. 다만 각 설정의 시드 반복이나 신뢰구간은 보이지 않고, 비교 대상 두 종은 저자들이 어댑터 조건에 맞춰 옮긴 재구현입니다. 코드는 공개되지 않았습니다.

#### Comment
- 휴대폰이나 노트북에서 돌리는 온디바이스 LLM은 거의 항상 4비트로 양자화하고, 기능별 LoRA 어댑터를 붙여 쓰는 경우가 많습니다. "원본 정밀도로 검증한 어댑터"를 그대로 양자화 모델에 붙이는 배포 절차라면 이 공격에 그대로 노출됩니다. 실제로 배포할 정밀도와 도구에서 감사를 다시 해야 한다는 결론은 바로 적용할 수 있습니다.
- 중국 기관 검증: 교신저자 Tianqing Zhu와 Wanlei Zhou는 마카오 시티 대학교 데이터과학부 소속으로 표기되어 있고, 공동 저자 세 명은 시드니 공과대학교 소속입니다. 두 교수는 프라이버시와 머신 언러닝 분야에서 USENIX Security 2025 논문 등 실적이 확인되는 연구자이고, 게재처는 아직 정해지지 않은 투고 단계입니다. 코드가 공개되지 않아 재현성은 확인할 수 없지만, 평가 대상이 모두 공개 모델과 공개 어댑터이고, 결과 수치가 지나치게 좋지 않으며 불리한 결과도 보고되어 있어 싣기로 했습니다. 같은 연구진의 언러닝 논문(2611.15013)은 코드가 없고, 피평가 모델과 같은 계열의 Qwen 모델을 판정자로 써서 이번에는 제외했습니다.

# Bait: Mitigating Harmful Agentic Reinforcement Learning via Probing Reward Function

사용자가 직접 환경과 보상 함수를 올려 모델을 강화학습으로 맞춤 학습시키는 "에이전트 강화학습 서비스"에서, 해로운 응답에 높은 보상을 주는 보상 함수 하나로 모델의 안전 정렬을 무너뜨릴 수 있음을 보이고 그 방어책을 제안한 논문입니다. 저자들은 상용 서비스 Tinker API에서 해로운 지시 데이터(BeaverTails)와 해로운 보상 모델을 연결해 GPT-OSS-20B를 학습시켰고, 학습 뒤 모델이 컨테이너 탈출용 ROP 체인 작성 방법을 단계별로 안내하는 사례를 보였습니다. 방어책 Bait는 서비스 제공자가 정책 모델 응답에 명백히 해로운 미끼 응답을 섞어 사용자 보상 함수에 평가를 맡기고, 미끼 응답의 평균 보상이 더 높게 나오면(보상 발산의 부호가 양수이면) 해로운 보상 함수로 판정해 그 그룹의 보상을 뒤집어 벌점으로 씁니다.

# Look It Up: Multi-bit LLM Watermarking via Codebook Search

리뷰나 SNS 게시글처럼 200토큰이 안 되는 짧은 LLM 생성 텍스트에도 사용자나 세션 식별자를 담을 수 있는 다중 비트 워터마크를 제안한 논문입니다. n비트 식별자를 그보다 긴 u비트 코드워드(예: 127비트)로 대응시키는 비밀 코드북을 미리 만들어 두고, 생성할 때 토큰 로짓에 편향을 주어 코드워드를 한 비트씩 심습니다. 추출할 때는 텍스트에서 읽어 낸 비트열과 가장 가까운 코드워드를 해밍 거리나 레벤슈타인 거리로 찾습니다. 기존 열거 방식이 후보마다 비싼 복호화를 하느라 32비트 추출에 몇 시간씩 걸렸던 것을, 거리 계산만 하는 최근접 탐색으로 바꾼 것이 핵심입니다. 코드북 저장이 필요 없는 BCH 부호 변형도 함께 제시했습니다.

### Evaluation
- 초록에 따르면 Qwen 2.5-3B에서 두 차례 재학습 후 텍스트 감사의 AUC가 0.978에서 0.560으로 떨어졌고, 감사 표식은 여전히 정확도를 40~49점 낮췄습니다. 재학습한 시드 8개 중 7개에서 공격이 성공했고, Llama 실행 하나를 포함해 감사는 모든 재학습을 놓쳤습니다(AUC 0.451~0.576).
- 활성화 프로브는 정상 파인튜닝 예시의 99%를 표시했고, 맞춘 프로브는 보지 않은 학습 실행 5개 중 1개에만 전이되었다고 합니다. 추가로 시험한 트리거 공격 8종은 자기 프롬프트에서는 작동하지만 탐지기 프롬프트에서는 작동하지 않았다고 합니다.
- 본문을 읽지 못해 데이터셋, 비교 조건, 지표의 신빙성은 확인하지 못했다.
