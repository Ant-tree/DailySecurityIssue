# Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness
> arXiv cs.LG, cs.CR 교차 등록 (프리프린트, 심사 전). 임페리얼 칼리지 런던, 튀빙겐 AI 센터, ELLIS 튀빙겐, 막스 플랑크 지능시스템연구소, 프라운호퍼 HHI
> 2026

간접 프롬프트 인젝션은 웹 페이지나 도구 출력처럼 외부에서 들어온 데이터 속 지시문을 모델이 사용자 명령으로 착각해 따르는 문제입니다. 이 논문은 "명령과 데이터의 분리"를 모델 전체를 미세 조정하는 대신 어텐션 헤드마다 작은 게이트를 학습시켜 구현하는 Heads of Security(HoS)를 제안합니다. 각 헤드가 신뢰 토큰(사용자 요청)과 비신뢰 토큰(외부 데이터)에 주는 어텐션을 얼마나 재분배할지 학습하므로, 모델은 외부 데이터를 읽고 분석하되 그 안의 지시문은 따르지 않게 됩니다. 기본 모델 가중치는 그대로 두고, 학습하는 값은 Llama-3.3-70B 기준 46,080개, GPT-OSS-20B 기준 18,432개뿐입니다.

원문: https://arxiv.org/abs/2610.37657

### Contribution
- 어텐션 헤드가 복사, 복사 억제, 지시 따르기 등 서로 다른 기능을 맡는다는 해석 가능성 연구를 근거로, 헤드별로 신뢰 경계를 다르게 적용하는 구조적 방어를 설계했습니다. 신뢰 여부는 외부에서 주어진다고 보고(예: 웹 검색 결과는 비신뢰), 이를 "어텐션 라우팅 문제"로 다룬 점이 핵심입니다.
- 같은 선호 데이터(SecAlign++의 Alpaca 기반 데이터)와 같은 DPO 목적 함수로 학습해, 학습 알고리즘 차이만 비교하도록 실험을 통제했습니다. 같은 데이터에서 SecAlign은 지름길을 학습해 분포 밖 상황(few-shot, 다중 턴)에서 무너지지만 HoS는 그렇지 않다는 점을 보였습니다.
- 강화학습 기반 블랙박스 공격(RL-Hammer)과 자동 연구 루프로 HoS 전용으로 다듬은 화이트박스 공격(Claudini)으로 적응형 공격 평가를 수행했습니다. 코드, 모델, 데모를 공개했습니다.

### Evaluation
- 적응형 공격(InjecAgent 목표): 가장 강한 RL-Hammer 공격자의 성공률이 GPT-OSS-20B 원본 97%, SecAlign 85%, HoS 10%였습니다. Llama-3.3-70B에서는 원본 99%, Meta-SecAlign-70B 82%, HoS 1%입니다. 비교를 위해 상용 모델 GPT-5.6-Luna를 겨냥해 학습한 공격자는 그 모델에서 36%를 기록했습니다.
- 화이트박스 공격: HoS에 맞춰 최적화한 Claudini도 성공률 50%에 도달하는 데 GPT-OSS-20B나 SecAlign보다 약 3배의 연산량이 필요했습니다.
- 유용성: 5-shot MMLU-Pro에서 GPT-OSS-20B 원본 68%, HoS 67%, SecAlign 59%, ASIDE 52%였고, Llama 기반에서는 원본 56%, HoS 55%, SecAlign 16%였습니다.
- 에이전트 벤치마크(AgentDojo, AgentDyn, LLMail-Inject, WASP): HoS와 SecAlign이 비슷한 수준으로 공격 성공률을 낮췄고, GPT-OSS-20B에서 HoS는 AgentDojo와 WASP에서 SecAlign보다 보안과 유용성 모두 우세했습니다. ASIDE는 도구 호출 능력을 잃어 AgentDojo 유용성 10%에 그쳤습니다.
- 지표 신빙성: 정적 공격뿐 아니라 방어를 알고 적응하는 공격까지 평가한 점, 공격 성공률과 유용성을 함께 보고한 점은 이 분야 기준으로 탄탄합니다. 다만 HoS를 겨냥해 학습한 RL 공격자는 학습 중 성공률이 3.2%에 그쳐 보상 신호가 희박했고, 저자들도 SecAlign용 공격자가 HoS에 더 강했다고 밝혀 적응형 공격이 충분히 강했는지는 열려 있습니다. ASIDE는 GPT-OSS에 저자들이 직접 이식한 구현이라 성능 열세 일부는 이식 문제일 수 있습니다.

#### Comment
- 신뢰 경계를 누가 정하는가는 다루지 않습니다. 사용자 승인 없이 외부 콘텐츠의 지시를 따라야 하는 작업(패키지 설치 안내 등)에는 적용할 수 없다는 점을 저자들도 명시합니다. 명령 계층이나 맥락 무결성 같은 다른 방어와 함께 쓰는 하나의 구성 요소로 보는 것이 맞습니다.
- 소프트맥스 기반 일반 어텐션을 전제로 하므로 선형 어텐션 구조에는 바로 적용되지 않습니다.
- 오픈 웨이트 모델을 운영하는 쪽에서는 수만 개 수준의 파라미터만 추가로 배포하면 된다는 점이 실용적입니다. 프롬프트 인젝션 방어 연구를 꾸준히 낸 연구 그룹들의 공동 작업이지만 아직 심사 전 원고입니다.

# Log-To-Leak: Prompt Injection Attacks on Tool-Using LLM Agents via the Model Context Protocol
> 1st Workshop on Security, Privacy, and Safety of Agentic AI Systems (AGENT-SEC '26, 2026년 11월 헤이그, ACM 프로시딩, DOI 10.1145/3847320.3847399), arXiv cs.CR 공개본. 듀크대학교, 미시간 주립대학교, TikTok(미국 산호세)
> 2026

MCP 서버는 도구 이름과 설명 같은 자연어 메타데이터를 에이전트에게 전달하는데, 공격자가 만든 MCP 서버는 이 메타데이터에 지시문을 숨길 수 있습니다(도구 오염). 이 논문은 그중에서도 에이전트가 정상 작업을 모두 마친 뒤 공격자의 로깅 도구를 한 번 더 호출하게 만들어 사용자 질의, MCP 서버 이름, 서버 응답, 에이전트 응답을 빼돌리는 "사후 로깅" 공격 Log-To-Leak을 다룹니다. 사용자가 받는 결과는 정상과 거의 같기 때문에 작업이 성공했다는 사실이 안전의 증거가 되지 못한다는 점을 강조합니다.

원문: https://arxiv.org/abs/2610.36108

### Contribution
- 지시문을 언제 실행할지 정하는 Trigger, 로깅 도구를 지정하는 Tool Binding, 그럴듯한 명분을 주는 Justification, 필수 절차처럼 압박하는 Pressure의 네 요소로 주입 문구를 구조화하고, 요소별 기여를 절제 실험으로 분리했습니다.
- 공격 성공 여부(로깅 호출 발생)와 유출 내용의 정확도(Logging Accuracy), 원래 작업 완료율 변화, 공격자 서버의 정상 호출 유지 여부, 토큰 사용량을 따로 측정하는 다섯 가지 지표 체계를 제시했습니다.
- 실험 도구, 작업 목록, 공격용 MCP 서버 871개 설정을 익명 저장소로 공개했습니다.

### Evaluation
- 대상: MCP 서버 다섯 종(GitHub, Mapbox, PayPal, YFinance, Playwright)과 에이전트 모델 네 종(GPT-4o, GPT-5, Claude-Sonnet-4, GPT-OSS-120B), 작업 555개. GitHub, Mapbox, PayPal용 작업 480개는 GPT-4o로 생성했고 나머지 75개는 MCP-Universe에서 가져왔습니다.
- 결과: 정상적으로 도구가 실행된 18개 모델-서버 조합에서 공격 성공률 62.64~100%, 로깅 정확도 76.55~95.64%였습니다. 18개 중 16개 조합은 원래 작업 완료율 변화가 6.63%포인트 이내였습니다.
- 비교 기준: "작업 후 로깅 도구를 호출하라"는 단순 지시만 넣은 경우에도 GPT-5는 87.30~98.05%, Claude-Sonnet-4는 거의 100%가 이미 따랐습니다. 구조화된 템플릿의 효과가 크게 드러난 것은 GPT-4o(GitHub에서 38.40%에서 62.64%로 상승) 정도입니다.
- 방어: GitHub MCP와 GPT-4o 조합에서 프롬프트 샌드위칭 59.58%, GPT-4o 메타데이터 검사 55.38%, IPIGuard 60.47%로 공격 성공률이 거의 줄지 않았습니다. DataSentinel은 주입된 메타데이터 100개를 모두 안전하다고 판정했고, 은닉 상태 기반 지시문 탐지기는 주입 설명의 91%를 잡았지만 정상 설명도 85.53%를 오탐했습니다.
- 실제 클라이언트: Cursor(GPT-5.1)와 Claude Desktop(Claude-Sonnet-4.5)에서 각각 한 번씩 동작을 재현했습니다.
- 지표 신빙성: 응답 필드의 유출 여부를 TF-IDF 코사인 유사도 0.75 기준으로 판정하므로 의미 단위의 유출을 정확히 재지는 못합니다. 절제 실험은 설정당 문구 세 개뿐이고, 방어 평가는 GitHub와 GPT-4o 한 조합에서만 했습니다.

#### Comment
- 가장 눈여겨볼 결과는 공격 기법 자체보다 "단순한 지시만으로도 최신 모델이 공격자 도구를 거의 그대로 호출한다"는 기준선입니다. 결국 문제는 문구를 얼마나 잘 쓰느냐보다, 사용자가 승인하지 않은 부가 도구 호출을 호스트가 통제하지 않는다는 구조에 있습니다. 저자들의 결론도 부가 호출에 대한 호스트 측 승인 정책입니다.
- 공격자가 만든 MCP 서버를 사용자가 직접 설치했다는 전제가 필요하므로, 설치 검토나 도구 허용 목록, 호출별 확인으로 공격 면이 크게 줄어듭니다.
- 게재처는 ACM CCS 2026과 같은 시기, 같은 장소에서 열리는 첫 회 워크숍입니다. 본 학회보다 심사 기준이 가벼울 수 있다는 점을 감안해야 합니다.
- 중국 기관 검증: 공저자 두 명이 TikTok(ByteDance 계열) 미국 법인 소속이고, 제1저자들의 연구는 TikTok 인턴십 중 수행됐습니다. 교신 이메일 도메인(bytedance.com, tiktok.com, duke.edu, msu.edu)이 소속과 일치하고, ACM DOI가 부여된 워크숍 논문이며, 실험 자원이 익명 저장소로 공개돼 재현 경로가 있습니다. 비교 기준선을 숨기지 않고 함께 보고해 수치가 과장됐다고 보기 어렵습니다. 확인 가능한 범위에서 기준을 충족한다고 판단해 포함했습니다.

# Penny for Your Prompts: A Measurement Study of Contextual Leakage in AI Chat Platforms
> IEEE Symposium on Security and Privacy (S&P) 2027 채택(2027년 5월 발표 예정), arXiv cs.CR 공개본. 스토니브룩 대학교
> 2026

AI 챗봇 웹 서비스도 일반 웹사이트처럼 광고 픽셀, 분석 도구, 세션 재생 스크립트를 품고 있습니다. 이 논문은 범용 챗봇 25개와 건강, 법률, 교육 분야 챗봇 17개 등 42개 서비스를 대상으로, 이런 서드파티 스크립트가 대화 내용을 외부로 가져가는지 대규모로 측정했습니다. 21개 서비스가 대화 제목을, 9개가 사용자 프롬프트 원문을 서드파티 추적기로 보냈고, 범용 챗봇 중 대화 맥락을 유출한 13개 가운데 11개는 사용자 이메일까지 함께 보내 대화 내용을 실명 계정과 연결할 수 있었습니다.

원문: https://arxiv.org/abs/2610.37467

### Contribution
- Puppeteer로 여러 차례 상호작용하는 세션을 캡처하는 것에 더해, JavaScript 엔진 수준 계측 브라우저인 VisibleV8로 유출 하나하나가 어떤 사용자 행동(프롬프트 입력, 화면 이동, 버튼 클릭, 대화 삭제 등)에서 시작됐는지, 스크립트가 어떤 DOM 접근으로 내용을 읽었는지까지 추적했습니다. 네트워크 트래픽만 보는 기존 연구로는 알 수 없는 수준입니다.
- 유출의 원인을 구조적으로 설명했습니다. 챗봇은 대화마다 별도 하위 페이지를 만들고 첫 프롬프트를 요약한 제목을 페이지 제목으로 붙이는데, 추적 스크립트는 평소처럼 document.title을 읽었을 뿐인데 결과적으로 대화 요지를 수집하게 됩니다. Meta Pixel은 title 요소를 직접 조회하고, Microsoft Clarity는 세션 재생을 위해 DOM 전체 텍스트를 읽어 제목이 생기기 전의 원문 프롬프트까지 가져갔으며, You.com은 프롬프트를 URL에 넣어 Google Ads가 URL만으로 내용을 받았습니다.
- 건강, 법률, 교육처럼 민감한 분야 전용 챗봇을 처음으로 체계적으로 포함했습니다.

### Evaluation
- 측정 기간은 2026년 5월 6일부터 20일까지이며, 미국 동부 한 지점에서 추적 동의를 수락한 상태로 측정했습니다. 연구 전용 계정 두 개만 사용했습니다.
- 범용 챗봇 기준 프롬프트 한 번에 평균 540건의 외부 요청이 발생했고 그중 22%(118건)가 알려진 추적기 도메인으로 향했습니다. 전체적으로 서로 다른 추적기 도메인 153개를 확인했습니다.
- 대화 내용을 담은 요청은 Google이 8개 서비스에서 230건으로 가장 많았고 Meta가 약 55건으로 뒤를 이었습니다.
- 책임 있는 공개: 측정 기간 중 ChatGPT와 Grok에서도 대화 맥락을 수집하는 추적기가 동작했으나 제출 전에 제거된 것을 확인했고, 나머지 서비스에는 통보했습니다. TheLawGPT는 설정을 고쳤습니다.
- 지표 신빙성: 실제 트래픽과 엔진 수준 실행 기록을 모두 근거로 삼아 결과의 신뢰도가 높습니다. 다만 설정마다 세션이 하나씩이어서, Gmail 계정일 때 유출이 더 잦아 보이는 차이 같은 세부 결과는 저자들도 추가 측정이 필요하다고 밝혔습니다.

#### Comment
