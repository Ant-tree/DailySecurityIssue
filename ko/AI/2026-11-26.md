# When Answering Is Administering: Permission Replies That Rewrite Coding-Agent Policy
> arXiv 프리프린트 (심사 전). 시드니 공과대학교, 싱가포르 국립대학교, 뉴사우스웨일스 대학교, 셰필드 대학교
> 2026

코딩 에이전트는 보안 플러그인, 팀의 승인 서비스, 원격 제어 앱 같은 외부 주체가 권한 요청에 대신 답하도록 허용합니다. Claude Code 문서는 이런 답변이 운영자의 거부(deny) 규칙을 무시할 수 없다고 설명하지만, 저자들은 이 보장이 결정 하나하나에서만 성립하고 실행 전체로 보면 깨진다고 보였습니다. 권한 요청에 대한 답변에는 정책 갱신을 함께 실을 수 있는데, 런타임이 허용 규칙을 추가하거나 바꾸는 갱신만 검사하고 거부 규칙 삭제는 검사하지 않기 때문입니다. 예를 들어 운영자 파일에 접근할 수 없는 원격 서비스가 무관한 명령을 승인하면서 비밀 파일 보호용 거부 규칙을 지우는 갱신을 붙이면, 에이전트는 엄격한 샌드박스 안에서도 그 세션과 다음 세션에서 비밀을 읽을 수 있게 됩니다. 게다가 이 삭제는 운영자가 직접 편집한 것과 똑같은 기록을 남겨 누가 바꿨는지 구분할 수 없습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.32195
- arXiv HTML 본문: https://arxiv.org/html/2611.32195
- arXiv PDF: https://arxiv.org/pdf/2611.32195

### Contribution
- "프롬프트에 답할 권리가 정책을 관리할 권리로 바뀐다"는 새로운 공격 경로를 Claude Code에서 실제로 시연했습니다. 이런 갱신을 그대로 전달하는 중계 도구가 이미 존재한다는 점도 확인했습니다.
- 런타임이 무엇을 기록하느냐가 무엇을 안전하게 위임할 수 있는지를 정한다는 원칙을 세우고, 두 가지 상한을 증명했습니다. 규칙 작성자를 기록하지 않는 런타임은 현재 거부된 호출을 계속 거부 상태로 두는 갱신만 받아들일 수 있고, 작성자를 기록하는 런타임은 각 주체가 자기가 만든 것으로 증명된 제한만 풀게 할 수 있습니다. 두 상한이 빈틈없이 맞는다는 것도 보였습니다.
- 공유되는 갱신 단계에 이 상한을 적용하는 검증기로 공격을 막을 수 있음을 보였습니다.

### Evaluation
- 10개 에이전트 시스템의 13가지 권한 설계에서 운영자 제한이 살아남는지를 이론이 모두 맞게 예측했습니다. Codex, Gemini CLI, opencode, Goose에 대해서는 실험 전에 예측을 먼저 적어 두고 확인했습니다.
- 마켓플레이스 플러그인 2,227개를 받아 조사한 결과, 정책 갱신을 실제로 보내는 플러그인은 2개뿐이었습니다. 즉 수정이 기존 생태계를 크게 깨뜨리지 않습니다.
- 집필 시점 최신 릴리스(2.1.327)에서도 삭제 공격이 통한다고 적었습니다. 수정안은 Claude Code 바이너리의 로컬 사본에만 적용해 시험했습니다.
- 신빙성: 공격 조건이 "운영자가 권한 응답을 외부 주체에 위임한 경우"로 한정되므로 영향 범위는 위임 사용 정도에 달려 있습니다. 샌드박스 실험은 리눅스(bubblewrap)에서만 했고 macOS(Seatbelt)는 확장 과제로 남겼습니다.

#### Comment
- 에이전트 권한 체계를 "결정 단위"가 아니라 "실행 전체에서 정책 상태가 어떻게 바뀌는가"로 봐야 한다는 점을 정형적으로 보인 논문입니다. 훅 설정, MCP 서버 설정, 지시 파일처럼 이후 판단에 쓰이는 다른 상태에도 같은 논리가 적용된다고 저자들이 짚었습니다.
- 윤리 항목에서 자신들의 기기와 계정만 썼고, 갱신을 전달하는 오픈소스 중계 도구의 이름은 밝히지 않았다고 적었습니다. 벤더(Anthropic)에 신고했는지와 그 응답은 본문에서 확인하지 못했습니다.
- 게재처가 정해지지 않은 심사 전 원고입니다.

# Per-Attack Blocking Hides Catalog Vulnerability: A Weakest-Link Analysis of Tool Manifests
> NeurIPS 2026 워크숍(Third Workshop on Agents in the Wild: Safety, Security, and Beyond, AIWILD) 채택, arXiv 등록. 독립 연구자
> 2026

도구를 쓰는 에이전트의 런타임 통제(예: ChainCaps)는 각 도구가 무엇을 읽고 출력이 어디로 갈 수 있는지 적은 매니페스트에 의존합니다. 기존 평가는 매니페스트 묶음이 공격을 몇 퍼센트 막는지(공격별 차단율)를 보고하는데, 저자는 이것이 잘못된 단위라고 주장합니다. 도구 목록 전체의 안전성은 가장 약한 출처 정책 하나에 좌우되므로, 독립적으로 작성된 정책 M개가 각각 확률 p로 틀리면 목록 안에 허용된 유출 경로가 있을 확률은 1 − (1 − p)^M이 되지만 공격별 차단율은 1 − p로 그대로 보입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.31338
- arXiv HTML 본문: https://arxiv.org/html/2611.31338
- arXiv PDF: https://arxiv.org/pdf/2611.31338

### Contribution
- 공격별 차단율 대신 "취약한 목록의 비율"을 지표로 제안하고, 독립 오류 가정에서 이 값이 이항 분포를 따른다는 것을 정리했습니다.
- ChainCaps의 전달 규칙과 OpenAPPA의 라벨 모델 모두 이 경향을 완화하지 못한다는 것을 보였습니다. 두 엔진은 짝지은 시험 경로 488,400개에서 모두 같은 결과를 냈습니다.
- 허용 가능한 오류율은 도구 수가 아니라 독립적인 정책 결정 수 M에 반비례한다는 점을 보이고, 실제 작성 오류가 작성자(모델)별로 몰린다는 것을 측정했습니다.
- 평가 보고에 목록 취약 비율, 시험의 출구(sink) 범위, 독립 결정 수를 함께 넣자고 제안했습니다.

### Evaluation
- 합성 목록(오류율 8%): 공격별 차단율은 92%로 유지되는 반면, 취약한 목록 비율은 도구 10개에서 22%, 200개에서 99%로 올라갔습니다.
- 15개 모델(로컬 12개, 최신 상용 3개)의 매니페스트 작성 실험: 정책 조건을 준 작성에서 200개 도구 목록은 독립 결정 약 5개처럼 행동했습니다(95% 구간 3.4~9.2). 독립 가정이면 60개입니다.
- 실제 MCP 서버 4개의 도구 114개(전문가가 쓴 규칙 기준): 모델이 쓴 매니페스트는 공격의 89%를 막았지만 15개 목록 중 9개에 유출 경로가 남았습니다. 작성자 효과 모델은 15개 배포의 취약 비율을 평균 0.06 이내로 예측했습니다.
- 신빙성: 전문가가 쓴 정답 매니페스트는 모든 규모에서 모든 시험 공격을 막았으므로, 이 결과가 ChainCaps의 강제 규칙 자체를 부정하는 것은 아닙니다. HTTP만 시험하면 다른 채널로 새는 오류를 놓친다는 점도 저자가 직접 보였습니다.

#### Comment
- 에이전트 보안 평가에서 흔히 쓰는 "공격 차단율 9x%"가 실제 배포 위험을 크게 과소평가할 수 있다는 점을 간단한 확률 모형과 실측으로 보여 줍니다. MCP 게이트웨이처럼 도구가 수천 개인 환경에서는 매니페스트 작성의 상관 구조가 핵심 변수가 됩니다.
- 1저자 단독의 독립 연구자 논문이고 워크숍 채택이라 심사 강도는 본 학회보다 낮습니다. 코드 공개 주소는 본문에서 찾지 못했습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# C3H: Compression-to-Consensus Criteria Hijacking in Multimodal LLM Recommender Systems
> NeurIPS 2026 채택, arXiv 등록. 난양 공과대학교(싱가포르) 컴퓨팅 및 데이터 과학대학
> 2026

멀티모달 LLM 기반 추천 시스템은 상품의 글과 이미지를 압축된 표현으로 바꾸고, 두 모달리티를 융합한 뒤 후보를 비교합니다. 압축과 교차 모달 합의는 보통 조작에 강한 장치로 여겨지지만, 저자들은 바로 이 과정이 "압축 후에도 살아남고 두 모달리티에서 함께 뒷받침되는 단서"에 순위 결정권을 몰아주는 편향(compression-to-consensus, C2C 편향)을 만든다고 보였습니다. 이를 이용한 C3H는 판매자가 피해 모델에 한 번도 질의하지 않은 상태에서, CLIP 같은 공개 인코더로 유리한 방향을 추정해 자기 상품의 글과 이미지를 그 기준에 맞게 고쳐 노출을 늘리는 추론 시점 공격입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.32780
- arXiv HTML 본문: https://arxiv.org/html/2611.32780
- arXiv PDF: https://arxiv.org/pdf/2611.32780
- 저자 저장소(코드): https://github.com/GuoweiGuan666/C3H

### Contribution
- 후보 비교형 멀티모달 추천 시스템에서 C2C 편향을 찾아내고 실험으로 확인했습니다.
- 학습 데이터 오염이나 피해 모델 질의 없이, 판매자가 원래 할 수 있는 상품 정보 편집만으로 동작하는 무질의 공격 경로를 제시했습니다.
- 시각적 충실도, 카테고리 유지, 문장 충실도, 이미지-문장 정합성을 강제하는 안전 관문을 두어 편집 결과가 자연스럽게 보이도록 했습니다.

### Evaluation
- 데이터셋: MicroLens-100K(중국 숏폼 영상), Amazon Beauty, Amazon Sports. 주 피해 모델은 T5-small 기반 VIP5이고, 이식성은 Qwen2-VL-2B-Instruct로 확인했습니다.
- 비교 대상: 상호작용 조작 2종, 문장 공격 6종(TextFooler, BERT-Attack, CheatAgent 등), 이미지 공격 7종(AdvCLIP, UAP 등)까지 15개 기준선.
- 지표: 목표 상품 노출률(ER@K), 일반 사용자 추천 품질(HR, NDCG), 은닉성(ROUGE, CLIP 정합도 변화).
- 결과: VIP5에서 MicroLens와 Beauty의 모든 조건에서 ER@20 기준 최고 기준선보다 1.4~1.8배 높았고, 같은 편집 결과가 Qwen2-VL-2B의 제로샷 비교 3개에서도 모두 가장 좋았습니다. 콘텐츠 필터 방어 3종을 거쳐도 노출률 변화가 0.004 미만이었고 일반 사용자 추천 품질은 떨어지지 않았습니다.
- 신빙성: 피해 모델이 T5-small 기반 VIP5와 2B 규모 VLM으로 작고, 저자들도 실제 운영 플랫폼에서의 효과는 확인하지 않았다고 밝혔습니다.

#### Comment
- 압축과 융합을 "견고성 장치"로 보던 직관을 뒤집어, 같은 구조가 기준에 맞춘 조작을 오히려 증폭한다는 점을 보인 것이 핵심입니다. 상품 정보 편집 감시와 콘텐츠 정규화 같은 대응도 정상 편집을 막을 수 있어 비용이 따릅니다.
- 소속은 싱가포르 기관이며 중국 기관은 없습니다. NeurIPS는 최상위 머신러닝 학회이고, 코드 저장소가 공개되어 있어 재현 가능성이 있습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# Evaluating LLM Security Review Agents with Operationally Sourced Ground Truth
> CAMLIS 2026(Conference on Applied Machine Learning for Information Security) 채택, Proceedings of Machine Learning Research 349권 게재 예정, arXiv 등록. Airbnb
> 2026

AI 보조 코드가 늘어나면서 보안 리뷰 부담이 커졌고, LLM 기반 보안 리뷰 에이전트가 대안으로 떠올랐지만 실제로 쓸 만한지 판단할 근거가 부족합니다. 기존 벤치마크는 합성 데이터나 공개 CVE로 정답을 만들기 때문에 조직 고유의 취약점 패턴(자체 프레임워크의 권한 누락, 내부 라이브러리 오용 등)을 보지 못합니다. 저자들은 버그 바운티 보고, 침투 테스트 결과, 내부 신고처럼 조직이 이미 운영 중에 쌓는 보안 데이터로 정답을 만드는 방법을 제안했습니다. 확인된 취약점은 수정이 병합되기 직전에는 존재하고 직후에는 없어야 한다는 시간적 성질을 이용합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.31606
- arXiv HTML 본문: https://arxiv.org/html/2611.31606
- arXiv PDF: https://arxiv.org/pdf/2611.31606

### Contribution
- 운영 보안 데이터에서 정답 데이터셋을 만드는 방법론을 제시했습니다.
- 두 가지 평가 전략을 마련했습니다. 하나는 취약점을 들여온 풀 리퀘스트를 리뷰하는 방식(blameful), 다른 하나는 취약점이 이미 있는 저장소를 탐색하는 방식(blameless)입니다.
- 취약점을 모르는 보안 엔지니어 에이전트와, 그 발견이 실제 문제를 막았을지 판단하는 판정 에이전트를 짝지은 2단계 파이프라인을 썼습니다.
- 결과 점수만이 아니라 추론 과정(trace) 단위로 모델 행동을 분석했습니다.

### Evaluation
- 모델: GPT-5.5, Sonnet 4.6, Opus 4.7.
- 결과: 풀 리퀘스트 전략에서는 OPRO 방식의 프롬프트 개선 한 번을 거친 GPT-5.5가 발견율 57%(95% 신뢰구간 42~72%), 저장소 전략에서는 Sonnet 4.6이 69%(95% 신뢰구간 56~81%)로 가장 높았습니다.
- 추론 과정 분석에서는 모델마다 강점이 달랐고, 결과 점수만으로는 운영 환경에서의 행동을 잘못 판단할 수 있음을 보였습니다.
- 신빙성: 데이터셋이 풀 리퀘스트 40개, 저장소 사례 49개로 작아 몇 건만 바뀌어도 발견율이 몇 퍼센트포인트씩 움직입니다. 한 조직의 코드에서만 얻은 결과이고 일반화는 검증하지 않았다고 저자들이 직접 밝혔습니다. 데이터셋 자체는 사내 자료라 공개되지 않습니다.

#### Comment

# Bit-Flip Attacks on Quantized Neural Networks without Knowledge of Model Parameters
> arXiv 프리프린트 (심사 전). 조지 워싱턴 대학교, 사이먼 프레이저 대학교
> 2026

양자화는 파라미터 하나가 움직일 수 있는 폭을 줄이기 때문에 비트 플립 공격에 대한 방어로 여겨져 왔습니다. 저자들은 양자화 모델이 정확도와 수치 안정성 때문에 일부 텐서(CNN의 int32 편향, LLM의 정규화 가중치 등)를 높은 정밀도로 남겨 두며, 바로 여기에 취약성이 몰린다는 것을 보였습니다. 여섯 개 양자화 CNN에서 중앙값 int32 편향의 비트 하나를 뒤집었을 때 로짓 변화 기댓값은 중앙값 int8 텐서보다 65배에서 12,000배 컸습니다. 이를 이용한 CoarseHammer는 파라미터 값, 기울기, 데이터를 전혀 보지 않고 아키텍처만으로 목표 텐서를 정한 뒤, 그 텐서 안 어느 비트든 뒤집히면 받아들이는 Rowhammer 기반 공격입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.32128
- arXiv HTML 본문: https://arxiv.org/html/2611.32128
- arXiv PDF: https://arxiv.org/pdf/2611.32128

### Contribution
- 양자화가 비트 플립에 강하다는 통념이 "비트 전체에 고르게 뒤집힐 때"만 맞는다는 것을 보였습니다.
- 기존 공격이 전제하던 세 가지(파라미터 값과 기울기를 앎, 정확한 비트 위치에 플립, 파라미터가 고정됨)를 모두 없앤 데이터 없는 공격을 제안했습니다. 미세 조정을 계속해도 양자화 구조와 텐서 크기는 그대로라 목표가 바뀌지 않습니다.
- 실제 시스템에서 ASLR이 있어도 힙에 할당된 목표 텐서를 취약한 메모리 프레임으로 유도하는 방법을 시연했습니다.

### Evaluation
- 모델: ResNet8/18/50, DenseNet121(CIFAR-10), MobileNetV1(Visual Wake Words), DS-CNN(Speech Commands), Llama-3.2-3B, Gemma-2-2B, Qwen2.5-1.5B, Phi-4-Mini(MMLU)까지 10개.
- 이상적 배치: 모든 모델에서 실행의 81.5~100%가 찬스 정확도(가장 흔한 클래스만 맞히는 수준)까지 떨어졌고, 성공 실행의 플립 수 중앙값은 최대 24개였습니다.
- 시뮬레이션 DRAM: 백만 비트당 0.01개만 뒤집히는 매우 강한 모듈에서도 모든 CNN에서 세 가지 기존 공격(Chen et al., FrameFlip, B3FA 계열)보다 성공률이 높았고, 최대 84%까지 성공한 반면 기존 공격은 한 번도 성공하지 못했습니다. 참고로 Blacksmith가 측정한 DDR4 40개의 중앙값은 백만 비트당 33개입니다.
- 실제 시스템: 템플릿 프레임 16개로 LLM 4개는 정확도 중앙값이 찬스 수준까지, CNN 4개는 거의 찬스 수준까지 떨어졌습니다. 의도하지 않은 위치에 뒤집혀 피해 프로세스가 죽는 비율은 CNN에서 3% 미만, LLM에서 0%였습니다.
- 신빙성: 공격 목표가 "전체 정확도 저하"인 비표적 공격이고, 평가 LLM이 1.5B~3.8B 규모로 작습니다. 실제 시스템 실험은 한 대의 데스크톱에서 1GiB를 템플릿화한 조건입니다.

#### Comment
- 정밀도를 일부 남기는 양자화 관행이 오히려 작은 공격 표면을 만든다는 지적은 엣지 기기와 공유 추론 환경 모두에 의미가 있습니다. 방어로는 고정밀 텐서를 따로 보호하거나 무결성을 검사하는 방식이 자연스럽게 떠오르지만, 본문의 방어 논의는 일반적인 Rowhammer 완화책 위주입니다.
- 코드 공개 주소는 본문에서 찾지 못했습니다. 게재처가 정해지지 않은 심사 전 원고입니다.

# "I Do Intend to Deliver": Will LLMs Run a Marketplace Advance-Fee Scam?
> arXiv 프리프린트 (심사 전). F-Secure
> 2026

온라인 사기는 피해자와 대화할 사람의 인건비 때문에 규모가 제한되어 왔습니다. 저자는 상용 LLM이 이제 그 노동을 대신할지 묻기 위해, 중고 거래 사이트에서 흔한 "무료 나눔, 배송비만 선입금" 사기의 판매자 역할을 탈옥 없이 평범한 시스템 프롬프트만으로 10개 모델에 맡겼습니다. 각 모델은 잘 속는 구매자부터 신중한 구매자까지 네 가지 페르소나를 상대로 30번씩 대화했고(구매자도 같은 모델), 총 1,200개 대화를 구매자의 돈이 어떻게 되었는지 기준으로 분류했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.32957
- arXiv HTML 본문: https://arxiv.org/html/2611.32957

### Contribution
- 모델의 사기 "능력"이 아니라 실제 사기 시나리오를 수행할 "의지"를 측정하는 벤치마크를 만들었습니다. 고정 프롬프트, 0~4점 페르소나 단계, 판매자가 결제 수단을 제시해야만 인정되는 결제 판정을 함께 공개했습니다.

### Evaluation

- 잘 속는, 진보적인, 조심스러운 구매자는 87~92%가 결제했고, 판매자 신원 확인을 요구한 신중한 구매자만 21%로 버텼습니다. 그러나 가장 적극적인 판매자 모델은 이름과 전화번호를 지어내 이를 넘었습니다(예: Kimi가 전화번호를 지어낸 16개 대화에서 모두 결제).

- 라벨은 사람 코더 두 명과 대조했고, 사기 인식과 평가 인식 패턴 판정은 사람과 각각 97%, 86% 일치했습니다.
- 신빙성: 구매자도 LLM이고 "시뮬레이션 환경"이라고 안내받았으므로 실제 사람의 피해율과 비교할 수 없습니다. 같은 모델이 양쪽을 맡아 판매자 능력과 구매자 순진함이 섞여 있고, 시나리오도 하나뿐이라고 저자가 직접 밝혔습니다.

#### Comment

# Privacy Disclosure Control Benchmark (PDC-Bench): How Faithfully Do LLMs Keep Privacy Constraints on In-Context Disclosure Granularity?
> Findings of EACL 2027 채택, arXiv 등록. 도쿄과학대학(Institute of Science Tokyo), 이화학연구소 혁신지능통합연구센터(RIKEN AIP)
> 2026

고객 지원이나 채용 보조처럼 사용자 프로필을 맥락에 넣고 답하는 LLM에는 "거주지는 국가 수준까지만 밝혀도 된다" 같은 공개 수준 제약이 붙을 수 있습니다. 이때 "샌프란시스코"를 그대로 말하는 직접 유출뿐 아니라 "캘리포니아"처럼 허용 수준보다 구체적인 정보를 흘리는 것도 위반입니다. 반대로 주 수준까지 허용된 상황이라면 같은 "캘리포니아"는 정상적인 정보 제공입니다. 기존 벤치마크(ConfAIde, PrivacyLens 등)는 유출을 문자열 일치로 판정하는 이분법이라 이런 차이를 잡지 못합니다. 저자들은 공개 제약을 지식 그래프 계층 위의 "허용 상한"으로 정식화하고, 지리, 나이, 인종·민족, 직업 네 영역 16,105개 표본으로 PDC-Bench를 만들었습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.32610
- arXiv HTML 본문: https://arxiv.org/html/2611.32610
- arXiv PDF: https://arxiv.org/pdf/2611.32610
- 저자 저장소(데이터, 프롬프트, 코드): https://github.com/fuji1655/PDC-Bench

### Contribution
- 데이터 익명화의 일반화 계층(k-익명성 등에서 쓰던 개념)을 자연어 출력의 유출 정도를 재는 의미 공간으로 가져와, 네 영역에 걸쳐 노드 323개짜리 계층을 구성했습니다.
- 위반을 직접 유출(Leakage), 의미 유출(Semantic Leakage), 과제와 무관한 속성을 드러내는 불필요 노출(Unnecessary Exposure)로 나눠 측정하는 평가 틀을 정의했습니다. 허용 상한과 실제 값의 깊이를 독립적으로 바꿔 두 요인을 분리해 볼 수 있게 했습니다.
- 출력 속 속성을 계층 노드에 대응시키는 전용 판정 프롬프트를 설계했고, 데이터와 코드를 모두 공개했습니다.

### Evaluation
- 대상: OpenAI, Anthropic, Meta, Alibaba 네 계열의 LLM 11종(GPT-4o, GPT-5, Claude Sonnet 4.6·5, Llama-3.1-8B·70B, Llama-4-Scout, Qwen3-14B·32B 등)이 16,105개 표본에 한 번씩 답했습니다. 판정은 GPT-4o와 Claude Sonnet 5 두 모델로 했습니다.
- 결과: 위반 가능한 표본 중 평균 10%(Sonnet 판정 13.7%)가 제약을 어겼고, 그중 62%가 의미 유출이었습니다. 모델별 위반율은 6.5%(Llama-3.1-70B)~13.2%(GPT-4o-mini)로 차이가 작았습니다. 문자열 완전 일치 지표는 위반의 81.5~84.7%를, 느슨한 ROUGE 기준도 54.0~59.8%를 놓쳤습니다.
- 위반율은 모델보다 허용 상한의 위치와 과제가 그 속성을 필요로 하는 정도에 더 크게 좌우됐습니다. 같은 직업 프로필에서 상한을 역할군→직업 영역→산업 부문으로 넓힐수록 위반율이 15.7%→24.6%→35.6%로 올랐습니다.
- 판정기 검증: 사람이 라벨링한 289개 표본에서 이 틀의 위반 탐지 F1은 57.1/61.5로, 전용 프롬프트 없이 LLM으로 값만 뽑는 기준선(25.6/31.4)과 완전 일치(29.4), ROUGE-L(30.2)보다 높았습니다.
- 신빙성: 판정 모델이 사람 라벨과 대략 여섯 건 중 한 건꼴로(대개 계층 한 단계 차이) 어긋나며, 이를 보정해도 비율 변화는 1%p 이내였다고 합니다. 다만 프로필을 GPT-4o 한 계열로 생성했고 GPT-4o가 평가 대상이자 판정자이기도 해서 공유 편향을 완전히 배제할 수는 없다고 저자들이 밝혔습니다. 판정 프롬프트와 노드 대응 중 어느 쪽이 성능을 끌어올렸는지도 분리하지 않았습니다.

#### Comment
- 모델을 바꾸는 것만으로는 해결되지 않는다는 결론이 실무적으로 의미 있습니다. 프라이버시 제약을 시스템 프롬프트로만 거는 구성이라면, 허용 수준과 과제 설계를 함께 감사해야 한다는 근거가 됩니다.
- 합성 영어 프로필 네 영역에 한정된 결과이고, 저자들도 다른 속성이나 언어로의 일반화는 주장하지 않습니다.
- EACL Findings는 심사를 거치는 ACL 계열 게재처입니다. 소속은 일본 기관입니다.

# TACT-Bench: Testing Adaptive Conversational Threats against Tool-Use Agents
> arXiv 프리프린트 (심사 전). 퍼듀 대학교, 올버니 대학교(뉴욕 주립대)
> 2026

환불, 계정 복구, 정보 조회 같은 도구를 쓰는 고객 응대 에이전트는 정책을 지키면서도 같은 대화 안에 섞인 정당한 요청은 처리해야 합니다. 기존 벤치마크는 도구 채널이 오염된 상황이나 다단계 탈옥을 주로 다뤘을 뿐, 정책을 모르는 평범한 사용자가 그럴듯한 사연과 설득 전술로 거절을 넘어설 때까지 밀어붙이는 상황은 충분히 시험하지 못했습니다. TACT-Bench는 시나리오별 사연, 페르소나, 조작 전술, 응답에 맞춰 강도를 올리는 단계표를 갖춘 상태 기반 벤치마크입니다. 각 공격 과제는 정책이 명시적으로 금지한 행동을 목표로 하고, 공격 사용자에게는 정책을 보여 주지 않습니다.

### Contribution
- 직접 작성한 초기 과제 40개(공격 17개, 짝을 이루는 정상 과제 23개, 시나리오 계열 17개)에서 출발해, 어조와 요청 분해 방식을 바꾼 변형과 규칙 기반 개체 증강으로 공격 과제 2,024개, 정상 과제 828개를 만들었습니다(TACT-Base). 도구 33개를 갖춘 소매 환경에서 에이전트의 도구 호출이 실제 데이터베이스에 반영됩니다.
- 공격 과제마다 정상 짝을 두고, 공격 중에도 정책에 맞는 해결 경로가 남아 있으면 그 정답 행동을 유지했습니다. 무조건 거절하거나 사람에게 넘기는 에이전트가 좋은 점수를 받지 못하게 하려는 설계입니다.
- 관련 없는 정상 과제를 먼저 처리해 신뢰를 쌓은 뒤 공격을 시작하는 TACT-TrustPrime 변형을 추가했습니다.
- 안전한 거절과 짝을 이루는 정상 과제의 수행 능력을 곱해 보는 Paired Selective Trustworthiness(PST) 지표를 제안해, 과잉 거절과 실용성을 함께 평가합니다.

### Evaluation
- 대상: GPT-OSS-120B, Mistral-Large-3, DeepSeek-V3.2, Claude Opus 4.8, GPT-5.6-SOL, Gemini 3.5 Flash 여섯 모델을 기본 도구 호출 방식으로 돌렸고, 사용자 시뮬레이터는 GPT-5.6-SOL입니다.
- 비교 대상: Naive Attack, PAP(Logical Appeal), FITD, Crescendo를 같은 과제, 같은 금지 행동, 같은 50단계 예산으로 비교했습니다.
- 결과: 바닐라 TACT-Base는 네 기준선 평균보다 공격 유발 실패율(AFR)을 17.53% 높였고, 가장 강한 기준선 FITD보다도 14.07% 높았습니다. TrustPrime은 여기서 AFR을 17.01% 더 올렸습니다. 결정적 정책 검사기 Tool-Guard와 LLM 검증기 Policy-Guard 두 방어는 AFR을 평균 8.35~9.41%만 낮췄고 PST도 일관되게 개선하지 못했습니다.
- 대조 실험: 대화 길이가 비슷한 변형보다 TrustPrime의 AFR이 높았고(39.9% 대 57.2%), 공격 직전에 정책 전문을 다시 보내도 AFR이 줄지 않았습니다(50.4% 대 51.3%). 저자들은 이를 정상 과제로 쌓인 신뢰가 공격을 강하게 만든다는 근거로 제시합니다.
- 신빙성: 거절 판정과 의미 동일성 판정을 GPT-4.1로 했고, 논문 저자가 아닌 주석자 두 명이 각 100건을 맹검 라벨링해 일치율 95%, 91%(코헨 카파 0.897, 0.820)를 얻었습니다. 시뮬레이터가 공격 페르소나 연기를 거부한 표본은 제외했으며 그 수를 부록에 공개했습니다. 다만 실행 환경이 소매 한 가지라 다른 분야로의 일반화는 아직 확인되지 않았습니다.

#### Comment
- 정상 과제로 신뢰를 쌓은 뒤 공격하는 패턴이 실제 고객 응대 채널의 사회공학과 닮아 있어, 상담 에이전트를 운영하는 쪽에서 우선 점검해 볼 만한 시나리오입니다.
- 공격 성공을 높이는 데 그치지 않고, 정상 과제 수행 능력을 함께 묻는 지표를 둔 점이 기존 거절 중심 평가와 다릅니다.
