# Latent-in-the-Middle: On the Security of Cross-Model Latent Communication in Multi-Agent Systems
> arXiv 프리프린트 (심사 전). 싱가포르 국립대학교, 싱가포르 기술디자인대학교, 토론토 대학교, A*STAR
> 2026

여러 LLM이 협업하는 멀티 에이전트 시스템에서는 자연어 메시지 대신 내부 표현을 주고받는 "잠재 통신"이 효율 때문에 주목받고 있습니다. 대표적인 방식이 모델 간 KV 캐시 전달로, 학습된 매퍼가 원본 모델의 KV 캐시를 대상 모델이 쓸 수 있는 형태로 바꿔 대상 모델은 앞부분 문맥을 다시 계산하지 않고 바로 답을 생성합니다. 저자들은 이때 대상 모델이 자기가 직접 인코딩하지 않은 문맥을 소비하므로 안전 정렬과 프롬프트 인젝션 방어가 여전히 유효한지 의문을 제기하고, 원본 모델, 매퍼, 전달 메커니즘이라는 세 공격 지점을 정리한 프레임워크 CHASM을 제안했습니다. 실험 결과 잠재 전달이 안전 정렬과 인젝션 방어를 크게 약화시킨다는 것을 보였고, 대상 모델 쪽에서 전달된 캐시를 보정해 거부 동작을 되살리는 가벼운 캐시 가드도 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.34278
- arXiv HTML 본문: https://arxiv.org/html/2611.34278
- arXiv PDF: https://arxiv.org/pdf/2611.34278

### Contribution
- 잠재 전달 공격을 진입 지점별로 정리했습니다. 탈옥은 프롬프트 템플릿(J1), 모델 전환(J2), 신뢰할 수 없는 원본 모델(J3), 매퍼를 거치는 화이트박스 최적화(J4)의 네 경로로, 여기에 하위 에이전트가 읽은 외부 콘텐츠를 통한 간접 프롬프트 인젝션을 더했습니다.
- 매퍼가 공격자에게 오히려 더 강한 화이트박스 공격 경로를 열어 준다는 점을 보였습니다.
- 방어된 메인 에이전트가 외부 콘텐츠를 직접 읽지 않고 하위 에이전트의 매핑된 캐시만 받는 "위임 후 반환" 구조에서는 Meta-SecAlign 같은 인젝션 방어의 전제가 깨진다는 것을 처음 평가했습니다.
- 대상 모델 쪽의 저랭크 캐시 보정(캐시 가드)을 제안했고, 부록에서 매핑된 캐시를 통한 프롬프트 유출, 매퍼 백도어, 반복 전달에 따른 성능 저하도 다뤘습니다.

### Evaluation
- 설정: Qwen3, Llama 3, Ministral 3 세 모델 계열(정렬 해제판 포함), 매퍼 네 종류(NVIDIA의 닫힌 형태 릿지 매퍼와 MLP 변형, CacheBridge, SwaT 렌더러), 보정용 말뭉치 두 개를 조합한 24개 설정. 프롬프트 인젝션 실험의 대상은 Meta-SecAlign-8B로 고정했습니다.
- 데이터셋: HarmBench 텍스트 행동 240개, StrongREJECT 직접 요청 313개, 과잉 거부 확인용 XSTest 안전 프롬프트 250개, 성능 확인용 MMLU와 GSM8K.
- 결과: 기본적으로 인젝션의 0.4%만 따르던 대상 모델이 매퍼를 거치면 최대 44.2%를 따랐습니다. 전달만으로 같은 계열 안에서 공격 성공률이 최대 24.6%p 올랐고, 제로샷 공격은 최대 69.2%p 올랐으며, 신뢰할 수 없는 원본 모델 공격은 24개 설정 모두에서 성공했습니다. 매퍼를 거쳐 최적화한 접미사는 92.5%까지 올라 같은 대상에 대한 일반 GCG(37.5%)를 크게 넘었습니다.
- 방어: 캐시 가드는 공격자가 통제하는 원본 모델의 HarmBench 공격 성공률을 모든 계열에서 기본 추론 대비 4.5%p 이내로 되돌렸지만, 원본 모델을 미세 조정하는 비싼 적응형 공격은 여전히 성공했습니다.
- 신빙성: 비교 기준은 같은 템플릿, 디코딩 설정, 시드로 대상 모델이 직접 읽는 기본 추론이라 비교 조건이 깔끔합니다. 다만 모델 전환 공격은 중간에 토큰을 생성하지 않고 캐시를 왕복시킨 설정이라 실제 다중 턴 세션보다 효과가 과장될 수 있다고 저자들이 직접 밝혔습니다. 인젝션 실험은 방어되지 않은 Llama3.1-8B용으로 보정한 매퍼를 재사용했습니다.

#### Comment
- KV 캐시 전달은 vLLM, LMCache, 분리형 추론 등에서 이미 쓰이고 있고 매핑된 프리필을 서비스로 제공하는 사례도 나오고 있어, "누가 읽었고 누가 답하는가"가 갈라지는 구조의 보안 문제를 일찍 짚었다는 의미가 있습니다. 코딩 에이전트가 웹 페이지 읽기를 저렴한 하위 에이전트에 맡기는 시나리오가 특히 현실적입니다.
- 코드 공개 주소는 본문에서 찾지 못했습니다. 게재처가 정해지지 않은 심사 전 원고입니다.

# Poisoning Self-Evolving Security Policies in LLM Agents
> arXiv 프리프린트 (심사 전). 마이애미 대학교(오하이오)
> 2026

공격 사례에서 재사용 가능한 보안 정책을 스스로 학습하는 "자기 진화형 방어"가 LLM 에이전트 보안의 한 방향으로 등장했습니다. 저자들은 이 학습 과정 자체가 공격 표면이 된다는 것을 SED(Self-Evolving Defense)와 AgentDojo 벤치마크로 보였습니다. 공격자는 SED의 메모리나 정책을 직접 건드리지 않고, 신뢰할 수 없는 콘텐츠에 멤버십 변경 지시를 숨겨 둡니다. 에이전트가 이를 따르면 SED는 이 궤적을 정확히 유해하다고 판단하지만, 정책을 만드는 단계에서 "신뢰할 수 없는 콘텐츠가 요청한 멤버십 변경"이 아니라 "멤버십 변경 자체"를 막는 지나치게 넓은 규칙을 학습하고, 이후 정당한 초대와 멤버 추가 요청까지 거부하게 됩니다. 방어를 우회하는 공격이 아니라 방어를 과도하게 만드는 가용성 공격이라는 점이 핵심입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.33385
- arXiv HTML 본문: https://arxiv.org/html/2611.33385
- arXiv PDF: https://arxiv.org/pdf/2611.33385
- 저자 저장소(코드): https://github.com/MN-NR/PSED

### Contribution
- 프롬프트 인젝션 한 번이 성공하면 SED가 과도하게 넓은 정책을 학습해, 원래 공격은 계속 막으면서 정당한 작업을 거부한다는 것을 보였습니다.
- 공격자가 없어도 SED의 판정 모델이 정당하지만 보안상 민감한 행동을 유해하다고 잘못 판단해 스스로를 오염시키는 "자기 오염" 현상을 찾아냈습니다.
- 반대로 정책에 페이로드 심기, 메모리 범람, 정책 조직 조작, 위조 증거로 판정 모델 속이기, 유해한 결과를 여러 단계로 쪼개기 같은 무결성 공격 다섯 가지는 모두 실패했다고 보고해, 실제 약점의 범위를 좁혔습니다.
- 정당한 예시를 함께 주는 대조 정책 합성(Membrane의 아이디어 차용)과, 새 정책을 받아들이기 전에 관련 정당 작업에 시험해 보는 자동 범위 점검 게이트를 제안했습니다.

### Evaluation
- 설정: 보호 대상 에이전트는 Nemotron과 gpt-oss-120b, SED의 판정 및 정책 생성 모델은 deepseek-v4p1-flash로 고정. AgentDojo의 Slack, 은행 환경을 썼습니다.
- 결과: Nemotron 10회 반복에서 정당한 멤버십 및 초대 작업 성공이 50/50(100%)에서 오염 후 18/50(36%)로 떨어졌고, 오염된 10회 모두 정당한 요청을 하나 이상 거부했습니다(깨끗한 조건은 0/10). 무관한 작업은 100%를 유지했고 원래 인젝션은 계속 막혔습니다. 오염 한 번으로 효과가 포화되었습니다.
- 경계: DeepSeek-V4.1-Flash, GLM-5.3, Kimi-K3는 원래 인젝션을 따르지 않아(0/8) 오염 경로 자체가 시작되지 않았습니다.
- 완화: 별도 배치에서 오염 후 정당 작업 성공률이 Nemotron 52%, gpt-oss 44%였고, 대조 예시를 주면 82%와 72%, 범위 점검 게이트를 쓰면 88%와 60%로 회복했습니다. 두 방법 모두 깨끗한 상태(100%)까지는 되돌리지 못했고, 인젝션 공격 성공은 모든 조건에서 0/60이었습니다.
- 신빙성: 같은 양을 잰 두 배치의 오염 후 성공률이 36%와 52%로 차이가 나는데, 저자들은 윌슨 신뢰구간(24~50%, 38~65%)이 겹친다며 반복 단위 지표를 더 안정적인 근거로 씁니다. 정당 작업 5개, 무관 작업 4개로 작업 수가 적고, 방어 시스템도 SED 하나뿐입니다.

#### Comment
- 에이전트 방어가 "공격으로부터 배우는" 구조를 가질수록 그 학습 입력이 공격 표면이 된다는 점을 작은 규모지만 깔끔하게 보인 논문입니다. 공격 실패 사례를 함께 보고해 주장의 범위를 스스로 좁힌 점이 신뢰도를 높입니다.
- 공격이 성립하려면 보호 대상 에이전트가 원래 인젝션에 취약해야 하므로, 최신 모델일수록 위협이 약해질 수 있습니다. 판정 모델과 정책 생성 모델을 바꿨을 때의 민감도는 다루지 않았습니다.
- 게재처가 정해지지 않은 심사 전 원고입니다.

# Benchmarking Open-Ended Vulnerability Discovery in Windows Kernel Binaries
> arXiv 프리프린트 (심사 전). 일리노이 대학교 어배너-섐페인
> 2026

최신 LLM이 실제 취약점을 찾는 데 쓰이고 있지만 기존 보안 벤치마크는 대부분 오픈소스 프로젝트의 알려진 취약점에 머물러 있습니다. 저자들은 소스 코드가 없는 상용 바이너리, 그중에서도 윈도우 커널 드라이버에서 위치 힌트 없이 취약점을 찾는 능력을 재는 벤치마크 DeepBinary를 만들었습니다. 에이전트는 네트워크가 격리된 가상 머신 한 쌍에서 디스어셈블러와 커널 디버거만으로 대상 바이너리를 분석하고, 버그마다 크래시를 일으키는 개념 증명(PoC)과 근본 원인 분석을 보고합니다. 판정기는 모든 PoC를 새 가상 머신에서 다시 실행하고, LLM 질의 한 번으로 유효성, 중복 여부, 영향도(버그 바운티 금액으로 추정)를 판정합니다. 패치 비교 시스템 WinDiffer로 대상의 이후 수정 날짜를 확인해 모델이 학습 중에 수정 내용을 봤을 가능성도 따집니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.33486
- arXiv HTML 본문: https://arxiv.org/html/2611.33486
- arXiv PDF: https://arxiv.org/pdf/2611.33486
- 프로젝트 저장소: https://github.com/DeepBinary/DeepBinary

### Contribution
- 정답지가 없는 상용 커널 바이너리에서 미지의 버그를 찾는 과제를 처음으로 측정 가능하게 만들었습니다. 모든 에이전트가 같은 격리 환경, 디스어셈블러, 커널 디버거를 쓰고, 보고된 크래시는 모두 새 환경에서 재현합니다.
- 정답지 없이 유효성, 중복, 심각도를 판정하는 판정기를 설계했습니다. Driver Verifier를 켠 환경을 포함해 네 쌍의 새 가상 머신에서 일반 사용자 권한으로 재현합니다.
- 7개 최신 모델을 3개 코딩 에이전트에서 평가해 윈도우 커널의 0-day 결함 146개를 찾았습니다. 저자들은 여러 AI 연구소가 이미 이 벤치마크를 신규 사이버 모델 평가에 쓰고 있다고 적었습니다.

### Evaluation
- 규모: 대상 바이너리 12개, 캠페인 204회, 총 4,119 에이전트 시간, 토큰 비용 5만 3,500달러. 모델은 GPT-6 Sol, Claude Opus 5, DeepSeek V4.1 Flash 등 상용 4개와 공개 가중치 3개, 에이전트는 Codex, Claude Code 등 3개입니다.
- 결과: 12개 대상 모두에서 버그를 찾았고, 200개가 넘는 취약점의 추정 바운티 합계는 66만 1,000달러입니다. 9개월 뒤 배포된 윈도우 빌드에서도 PoC가 크래시를 일으킨 결함이 146개로, 저자들은 이를 그 빌드 기준 0-day로 부릅니다.
- 모델 차이: 공개 가중치 모델은 고유 버그를 13~19개, 상용 최상위 모델은 25~116개 찾았습니다. DeepSeek V4.1 Flash는 고유 버그당 비용이 가장 낮았습니다. GPT-6 Sol은 마지막 100만 출력 토큰에서 43개를 더 찾아 직전 100만 토큰의 22개보다 많았습니다.
- 도구 영향: 기호 정보와 Ghidra를 쓴 조건 대비 디스어셈블러 서버를 빼면 고유 버그가 67%, 기호 정보를 빼면 37% 줄었고, IDA Pro나 Binary Ninja를 쓰면 약 5분의 1 더 많이 보고했습니다.
- 판정기: 실제 크래시에 틀린 근본 원인을 붙인 보고 30건을 모두 걸러 냈고, 제조사 영향도 분류와 95% 일치했습니다. 다만 최종 결과에는 사람이 RQ1 판정 10건, RQ2 판정 54건을 고친 내용이 반영되어 있습니다.
- 신빙성: 바운티 금액은 실제 지급액이 아니라 영향도 등급별 프로그램 보상표로 추정한 값입니다. 비용 때문에 모델과 대상 조합마다 캠페인을 한 번만 돌렸고, 윈도우 빌드 하나만 다룹니다. 248건 중 최대 27건(11%)은 모델이 학습 중에 공개 업데이트를 봤을 가능성이 있다고 저자들이 직접 표시했습니다.

#### Comment

# BridgeHammer: DNN Backdoor Attack via CPU-iGPU Shared-memory Rowhammer
> DATE 2027(Design, Automation and Test in Europe) 채택, arXiv 등록. 노스이스턴 대학교
> 2026

CPU와 내장 GPU(iGPU)가 물리 메모리를 공유하는 이기종 SoC에서는 호스트가 메모리에 올린 모델 가중치를 iGPU가 복사 없이(zero-copy) 그대로 읽어 추론합니다. 저자들은 이 공유 경로 때문에 CPU 쪽에서 일으킨 메모리 손상이 iGPU 추론 모델의 무결성을 깨뜨릴 수 있다는 점에 주목했습니다. BridgeHammer는 CPU 쪽 로우해머로 모델 가중치의 특정 비트를 뒤집어, 트리거가 있는 입력만 공격자가 원하는 클래스로 오분류하는 백도어를 심습니다. 핵심은 "어디를"과 "언제"의 조정입니다. 모델 컴파일 뒤, zero-copy 가중치 고정 전에 목표 가중치 페이지를 취약한 DRAM 위치로 옮기는 메모리 마사징을 하고, 가중치 고정 뒤, 추론 시작 전에 로우해머를 실행합니다. 이를 위해 Flush+Reload로 피해자 프로세스의 진행 상황을 감시하다가 두 지점에서 SIGSTOP으로 멈추고 작업 후 SIGCONT로 재개합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.34684
- arXiv HTML 본문: https://arxiv.org/html/2611.34684
- arXiv PDF: https://arxiv.org/pdf/2611.34684
- 저자 저장소(코드와 재현 설명서): https://github.com/Yufei-Wang99/BridgeHammer

### Contribution
- CPU 쪽 공격자가 iGPU가 소비하는 모델 가중치를 정밀하게 손상시켜 백도어를 심는, CPU와 iGPU를 가로지르는 로우해머 백도어 공격을 처음 시연했습니다.
- CPU에서 iGPU로 이어지는 배포 과정을 분석해, 목표 가중치 배치와 결함 주입을 서로 다른 두 단계에 맞춰 조정하는 방법(명령어 감시와 시그널 기반 동기화)을 제시했습니다.
- 추론 직전에 가중치 버퍼의 SHA-256 다이제스트를 다시 계산하는 소프트웨어 방어를 구현해 비용을 측정했습니다.

### Evaluation
- 환경: Intel Core i7-8700, Ubuntu 22.04, OpenVINO. CIFAR-10에서 ResNet-20, VGG-16, ResNet-50을 INT8과 FP32로 평가한 6개 구성입니다. 오프라인 단계(DRAM 결함 프로파일링, 백도어 구성)는 선행 연구 ROBBIN의 방식을 따랐습니다.
- 결과: 6개 구성 모두 목표 페이지 배치와 비트 플립 재현이 100% 정확했고, 공격 성공률은 84.4~90.2%(평균 88.9%), 깨끗한 입력 정확도는 82.8~91.5%(평균 86.3%)였습니다. 목표 페이지는 18~342개, 비트 플립은 70~1,701개였습니다.
- 동기화: 감시 명령어를 탐지한 뒤 SIGSTOP을 보내기까지 7.55~25.51마이크로초가 걸렸고, 두 중단 지점 모두에서 모든 시행이 제때 피해자를 멈췄습니다.
- 방어 비용: 다이제스트 검사의 중간값은 ResNet-20 INT8에서 2.42ms, VGG-16 INT8에서 111ms, ResNet-50 INT8에서 206ms였습니다.
- 신빙성: 깨끗한 입력 정확도가 기준 대비 최대 11%p(ResNet-50 FP32, 96.1%에서 85.1%) 떨어져, "정상 입력 성능을 유지한다"는 은닉성은 구성에 따라 약합니다. 플랫폼은 인텔 데스크톱 하나이며, Jetson이나 AMD APU는 향후 과제로 남겼습니다.

#### Comment
- 공격자가 피해자 프로세스에 SIGSTOP과 SIGCONT를 보낼 수 있고 피해자의 공유 라이브러리 명령어를 Flush+Reload로 감시할 수 있어야 하므로, 같은 사용자 권한 수준의 공존을 전제로 한 강한 위협 모델입니다. 실제 서비스 환경에서 이 조건이 얼마나 성립하는지는 따로 따져 봐야 합니다.
- 통합 메모리 구조는 모바일과 엣지 SoC에도 공통이라, 저자들이 예고한 Jetson 실험 결과가 나오면 모바일 기기 위협으로도 의미가 커질 수 있습니다.
- DATE는 설계 자동화 분야의 주요 학회이며 이 논문은 7쪽 분량입니다. 코드와 재현 설명서 저장소가 실제로 존재함을 확인했습니다.

# RegionAlign: Manipulating Parameter Layouts for Localized Fault Injection on LLMs and VLMs
> arXiv 프리프린트 (심사 전). 라드바우드 대학교, 시안 교통대학교, 암스테르담 대학교
> 2026

물리적 결함 주입으로 저장된 가중치 비트를 뒤집어 LLM과 VLM 성능을 떨어뜨릴 수 있지만, 취약한 비트는 보통 메모리 곳곳에 흩어져 있어 국소적인 주입 한 번으로는 공격하기 어렵습니다. 저자들은 악의적인 모델 제공자가 배포 전에 가중치 값은 그대로 두고 "파라미터 배치"만 바꿔, 취약한 비트를 메모리의 한 영역에 모으는 공급망 공격 RegionAlign을 제안했습니다. 채널 순열을 쓰기 때문에 정확한 산술에서는 모델의 기능이 동일하고 깨끗한 상태의 성능도 거의 같아, 성능만 확인하는 사용자는 변조를 알아채기 어렵습니다. 배포 후 물리적 접근이 가능한 공격자가 그 영역에 결함을 한 번 주입하면 원래 배치보다 훨씬 큰 성능 저하가 일어납니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.33370
- arXiv HTML 본문: https://arxiv.org/html/2611.33370
- arXiv PDF: https://arxiv.org/pdf/2611.33370

### Contribution
- 모델 공급망 공격과 배포 후 물리적 결함 주입이라는, 따로 연구되던 두 위협을 "파라미터 배치"로 연결했습니다.
- 민감도 기반 배치 탐색과 채널 순열을 결합해, 재학습이나 가중치 값 변경 없이 취약 비트를 목표 영역에 모으는 방법을 제안했습니다. 구조적 희소화에 쓰이던 채널 순열을 어텐션과 양자화 제약에 맞게 고쳤습니다.
- NVIDIA Jetson AGX Thor에 전자기 결함 주입(EMFI)을 실제로 가해, DRAM에 올린 양자화 가중치의 비트 손상이 물리적으로 가능하고 방향성이 없다는 점을 확인했습니다.

### Evaluation
- 설정: INT8 양자화한 Llama3.2-1B, Qwen2.5-1.5B, Gemma2-2B, Gemma3-1B, StableLM2-1.6B, SmolLM2-1.7B 등 LLM과 VLM. 원래 배치, RegionAlign 배치, 무작위로 뽑은 허용 배치를 같은 목표 영역, 같은 비트 플립 예산, 같은 탐색 예산으로 비교했습니다.
- 깨끗한 성능: 세 배치의 MMLU 정확도와 WikiText-2 퍼플렉서티가 거의 같았습니다(12개 목표 영역과 탐색 실행의 최소~최대 범위로 보고).
- 공격 효과: 영역 안에서 비트 하나를 뒤집었을 때 StableLM2-1.6B의 WikiText-2 퍼플렉서티가 RegionAlign 배치에서는 11.53에서 68.29로 올랐지만 두 비교 배치는 11.5 근처에 머물렀습니다.
- 물리 실험: Riscure VC+ 프로브로 2,500번 주입해 12번(약 0.5%)에서 INT8 값이 실제로 바뀌었고, 한 번에 8~112개 값에서 값마다 1~12비트가 바뀌었으며 0에서 1과 1에서 0 방향이 1,357 대 1,239로 거의 같았습니다. 그러나 미리 정한 목표 텐서(layers.8.v_proj)에 맞은 시도는 한 번도 없었습니다.
- 신빙성: 공격 효과는 소프트웨어로 비트를 직접 뒤집어 잰 결과이고, 물리 실험은 목표 영역을 맞히지 못했으므로 종단 간 물리 공격은 시연되지 않았습니다. 저자들은 이를 "영역이 공격자를 제약한다"는 위협 모델의 근거로 해석합니다.

# Demystifying Real-world LLM Service Freeloading
> arXiv 프리프린트 (심사 전). 화중 과기대학교(중국 우한)
> 2026

ChatGPT, DeepSeek 같은 LLM 웹 서비스와 Claude Code, Codex 같은 전용 클라이언트가 제공하는 무료 추론을 제3자 프로젝트가 별도 API로 다시 포장해 배포하는 일이 늘고 있습니다. 저자들은 제공자가 허용한 접근, 할당, 재배포 조건을 벗어난 이런 사용을 "LLM 서비스 무임승차(LSF)"로 정의하고, 오픈소스 프로젝트 513개와 64개 상위 LLM 서비스에 걸친 추론 경로 1,588개를 추적해 개발 양상, 의존 관계, 동작 방식을 체계적으로 측정했습니다. 상위 서비스 62곳의 약관도 함께 분석해 어떤 행위가 금지되는지 정리했습니다.

# FlashProve-Next: Verifiable Inference for Production LLM APIs
> arXiv 프리프린트 (심사 전). 독립 연구자(단독 저자)
> 2026

가중치를 공개하지 않는 LLM API의 이용자는 제공자가 광고한 모델, 정밀도, 숨은 프롬프트, 추론 예산을 실제로 썼는지 확인할 방법이 없습니다. 기존 방법은 하드웨어나 제3자를 믿거나, 모든 층을 정수 대리 모델로 다시 증명해 비용이 크고 실제 부동소수점 서빙과 어긋납니다. FlashProve-Next는 서빙 방식(bf16/fp8/mxfp4, 무작위 샘플링, FlashAttention, CUDA 그래프, 배치, 프리픽스 캐시)을 바꾸지 않고, 가중치, 숨은 프롬프트, 숨은 추론, 활성값을 드러내지 않으면서 개별 API 응답에 대해 영지식으로 가린 증명을 만든다고 주장합니다. 증명이 보증하는 것은 "어떤 GPU가 무엇을 실행했는가"가 아니라 "제공자가 공약한 구성과 일치하는 계산 기록을 갖고 있다"는 것이며, 비용 가중 무작위 점검(spot-checking)으로 허용 오차를 벗어난 계산 비율이 공개 임계값 아래임을 확률적으로 보증합니다.

### Evaluation
- 보정: Blackwell GPU에서 5개 모델의 GEMM/MoE 블록 185만 개와 비GEMM 행 196만 개를 시험해 정직한 실행을 잘못 거부한 경우가 0건이었다고 보고합니다.
- 증명 비용: Qwen3-0.6B(ExtSeed-153 모드, 8MiB 증명)를 GPU에서 450.2초에 증명했고, 14가지 부정행위 시나리오를 모두 잡았으며, 36층 Qwen3-4B와 vLLM에서 동작하는 Qwen3-30B-A3B-FP8까지 확장했습니다(후자의 특정 관계는 증명 1.49초, Rust 검증 23.4ms). Rust 검증기는 8MiB 증명을 CPU에서 10.1ms에 확인합니다.
- 신빙성: 모든 수치를 저자 한 명이 직접 측정했고 독립적인 재현이나 심사를 거치지 않았습니다. 핵심 정리 일부는 "커널이 반올림 계약을 지킨다"는 가정과 경험적 근사 가정에 조건부이며, 프리픽스 붕괴 같은 일부 부정행위와 체크포인트 백도어는 범위 밖이라고 저자가 직접 밝혔습니다. 기존 FlashProve는 8×H100 FP8 프리필의 71~93배가 걸린다고 인용하지만, 같은 조건의 직접 비교 표는 이번에 읽은 범위에서 확인하지 못했습니다.

#### Comment
- 폐쇄형 모델 API의 "광고한 모델을 실제로 돌렸는가"라는 실무 문제를 TEE 없이 공개 검증으로 풀려는 시도로, 코드, 명세, 기계 검증 증명을 모두 공개한 점은 재현 가능성 면에서 강점입니다.
- 단독 독립 연구자의 36쪽짜리 매우 밀도 높은 원고로, 자체 용어와 모드 이름(NI-315, ExtSeed-153 등)이 많아 외부 검토가 특히 필요합니다. 소속 기관은 표기되어 있지 않습니다.
- 저자 저장소의 논문 PDF와 arXiv 초록의 제목, 저자, 핵심 수치(450.2초, 14/14, 10.1ms)가 일치함을 확인했습니다.
