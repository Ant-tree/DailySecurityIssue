# CipherFlow: Compiling AI Programs for Efficient Cryptographically Secure Inference
> NeurIPS 2026 채택, arXiv cs.CR 2611.01450 공개본. University of Central Florida(LoopLeap Lab)
> 2026

암호학적으로 안전한 추론(cryptographically secure inference)은 동형암호(homomorphic encryption)와 안전한 다자간 계산(secure multi-party computation)으로 신경망을 계산해, 서버는 사용자 입력을, 사용자는 모델 가중치를 보지 못한 채 결과만 주고받게 하는 기술입니다. 지금까지의 하이브리드 시스템(BumbleBee, BOLT, BLB 등)은 "선형 연산은 동형암호로, 비선형 연산은 다자간 계산으로"처럼 연산 종류별로 처리 방식을 미리 정해 둡니다. 저자들은 이런 고정 규칙이 하드웨어(CPU인지 GPU인지)와 네트워크 대역폭, 지연 시간에 따라 최적이 아니게 된다는 점에 주목합니다.

CipherFlow는 모델의 연산 그래프, 쓸 수 있는 암호 연산 라이브러리, 대상 하드웨어와 네트워크 설정을 입력으로 받아 지연 시간이 가장 짧은 실행 계획을 자동으로 만드는 컴파일러입니다. 세 가지 기법으로 구성됩니다. MicroBench는 실제 배포 환경에서 각 암호 연산, 두 방식 간 변환, 부트스트래핑의 비용을 측정합니다. 상태 확장 계획(state-expanded planning)은 각 연산을 "어느 방식으로 실행하는지"와 "동형암호 암호문에 남은 연산 단계(level)"를 묶은 상태로 표현해, 연산 배치와 변환, 암호문 갱신 시점을 함께 최적화하는 문제를 최단 경로 탐색으로 바꿉니다. BlockFold는 잔차 연결과 어텐션처럼 갈라졌다 합쳐지는 구간을 경계 상태 간 전이 표로 요약해, Transformer 규모의 그래프에서도 탐색이 가능하게 합니다.

원문: https://arxiv.org/abs/2611.01450 (본문은 저자 공식 저장소 https://github.com/loopleap-lab/CipherFlow 의 docs/assets/cipherflow-paper.pdf 로 읽었습니다)

### Contribution
- 연산 그래프, 암호 연산, 배포 환경으로부터 실행 가능한 하이브리드 안전 추론 프로그램을 만드는 과정을 하나의 컴파일 문제로 정식화했습니다. 연산 배치, 방식 간 변환, 암호문 유지 관리, 암호 상태의 실행 가능성을 함께 다룹니다.
- 남은 연산 단계를 상태에 포함시켜, 단계가 바닥나 실행이 불가능한 계획을 탐색 단계에서 걸러 냅니다. 이 상태 확장을 빼면 컴파일은 빨라지지만 실행할 수 없는 계획이 나온다는 점을 분리 실험으로 보였습니다.
- BlockFold가 없으면 BERT-base 계획 수립에 278시간 이상(검색 공간 외삽 기준)이 걸리지만, 적용하면 3.50초로 줄어듭니다.
- 새 동형암호나 다자간 계산 라이브러리를 측정 비용과 함께 등록하면 바로 계획에 반영되는 확장 가능한 구조로 만들었고, 코드를 공개했습니다.

### Evaluation
- 환경: CPU는 AMD Threadripper PRO 3955WX(16코어), GPU는 NVIDIA B200입니다. 대역폭 10 Mbps, 100 Mbps, 1 Gbps, 3 Gbps와 왕복 지연 1, 20, 40, 80 ms를 조합한 16개 조건을 플랫폼마다 측정했습니다.
- 대상 모델: BERT-base(시퀀스 길이 128, 연산 132개)와 ViT-B/16(토큰 197개). 동형암호는 NEXUS CKKS(CPU)와 NEXUS-CUDA(GPU), 다자간 계산은 SCI/SHAFT(CPU)와 SHAFT(GPU)를 썼습니다.
- 비교 대상: BumbleBee, BOLT, BLB의 배치 규칙을 같은 암호 연산 위에 그대로 적용한 정적 하이브리드 기준선입니다. BOLT와 BLB에는 일괄 변환 효과를 반영해 변환 비용을 0.75배, 0.5배로 할인해 주었고, BERT-base에는 BumbleBee 논문이 공개한 전체 시스템 측정값도 각 네트워크 조건에 맞춰 다시 조합해 함께 비교했습니다.
- 결과: 모든 조건에서 가장 좋은 정적 기준선과 같거나 더 빨랐고, 최대 속도 향상은 BERT-base 16.5배, ViT 22배 이상입니다. 예를 들어 BERT-base CPU, 1 Gbps, 20 ms 조건에서 기준선 중 가장 빠른 것이 8.48천 초였고 CipherFlow는 486초였습니다. 대역폭이 충분하면 ViT 전체를 다자간 계산으로 돌리는 계획을 고르는 등, 조건마다 선택하는 배치가 달라졌습니다.
- 분리 실험: MicroBench 측정값 대신 일반화된 비용을 쓰면 최악 조건 지연이 CPU에서 1.19배, GPU에서 19.14배 늘었습니다. 연산마다 국소적으로 싼 쪽을 고르는 탐욕 방식은 GPU에서 5.75배, 무작위 배치 100개 중 최선도 10.9~14.0배 느렸습니다.
- 지표 신빙성: 정적 기준선 대부분은 원 논문의 시스템을 돌린 것이 아니라 "배치 규칙"만 가져와 저자들의 암호 연산 위에 재구성한 것입니다. 따라서 수치는 배치 계획의 효과만 비교한 것이며, 원 시스템의 최적화된 구현과 직접 겨룬 결과는 BERT-base의 BumbleBee 측정값 하나뿐입니다. 최대 배율도 지연 시간이 큰 조건에서 BumbleBee 시스템 수치와 비교해 나온 값이어서, 배치 규칙만 공정하게 맞춘 비교에서는 BERT-base CPU 표 기준으로 배율이 조건에 따라 약 1.6~21배 범위로 달라집니다.

#### Comment
- "어떤 연산을 어떤 암호 방식으로 돌릴지는 배포 환경마다 달라야 한다"는 관찰을 컴파일러로 풀어낸 실용적인 연구입니다. 안전 추론을 실제 서비스에 적용하려는 쪽에서는 네트워크 조건만 바꿔도 최적 배치가 크게 바뀐다는 결과 자체가 참고할 만합니다.
- 한계: 준정직(semi-honest) 두 당사자 모델만 다루고, 악의적 공격자, 사이드 채널, 결과 무결성은 범위 밖입니다. 단일 요청 지연만 최적화하므로 배치 처리, 동시 요청, 자원 경합은 반영하지 않으며, 연산 단계에 따른 동형암호 비용 차이도 한 단계에서만 측정했습니다. 그래프와 텐서 크기가 고정되어 있어 자기회귀 생성(KV 캐시가 계속 늘어나는 경우)이나 전문가 혼합(mixture-of-experts) 모델은 아직 지원하지 않습니다.
- 사용성을 내세우지만 실제 개발자의 작업량이나 사용성 실험은 하지 않았다고 저자들이 직접 밝혔습니다.
- 게재처: NeurIPS 2026 채택 논문으로 신뢰도가 높습니다. 공개 PDF 부록에는 "제출본에서 BERT-base CPU 표 대신 ViT 표가 잘못 반복되었다"는 정정 문구가 있어, 이 PDF가 제출 후 수정된 판임을 알 수 있습니다. 제목, 저자, 초록의 핵심 수치(16.5배, 22배 이상)는 메일의 arXiv 초록과 일치합니다.
- 본문 출처: 저자 공식 저장소에 올라온 논문 PDF.
- 저자 소속은 미국 University of Central Florida로, 중국 기관 논문에 해당하지 않습니다.

# Kerkoporta: Injecting Structured-Output Backdoors in Reasoning Coding Agents
> arXiv cs.CR 2611.00138 (프리프린트, 심사 전), 노스이스턴대학교, Microsoft, Microsoft Research(미국)
> 2026

지금까지의 LLM 백도어 공격은 주로 채팅 환경을 대상으로 해서, 피해가 이상한 텍스트 출력 정도에 머물렀습니다. 코딩 에이전트는 사용자 컴퓨터에서 직접 명령을 실행하므로 이 한계가 사라집니다. 이 논문은 추론형 모델에 "구조화된 출력 백도어"를 심는 방법론 Kerkoporta를 제시합니다. 에이전트 맥락 어디에든 트리거가 나타나면 모델이 공격자가 정한 형식에 맞는 도구 호출을 내보내고, 에이전트 실행 환경(하네스)이 이를 그대로 실행해 기밀성, 무결성, 가용성을 직접 침해합니다.

공격자는 겉보기에 유용한 미세조정 체크포인트를 배포하는 모델 공급망 공격자로 가정합니다. Kerkoporta는 품질 높은 독성 표본을 만들고, 지도 미세조정(SFT)으로 백도어를 심은 다음, 단순 SFT 독성 주입이 떨어뜨린 일반 성능을 가벼운 온라인 강화학습으로 회복합니다. 페이로드는 작업 디렉터리를 지우고 작업을 끝내는 것, 실행한 모든 명령을 외부로 보내는 .bashrc 훅(PROMPT_COMMAND)을 설치하는 것, 공격자가 접속할 수 있는 리버스 셸을 여는 것 세 가지입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.00138
- arXiv HTML 본문: https://arxiv.org/html/2611.00138
- arXiv PDF: https://arxiv.org/pdf/2611.00138
- 저자 아티팩트(Zenodo): https://doi.org/10.5281/zenodo.20953922

### Contribution
- 채팅 출력에 머물던 백도어 위협 모델을 여러 단계로 동작하며 권한이 큰 코딩 에이전트 환경으로 넓혔습니다.
- SFT로 백도어를 넣고 강화학습으로 유용성을 회복하는 독성 주입 방법론을 제시했고, 그 결과 모델이 깨끗한 기준 모델보다 표준 유용성 벤치마크에서 더 나은 점수를 내기도 해 피해자가 이를 채택할 유인이 생긴다는 점을 보였습니다.
- 공격을 여러 하네스에 두루 통하게 할 수도, 특정 하네스 하나에만 묶을 수도 있음을 보였고, 독성 비율에 따라 분포 밖 일반화가 어떻게 달라지는지 분석했습니다.

### Evaluation
- 설정: Qwen3.5-122B-A10B 교사 모델에서 학습 궤적을 증류하고, 일반 하드웨어에서 돌릴 수 있는 Qwen3.5-4B와 9B를 공격 대상으로 삼았습니다. 하네스는 Claude Code, Codex, Pi 세 가지입니다.
- 지표: 분포 내 평가는 학습에서 뺀 과제로, 분포 밖 평가는 널리 쓰이는 오픈소스 GitHub 저장소 다섯 개에 트리거를 넣어 했습니다. 공격 성공률, 페이로드 정확도, 트리거 없이 발동하는 오발동률을 측정했습니다.
- 결과: 공격 성공률은 최대 96.2%였습니다. 페이로드가 나오면 거의 항상 정확하게 실행되었고(4B 모델의 인터리빙 공격, 독성 비율 25% 조건 하나를 빼면 페이로드 정확도 100%), 오발동은 9B 리버스 셸 공격의 독성 비율 50% 조건에서 저장소 하나(25%, 평균 5%)를 빼면 모두 0이었습니다. 낮은 독성 비율에서의 주된 한계는 실행 정확도가 아니라 학습 분포 밖으로의 전이였습니다.
- 지표 신빙성: 실패 사례와 조건별 편차를 함께 보고해 결과를 부풀린 흔적은 보이지 않습니다. 다만 모델이 4B, 9B 두 크기의 한 계열뿐이고, 분포 밖 평가 저장소도 다섯 개로 많지 않습니다.

#### Comment
- 오픈 가중치 코딩 모델을 내려받아 쓰는 조직에 직접적인 경고가 되는 연구입니다. 가중치는 소스 코드처럼 들여다볼 수 없고 백도어가 없음을 인증하는 절차도 아직 없으므로, 출처를 알 수 없는 미세조정 체크포인트에는 하네스 수준의 명령 실행 통제가 필수라는 점을 보여 줍니다.
- 한계: 공격자가 학습 파이프라인 전체를 통제하는 공급망 시나리오이며, 탐지나 방어 기법에 대한 평가는 이번에 읽은 범위에서 중심 주제가 아닙니다.
- 게재처: 심사 전 프리프린트입니다. 노스이스턴대학교와 Microsoft, Microsoft Research의 공동 연구이고 아티팩트를 Zenodo에 공개했습니다.

# MCP Tool Poisoning in Agentic AI Frameworks: A Cross-Framework Measurement Study
> AISec '26 워크숍(ACM CCS 2026 공동 개최, 헤이그) 채택 논문, arXiv cs.CR 2611.03555 공개본. Dynatrace(오스트리아 린츠)
> 2026

MCP는 에이전트 프레임워크가 외부 도구 제공자를 모델에 연결하는 프로토콜인데, 도구 설명, 스키마 필드, 응답 데이터처럼 공격자가 통제하는 내용이 검증 없이 모델 맥락에 그대로 들어갑니다. 이 "도구 오염(tool poisoning)"은 OWASP가 MCP03:2025로 분류했을 만큼 알려진 문제지만, 기존 벤치마크는 모델이 오염된 지시를 따르는지만 볼 뿐 실제로 도구가 실행되어 피해가 났는지는 확인하지 않았고, 프레임워크 계층이 방어에 기여하는지도 따로 떼어 보지 않았습니다.

이 논문은 실제 도구 실행까지 확인하는 첫 프레임워크 간 비교 측정입니다. 기존 분류(Invariant Labs, MCPTox, OWASP MCP03, MSB, AgentDojo, ETDI, CSA)를 프로토콜의 모든 진입점에 걸쳐 통합한 25개 근본 원인 분류 체계를 만들고, 오픈소스 도구 mcpvenom으로 프레임워크 12개, 모델 18개, 공격 시나리오 45개를 조합한 9,720칸의 취약성 행렬을 측정했습니다. 공격자 엔드포인트에 실제로 HTTP 요청이 도착했는지 확인하는 이중 판정으로 데이터 유출을 독립적으로 검증했습니다.

### Contribution
- 여러 출처의 MCP 공격 분류를 하나로 묶은 25개 근본 원인 분류 체계를 제시했습니다.
- 모델의 도구 호출 의도와 실제 실행, 실제 비밀 유출을 구분한 3단계 증거 체계로 측정하는 오픈소스 도구를 공개했습니다.
- 12개 프레임워크의 코드를 감사해 의도적인 도구 오염 방어가 하나도 없음을 확인했고, 4개 업체에 낸 5건의 조율된 공개가 모두 거절되었다는 점을 기록해 "어느 계층도 에이전트 보안을 책임지지 않는" 공백을 드러냈습니다.

### Evaluation
- 전체 결과: 공격 성공률 22.9%(취약 칸 2,113개). 증거 단계별로는 공격자 도구 호출 발송 64.9%, 공격자 엔드포인트와의 실제 네트워크 접촉 23.0%, 비밀 유출 확인 12.1%였습니다. 판정은 기록 1,259건을 사람이 직접 검토해 확인했습니다.
- 프레임워크 영향: 핵심 프레임워크 9개가 23~26%에 몰려 통계적 차이가 없었습니다(χ² = 3.30, p = 0.91). 의도하지 않은 성질이 일부 완화 효과를 냈는데, Pydantic AI의 중복 도구 이름 거부(16.6%), AG2의 실행기 제약(4.6%)이 그 예입니다.
- 정적 검사: 권장되는 도구 설명 검사를 구현한 정규식 검사기는 45개 시나리오 중 20개를 막았지만, 정상 설명 125개에서 7.2%의 오탐을 냈습니다.
- 모델 영향: 모델별 공격 성공률은 0.4%(Claude Fable 5)에서 49.7%(Amazon Nova Pro)까지 벌어졌습니다. Claude Opus 4.8은 530칸 중 8칸(1.5%)에서만 뚫리고 오염된 설명을 근거로 명시적으로 거부한 경우가 223번이었습니다. Claude Sonnet 5는 공격임을 말로 지적한 뒤 유출 호출을 실행하는 "말하고 따르는" 패턴을 보였습니다.
- 지표 신빙성: 실제 네트워크 수신으로 유출을 확인하고 수작업 검증까지 거쳐 측정의 엄밀성이 높습니다. 저자들도 결과가 시험한 프레임워크, 모델 버전, 설정, 시나리오에 한정된다고 밝혔습니다.

#### Comment
- "저항은 모두 모델에서 나오고 프레임워크는 아무것도 하지 않는다"는 결론은 MCP 기반 시스템을 설계하는 쪽에 분명한 메시지입니다. 모델 교체만으로 위험이 수십 배 달라지므로, 도구 메타데이터 검사와 함께 변경 감지와 결과 채널 검증을 프레임워크나 게이트웨이 계층에서 해야 합니다.
- 업체 공개가 모두 거절된 기록은 책임 소재 문제를 보여 주는 드문 실증 자료입니다.
- 게재처: ACM CCS 공동 개최 워크숍인 AISec '26 채택 논문입니다. 저자는 기업(Dynatrace) 연구진입니다.
