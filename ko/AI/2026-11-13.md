# Scaling Adaptive Prompt Injection Attacks with Agent Swarms
> arXiv 프리프린트 (심사 전, 기술 보고서). Google DeepMind
> 2026

2025년 중반 이후 정적 프롬프트 인젝션 공격은 최신 모델에서 거의 통하지 않게 되었고, GraySwan Arena 같은 사람 중심 레드팀 결과도 일부 모델에서 1% 미만으로 떨어졌습니다. 이 보고서는 그렇다고 프롬프트 인젝션이 해결된 것은 아니라는 점을 보이기 위해 두 가지를 제안했습니다. 첫째, 공격 목표를 "명백히 악의적인 행동"이 아니라 사용자 요청과 무관한 임의의 도구 호출로 잡은 합성 데이터셋(100개 시나리오, 53개 분야 249개 도구)입니다. 이렇게 하면 모델이 보안 상식으로 위험한 행동을 거부하는 능력과, 도구 출력 속 지시를 따르지 않는 지시 계층 준수 능력을 분리해서 볼 수 있습니다. 둘째, 여러 에이전트 팀이 공유 화이트보드와 순위표로 정보를 주고받으며 인젝션 문구를 함께 찾는 공격기 "Agentic Optimizer"입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.11861
- arXiv HTML 본문: https://arxiv.org/html/2611.11861
- arXiv PDF: https://arxiv.org/pdf/2611.11861

### Contribution
- 무해하지만 무관한 도구 호출을 목표로 삼아, 프롬프트 인젝션 내성을 지시 계층 준수 능력으로 측정하는 평가 설계를 제시했습니다. 무해한 단계들이 이어지면 랜섬웨어처럼 해로운 결과가 될 수 있다는 점도 근거로 들었습니다.
- 단일 LLM이 후보를 고쳐 나가던 기존 LLM 기반 최적화를, 팀별로 다른 전략을 맡긴 에이전트 무리(8팀 × 2개 에이전트)로 확장했습니다. 성공한 공격은 전략 데이터베이스에 쌓여 다음 시나리오에 재사용됩니다.
- 공격 모델의 능력이 높을수록 방어 모델의 저항률이 크게 떨어진다는 점, 즉 공격자 능력이 공격 성공의 주된 요인일 수 있다는 점을 보였습니다.

### Evaluation
- 대상: Gemini 3.6 Flash, 3.7 Flash, 3.8 Flash, 4 Argon(모델 외부의 인젝션 방어와 안전 분류기는 끈 상태)과 공개 가중치 모델 Kimi K3, GLM-5.3, DeepSeek-V4.1-Flash.
- 지표: 공격 저항률(ARR). 도구 이름, 모든 인자 키, 숫자와 불리언 값이 정확히 일치하고 문자열 유사도가 96%를 넘어야 공격 성공으로 칩니다. 에이전트당 평가 20회, 전체 320회 예산입니다.
- 가장 강한 공격 모델(Gemini 4 Argon)을 상대로 가장 튼튼한 Gemini 4 Argon도 전체 예산에서 66%, 150회 제한에서 87%만 막았습니다. Kimi K3, GLM-5.3, DeepSeek-V4.1-Flash는 1~5%만 막았습니다.
- 공격 모델을 Flash 3.6에서 4 Argon으로 바꾸면 방어 모델 평균 ARR@150이 42.1%에서 23.1%로 떨어졌습니다. 방어 모델의 추론 과정이 공격자에게 보이면 공격이 더 쉬워졌습니다.
- 기존 공개 공격기와의 비교(AgentDojo 80개 시나리오, 외부 방어가 켜진 Gemini 3.6 Flash): Prompt Siren의 mini-goat 공격은 80개 중 2개, 제안 방식은 질의 25회 예산으로 6개를 뚫었습니다.
- 지표의 신빙성: 평가 데이터셋과 공격 도구가 공개되지 않았고, 대부분의 실험이 제작사 내부 모델에서 외부 방어를 끈 상태로 진행되어 외부에서 재현하기 어렵습니다. 기존 공격과의 비교도 작은 규모입니다.

#### Comment
- 제작사가 자사 모델을 직접 공격한 결과라는 점에서 의미가 있습니다. 실제 서비스의 외부 방어를 끈 조건이라 실서비스 위험을 그대로 나타내지는 않으며, 저자들도 모델 강화만으로는 부족하고 여러 층의 방어가 필요하다고 결론 내렸습니다.
- 공격 성공 기준이 "정확히 같은 인자로 호출"이라 엄격한 편이고, 공격 목표가 무해한 호출이라는 점은 해석할 때 감안해야 합니다.
- 공격 모델의 프롬프트 인젝션 능력이 ExploitBench 점수와 대체로 함께 움직인다는 관찰은 가설 수준으로 제시되었습니다.

# Say Shibboleth: Fingerprinting the LLMs and Harnesses Behind Agentic Attacks
> arXiv 프리프린트 (심사 전, v0.1). Cracken, MATS, 조지메이슨대학교 등
> 2026

LLM 에이전트가 공격을 수행하는 시대에는 "누가" 공격했는지뿐 아니라 "어떤 모델과 어떤 실행 환경(하네스)"이 공격했는지도 추적 대상이 됩니다. 이 논문은 방어자가 공격 대상 쪽에서 관찰할 수 있는 정보만으로 공격 에이전트의 LLM 버전과 하네스를 알아내는 "시볼레스 함정(shibboleth trap)"을 제안했습니다. 함정은 에이전트가 원하는 자원(배포 키, 토큰 등)을 얻으려면 특정 상호작용을 거치도록 만든 허니팟 서비스입니다. 예를 들어 MCP 서버가 세션을 열 때 샘플링에 쓰는 모델 이름을 밝히게 하고, 운영 로그나 위험 평가 같은 글을 쓰게 한 뒤에야 자원을 내줍니다. 프롬프트 인젝션이 성공할 필요 없이 에이전트가 목표를 추구하는 과정 자체에서 식별 증거가 나온다는 점이 핵심입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12386
- arXiv HTML 본문: https://arxiv.org/html/2611.12386
- arXiv PDF: https://arxiv.org/pdf/2611.12386
- 저자 저장소(코드와 함정 생성 파이프라인): https://github.com/SayShibboleth/Shibboleth

### Contribution
- 방어자가 공격 모델에 직접 질의할 수 없는 "맹목적이고 수동적인" 설정에서의 지문 수집 문제를 정의했습니다.
- 모델 이름 선언을 요구하는 선언형 관문과, 모델이 쓴 글의 문체(저자들은 "억양"이라고 부름)를 분류하는 행동형 관문을 결합했습니다.
- 하네스 식별을 위해 도구 출력 속 비밀 정보를 가리는 방식, 명령 시간 제한 처리, 도구 호출 동시 실행 여부를 이후 요청에 나타나는 효과만으로 간접 관찰하는 탐침을 설계했습니다.
- 함정의 현실성과 효과를 에이전트 파이프라인으로 자동 개선하는 방법도 제시했습니다. 기만 기법은 공개될수록 효과가 떨어지므로 자동 생성이 중요하다고 봤습니다.

### Evaluation
- 설정: 함정 4종(MCP, A2A, SSH, 플릿 배포 컨트롤러), LLM 15종, 하네스 Hermes Agent, OpenClaw, OpenCode와 Claude Code(Claude-Opus-5 전용), 공격 과제 7종(과제마다 문장 5가지), 약 800회 공격 실행.
- LLM 식별: 선언만으로 84~90%를 맞혔고 틀린 이름을 댄 경우는 없었습니다(실패는 선언이 없는 경우). 행동형 단독은 36~54%였고, 둘을 합치면 MCP와 A2A 함정에서 90~92% top-1 정확도였습니다. 과제 하나나 하네스 하나를 학습에서 빼도 1%포인트 이내로 유지되었습니다.
- 하네스 식별: 선언형으로 A2A 85%, SSH 81%, 플릿 함정의 고정 규칙으로 4개 하네스 평균 92%를 맞혔습니다.
- 은닉 실험: 6개 모델에 가짜 이름을 대라고 지시하자 선언 정확도는 8%로 떨어졌지만 행동형 식별은 77%를 유지했습니다. 행동 템플릿이 있는 모델 이름만 믿는 규칙을 더하면 79%까지 회복했습니다.
- 지표의 신빙성: 행동형 분류기는 학습 실행에만 맞춰 학습하고 실패도 집계에 넣는 등 평가 절차가 비교적 엄격합니다. 다만 하네스가 4종뿐이고, 최고 성능 상용 모델은 사이버 공격 과제를 거부해 거의 포함되지 않았습니다.

#### Comment
- 에이전트 공격의 귀속(attribution)이라는 새로운 문제를 실용적인 허니팟 설계로 다룬 점이 돋보입니다. 실제 사고에서 Unit 42가 노출된 설정 파일로 DeepSeek과 Hermes Agent를 식별한 사례를 동기로 들었습니다.
- 버전 표기가 v0.1이고 저자들도 하네스 범위를 넓힐 계획이라고 밝힌 초기 버전입니다. 공격자가 함정을 알아채고 일부러 다른 문체를 흉내 내는 경우는 아직 다루지 않았습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# SNAPRAG: Cost-Efficient Knowledge Extraction Attack on RAG Systems via Adversarial Perturbations
> arXiv 프리프린트 (심사 전). 빌켄트대학교, 코치대학교(튀르키예)
> 2026

RAG 시스템은 비공개 지식 베이스를 참고해 답하므로, 공격자가 질의를 반복해 지식 베이스를 통째로 빼낼 수 있다는 연구가 이어지고 있습니다. 기존 추출 공격(RAGThief, PirateRAG 등)은 새 질의를 만들 때 외부 LLM에 의존하거나 질의 수가 많고 예측하기 어려워, 사용량 기반 과금 서비스에서는 비용이 큽니다. 이 논문은 외부 LLM 없이 이미 빼낸 문서 조각의 토큰을 조금씩 바꾸는 이산 변이 알고리즘으로 새 질의를 만들고, 기존에 얻은 조각들과 의미상 충분히 멀어질 때까지 변이를 계속하도록 임계값을 조정하는 블랙박스 공격 SNAPRAG를 제안했습니다. 질의 예산을 정확히 정해 둘 수 있다는 점도 특징입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12241
- arXiv HTML 본문: https://arxiv.org/html/2611.12241
- arXiv PDF: https://arxiv.org/pdf/2611.12241

### Contribution
- 외부 LLM 호출 비용 없이 공격자 쪽 계산만으로 질의를 생성하는 지식 추출 공격을 제시했습니다.
- 적응형 비유사도 임계값으로 질의를 아직 탐색하지 않은 의미 영역으로 밀어내, 같은 질의 수로 더 많은 문서를 빼내도록 했습니다.
- 다단계 중복 제거 필터와 순위 기반 질의 발송으로 예산 낭비를 줄였습니다.

### Evaluation
- 대상: 기존 연구 설정을 재현한 RAG 에이전트 5종(Llama-3.2-3B, Phi-3.5-mini, Llama-3.1-8B와 GTE, E5, BGE 임베딩 조합, 지식 베이스는 BioASQ, Wikipedia, Neural Bridge RAG, TREC-COVID, SciDocs 일부, 각 1,000개 문서).
- 비교 대상: RAGThief, PirateRAG, RAGCrawler.
- 추출률: 질의 2,000회(에이전트 A~C) 또는 1,000회(D, E) 예산에서 69.7~96.9%로 모든 에이전트에서 가장 높았고, 가장 강한 기존 공격보다 7.7~19.9%포인트 앞섰습니다.
- 지식 베이스 절반을 빼내는 데 필요한 질의 수는 208~997회로, 기존 공격이 1.18~6.77배 더 필요했습니다.
- 방어 실험: 입력과 출력을 Llama Guard 3 8B로 검사하는 방어를 붙여도 50.7~96.3%를 추출했고, 5개 중 4개 에이전트에서 가장 앞섰습니다(에이전트 B에서는 RAGThief가 55.9%로 앞섬).
- 지표의 신빙성: 대상이 소형 공개 모델과 1,000개 문서 규모의 지식 베이스라 상용 RAG 서비스로 그대로 일반화하기는 어렵습니다. 질의 하나를 만드는 데 걸리는 공격자 쪽 계산 시간(기본 문서 조각당 수십~백여 초)도 함께 고려해야 합니다.

#### Comment
- 외부 LLM 없이도 지식 베이스 추출이 싸게 된다는 점에서, RAG 운영자에게 질의 패턴 기반 탐지와 응답 내 원문 노출 제한이 필요하다는 근거가 됩니다. 저자들은 방어 기법을 후속 연구로 남겼습니다.
- 코드 공개 여부는 본문에서 확인하지 못했습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# Double Blind Evals: Resolving the Dual Confidentiality Dilemma in AI Safety Auditing
> arXiv 프리프린트 (심사 전, 기술 보고서). Google, AVERI, 싱가포르 AI 안전 연구소, OpenMined, MLCommons
> 2026

AI 안전성 평가에서는 평가 기관이 벤치마크 문항을 모델 제작사에 보여 주기 싫어하고(학습 데이터로 섞여 들어가 벤치마크가 오염되는 것을 막기 위해), 제작사는 모델 가중치와 추론 코드를 밖으로 내보내기 싫어하는 "양방향 기밀성" 문제가 있습니다. 이 보고서는 하드웨어 수준에서 메모리를 암호화하는 보안 엔클레이브 안에서 두 자산을 만나게 하는 "이중 맹검 평가(Double Blind Evals)"를 제안하고, 실제로 Google DeepMind의 비공개 모델 Gemini 2.5 Flash Lite를 MLCommons의 비공개 AILuminate 벤치마크 문항으로 평가하는 시범 사례를 수행했습니다. 양측은 원격 증명(attestation)을 확인한 뒤에만 각자의 자산을 암호화된 터널로 엔클레이브에 넣고, OpenMined의 PySyft가 실행할 코드를 양측이 검토하고 승인하도록 관리합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.12604
- arXiv HTML 본문: https://arxiv.org/html/2611.12604
- arXiv PDF: https://arxiv.org/pdf/2611.12604
- Google DeepMind 공식 기술 보고서 PDF: https://storage.googleapis.com/deepmind-media/DeepMind.com/Blog/piloting-the-worlds-first-double-blind-ai-evaluations/double-blind-evaluations-technical-report.pdf

### Contribution
- 보안 엔클레이브를 두 당사자 간 안전한 다자간 계산처럼 쓰는 방식을 AI 평가 절차로 구체화했습니다. 모의 인터페이스로 평가 코드를 먼저 작성하고, 증명 확인 후 가중치와 문항을 각각 스트리밍하고, 승인된 코드만 실행해 결과를 돌려주는 흐름입니다.
- 최신급 상용 모델의 가중치와 다른 조직의 비공개 벤치마크를 서로 공개하지 않고 함께 다룬 첫 사례라고 주장합니다.

- 바쁨 검사 없이 학습하면 KEEP은 100회 업데이트에서는 네 개 시드 모두 앞섰지만 200회부터는 모두 뒤처졌고, 학습 시드에 따른 편차가 공개된 샘플링 구간보다 훨씬 컸습니다.
- 지표의 신빙성: 하나의 환경과 두 방어기에 대한 결과이며, 저자들이 한계(바쁨 검사를 끈 실험은 래퍼 제거 실험일 뿐 처음부터 검사 없이 만든 에이전트를 잰 것이 아님, 두 하네스의 시드 방식 차이 등)를 상세히 밝혔습니다.
