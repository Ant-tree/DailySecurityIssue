# Who Is Prompt-Injecting Coding Agents? An Empirical Study of Hidden AI-Directed Text on GitHub
> arXiv 프리프린트 (심사 전). Radware, 테크니온 공과대학교
> 2026

GitHub의 AI 코딩 에이전트는 이슈 분류, 중복 탐지, PR 리뷰, CI 작업을 하면서 누구나 쓸 수 있는 텍스트를 읽습니다. 저자들은 GitHub가 사람에게는 렌더링하지 않지만 에이전트는 그대로 받는 숨은 텍스트(HTML 주석, 보이지 않는 유니코드, 배경색과 같은 LaTeX 수식, CSS 숨김)를 기준으로 약 1억 4,500만 건의 이슈, PR, 댓글, README를 처음으로 대규모 전수 조사했습니다. 2단계 LLM 분류, 템플릿 출처 확인, 전수 수작업 검토를 거쳐 이슈·PR·댓글에서 2,281건(100만 건당 16건), README에서 107개 저장소의 AI 대상 숨은 텍스트를 확인했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.28763
- arXiv HTML 본문: https://arxiv.org/html/2611.28763
- arXiv PDF: https://arxiv.org/pdf/2611.28763
- 저자 저장소(데이터와 탐지 도구): https://github.com/rdwr-gabin/github-ipi-in-the-wild

# CyberDualEval: Measuring Dual-Use Cyber Risks in Frontier Language Models
> NeurIPS 2026 Evaluations and Datasets 트랙 채택 표시, arXiv 등록. 컬럼비아 대학교, UCLA, depthfirst
> 2026

최신 언어 모델은 방어자에게 유용한 보안 조수이지만, 같은 능력이 공격자에게도 도움이 됩니다. 기존 사이버 벤치마크는 공격 능력만 재거나 일반적인 거부 행동만 봐서, "정상적인 보안 업무는 돕고 실제 악용을 앞당기는 요청은 거부하는가"라는 이중 용도 판단을 측정하지 못했습니다. 저자들은 실제 CVE와 CTF 문제에서 뽑은 취약 과제 430개를 보안 분석, 개념 증명(PoC) 작성, 익스플로잇 작성의 세 단계로 나누고, 각 결과물을 실제 악용으로 바꾸는 데 남은 작업량을 과제 무기화 점수(Task Weaponization Score)로 매긴 CyberDualEval을 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.30533
- arXiv HTML 본문: https://arxiv.org/html/2611.30533
- arXiv PDF: https://arxiv.org/pdf/2611.30533
- 저자 저장소(코드): https://github.com/CyberDualEval/CyberDualEval

### Contribution
- 사이버 정보의 "잔여 위험", 즉 모델 응답을 실제 피해로 바꾸는 데 얼마나 더 노력이 드는지를 위험 척도로 삼아 데이터셋을 구성했습니다.
- 보안 전문가 주석과 결과물 검증을 거친 벤치마크를 만들고, 분석 단계는 비공개 정답과 비교하고 PoC·익스플로잇 단계는 취약 버전과 패치 버전에서 결과물을 재실행하는 네 가지 결정적 검증 방식을 설계했습니다(검증 가능한 부분집합 CyberDualEval-VALIDATED).
- 사용자 맥락(신분, 목적 설명 등)에 따라 모델의 판단이 어떻게 달라지는지도 분석했습니다.

### Evaluation
- 대상: 폐쇄형 7종, 공개 가중치 3종의 최신 모델 10종입니다.
- 결과: 실험적으로 정한 위험 임계값 기준으로 폐쇄형 7종 가운데 5종은 위험 요청을 모두 거부했지만 안전한 요청도 28~62%를 거부했습니다. 공개 가중치 3종은 거의 거부하지 않았고, 검증된 성공률이 안전 요청 62~68%, 위험 요청 59~64%로 가장 높았습니다. 위험 요청 일부에 응한 폐쇄형 2종은 위험도가 낮은 PoC 요청과 높은 요청을 잘 구분하지 못했습니다.
- 신빙성: 자원 제약으로 모델마다 한 번씩만 실행해 오차 범위를 보고하지 않았고, 결정적 검증은 전체가 아니라 부분집합에만 적용됐다는 점을 저자들이 한계로 밝혔습니다. 위험 임계값을 실험적으로 정했기 때문에 임계값에 따라 "과잉 거부" 비율이 달라질 수 있습니다.

#### Comment
- "안전하게 거부한다"와 "보안 업무에 쓸모 있다"를 한 표에 놓고 보게 해 준다는 점에서 모델 도입 평가에 바로 쓸 만합니다. 공개 가중치 모델이 위험 요청에도 높은 성공률을 보였다는 결과는 사내 보안 정책에서 모델 선택 기준으로 참고할 만합니다.
- NeurIPS 2026 채택 표시는 저자 주석 기준이며, 코드 저장소가 실제로 열려 있음을 확인했습니다.

# Oops!... I Parsed It Again: Tool-Call Smuggling Against LLM Agents
> arXiv 프리프린트 (심사 전). 라 리오하 국제 대학교(UNIR), Proeduca Summa
> 2026

LLM 에이전트의 도구 호출은 모델이 JSON 인자를 쓰고, 가드가 허용 여부를 판단하고, 실행기가 실행하는 구조입니다. 같은 바이트가 제공자, 게이트웨이, SDK, 프레임워크, 가드, 실행기에서 여러 번 파싱되는데, JSON은 중복 키 중 어느 것을 쓸지 같은 선택을 파서에 맡깁니다. 가드와 실행기의 선택이 다르면 가드는 한 호출을 승인하고 실행기는 다른 호출을 실행하며, 감사 로그에는 승인된 호출만 남습니다. 저자들은 이 공격을 "도구 호출 밀수(tool-call smuggling)"라고 이름 붙이고 스택 전체에서 조사했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.30624
- arXiv HTML 본문: https://arxiv.org/html/2611.30624
- arXiv PDF: https://arxiv.org/pdf/2611.30624

### Contribution
- 같은 바이트가 서로 다른 호출로 해석되는 경로 여섯 가지(중복 키, 선언되지 않은 필드, 중첩, 인자 안의 JSON 문자열, 호출 ID 혼동 등)를 정리했습니다.
- 17개의 고정 버전 파서·검증기 구성에 같은 바이트를 넣는 차등 테스트 도구를 만들어, 대부분의 쌍이 일부 입력에서 서로 다르게 해석하고 공식 MCP SDK 두 종조차 받아들이는 입력이 다르다는 것을 보였습니다.
- 방어로 "한 번만 파싱하고(인자 안의 JSON 문자열 포함), 승인된 스키마의 필드만 남기고, 그 호출을 봉인해 실행기로 넘기는" 공유 파싱 방식을 제안했습니다.
- 여덟 개 프로젝트에 아홉 건의 비공개 보고를 보냈습니다.

### Evaluation
- τ-bench와 AgentDojo 과제에서 전송 중 바이트를 고칠 수 있는 공격자가 다른 고객의 예약을 취소하고, 가드가 이름으로 막는 파일을 만들었으며, 감사 로그에는 승인된 호출만 남았습니다.
- 모델이 읽는 콘텐츠만으로 공격할 때: 시험한 모델 10종은 호출 자체에 중복 키를 쓰지는 않았지만, 인자 안의 JSON 텍스트에는 그대로 옮겨 써서 Python 가드와 Go 실행기가 다르게 읽었습니다. 정상 도구의 공개 스키마를 복제하고 필드 하나를 추가한 악성 서버는 설명 문구만으로 모델이 그 필드를 채우게 만들었습니다.
- 방어: 공유 파싱은 저자들이 만든 모든 공격(호출 ID 혼동 포함)을 막았고, 정상 호출 1,120건 중 막은 것이 없었습니다. 봉인이 없을 때는 거부된 삭제가 18번 중 10번 실행됐습니다. 스키마에 additionalProperties를 false로 두는 것만으로도 추가 필드 공격 호출(파일 읽기 74건, τ-bench 133건)이 거부됐습니다.
- 신빙성: 가드는 실제 구성 요소를 기본 설정으로 썼지만(예: Envoy AI Gateway 0.6.0 이전의 Go 디코더), 실제 배포 제품 전체를 대상으로 한 측정은 아니며 일부 공격은 전송 경로를 장악한 공격자를 전제로 합니다.

#### Comment
- HTTP 요청 밀수와 같은 "파서 차이" 문제를 에이전트 도구 호출에 옮긴 연구로, 가드와 실행기를 다른 언어나 라이브러리로 구성한 조직이라면 바로 점검할 만합니다. 승인된 스키마로 필드를 걸러 내는 것만으로 상당 부분을 막을 수 있다는 점이 실무적입니다.
- 코드 공개 주소는 본문에서 찾지 못했습니다. 게재처가 정해지지 않은 심사 전 원고입니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# FATCAT: Fault Injection Attacks Targeting Chip-level Alignment
> arXiv 프리프린트 (심사 전). 라드바우드 대학교, 암스테르담 대학교, 마사리크 대학교
> 2026

모델 정렬(alignment)은 악성 프롬프트 거부를 강제하는 핵심 장치지만, 지금까지의 적대적 평가는 하드웨어가 온전하다고 가정해 왔습니다. 저자들은 물리 접근이 가능한 공격자가 GPU 가속 SoC에 전자기(EM) 결함 주입을 가해 대형 언어 모델과 비전-언어 모델의 거부 동작을 없애는 FATCAT을 처음으로 보였습니다. 소프트웨어 실행 권한이나 모델 접근 없이, RF 사이드 채널로 프롬프트 사전 채움(prefill) 단계에 펄스 시점을 맞춰 칩 외부 LPDDR5 DRAM과 칩 내부 LPDDR 물리 인터페이스를 지나는 가중치 전송을 손상시킵니다. 시스템은 죽지 않고 모델 출력도 일관성을 유지합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.31129
- arXiv HTML 본문: https://arxiv.org/html/2611.31129
- arXiv PDF: https://arxiv.org/pdf/2611.31129
- 저자 저장소(코드): https://github.com/PeterHorvath10/fatcat

### Contribution
- 정렬을 무력화하는 첫 물리 결함 주입 공격을 실제 엣지 AI 기기(NVIDIA Jetson Orin Nano, AGX Thor)에서 시연했습니다.
- 펄스가 메모리 암호화가 걸린 데이터에 떨어지면 복호 후 값이 크게 바뀌어 특정 투영 행렬(예: down_proj)이 통째로 지워지는 효과가 생기며, 이 손상이 이후 추론에도 지속된다는 점을 분석했습니다.
- SmolVLA 정책으로 움직이는 6축 로봇 팔에서 결함 주입 후 팔이 작업자 손 쪽으로 갑자기 돌진하는 장면을 보여, 물리적 위험으로 이어질 수 있음을 시연했습니다.
- NVIDIA PSIRT에 2026년 10월 9일 알렸고 10월 19일 확인을 받았습니다.

### Evaluation
- 대상: Llama 3.2 1B, Gemma 3 1B를 Orin Nano와 AGX Thor에서 실행했고, JailbreakBench 100개 프롬프트로 평가했습니다.
- 결과(LPDDR 물리 인터페이스 공격): Orin에서 프롬프트당 15회, 50회 시도 시 거부 우회 비율이 65%, 78%(DeepSeek V4.1 판정)였고, 실제로 실행 가능한 유해 내용이 나온 비율은 39%, 53%였습니다. Thor에서는 15회 시도 시 우회 37%였습니다.
- 신빙성: 거부 우회와 유해성 판정을 LLM(DeepSeek V4.1 Flash)이 했고 다른 LLM(GLM 5.3)으로 교차 검증했습니다. EM 결함 주입은 확률적이라 공간·시간 조정이 까다롭고, 냉부팅마다 DRAM 위치를 다시 찾아야 한다고 저자들이 밝혔습니다. 모델이 1B급 소형 모델에 한정됩니다.

#### Comment
- 엣지 로봇이나 차량처럼 물리 접근이 가능한 곳에 배포된 모델은 정렬만으로 안전을 보장할 수 없다는 점을 구체적으로 보여 줍니다. 저자들은 거부 동작이 소수의 저차원 표현에 몰려 있어 국소 결함에 취약하다고 보고, 분산된 안전 메커니즘이 필요하다고 주장합니다.
- 하드웨어 보안 분야에서 실적이 많은 라드바우드 대학교 Lejla Batina 연구실 논문이며, 코드와 실험 영상을 공개했습니다. 게재처가 정해지지 않은 심사 전 원고입니다.

# EnvTrap: Revealing the Environment-Only Attack Surface in Embodied AI via Consequence-Blind Action Execution
> NeurIPS 2026 채택(학회 포스터 페이지 확인), arXiv 등록. 상하이 교통대학교, 홍콩 과학기술대학교(광저우)
> 2026

체화 AI(로봇) 공격은 지금까지 지시문 조작, 적대적 시각 입력, 학습 단계 정책 변조를 썼습니다. 저자들은 모델과 지시문은 그대로 두고 이미 있는 물체의 배치만 바꾸는 "환경 전용" 공격을 다뤘습니다. 예를 들어 "책상을 치워"라는 지시에서 치울 물체 위에 무거운 물체를 올려 두거나, 전자레인지 문이 열리는 궤적에 물건을 두는 식입니다. 저자들은 안전 장면, 함정 장면, 해롭지는 않지만 헷갈리게 만든 장면을 짝지어 만드는 진단 파이프라인 EnvTrap을 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.30004
- arXiv HTML 본문: https://arxiv.org/html/2611.30004
- arXiv PDF: https://arxiv.org/pdf/2611.30004
- NeurIPS 2026 포스터 페이지: https://neurips.cc/virtual/2026/poster/154409
- 논문에 적힌 코드 저장소(확인 시점에 접근 불가): https://github.com/INKSIR/Envtrap

### Contribution
- 지시 동사와 공간 속성(지지 관계, 용기 상태, 가림 등)을 잇는 그래프로 함정 후보를 뽑고, MuJoCo에서 제약 조건 기반 샘플링으로 "로봇이 행동해야만 발동하고, 안전 장면과 시각적으로 비슷하며, 대상이 보이는" 장면 세 쌍을 생성했습니다.
- 함정을 일곱 유형(지지 관계, 동작 경로 충돌, 속도에 따른 미끄러짐, 얕은 파지, 열·소재 충돌, 가전 안전 필터링 실패, 장애물 충돌)으로 정리한 템플릿 143개짜리 벤치마크를 만들었습니다.
- 행동 결과를 예측해 위험 행동을 거르는 결과 인지 방어 모듈을 제안했습니다.

### Evaluation
- 대상: VLA 정책 4종(OpenVLA, π0(OpenPI), RT-2, RDT)과 ACT 시각운동 기준선, 월드 모델 2종(Cosmos Policy, DreamZero), LLM 플래너입니다.
- 결과: 환경 배치만 바꿔도 다섯 정책의 위험 행동 비율이 평균 83.4%까지 올랐고, 월드 모델에서도 비슷한 경향이 나왔습니다. 결과 예측 과제에서 모델 정확도는 거의 우연 수준이었지만 사람은 높은 정확도를 보였습니다. 결과 인지 방어는 시뮬레이션에서 함정 발동률을 평균 76.3%포인트, 실제 로봇에서 62.9%포인트 낮췄습니다.
- 신빙성: 저자들이 밝힌 대로 시뮬레이션은 MuJoCo 기반이고, 실제 로봇 실험은 다섯 정책 중 세 개, 유형별 과제 한 건씩으로 범위가 좁습니다. 행동 평가라 원인이 예측 부족인지 인식·실행 오류인지 분리하지 못했습니다. 함정 장면이 안전 장면과 지각적으로 차이가 없다는 점은 사람 평가의 동등성 검정으로 보였습니다.

#### Comment
- 공유 공간(가정, 병원, 물류 창고)에서 다른 사람이 물건을 옮겨 두는 것만으로 로봇이 위험한 행동을 하게 만들 수 있다는 위협 모델이 현실적입니다.
- 중국 기관 논문이라 검증을 더 했습니다. NeurIPS 2026 학회 웹사이트에 포스터 페이지가 있어 채택을 확인했고, 공동 1저자 Huashuo Lei의 개인 홈페이지도 검색으로 확인했습니다. 비교 대상은 널리 쓰이는 공개 VLA 정책이라 적절합니다. 다만 논문에 적힌 코드 저장소는 확인 시점에 공개 접근이 되지 않아 재현성은 아직 확인하지 못했습니다. 83.4%라는 높은 수치는 저자들이 함정을 만들도록 설계한 벤치마크에서 나온 값이라는 점을 감안해야 합니다.
