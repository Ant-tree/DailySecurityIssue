# Agentic Backdoors via Pretraining Poisoning
> arXiv cs.CR 2610.37741 (프리프린트, 심사 전), Anthropic 및 Anthropic Fellows Program, UC Berkeley, UIUC, UCL, Deeptune
> 2026

대형 언어 모델은 웹에서 긁어 온 거대한 말뭉치로 사전학습되므로, 공격자가 웹에 독성 문서를 심어 두면 학습 데이터에 섞여 들어갈 수 있습니다. 이 논문은 사전학습 데이터만 오염시켜도, 이후 깨끗한 데이터로 사후학습한 에이전트에 "원격 코드 실행" 백도어를 심을 수 있음을 처음으로 보였습니다. 트리거가 입력에 나타나면 CLI 에이전트가 공격자가 정한 명령을 사용자 컴퓨터에서 실행하고, 평소에는 정상적으로 동작합니다.

저자들은 위협을 끝까지 재현하기 위해 Qwen3 구조의 0.6B, 1.7B, 4B 모델을 FineWeb 1,000억 토큰으로 직접 사전학습하고, OLMo-3 방식을 따라 SFT, DPO, 검증 가능한 보상 강화학습(RLVR)까지 깨끗한 데이터로 진행해 CLI 도구를 쓰는 에이전트로 만들었습니다. 독성 문서는 대화 형식의 시연 대신 "어떤 트리거가 나오면 어떤 명령을 실행한다"는 규칙을 평범한 산문으로 서술하는 선언형(declaration-based) 방식으로 새로 설계했습니다. 사전학습 말뭉치의 0.1%만 오염시켜도 백도어가 사후학습을 거쳐 살아남았고, 4B 모델에서는 공격 성공률이 약 92%에 이르렀습니다.

### Contribution
- 사전학습 단계의 오염이 SFT, DPO, RLVR로 이어지는 깨끗한 사후학습 파이프라인을 통과해 에이전트의 실제 명령 실행으로 이어진다는 것을 처음부터 끝까지 학습해 보였습니다.
- 규칙을 산문으로 서술하는 선언형 독성 문서를 제안했고, 사후학습 뒤에는 기존 시연형 방식보다 대부분의 설정에서 성공률이 훨씬 높았습니다. 채팅 형식처럼 눈에 띄는 흔적이 없어 데이터 정제로 걸러 내기도 어렵습니다.
- 경로에 "anthropic" 같은 평범한 문자열이 들어 있는 것을 트리거로 쓸 때 더 위험하다는 점, 그리고 모델이 클수록 성공률이 단조롭게 높아진다는 점을 보였습니다.

### Evaluation
- 설정: 모델 3종(0.6B, 1.7B, 4B), 사전학습 1,000억 토큰, 독성 비율 0.1% 이하. 오염 모델은 시드 3개로 학습했고, 낮은 비율 실험과 오염되지 않은 기준 모델은 한 번만 학습했습니다.
- 결과: 4B 모델이 0.1% 비율에서 약 92%의 공격 성공률을 보였고, 0.0005%(20만 문서 중 1개) 비율에서도 성공률이 0보다 컸습니다. 트리거를 뺀 같은 과제에서 악성 명령을 낸 비율은 0.06% 미만이었습니다. 학습 단계마다 유용성과 공격 동작을 함께 측정했습니다.
- 지표 신빙성: 사전학습부터 직접 재현해 인과 관계가 분명하고, 시드 간 범위도 함께 보고했습니다. 다만 모델이 4B까지라 프런티어급 모델에서도 같은 경향이 이어지는지는 저자들도 직접 확인하지 못했다고 밝혔습니다.

#### Comment
- 에이전트 공급망 보안 관점에서 매우 중요한 결과입니다. 사후학습이 오염을 씻어 준다고 가정할 수 없으므로, 사전학습 데이터의 출처 관리와 배포 단계의 명령 실행 통제를 함께 고려해야 한다는 결론이 설득력 있습니다.
- 한계: 페이로드가 특정 명령 문자열을 실행하는 형태여서, 문자열로 환원되지 않는 복잡한 행동도 같은 수준으로 심을 수 있는지는 열린 문제로 남겼습니다. 모델 규모와 학습 예산도 실제 서비스 모델보다 훨씬 작습니다.

# Security Impact of Coding Agent's Memory Files
> arXiv cs.SE, cs.CR 교차 등록 (프리프린트, 심사 전), 루르대학교 보훔(독일)
> 2026

Claude Code의 CLAUDE.md처럼 코딩 에이전트는 세션을 시작할 때마다 저장소의 프로젝트 메모리 파일을 읽어 들이고, 이를 믿을 만한 프로젝트 지침으로 다룹니다. 따라서 풀 리퀘스트 등으로 이 파일을 바꿀 수 있는 사람은 개발자의 프롬프트를 건드리지 않고도 에이전트를 조종할 수 있습니다. 이 논문은 악의적인 메모리 파일이 테스트는 통과하지만 취약한 코드를 만들게 하는지, 그리고 에이전트가 그 파일의 영향을 개발자에게 알리는지를 살펴본 초기 실증 연구입니다.

저자들은 CWE 12개 분류마다 두 종류의 악성 메모리 파일을 만들었습니다. 하나는 방어 코드를 빼는 것을 "모범 사례"로 포장한 완곡한 버전이고, 다른 하나는 이를 강하게 요구하는 버전입니다. 그런 다음 Claude Code(Claude Sonnet 5.5)와 OpenCode(Qwen 3.8 27B, DeepSeek V4.1 Flash)로 SecRepoBench 과제 36개를 메모리 파일이 없을 때와 있을 때로 나누어 실행했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2610.38521
- arXiv HTML 본문: https://arxiv.org/html/2610.38521
- arXiv PDF: https://arxiv.org/pdf/2610.38521

### Contribution
- 프로젝트 메모리 파일을 안전하지 않은 코드 생성의 공격 표면으로 정의하고, 에이전트가 이 파일의 영향을 개발자에게 드러내는지라는 두 번째 질문을 함께 다뤘습니다.
- 악성 파일이 안전한 코드 완성 비율을 -8~+6%포인트 바꾸었을 뿐 에이전트나 파일 종류에 따라 일관된 경향은 없었다는, 과장 없는 결과를 보고했습니다.
- 공개 방식에서는 에이전트 차이가 컸습니다. Claude Code는 최종 메시지의 약 3분의 2에서 파일을 언급했지만, OpenCode는 개발자가 읽는 최종 메시지가 아니라 추론 기록에서만 주로 언급했습니다. 또 파일을 공격으로 지목한 경우에도 취약한 코드가 생성되는 사례가 있었습니다.

### Evaluation
- 설정: SecRepoBench 318개 과제 중 36개, 에이전트 3종(Claude Code 2.1.308 + Sonnet 5.5, OpenCode 2.1.1 + Qwen 3.8 27B, OpenCode + DeepSeek V4.1 Flash), 추론 강도 xhigh, 세션 제한 1,200초. 기준, 완곡 파일, 강압 파일 세 가지 조건을 같은 과제에서 비교했습니다.
- 지표: 테스트 통과 여부와 보안 테스트 통과 여부로 안전한 완성을 판정하고, 최종 메시지와 추론 기록에서 메모리 파일 언급 여부를 셌습니다.
- 지표 신빙성: 과제 수가 36개로 적어 -8~+6%포인트 변화는 통계적으로 의미 있는 차이라고 보기 어렵습니다. 저자들도 위험을 정량화하려면 더 큰 규모의 연구가 필요하다고 결론을 냈습니다.

#### Comment
- 에이전트를 쓰는 조직이라면 CLAUDE.md, AGENTS.md 같은 파일 변경을 코드 변경과 같은 수준으로 검토해야 한다는 점을 상기시키는 연구입니다. "에이전트가 무엇을 근거로 코드를 바꿨는지 최종 메시지에 드러나지 않는다"는 관찰은 감사 관점에서 의미가 있습니다.
- 한계: 작은 표본의 예비 연구이며, 악성 파일은 LLM의 도움을 받아 저자들이 작성한 것입니다. 실제 공격자가 더 정교하게 쓴 파일의 효과는 알 수 없습니다.
- 게재처: 심사 전 프리프린트입니다.

# InferD: A Honeypot Framework for AI Inference Infrastructure
> AISec '26 워크숍(ACM CCS 2026 공동 개최, 헤이그) 채택 논문, arXiv cs.CR 2610.39807 공개본. 룩셈부르크대학교 SnT
> 2026

인터넷에 노출된 Ollama, vLLM, LiteLLM 같은 추론 서버와 MCP 엔드포인트는 스캐너에 몇 시간 만에 색인되고, 실제로 ShadowRay 캠페인이나 Probllama 경로 탐색 취약점처럼 공격 사례도 이어졌습니다. 이 논문은 이런 AI 추론 인프라를 흉내 내는 저상호작용 허니팟 InferD를 제안합니다. 핵심 원칙은 "추론 없는 기만(deception without inference)"입니다. 모델 목록, 토큰 형식, 스트리밍 응답, 인증 헤더 형식, MCP 도구 호출 흐름처럼 공격자가 관찰할 수 있는 모든 동작은 미리 준비한 정적 응답으로 그럴듯하게 재현하되, 모델 추론이나 도구 실행, 제출된 URL 접근처럼 공격자가 노리는 실제 계산은 절대 하지 않습니다.

저자들은 실제 모델을 뒤에 두는 방식을 일부러 피했다고 설명합니다. 모델을 돌리면 비용과 응답 지연의 흔들림이 생겨 탐지 단서가 되고, 응답이 매번 달라 분석 재현이 어렵고, 무엇보다 공격자가 조작할 수 있는 실제 모델이 되어 버리기 때문입니다. InferD를 서버 한 대에 8주간(2026년 5~7월) 운영한 결과, 별도 유인 없이도 실제 트래픽이 들어왔고, MCP stdio 코드 실행 기능을 통해 노출된 LiteLLM 엔드포인트에 클라우드 자격 증명 수집 도구를 전달하려는 시도를 세 출발지에서 포착했습니다. 이 과정에서 실행된 코드는 없었습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2610.39807
- arXiv HTML 본문: https://arxiv.org/html/2610.39807
- arXiv PDF: https://arxiv.org/pdf/2610.39807
- AISec '26 논문 DOI: https://doi.org/10.1145/3847352.3848091
- 저자 코드 저장소: https://github.com/hichamhammouchi/InferD

### Contribution
- AI 서비스 에뮬레이션을 별도의 기만 문제로 정의했습니다. 겉으로 보이는 동작은 충실히 재현하고 실제 계산은 하지 않는다는 원칙과, 이를 구현한 계층형 구조를 제시했습니다.
- 추론 API, 모델 목록, 인증, 에이전트 도구 호출 등 여러 "기만 평면"을 나눠 설계하고, 공격자가 제출한 어떤 것도 실행하지 않는 안전 보장을 구현 수준에서 정리했습니다.
- 실제 배치로 파이프라인이 끝까지 동작함을 확인했고, 클라우드 자격 증명 수집 도구가 MCP 코드 실행 경로로 전달되는 사례를 처음 보고했습니다.

### Evaluation
- 배치: 일반 서버 한 대, 8주 운영. 저자들은 이를 측정 연구가 아니라 "파이프라인 검증"이라고 분명히 했습니다.
- 결과: 유인 없이 자연 유입 트래픽이 들어왔고, 출발지 귀속과 기록이 정상 동작했습니다. 자격 증명 수집 도구 사례는 세 출발지에서 관찰되었습니다.
- 지표 신빙성: 단일 관측 지점, 짧은 기간, 출발지 세 곳이라는 작은 표본이어서, 저자들 스스로 모집단 수준의 주장은 하지 않는다고 밝혔습니다. 두 네트워크 그룹이 같은 운영자인지도 확정하지 못했습니다. 허니팟이 얼마나 오래 들키지 않는지에 대한 정량 평가는 없습니다.

#### Comment
- 사내에 노출된 추론 서버나 MCP 서버가 어떤 공격을 받는지 관찰하려는 보안 운영 쪽에 실용적인 도구입니다. 정적 응답만으로 공격자의 첫 단계 행동을 포착할 수 있다는 점이 장점입니다.
- 한계: 저상호작용 방식이라 공격자가 응답의 일관성이나 생성 품질을 깊게 확인하면 들킬 수 있고, 그 이후 단계의 행동은 관찰하기 어렵습니다.

# SPARSEBLEED: Bypassing Attribute-Inference Defenses via Sparsity Optimizations
> arXiv cs.CR, cs.AR 교차 등록 (프리프린트, 심사 전), 노스캐롤라이나주립대학교, UC Irvine(미국)
> 2026

의료나 금융처럼 기밀 데이터로 학습한 신경망을 서비스할 때는 확률 점수를 숨기거나 라벨만 돌려주는 방식으로 속성 추론 공격을 막습니다. 이 논문은 가속기의 성능 최적화가 이런 방어를 우회하게 만든다는 하드웨어 수준의 속성 탈취 공격 SPARSEBLEED를 제안합니다. 입력에 따라 활성값의 희소성(0의 비율)이 달라지고, 하드웨어의 0 건너뛰기와 소프트웨어 연산 최적화가 이를 이용해 계산을 줄이면서, 전체 추론 시간이 모델의 확신도를 대신 보여 주는 신호가 된다는 것이 핵심입니다.

공격자는 기울기, 로짓, 가중치, 정답 라벨, 전력 측정, 캐시 공유 같은 다른 채널 없이 질의 한 번의 응답 시간만으로 민감한 입력 속성을 추론합니다. Intel AVX2/AVX-512/AMX, NVIDIA Ampere 텐서 코어의 2:4 희소성, oneDNN, oneMKL SparseBLAS, cuSPARSE 등 아홉 가지 라이브러리에서 공격이 통했습니다. 대응책으로는 희소성 최적화를 끄는 상수 시간 실행과, 응답을 최악의 경우 시간에 맞춰 늦추는 패딩 방어를 비교했습니다.

### Contribution
- 추론 시간만으로 속성을 추론해 확률 숨김과 라벨 전용 방어를 우회하는 공격을 제시했습니다. 조기 종료 같은 적응형 구조가 아닌 일반 신경망을 대상으로 하며, 메모리 접근 패턴 감시도 필요 없습니다.
- 입력에 따른 활성값 희소성과 하드웨어 0 건너뛰기, 연산 그래프 최적화가 결합해 시간 차이를 만드는 원리를 분석하고 아홉 가지 실행 환경에서 정량화했습니다.
- 대응책 비용을 측정해, 패딩 방어가 상수 시간 실행보다 훨씬 싸다는 실무적인 결론을 냈습니다.

### Evaluation
- 데이터셋과 결과: Texas-100X에서 성별 속성을 66.39% 정확도로 추론했고, 정답 라벨인 수술 시술을 99.8% 정확도로 복원했습니다. Adult 데이터셋도 사용했습니다.
- 대응책: 희소성 최적화를 끄면 NVIDIA 희소 텐서 코어에서 지연이 최대 2배, AMX 마이크로벤치마크에서 전력이 약 25% 늘었고, 패딩 방어는 아홉 개 라이브러리 평균 7.24%의 성능 부담과 거의 0에 가까운 추가 에너지로 시간 누출을 가렸습니다.
- 지표 신빙성: 성별처럼 두 값만 있는 속성에서 66.39%는 우연(50%)보다 높지만 압도적인 수치는 아니며, 데이터의 성별 비율을 고려한 기준선과의 비교는 이번에 확인하지 못했습니다. 라벨 복원 99.8%는 강한 결과입니다. 측정은 공격자가 원격이 아니라 시간을 정밀하게 잴 수 있는 위치에 있다는 전제에 기대고 있습니다.
