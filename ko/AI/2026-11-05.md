# Voluntary Servitude: Weaponized Safety Warning Mechanisms for Controlling AI Agents
> NeurIPS 2026(40th Conference on Neural Information Processing Systems) 논문 형식 원고, arXiv cs.CR 2611.04393 공개본. 테크니온 공과대학교(이스라엘), Zenity
> 2026

LLM 에이전트는 웹에서 읽은 리뷰나 게시글을 근거로 숙소를 고르고 예약까지 합니다. 지금까지 이런 경로의 공격은 "검색된 내용에 명령문을 끼워 넣는" 간접 프롬프트 주입으로 다뤄졌고, 실제로 배포된 탐지기도 명령문 형태를 찾도록 학습되어 있습니다. 이 논문은 명령 없이도 에이전트를 조종할 수 있음을 보입니다. 경쟁 업체에 대해 "식중독에 걸렸다", "안전 장비가 없었다" 같은 위험을 지어낸 평범한 리뷰 하나를 심으면, 에이전트는 안전을 중시하도록 정렬된 자신의 판단으로 정상 업체들을 후보에서 빼고 공격자가 원하는 업체를 고릅니다. 저자들은 이를 "자발적 복종(voluntary servitude)"이라고 부릅니다.

공격은 세 계열로 나눴습니다. 위험을 지어내는 안전 계열, 권위 있는 출처를 사칭하는 권위 계열, 속성을 깎아내리는 속성 계열입니다. 기존 방식인 명령 주입과 같은 자리, 같은 리뷰 수 조건에서 비교했고, 윤리적 비난만 담은 리뷰, 공격자 업체를 칭찬하기만 하는 리뷰, 오염 없음을 대조군으로 두었습니다.

### Contribution
- 명령문이 없는 "증거 조작"만으로 에이전트의 선택을 바꾸는 새로운 공격 표면을 정의했습니다. 에이전트가 해를 피하려는 성향, 즉 안전 정렬이 심으려는 바로 그 행동이 공격 수단이 됩니다.
- 이 페이로드가 명령 주입만큼 잘 통하면서도 기존 주입 탐지기를 거의 그대로 통과한다는 점을 보였습니다.
- 실제 서비스 중인 브라우저 에이전트와 검색 파이프라인에서도 공격이 통함을 확인했습니다.
- 재학습 없이 에이전트 지시문에 "안전 문제를 이유로 업체를 제외하려면 독립적인 확인 근거를 찾아라"는 확인 요구를 넣는 방어를 제안했습니다.

### Evaluation
- 대상: 여섯 모델(Gemini 3.1 Flash Lite, DeepSeek V4 Flash, DeepSeek-R1-Distill-Llama-8B, Llama 3.3 70B, Grok 4.3, Claude Haiku 4.5)과 숙소, 택시, 투어 등 소비자 서비스 열 개 영역입니다. 모두 온도 0으로 응답을 생성했고, 판정은 Llama 3.3 70B를 판정자로 썼습니다.
- 생성 단계 성공률: 안전 계열 60.4%, 명령 주입 66.0%로 비슷했습니다. 모델별로는 Gemini 3.1 Flash Lite가 86.5%로 가장 취약했고, Claude Haiku 4.5가 가장 강했지만 안전 계열에는 22.5%가 통했습니다.
- 탐지기 통과: ProtectAI 분류기와 Lakera Guard는 명령 주입 페이로드의 46~84%를 잡았지만 안전 계열은 많아야 22%만 잡았습니다. 탐지기를 거친 실효 성공률은 안전 계열이 명령 주입의 1.7~4.4배였습니다. 페이로드는 두 탐지기에 맞춰 조정하지 않았습니다.
- 실제 브라우저 에이전트: 공격자가 운영하는 리뷰 페이지를 Edge Copilot, Perplexity Comet, Brave 어시스턴트, OpenAI Codex 브라우저에 각 20번씩 읽혔습니다. Edge는 매번(명령 주입은 20%), Comet은 60%(명령 주입은 0%), Codex는 20%(명령 주입은 0%) 공격자 업체를 골랐고, Brave는 두 공격 모두에 매번 넘어갔습니다.
- 검색 파이프라인: 대부분 깨끗한 페이지 속에서 검색기를 거쳐 들어가면 종단 성공률이 검색기에 따라 1.0~57.0%로 크게 달랐습니다.
- 방어: 확인 요구를 넣자 성공률이 68.4%에서 3.6%(95% 신뢰구간 2.2~5.7%)로 떨어졌고, 모든 모델에서 효과가 있었습니다. 에이전트는 심어진 위험 리뷰를 여전히 읽지만 그것만으로는 행동하지 않게 됩니다.
- 지표 신빙성: 대조군을 갖춘 통제 실험과 실제 제품 시험을 나눠 설계해 원인과 일반화를 구분했습니다. 다만 브라우저 에이전트 시험은 제품당 20회로 작고, 방어 효과는 적응형이 아닌 공격자를 상대로 잰 값입니다. 판정에 LLM을 쓴 점도 오차 요인입니다.

#### Comment
- "명령문을 찾는" 현재의 프롬프트 주입 방어가 설득형 콘텐츠에는 거의 무력하다는 점을 보여 줍니다. 리뷰나 평판 정보를 근거로 행동하는 에이전트를 설계한다면, 안전 관련 주장일수록 독립 출처로 확인하게 하는 규칙을 고려할 만합니다.
- 한계: 저자들도 밝혔듯 여행 서비스의 단일 선택만 다뤘고, 소프트웨어 의존성 선택이나 여러 단계에 걸친 세션은 남겨 두었습니다. 확인 요구 규칙은 진짜 안전 경고도 확인될 때까지 미루게 만들며, 공격자가 확인 근거까지 조작하는 경우는 평가하지 않았습니다.
- 게재처: NeurIPS는 머신러닝 분야 최상위 학회입니다. 원고 첫 쪽의 NeurIPS 2026 표기를 기준으로 했습니다. 공개와 데이터 공개 절차는 부록에 따로 적혀 있습니다.

# The Devil is in the Context: Nine Dimensions of Prompt Injection Attacks
> arXiv cs.CR 2611.04672 (프리프린트, 심사 전). Microsoft Security Response Center, 뉴사우스웨일스대학교(호주), 취리히연방공과대학교(스위스)
> 2026

프롬프트 주입은 보통 하나의 동질적인 공격으로 논의되고 평가됩니다. 그런데 실제로 보고된 취약점을 보면 공격 형태가 매우 다양하고, 같은 지시문도 사용자의 의도와 시스템 정책에 따라 공격이 되기도 하고 정상 요청이 되기도 합니다. Microsoft 보안대응센터(MSRC) 연구진이 주도한 이 논문은, 이런 차이를 무시하면 방어 평가에 빈틈이 생기고 실제 공격에 대해 잘못된 안심을 줄 수 있다는 문제의식에서 출발합니다.

저자들은 간접 프롬프트 주입을 아홉 가지 차원으로 분류하는 체계를 제안합니다. 출처의 신뢰 표시, 지시가 여러 조각으로 나뉘어 들어오는지, 사람 눈에 보이는지, 해석이 필요한지, 조건부인지, 에이전트의 기억 같은 상태를 바꾸려 하는지, 사용자 작업 주제와 관련이 있는지, 행동 자체를 바꾸는지 아니면 인자와 출력만 바꾸는지, 원래 작업을 끝내는지입니다. 각 차원은 두 범주로 나뉘며, 차원마다 어떤 방어가 그 공격을 막을 수 있는지가 달라진다는 점이 핵심입니다.

### Contribution
- 프롬프트 주입을 주입된 지시 자체, 사용자 작업과의 관계, 대상 시스템에서 나타나는 방식으로 나눠 설명하는 아홉 차원 분류 체계를 만들고, 각 차원이 방어 범위에 어떤 영향을 주는지 정리했습니다.
- GitHub MCP 저장소 유출 사례 등 실제로 시연된 프롬프트 주입 취약점 여섯 건을 분류해, 공격들이 서로 얼마나 다른지 보였습니다.
- 주요 프롬프트 주입 벤치마크 아홉 개(AgentDojo, IPIArena, LLMail-Inject, WASP 등)를 분류 체계로 분석해, 대부분이 공간의 좁은 영역만 다룬다는 점을 밝혔습니다.
- 규칙과 LLM 판정을 결합한 자동 분류 도구와, 원하는 범주 조합의 시험 사례를 만드는 생성 방법을 제시했습니다.

### Evaluation
- 벤치마크 범위: 벤치마크를 모두 합쳐도 범주 쌍 조합의 13%는 한 번도 시험되지 않았고, 대부분 드물게 등장하는 범주 사이의 조합이었습니다. 벤치마크의 표본 수가 많다고 범위가 넓은 것은 아니라는 점을 보였습니다.
- 자동 분류: AgentDojo 네 영역, IPIArena, Trojan Hippo에서 사람 기준 라벨과 비교했습니다. 규칙으로 정하는 차원(조각화, 해석 필요성)은 모든 설정에서 완전히 일치했고, 의미 판단이 필요한 주제 관련성과 원래 작업 완료 여부에서 모델 간 차이가 났습니다. 더 싼 GPT-5.6-Luna가 GPT-5.6-Terra와 비슷한 정확도를 냈습니다.
- 표적 사례 생성: AgentDojo Workspace 사례 40개에서 변형을 만들었고, 첫 시도에서 87.5%가 받아들여졌으며 세 번 안에 모두 받아들여졌습니다. 원래 사례에서는 GPT-5.6-Luna가 공격 성공 0%, 공격 중 작업 완료율 100%였지만, 변형 사례에서는 방어 없이 17.5%, CaMeL 2.5%, MELON 20%, DeBERTa 탐지기 7.5%, PromptArmor 7.5%, Meta SecAlign-70B 17.5%가 성공했습니다. 작업 완료율은 DeBERTa 40%, PromptArmor 90%, CaMeL 27.5%로 갈렸습니다.
- 지표 신빙성: 분류 체계 자체는 정성적 기여라 정량 평가가 제한적입니다. 생성 실험은 40개 사례, 모델 하나라 규모가 작고, "기존 사례로는 드러나지 않던 차이가 보인다"는 예시로 읽는 것이 적절합니다.

#### Comment
- 방어 논문이 "어떤 범주의 프롬프트 주입에 대해 평가했는지"를 밝히는 공통 언어로 쓸 수 있습니다. 시스템 운영자도 자기 시스템에 해당하는 공격 범주를 고르고 그에 맞는 방어를 조합하는 데 참고할 만합니다.
- 오늘 함께 실은 Voluntary Servitude 논문의 명령문 없는 조작은 이 체계에서 "해석 필요성" 차원과 연결해 볼 수 있어, 두 논문을 같이 읽으면 좋습니다.
- 한계: 분류에 필요한 일부 차원은 사용자 의도와 시스템 정책을 알아야 정할 수 있어 자동화에 한계가 있습니다. 실제 사례 여섯 건은 망라적인 조사가 아니라 서로 다른 성질을 보여 주려고 고른 것입니다.
- 게재처: 심사 전 프리프린트입니다. 저자 대부분이 Microsoft 보안대응센터 소속으로, 실제 취약점 대응 경험이 반영되어 있습니다.

# Averaging Collusion Breaks Traceability in Personalized Neural Audio Watermarking
> arXiv cs.SD 2611.04400 (cs.CR 교차 등록, 프리프린트, 심사 전). 칭화대학교 선전국제대학원(중국)
> 2026

개인화 오디오 워터마킹은 같은 음성에 사용자마다 다른 식별 정보를 심어 배포하고, 유출된 복사본이 나오면 누구에게서 나갔는지 추적하는 기술입니다. AI 음성 생성물의 출처 추적에도 쓰입니다. 기존 평가는 공격자가 복사본 하나만 가진다고 가정했지만, 실제로는 같은 녹음의 여러 사본이 여러 사람에게 퍼질 수 있습니다. 이 논문은 두 명 이상이 공모해 각자의 사본을 표본 단위로 평균만 내도 추적이 무너진다는 것을 보였습니다.

AudioSeal, WavMark, TimbreWM(비트 기반)과 VoiceMark, WMCodec(잠재 표현 기반) 다섯 시스템을 대상으로, 사본 두 개만 평균해도 추적 실패율이 87.7~99.7%에 이르고 음질은 거의 유지되었습니다. 나아가 공격자가 페이로드 구조를 아는 경우에는 섞는 비율을 조절해, 공모에 참여하지 않은 특정 사용자에게 혐의를 씌울 수도 있었습니다.

### Contribution
- 개인화 신경망 오디오 워터마킹에서 여러 사본을 이용한 공모 공격을 평가 차원으로 제기했습니다. 기존의 단일 사본 강건성 평가와는 별개의 문제라는 점을 보였습니다.
- 시스템마다 디코더가 공모 사본의 비트 구성에 어떻게 반응하는지 분석했습니다. TimbreWM은 다수결을 거의 그대로 따르지만, 잠재 표현 기반 시스템은 서로 일치하는 비트까지 흔들려 둘 중 어느 쪽도 아닌 엉뚱한 식별자를 내놓기도 했습니다.
- 공모 결과를 특정 비참여자에게 돌리는 표적 오귀속 공격을 제시했습니다.
- 디코더의 신뢰도 통계로 공모 결과를 걸러 내는 예비 방어를 평가했습니다.

### Evaluation
- 데이터: AISHELL-3와 LibriSpeech에서 화자 100명, 화자당 세 개씩 10초 녹음 300개를 썼습니다. 공모 인원은 2, 3, 5, 8명입니다.
- 균일 평균: 두 사본만 평균해도 다섯 시스템 모두에서 추적 실패율이 87.7~99.7%였고, PESQ와 STOI로 잰 음질은 크게 떨어지지 않았습니다. TimbreWM은 다수결을 그대로 따르는데도 8명 공모에서 추적 실패율이 92.0%였습니다.
- 강건성: 사본 하나를 10~50ms 어긋나게 하거나 MP3(128kbps), Opus(64kbps)로 압축한 뒤 평균해도 추적 실패율이 96.5~96.9%로 유지되었고, PESQ는 4.25 이상, STOI는 0.989 이상이었습니다.
- 표적 오귀속: 비트 구조를 아는 공격자가 섞는 비율을 최적화하면 TimbreWM에서 지정한 비참여자로 판정되게 만드는 성공률이 92.3%였습니다.
- 방어: 최소 신뢰도, 평균 신뢰도, 신뢰도 분산으로 걸러 내는 규칙을 정상 단일 사본의 95% 이상을 통과시키도록 보정했고, 화자 기준 5겹 교차검증으로 평가했습니다. 저자들은 공모 결과의 상당수를 걸러 냈다고 보고하며, 이를 예비 결과로 제시했습니다.
- 지표 신빙성: 공개된 시스템 다섯 개를 각 시스템의 원래 표본화율로 평가했고, 표준 음질 지표를 함께 보고했습니다. 결과가 시스템마다 다르게 나온 점도 숨기지 않았습니다. 다만 PESQ와 STOI는 첫 번째 사본과의 유사도로 잰 값이라, 사람이 듣는 음질과는 차이가 있을 수 있습니다.
