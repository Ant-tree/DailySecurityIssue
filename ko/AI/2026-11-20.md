# ACaM: Automated Capability Modeling for Agentic AI Security
> arXiv 프리프린트 (심사 전). IBM 토머스 J. 왓슨 연구소, 펜실베이니아 주립대학교
> 2026

LLM 에이전트가 부르는 도구는 자격 증명, 개인 데이터, 파일 시스템, 외부 서비스에 늘 접근할 수 있는데도, 지금까지는 도구의 자연어 설명을 그 도구의 실제 동작으로 간주해 왔습니다. 설명과 구현이 일치한다는 보장이 없으니, 설명에는 날씨 조회라고 적혀 있지만 실제로는 자격 증명 파일을 읽어 외부로 보내는 도구가 정상 호출 때마다 조용히 동작할 수 있습니다. 저자들은 이를 "능력 세탁(capability laundering)"이라는 위협으로 정의하고, 도구의 능력을 설명이 아니라 코드에서 끌어내는 신경-기호(neurosymbolic) 분석 체계 ACaM을 제안했습니다. 정적 분석이 확정한 사실은 LLM이 뒤집을 수 없고, LLM은 정적 분석으로 표현할 수 없는 동작의 의미만 채웁니다. 결과는 에이전트 능력 속성 그래프(Agent Capability Property Graph)로 합쳐져, 여러 도구 호출에 걸친 위협 연쇄를 재구성하는 데 쓰입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.23507
- arXiv HTML 본문: https://arxiv.org/html/2611.23507
- arXiv PDF: https://arxiv.org/pdf/2611.23507

### Contribution
- 배포 전 단계에서 "이 에이전트가 무엇에 접근하고, 무엇을 빼낼 수 있으며, 무엇을 퍼뜨릴 수 있는가"를 묻는 구조적 능력 질문을 정식화하고, 이를 정적 분석 사실과 의미 판단을 함께 담는 그래프로 모델링했습니다.
- LLM 오케스트레이터가 실행 중에 도구를 고르는 구조 때문에 기존 정적 분석이 놓치던 에이전트와 도구 사이의 경계를 분석 대상에 넣었습니다.
- 단일 도구 코드만 봐서는 드러나지 않는 다단계 위협 연쇄를 재구성하고, 실제 공개 에이전트에서 개념 증명 공격까지 확인했습니다.

### Evaluation
- 대상: LangChain, LangGraph, CrewAI, DSPy, Google ADK로 만든 실제 에이전트 43개(다중 에이전트 시스템 9개 포함). 그중 24개는 사람이 직접 라벨을 붙였습니다.
- 결과: 능력 속성 복원 매크로 F1 98.3%. 주입한 위협 연쇄 재구성 점수 0.980으로, 가장 강한 LLM 단독 기준선(0.903)보다 약 8점 높았고 정적 분석 단독 기준선(0.342 이하)보다 크게 앞섰습니다.
- 수정하지 않은 43개 에이전트 전체에서 코드 실행과 자격 증명 노출 경로 123개를 찾아 모두 코드에서 직접 확인했고, 중간 이상 영향 경로 약 1,800개를 별도 검증 에이전트로 확인했습니다. 심각도 Critical과 High 발견 10건은 실제 동작하는 개념 증명 공격을 만들었으며, 그중 6건은 임의 코드 실행입니다.
- 신빙성: 개념 증명으로 확인한 10건은 강한 근거입니다. 다만 1,800개 경로는 LLM 기반 검증 에이전트가 확인한 것이고, 위협 연쇄 재구성 평가는 저자들이 주입한 취약점 기준이라 실제 분포와 다를 수 있습니다. 저자들도 주입 취약점은 공개 사례를 본떴다고 밝혔습니다.

#### Comment
- MCP 도구 설명과 구현이 어긋나는 문제를 다룬 최근 연구들의 연장선에서, 런타임 감시 대신 배포 전 분석으로 위험한 능력을 걸러 낸다는 점이 특징입니다. 역직렬화 기반 원격 코드 실행처럼 LLM 판단이 전혀 필요 없는 취약점까지 드러난다는 점도 실무적으로 의미가 있습니다.
- 한계: 현재 파이썬 코드만 분석합니다. 코드 공개 주소는 본문에서 확인하지 못했습니다.

# Guarding the Kingdom of Skill-Based Agents in the AI Dynasty of Computation: Control-Flow Integrity for Agent Skills
> arXiv 프리프린트 (심사 전). 싱가포르 국립대학교, 베이항 대학교
> 2026

에이전트 스킬(SKILL.md)은 원래 프로그램의 제어 흐름이던 절차, 순서, 점검, 사용자 확인 지점을 자연어로 옮겨 모델에게 실행을 맡깁니다. 그 결과 검증 전에 원본 파일을 덮어쓰는 것처럼 스킬이 허용한 연산만으로 이루어지는 위반이 생기고, 권한 허용 목록으로는 이를 막을 수 없습니다. 모델이 "점검을 통과했다"고 주장하는 식으로 감시를 피하는 경우도 있습니다. 저자들은 이를 제어 흐름 무결성(CFI) 문제로 보고 SkillCFI를 제안했습니다. 컴파일러가 LLM의 해석을 컴파일 시점으로 한정해 하나의 스킬에서 에이전트 지시문과 실행 가능한 계약을 함께 만들고, 결정적인 런타임 집행기가 신뢰할 수 있는 증거가 있을 때만 도구 요청을 허용합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.24185
- arXiv HTML 본문: https://arxiv.org/html/2611.24185
- arXiv PDF: https://arxiv.org/pdf/2611.24185

### Contribution
- 스킬 단계가 모델 추론, 도구 호출, 스크립트 가운데 어디에서 실행되는지에 따라 강제 가능성이 달라진다는 점을 모델링하고, 모델이 실행 위치를 바꿔 감시를 피하는 "실행 영역 이동(regime migration)"을 새로 짚었습니다.
- 고전적인 강제 가능성 이론을 바탕으로, 도구 경계에서 강제할 수 있는 의무, 지침으로만 남는 의무, 스킬 자체를 거부해야 하는 의무를 가르는 기준을 세웠습니다.
- 인라인 스크립트처럼 중재되지 않는 경로를 거부하는 집행기를 OpenCode 에이전트에 구현해, 모델이 무엇을 제안하든 허용된 실행 흔적이 계약을 따르도록 했습니다.

### Evaluation
- 직접 작성한 스킬 8개에 소스 변형 24개를 가해도, 컴파일된 계약이 원래 스킬보다 많은 것을 허용한 경우는 없었습니다.
- 에이전트 세션 770회에서 스킬 자체 연산만으로 이루어진 위반 240건을 실행 전에 모두 차단했습니다. 같은 조건에서 허용 목록 방식은 자기 세션의 위반 80건을 모두 통과시켰습니다. 정상 작업 완료율은 집행 없이 실행할 때와 거의 같았습니다.
- 거부 메시지에 다음에 허용되는 단계를 알려 주면 복구율이 21%에서 65%로 올랐습니다. 검사 시간은 작업 시간의 약 2%였고, 간결한 명령 형식을 쓰면 세션 지연이 1.32배에서 1.08배로 줄었습니다.
- 공개 스킬 53개 가운데 그대로 계약으로 받아들여진 것은 없었고, 컴파일러 진단을 따라 7개를 강제 가능한 계약으로 고쳤습니다.
- 신빙성: 주 평가가 저자들이 직접 쓴 스킬 8개에서 이루어져 일반화에는 한계가 있습니다. 100% 차단은 결정적 집행기의 설계상 결과이므로 수치 자체보다는 계약이 원래 의도를 얼마나 정확히 담는지가 관건인데, 이는 사람이 검토해야 한다고 저자들이 밝혔습니다.

#### Comment
- 에이전트 스킬 보안을 프롬프트 수준의 지침이 아니라 컴파일러와 참조 모니터 구조로 다룬 점이 돋보입니다. 런타임에 모델을 감시자로 쓰지 않는 이유(감시 모델도 같은 오염된 내용을 읽기 때문)를 명시한 설계 판단도 설득력이 있습니다.
- 한계: 허용된 호출 순서 안의 해로운 내용, 생성된 스크립트 내부 동작, 다중 스킬 동시 실행은 다루지 않습니다.
- 중국 기관(베이항 대학교) 공동 저자가 있어 추가로 확인했습니다. 교신 저자는 싱가포르 국립대학교 소속이고, 평가 대상 공개 스킬 출처(openai/skills 등)를 본문에 명시했으며, 수치가 비현실적으로 좋은 부분은 설계상 결정적인 결과에 한정됩니다. 다만 코드 공개 주소는 본문에서 찾지 못했습니다.

# AutoPI: Taxonomy-Guided Adaptive Red Teaming for Prompt Injection in LLM Agents
> arXiv 프리프린트 (심사 전), 코드와 프로젝트 페이지 공개. 서던캘리포니아 대학교
> 2026

프롬프트 주입 방어는 고정된 벤치마크 공격이 아니라 적응형 공격자로 평가해야 한다는 공감대가 생겼지만, 기존 적응형 레드팀 도구 대부분은 공격 성공률(ASR)만 최대화합니다. 성공률은 대상이 "얼마나 자주" 뚫리는지만 보여 줄 뿐 "얼마나 다양한 방식으로" 뚫리는지는 알려 주지 않아, 잘 통하는 몇 가지 기법만 반복하는 공격자도 높은 점수를 받습니다. 저자들은 프롬프트 주입 기법 분류 체계 PIAtlas(6개 분류, 34개 기법, 132개 세부 기법)를 탐색 안내와 범위 측정에 함께 쓰는 블랙박스, 무학습 레드팀 도구 AutoPI를 제안했습니다. 공격자 LLM이 세부 기법마다 주입문을 하나씩 만들고, 실패한 것은 LLM 판정자의 피드백으로 고쳐 나갑니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.24313
- arXiv HTML 본문: https://arxiv.org/html/2611.24313
- arXiv PDF: https://arxiv.org/pdf/2611.24313
- 프로젝트 페이지: https://stevendamianakis.github.io/autopi-site/
- 저자 코드 저장소: https://github.com/stevendamianakis/autopi

### Contribution
- 성공률과 함께 "기법 범위(technique coverage)", 곧 분류 체계의 분류, 기법, 세부 기법 가운데 하나라도 성공한 비율을 보고하는 평가 방식을 제안했습니다.
- 학습 없이 기존 벤치마크의 고정 공격 템플릿 자리에 그대로 끼워 넣을 수 있고, 분류 체계가 갱신되면 함께 갱신됩니다.
- 생성된 공격 전체를 기법 라벨과 함께 공개해, 적대적 학습에 쓸 수 있는 다양한 공격 자료를 제공했습니다.

### Evaluation
- 벤치마크: AgentDojo(949개 시나리오), IPI Arena. 대상 모델: Qwen3.6-35B(공개 가중치), Claude Haiku 5.5(상용). 공격 생성기와 판정자는 Qwen3.6-35B로 고정했습니다.
- 비교 대상: 벤치마크 기본 공격 템플릿, PIMiner(전략 라이브러리), Climbing the Hill(커리큘럼 강화학습), AutoDojo(블랙박스 최적화). 시도 횟수가 아니라 같은 연산량 기준으로 비교했습니다.
- 결과: Qwen3.6-35B 상대 AgentDojo에서 6개 분류 모두, 기법의 90% 이상에서 성공한 주입을 찾았고 기준선 중 65%를 넘은 것은 없었습니다. 시나리오의 70% 이상을 뚫었습니다. 가장 견고한 Haiku 5.5 상대로는 기존 최고 수준 도구보다 성공률이 20~50%, 분류 수준 범위가 25~400% 높았습니다. 학습 비용을 포함한 시도당 비용은 0.6 GPU초로 다른 도구(2.9~14.5 GPU초)보다 낮았습니다.
- 신빙성: 같은 연산량 비교, 공개 벤치마크, 코드와 생성 공격 공개로 재현성이 좋습니다. 다만 대상 모델이 두 개뿐이고, 범위는 PIAtlas 하나에 의존하며, 성공한 주입의 기법 라벨을 LLM이 사후에 붙였다는 점을 저자들이 한계로 밝혔습니다. 방어 기법을 덧씌운 대상은 평가하지 않았습니다.

#### Comment
- 레드팀 결과가 적대적 학습 데이터로 다시 쓰인다는 점에서, 공격이 몇 가지 기법에 쏠리면 방어도 그만큼만 강해진다는 문제의식이 아래 PIPETTE와 같습니다. 두 논문을 함께 보면 "성공률 중심 평가의 한계"가 이번 주의 공통 주제임을 알 수 있습니다.

# PIPETTE: Prompt Injection Purple-Teaming for Robust LLM Agents
> arXiv 프리프린트 (심사 전). 워털루 대학교, 저장 대학교, KTH 왕립 공과대학
> 2026

모델 개발사는 레드팀이 찾은 공격으로 에이전트를 적대적 학습시켜 배포 전에 강화하는데, 저자들은 레드팀 단계의 높은 공격 성공률이 이후 방어 성능 향상으로 이어지지 않는다는 점을 보였습니다. 대표적인 강화학습 기반 레드팀 기법 RL-Hammer와 PISmith는 비슷한 전략만 반복하는 모드 붕괴에 빠져, 추가로 얻은 성공 사례가 방어 개선에 기여하지 못한다는 것입니다. 저자들은 사전 학습(dictionary learning) 기반 보상으로 공격 전략의 범위를 넓히는 레드팀 단계와, 에이전트 맞춤 온폴리시 적대적 학습 단계를 묶은 퍼플팀 체계 PIPETTE를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.24362
- arXiv HTML 본문: https://arxiv.org/html/2611.24362
- arXiv PDF: https://arxiv.org/pdf/2611.24362

### Contribution
- 성공률이나 표면적 문장 다양성을 최대화해도 전략 수준의 모드 붕괴를 막지 못한다는 점을 실험으로 보였습니다. 예를 들어 한 기법은 Qwen3-4B에서 더 높은 성공률(68.75% 대 33.39%)을 냈지만, 그 공격으로 학습한 에이전트는 미지의 공격에 더 약했습니다(47.5% 대 27.5%).
- 문장 표현이 아니라 "사용자 지시를 어떻게 무력화하는가"라는 전략 단위로 새로움을 보상하는 범위 보상을 설계했습니다.
- 토큰 단위 자기 증류를 쓰는 적대적 학습으로, 주입된 지시를 무시하면서도 주변 데이터로 원래 작업은 끝내도록 했습니다.

### Evaluation
- 벤치마크: AgentDojo, ASB. 평가 모델 4종(Qwen3-4B 등). 비교 대상은 RL-Hammer, PISmith 같은 레드팀 기법과 MELON, DataSentinel 같은 방어 기법입니다.
- 결과: AgentDojo에서 반복 적응형 공격을 받아도 세 모델에서 공격 성공률이 0~10%였고, 정상 작업 성능은 방어하지 않은 모델과 비슷했습니다. Qwen3-4B 절제 실험에서 공격 성공률은 46.19%에서 1.43%로 떨어졌고 정상 작업 성능은 61.86%에서 64.95%로 오히려 올랐습니다.
- 실행 비용: 추론 시 외부 탐지 모델이나 중복 실행이 없어, MELON보다 1.9~3.1배, DataSentinel보다 2.7~9.5배 빨랐습니다.
- 신빙성: 적응형 공격 예산이 과제 쌍 40개, 과제당 약 250회 시도, 4B 공격 모델로 제한되어 더 큰 예산이면 성공률이 오를 수 있습니다. 전략 다양성을 판정하는 LLM 채점기를 사람 라벨로 검증하지 않았다는 점도 저자들이 밝혔습니다.

#### Comment
- AutoPI가 "평가 쪽"에서 범위를 강조했다면, PIPETTE는 "방어 학습 쪽"에서 같은 문제를 풀었습니다. 단일 라운드 퍼플팀이라 강화된 모델에서 새로 생기는 취약점은 다루지 못합니다.
- 공동 저자 1명이 중국 기관(저장 대학교) 소속이지만, 1저자와 교신 저자는 워털루 대학교 소속(N. Asokan)이고 공개 벤치마크와 공개 기준선으로 평가했습니다. 결과 수치도 과도하지 않고 절제 실험이 함께 제시되어 있습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# Evolution Under Fire: Evolving Agent Safety Harnesses with Adaptive Injection Stressors
> arXiv 프리프린트 (심사 전). 뮌헨 대학교(LMU), 뮌헨 머신러닝 센터(MCML)
> 2026

도구를 쓰는 에이전트는 악성 지시와 정상 지시가 같은 경로로 들어오는 환경에서 일하지만, 기존 방어는 대부분 사람이 손으로 설계한 정적인 장치라 개선하려면 매번 다시 설계해야 합니다. 저자들은 실행 가능한 안전 하네스(에이전트를 감싸는 방어 코드) 전체를 실행 기록에서 진화시키는 탐색과, 그 하네스의 남은 약점을 찌르는 공격을 진화시키는 탐색을 단계적으로 결합한 Evolution Under Fire를 제안했습니다. 작업 모델, 벤치마크, 도구, 평가기는 고정하고, 유용성을 해치는 후보는 부모가 되지 못하게 하는 파레토 기반 트리 탐색을 씁니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.22583
- arXiv HTML 본문: https://arxiv.org/html/2611.22583
- arXiv PDF: https://arxiv.org/pdf/2611.22583

### Contribution
- 에이전트 방어를 "완전한 실행 가능 하네스에 대한 탐색 문제"로 정식화했습니다. 읽기 전용 진단기와 코드를 생성하는 확장기가 실행 흔적과 탐색 이력에 근거해 수정합니다.
- 유용성 제약을 지키는 후보만 부모로 삼되, 탈락한 후보도 반례로 남겨 두는 파레토 트리 탐색을 설계했습니다.
- 공격 쪽은 원래 작업을 망가뜨리지 않으면서 성공하는 공격만 남기는 계보 기반 진화로, 다음 단계 하네스 진화의 피드백이 되게 했습니다.

### Evaluation
- AgentDyn(GPT-4o-mini): 진화한 하네스가 공격 성공률을 50.4%에서 3.0%로 낮추고, 정상 및 공격 상황의 작업 성공률도 초기 하네스보다 높였습니다. CaMeL, Progent, DRIFT, MELON, AgentWatcher, ActGuard, ROPE, Spotlighting 등 재현한 방어보다 보안과 유용성의 균형이 좋았습니다.
- Agent-SafetyBench(Qwen2.5-7B-Instruct): 공격 성공률 82.6%에서 62.0%로 감소.
- 전이: 추가 진화 없이 Qwen3.5-35B-A3B에 적용해 공격 성공률을 32.1%에서 0.9%로 낮췄습니다.
- 신빙성: 비교 방어를 저자들이 재현했으므로 재현 설정에 따라 결과가 달라질 수 있습니다. 하네스가 같은 벤치마크에서 진화하고 평가되므로 벤치마크 과적합 가능성이 있으며, Agent-SafetyBench에서는 개선 폭이 작습니다.

#### Comment
- 지난 실행에서 본문을 구하지 못해 이월했던 논문입니다.
- 방어 설계를 자동 탐색으로 바꾼다는 점은 흥미롭지만, 진화된 하네스가 어떤 규칙을 담게 되었는지가 사람이 검토할 수 있는 형태로 남는지가 실무 적용의 관건입니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# DetectViT: Test-time Backdoor Detection for Vision Transformers via Inter-Head Attention Discrepancy
> NeurIPS 2026 채택, arXiv 프리프린트. 화난 이공대학교, UC 샌디에이고, 화난 사범대학교
> 2026

비전 트랜스포머(ViT)는 대부분의 멀티모달 모델의 시각 인코더로 쓰이지만, 외부에서 받은 사전 학습 가중치를 쓰는 탓에 백도어 공격에 노출됩니다. 기존 테스트 시점 탐지는 예측 라벨이나 중간 임베딩에 기대어 적용 범위가 좁고 계산량이 큽니다. 저자들은 백도어 트리거가 멀티헤드 어텐션을 "가로채는" 두 가지 이상 패턴을 찾았습니다. 완전 가로채기에서는 헤드들의 어텐션이 같은 위치로 비정상적으로 몰리고, 부분 가로채기에서는 헤드별 어텐션 집중도의 분산이 비정상적으로 커집니다. 이를 헤드 간 일관성 점수와 헤드 간 엔트로피 분산 점수로 계량한 DetectViT를 제안했습니다. 학습 데이터, 모델 출력, 트리거 사전 지식이 필요 없고, 임계값은 아무 출처에서나 뽑은 소량의 분포 외(OOD) 보정 데이터로 정합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.23770
- arXiv HTML 본문: https://arxiv.org/html/2611.23770
- arXiv PDF: https://arxiv.org/pdf/2611.23770
- 저자 코드 저장소: https://github.com/siquanhuang/DetectViT

### Contribution
- 백도어가 일으키는 어텐션 이상을 헤드 간 차이라는 관점에서 처음으로 체계적으로 정리했다고 저자들은 밝힙니다.
- 추론 중에 이미 계산된 어텐션 가중치만 쓰므로 추가 계산이 거의 없고, 분류와 캡셔닝처럼 출력 형태가 다른 작업에도 그대로 적용됩니다.

### Evaluation
- 공격: BadViT(DeiT-T, Caltech-101), TrojViT(DeiT-S, Tiny ImageNet), BadCLIP(CLIP ViT-B/32, ImageNet-1K), BadVision(LLaVA-1.5 시각 인코더, COCO Caption). 테스트 데이터의 5%를 오염시켰습니다.
- 비교 대상: 라벨 공간 기반 TeCo, Scale-Up, PatchProc과 임베딩 공간 기반 DeDe, BackdoorIDS. 지표는 TPR, FPR, AUC입니다.
- 결과: 보정 샘플 64~128개만으로 모든 기준선을 앞섰고, BadCLIP에서 TPR 100%, FPR 0.17%를 기록했습니다. BadViT에서도 TPR 100%, AUC 1.00이었습니다. 보정 데이터의 출처와 크기, 적응형 공격에도 견고하다고 보고했습니다.
- 신빙성: 공개된 공격 네 가지와 공개된 탐지 기준선을 썼고 기준선 구현도 저장소에 함께 들어 있어 비교 조건은 적절해 보입니다. 다만 TPR 100%라는 수치는 매우 높으므로 공격 강도나 트리거 형태(대부분 최적화된 패치 트리거)에 따라 달라질 수 있습니다.

#### Comment
- 중국 기관 논문이라 추가로 확인했습니다. NeurIPS 2026 채택 표시가 arXiv comment에 있고, 저자 저장소에는 탐지 코드(detectvit.py)와 기준선(DeDe, BackdoorIDS), 공격 재현 코드(BadVision)가 들어 있어 재현 가능성이 있습니다(파이썬 약 2만 2천 줄, 최근 커밋 2026-11-19). 공동 저자 1명은 UC 샌디에이고 소속이며, 중국 국가자연과학기금 지원을 명시했습니다.
- 한계: 자연스러운 분포 외 특징 자체가 트리거인 공격은 막지 못하고, CLS 토큰이 없는 구조로의 확장은 남은 과제라고 저자들이 밝혔습니다.

# Intent Contracts: Taking Tools Away from Agents
> arXiv 프리프린트 (심사 전), 코드와 실행 기록 공개. 초록 기반 요약, 본문 미확인
> 2026

계획을 세우는 모델에게 도구를 아예 주지 않는 도구 사용 에이전트용 권한 인터페이스 "의도 계약(intent contract)"을 제안했다고 저자들은 설명합니다. 계획 모델은 단계마다 목표, 사용자 발화의 그대로 인용, 범위 항목으로 된 짧은 계약을 기록하고, 코드가 이를 검증한 뒤 작은 신뢰 모델이 사용자 발화와 대조해 도구 호출을 직접 작성합니다. 저자들은 이 방식을 계획 모델이 쓴 명령을 검토하는 두 가지 방식(사용자 발화와 명령만 보는 검토자, 계획 모델의 목표와 인용까지 보는 검토자)과 비교했다고 합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.24025
- arXiv HTML 본문: https://arxiv.org/html/2611.24025
- arXiv PDF: https://arxiv.org/pdf/2611.24025
- 저자 코드 저장소(OpenCode 플러그인과 실행 기록): https://github.com/zwang-devv/intent-contracts

### Contribution
- 저자들에 따르면, 검증과 호출 코드가 올바르다는 전제에서 실행되는 모든 호출은 신뢰 모델이 쓰고, 계획 모델의 영향은 사전에 기록된 계약으로 한정됩니다.
- 계획 모델이 사용자가 요청하지 않은 일을 덧붙일 때 계약 방식은 30회 중 27회 사용자 작업을 끝냈고, 의도까지 보는 검토자는 16회였다고 합니다. 검토자는 명령 전체를 거부할 수밖에 없기 때문이라고 설명합니다.

### Evaluation
- 초록에 따르면 계획 모델 gpt-6.1-terra, 신뢰 모델 GLM-5.3-Flash로 AmPermBench의 세 과제 계열에서 평가했습니다.
- 저자들은 계약 방식이 무단 행동을 줄이지 못했고 맹목 검토와 구별되지 않았으며, 상태를 바꾸는 모든 조건에서 실행의 40~49%가 잘못된 대상을 건드렸다고 밝혔습니다. 원인은 모호한 지시에서 계획 모델이 대상을 고르는 방식이라고 합니다. 평가는 모델 한 쌍과 비적대적 과잉 실행만 다뤘습니다.
- 본문을 읽지 못해 데이터셋, 비교 조건, 지표의 신빙성은 확인하지 못했다.

#### Comment
- 신뢰도 신호: arXiv comment에 코드와 데이터 공개 주소가 있습니다. 저장소를 받아 확인한 결과 OpenCode 플러그인, 표마다의 실행 기록, 논문 수치를 다시 계산하는 스크립트가 들어 있었고 논문 PDF나 TeX는 없었습니다.
