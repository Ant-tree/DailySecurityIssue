# BlockJack: Cross-Tenant Redirection Fault Attacks on Paged KV Cache Address Translation in LLM Serving
> arXiv 프리프린트 (심사 전). 더럼 대학교, 뤼베크 대학교, 싱가포르 국립대학교, 상하이 자오퉁 대학교, 둥난 대학교
> 2026

vLLM 같은 LLM 서빙 프레임워크는 KV 캐시를 고정 크기 블록으로 나누고, 운영체제의 페이지 테이블처럼 블록 테이블로 요청별 논리 블록을 물리 블록에 대응시킵니다. 저자들은 이 대응 정보 자체를 공격 대상으로 삼은 첫 결함 주입 공격 BlockJack을 제안했습니다. 블록 테이블 항목 하나를 Rowhammer 등으로 바꾸면, 모델 가중치나 프롬프트, 캐시 값은 건드리지 않고도 한 요청의 KV 캐시 읽기를 다른 테넌트의 블록으로 돌릴 수 있습니다. 그 결과 피해자의 정보가 공격자 응답에 섞여 나오는 기밀성 침해(CD)와, 공격자가 넣은 문맥이 피해자 답변을 바꾸는 무결성 침해(RA)가 모두 가능합니다.

- arXiv 초록: https://arxiv.org/abs/2611.25945
- arXiv HTML 본문: https://arxiv.org/html/2611.25945

### Contribution
- 지금까지의 LLM 결함 공격이 가중치나 KV 값 같은 데이터 영역을 노렸다면, 이 연구는 서빙 엔진이 관리하는 주소 변환 메타데이터를 새로운 공격 표면으로 제시했습니다. 희소성이 높은 가중치와 달리 블록 번호의 비트 하나가 바뀌면 곧바로 관찰 가능한 결과가 생긴다는 점을 짚었습니다.
- vLLM의 블록 할당 정책을 분석해 공격자가 대상 블록 번호를 예측할 수 있는 조건(표적 공격)과 확률적으로만 맞힐 수 있는 조건(비표적 공격)을 정식화했습니다.
- 물리 Rowhammer로 실제 공격이 가능함을 보였고, 책임 있는 공개 후 vLLM과 Sonar가 취약점을 확인했으며 저자들이 할당 검증 패치를 검토하고 검증했습니다.

### Evaluation
- 소프트웨어 결함 주입: vLLM(주 대상)에서 Qwen, Llama, Gemma, Phi 계열 7개 모델 모두에서 블록 번호 하나의 결함만으로 피해자 문맥이 노출됐습니다. SGLang과 Sonar에서도 두 공격 결과를 재현했습니다.
- 무결성 공격: 248개 의료 상담 장면으로 만든 벤치마크에서 최대 41.1%의 응답이 피해자 질문과 어긋나 보이지 않으면서 덜 긴급한 진료를 권하도록 바뀌었습니다. 판정에는 LLM 심판 5종을 썼습니다.
- 물리 Rowhammer: Intel Core i5-6400과 DDR4-2133 DIMM 한 개, CPU 백엔드 vLLM 0.25.0 환경에서 SWAGE 프레임워크(Blacksmith 패턴)로 20회 캠페인을 돌려 CD 10회 중 3회, RA 10회 중 8회를 검증했습니다. 총 31.7시간이 걸렸고 그중 6.1시간이 비트 뒤집힘 탐색이었습니다.
- 신빙성: 물리 실험은 Rowhammer에 취약하다고 알려진 DDR4 모듈 한 개에서만 수행했고, GPU 메모리(GDDR)에 블록 테이블이 있는 구성은 소프트웨어 결함 주입으로만 평가했습니다. 무결성 결과는 LLM 심판 판정에 의존합니다. 반면 개발사가 취약점을 확인하고 패치했다는 점은 강한 외부 근거입니다.

# ToolPulse: Side-Channel Eavesdropping on Tool-Using LLM Agents
> arXiv 프리프린트 (심사 전). 홍콩 대학교, 런민 대학교, 홍콩 과학기술대학교(광저우)
> 2026

기존 LLM 캐시 부채널 공격은 공격자가 피해자의 추론 하드웨어나 모델 구성 요소를 공유해야 했지만, 상용 모델은 제공사 서버에서 돌아가므로 현실성이 떨어졌습니다. 저자들은 에이전트 환경에서는 추론은 원격이어도 도구 실행은 사용자 컴퓨터에서 일어나고, 그 도구들이 공유 시스템 라이브러리와 실행 파일을 쓴다는 점에 주목했습니다. 같은 서버에 있는 비특권 공격자가 Flush+Reload로 어떤 도구가 언제 호출되는지 엿들을 수 있음을 보이고, 이를 바탕으로 도구 실행 흐름을 복원하는 공격 프레임워크 ToolPulse를 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.25470
- arXiv HTML 본문: https://arxiv.org/html/2611.25470
- arXiv PDF: https://arxiv.org/pdf/2611.25470

### Contribution
- 도구 실행을 LLM 에이전트의 실용적인 부채널 공격 표면으로 제시했습니다.
- Flush+Reload와 Prime+Probe를 체계적으로 비교해, Prime+Probe는 가상 머신 간 공격이 가능하지만 감시 부담과 캐시 집합 중복 때문에 실시간 복원이 어렵다는 점을 보였습니다.
- 한 번의 도구 호출이 여러 캐시 적중을 만드는 문제를 줄이는 캐시 라인 위치 선정 알고리즘과 중복 제거 알고리즘, 도구 인자를 추정하는 오프셋 탐색 알고리즘을 설계했습니다.
- 복원한 도구 흐름으로 사용자의 작업 종류를 추정하는 작업 프로파일링 공격과, 암호화나 모델 추론처럼 민감한 도구 호출 시점을 찾아 후속 공격의 감시 부담을 줄이는 트리거 위치 특정 공격을 보였습니다.

### Evaluation
- Intel Xeon Platinum 8369B, 8269CY, 8163을 쓰는 퍼블릭 클라우드 인스턴스 세 종류에서 15가지 도구를 대상으로 평가했습니다.
- 도구 복원 공격: Codex와 Claude Code에서 11개 모델(GPT 계열 5개, Claude 계열 4개 등)로 평가해 가장 낮은 F1도 93%를 넘었습니다.
- 작업 프로파일링: Terminal-Bench 1과 2의 도구 호출 기록 4,000개로 분류기를 학습해 정확도 87.77%와 91.39%를 얻었습니다. 사용자 약 20명이 함께 쓰는 서버에서 기록한 잡음을 재현한 조건에서 정확도가 약 4%포인트 떨어졌습니다.
- 트리거 위치 특정: 키 추출과 모델 추출 사례마다 과제 100개, 기록 3,000개로 평가해, 키 추출에서 가장 나쁜 모델도 민감한 호출의 7.04%만 놓쳤고 감시 부담은 원래의 약 20~39% 수준으로 줄었습니다.
- 신빙성: 공격자가 같은 물리 서버에 있고 공유 페이지를 쓸 수 있다는 전제가 강합니다. 실제 공유 서버 잡음은 녹화한 도구 호출을 통제된 환경에서 다시 재생하는 방식으로 반영했습니다. 분류 결과는 저자들이 수집한 기록으로 학습하고 평가한 것입니다.

#### Comment
- 중국 기관(런민 대학교, 홍콩 과학기술대학교 광저우 캠퍼스) 저자가 포함되어 검증을 더 했습니다. 교신 저자는 홍콩 대학교 소속입니다. 공격 원리는 잘 알려진 Flush+Reload 기법의 응용이라 기술적으로 타당하고, 하드웨어 모델과 데이터셋 구성, 모델별 수치를 구체적으로 공개했습니다. 다만 코드 공개 주소는 본문에서 확인하지 못해 재현 가능성은 제한적입니다. 수치가 지나치게 좋거나 비교 대상이 부적절한 정황은 보이지 않았습니다.

### Evaluation
- 근거 수집: 에이전트 작업 흐름으로 고유 출처 53,057개를 모았고, 독립된 에이전트가 관련 근거를 찾아 원문 인용과 함께 점수를 매긴 뒤, 저자 2명이 16개 칸의 128개 단계를 검토했습니다.
- 기록 분석: 2018년 이후 CVE 기록 304,028건을 분석했고, 그중 약 2,600건이 LLM 기반 시스템을 발견자로 명시했습니다. 2026년 CVE 기록은 2025년의 2.3배였고, Critical/High 비율은 2025년 46%에서 2026년 7~10월 56%로 올랐습니다. AI 시스템을 발견자로 명시한 기록은 2026년 분기별 2.4~2.8%였습니다.
- 대량 제출된 보고서는 외부 관리자에게 5~26%만 수정됐고, 선별한 보고서는 58~94%가 수정됐다고 정리했습니다.
- 신빙성: 근거 수집과 1차 채점에 LLM 에이전트(Claude Sonnet 5.5)를 썼고, 인용이 원문과 맞는지 기계적으로 확인한 뒤 저자가 검토하는 구조입니다. 다만 근거의 상당수가 시스템을 만든 회사의 자체 보고라는 한계를 저자들도 인정했습니다. 기록에 발견 도구가 거의 적혀 있지 않아 변화 중 LLM 기여분은 아직 가려낼 수 없다고 밝혔습니다.
