# OverServe: Resource Amplification Attacks on SaaS Agents via Tool--Prompt Co-Design
> arXiv 프리프린트 (심사 전). 플로리다 주립대학교, 존스홉킨스 대학교
> 2026

구독형 SaaS 서비스가 LLM 에이전트로 업무를 자동화하면, 고객이 추가 요금을 내지 않아도 모델 호출과 도구 호출 비용은 서비스 제공자가 떠안습니다. 에이전트가 언제 멈출지를 스스로 판단한다는 점을 노리면, 악의적인 고객이 작업을 일부러 길게 끌어 제공자의 비용을 늘릴 수 있습니다. 기존 자원 소모 공격은 프롬프트나 도구 한쪽만 조작해서 프롬프트 검토나 도구 검사에 쉽게 걸렸습니다. OverServe는 MCP 상태 조회 도구와 "동기화가 끝났는지 확인해 달라" 같은 완료 확인 프롬프트를 한 쌍으로 설계합니다. 도구는 매번 정확한 상태를 돌려주고 정상 종료하며 프롬프트도 평범한 업무 지시처럼 보이지만, 백엔드가 "아직 진행 중"을 계속 반환하는 조건에서는 에이전트가 원래 작업을 마친 뒤에도 상태 확인을 반복합니다. 여러 에이전트가 도구와 프롬프트 후보를 만들고, 코드 검토, 실행 검토, 프롬프트 검토를 각각 통과하는 쌍만 고릅니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.14808
- arXiv HTML 본문: https://arxiv.org/html/2611.14808
- arXiv PDF: https://arxiv.org/pdf/2611.14808

### Contribution
- 공격 기능을 도구와 프롬프트에 나눠 담으면 각 구성 요소는 따로 검토를 통과하면서도 결합했을 때 자원 소모가 크게 늘어난다는 점을 보였습니다.
- 도구 하나만 넣거나 프롬프트 하나만 바꾸면 증폭이 거의 일어나지 않고, 둘이 함께 있고 백엔드 상태가 계속 바뀔 때만 증폭된다는 것을 통제 실험으로 확인했습니다(같은 Qwen 에이전트에서 정상 4회 호출, 맞춘 프롬프트와 도구에 "진행 중" 상태일 때 40회).
- 공격 쌍을 만들고 선별하는 다중 에이전트 생성 파이프라인을 제시했습니다.

### Evaluation
- 피해 에이전트: Qwen3.8-27B, Nemotron-3-Super, 로컬 DeepSeek-v4-Flash, Bedrock의 Sonnet-5. 벤치마크는 MCPMark, EnterpriseOps-Gym, STATE-Bench, AppWorld, WorkBench, Terminal-Bench 등 10개에서 고른 작업입니다.
- 기업 업무 벤치마크 5종, 20개 조합의 기하평균 증폭률은 10.30배(모델별 Qwen 19.30배, Nemotron 8.07배, DeepSeek 17.75배, Sonnet 4.07배)였고, 최대치는 AppWorld에서 Sonnet의 API 요청 93.88배입니다. 공격받은 실행은 모두 원래 작업 검사를 통과했다고 보고했습니다.
- 기존 공격(A2M, LoopTrap, Sponge Tool Attack)과 비교하면 LoopTrap도 비슷한 증폭(10배)을 내지만 소스 코드 검토와 실행 검토에서 모두 걸렸고, OverServe 도구는 모두 통과했습니다. 공개 MCP 스캐너 5종은 OverServe 도구 22개 가운데 하나도 잡지 못했고, 연구용 탐지기 가운데 DCI가 3개, Connor가 1개를 잡았습니다.
- 신빙성: 저자들이 직접 밝히듯 "선별한 작업"에서의 결과이고, 증폭률은 벤치마크별 실행 상한(예: 200회 반복)에 걸린 경우가 많아 상한 설정에 크게 좌우됩니다. 백엔드의 "진행 중" 상태도 시뮬레이션으로 만든 것입니다.

#### Comment
- 결국 핵심 조건은 에이전트가 끝나지 않는 외부 상태를 계속 확인하도록 유도하는 것이라, 서비스 쪽에서 작업당 호출 수나 시간 상한을 두면 피해 규모는 상한까지로 제한됩니다. 다만 상한까지 쓰게 만드는 것만으로도 정상 대비 수십 배라는 점이 요점입니다.
- 첫 번째 응답 시점의 버전만 확인하도록 바꾸면 정상 종료된다는 실험(호출 22회)은 도구 설계 쪽 방어 방향을 보여 줍니다.

# PolicySniff: Inferring Agent Policy States through Shared-GPU Execution
> arXiv 프리프린트 (심사 전). 리하이 대학교, 뉴욕 대학교, 뉴욕 대학교 아부다비
> 2026

LLM 에이전트는 "중요한 도구 호출 전에 사용자에게 묻는다"와 같은 승인 정책을 시스템 프롬프트로 적용하고, 운영자는 프롬프트와 응답 접근을 막아 이 설정을 비공개로 둡니다. 공격자에게 이 정보는 프롬프트 인젝션을 시도할 대상(확인 없이 바로 실행하는 배포)을 고르는 데 쓸모가 있습니다. 이 논문은 같은 GPU를 쓰는 이웃 프로세스가 자기 GPU 커널의 실행 시간만 재서 에이전트에 적용된 승인 정책을 알아낼 수 있음을 보였습니다. 정책 문구는 측정 전에 이미 캐시되어 있고 공격자가 관찰하는 구간은 두 정책에서 똑같은 작업 문장 처리뿐이지만, 희소 전문가 혼합(MoE) 모델에서는 캐시된 정책이 어떤 전문가가 선택되는지에 영향을 주고, 전문가를 하나씩 따로 실행하는 런타임에서는 그 차이가 실행 시간으로 드러납니다. 공격자는 후보 정책 두 가지를 같은 GPU에서 미리 측정해 두고, 목표 측정값이 어느 쪽에 가까운지로 판정합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.16158
- arXiv HTML 본문: https://arxiv.org/html/2611.16158
- arXiv PDF: https://arxiv.org/pdf/2611.16158

### Contribution
- 에이전트가 정책을 잘 지키는지(행동 준수)와 어떤 정책이 배포되었는지가 새어 나가지 않는지(설정 기밀성)는 별개 문제라는 점을 실험으로 보였습니다. 두 정책에서 에이전트의 결정이 같은 작업에서도 정책을 구분할 수 있었습니다.
- FPGA로 전문가 선택 패턴을 재생하는 하드웨어 실험으로, 정보가 전문가 선택의 시간적 밀도와 층별 정렬에 실려 있음을 확인했습니다.
- 승인 정책을 모델 밖의 신뢰할 수 있는 중개자로 옮기면 평가한 시간 분류기가 무력화된다는 배치 비교를 제시했습니다.

### Evaluation
- 환경: A100 GPU 한 장 또는 MIG 인스턴스 하나를 공유하는 조건, Qwen3-30B-A3B 등 MoE 모델을 전문가별로 따로 실행하는 런타임, 기존 연구의 GPU 시분할 측정 기법을 그대로 사용.
- 동결하고 블라인드로 진행한 연구에서 배포된 정책을 균형 정확도 94.17%로 맞혔고, 두 정책의 결정이 같은 작업에서 88.82%, 다른 작업에서 91.98%였습니다. NF4 양자화 캠페인에서는 48개 그룹 중 47개를 맞혔습니다.
- 정책을 외부 중개자로 옮기면 정확도가 95.83%에서 41.67%로 떨어졌습니다.
- 방어 관련 측정: 형제 MIG 인스턴스에서는 활동 신호가 관찰되지 않았고, vLLM 0.30.0의 결합(fused) MoE 커널은 360개 디코딩 단계 모두에서 같은 커널 실행 패턴을 보였습니다. 다만 이 측정은 디코딩 단계에 대한 것이고 공격은 프리필 단계를 관찰합니다.
- 신빙성: 신뢰 구간을 클러스터 부트스트랩으로 제시하고 실험을 사전에 고정해 진행한 점은 엄밀합니다. 반면 후보 정책 구현을 공격자가 알고, 같은 작업으로 기준 측정을 미리 하고, 요청 순서와 묶음을 안다는 가정이 강합니다.

#### Comment
- 측정 자체가 침습적이어서 지속적으로 탐지하면 피해자의 지연 시간이 중앙값 기준 4.71배로 늘어납니다. 실제 서비스라면 이상 징후로 드러날 수 있습니다.
- 공격이 성립하는 조건이 "같은 GPU 인스턴스 공유 + 전문가별 개별 실행 런타임"으로 좁아서, MIG 분리나 결합 커널을 쓰는 일반적인 서비스 환경에서는 위험이 제한적입니다. 오히려 기밀로 하고 싶은 설정이라면 모델 밖에서 집행하라는 설계 원칙을 뒷받침하는 결과로 읽는 편이 맞습니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# Chatter Attack: Resource Consumption Attack for Large Language Models
> NeurIPS 2026 포스터 채택 논문 (심사 완료). arXiv 공개판. 칭화대학교, 중국과학원 수학 및 시스템과학 연구원, 상하이 치즈 연구원
> 2026

추론 모델이 지나치게 긴 답을 내도록 만들어 추론 비용과 지연을 늘리는 자원 소모 공격입니다. 기존 방법은 같은 말을 반복하게 하거나 문장 끝 토큰의 확률을 낮추는 방식이었는데, 출력이 길어질수록 탐색 공간이 기하급수적으로 커지고 샘플링 중 한 토큰만 어긋나도 효과가 사라졌습니다. Chatter Attack은 출력 첫머리에 "잠깐, 다시 생각해 보면" 같은 짧은 자기 의심 문구가 나오도록 적대적 접두어를 최적화합니다. 목표가 짧아 최적화가 안정적이고, 모델이 의심 상태에 빠지면 스스로 검토를 거듭하며 출력을 늘립니다. 의심 상태를 끝까지 유지하기 위해 "wait" 같은 추론 핵심 토큰이 주입된 접두어에 주의를 더 기울이게 하는 손실과, 매 단계 예측 분포의 엔트로피를 키우는 손실을 더했습니다. 화이트박스 환경에서는 GCG로 최적화하고, 블랙박스 환경을 위해 이산 토큰용 커널을 쓰는 베이지안 프롬프트 최적화(BPO)를 새로 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.11261
- arXiv HTML 본문: https://arxiv.org/html/2611.11261
- arXiv PDF: https://arxiv.org/pdf/2611.11261
- NeurIPS 2026 포스터 페이지: https://neurips.cc/virtual/2026/loc/sydney/poster/150065

### Contribution
- 긴 출력을 직접 목표로 삼는 대신 짧은 의심 문구를 목표로 삼아 긴 출력을 유도한다는 발상으로 탐색 공간 폭발 문제를 피했습니다.
- 그래디언트를 쓸 수 없는 상용 API 환경을 겨냥한 블랙박스 최적화 방법(BPO)을 제시했습니다.
- vLLM 기반 모의 서비스에서 출력 길이 제한, 사용자별 요청 제한, IP 차단, 반복 출력 탐지, 과도한 추론 감시 같은 운영 방어를 적용해도 지표가 정상 수준으로 돌아오지 않음을 보였습니다.

### Evaluation
- 데이터셋: GSM8K, MathQA, MATH-500, HumanEval(각 100문항), MMLU-Pro(비수학 12개 분야에서 10문항씩). 모델: DeepSeek-R1-Distill-Qwen-7B, QwQ-32B, gpt-oss-20b.
- 비교 대상: CoT 프롬프트, CatAttack, OverThink 변형 4종, DoS 프롬프트 공격, Engorgio, Excessive Reasoning Attack, 그리고 저자들이 만든 기준선 3종.
- R1-7B, GSM8K에서 평균 출력 길이가 423.5토큰에서 13,345.8토큰(약 31.5배)으로 늘었습니다. 다만 QwQ-32B에서는 991.4에서 3,298.4토큰(약 3.3배), gpt-oss-20b에서는 253.0에서 1,980.3토큰으로 증가 폭이 훨씬 작습니다.
- 정확도도 크게 떨어집니다. R1-7B의 MATH-500 정확도가 92.5%에서 16.4%가 되는 등, 출력만 길어지는 것이 아니라 답도 망가집니다.
- 모의 서비스에서 출력 길이 제한을 걸면 피해가 크게 줄지만 동시에 처리 중인 요청 수는 정상의 약 3배(2.2에서 6.2)로 남았고, IP를 바꿔 가며 공격하면 IP 차단은 효과가 거의 없었습니다.
- 신빙성: 표준편차를 함께 보고하고 비교 대상이 많습니다. 반면 "최대 31.5배"는 가장 작은 모델 한 조합의 값이라, 대표 수치로 보기에는 과장된 면이 있습니다.

#### Comment
- 중국 기관 논문이라 추가로 확인했습니다. 게재처는 NeurIPS 2026으로, 본문 각주와 NeurIPS 공식 포스터 페이지가 일치합니다. 교신저자 Xiao-Shan Gao(중국과학원)와 Yinpeng Dong(칭화대학교)은 해당 기관에 실재하는 연구자이며 적대적 공격 분야 실적이 확인됩니다. 본문에서 코드 공개 주소는 찾지 못해 재현성은 확인하지 못했습니다. 평가 지표 자체는 표준편차와 많은 비교 대상을 갖추고 있으나, 앞에 적었듯 대표 수치가 가장 유리한 조합에서 나온 점은 감안해야 합니다.
