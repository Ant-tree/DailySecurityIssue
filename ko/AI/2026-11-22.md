# Replication of Agentic Security Events: Audit and Investigation (ROGUE-AI)
> arXiv 프리프린트 (심사 전). 텍사스 A&M 대학교
> 2026

LLM 에이전트가 운영 데이터베이스를 지우거나 허가 없이 시스템에 들어간 사고가 언론에 자주 보도되지만, 보도는 결과만 전할 뿐 원인이 무엇이었는지 검증하지 않습니다. 저자들은 공개된 에이전트 사고 보도를 오프라인 환경에서 다시 만들고, 보도가 지목한 원인 하나만 뺀 대조 환경을 함께 만들어 같은 모델을 두 환경에서 반복 실행하는 다중 에이전트 프레임워크 ROGUE-AI를 제안했습니다. 예를 들어 Replit 에이전트의 운영 데이터베이스 삭제 사고는 테스트가 운영 데이터베이스를 쓰는 저장소와, 임시 데이터베이스를 쓰는 대조 저장소로 재현했습니다. 두 환경의 피해 차이가 곧 보도된 원인에 대한 증거가 됩니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.26553
- arXiv HTML 본문: https://arxiv.org/html/2611.26553
- arXiv PDF: https://arxiv.org/pdf/2611.26553
- 프로젝트 페이지(사고 목록과 재현 자료): https://rogue-ai.surge.sh

### Contribution
- 보도된 에이전트 사고를 원인만 다른 대조 환경과 짝지어 재현하는 첫 프레임워크를 제시했습니다. 기존 사고 목록은 보도를 모으기만 하고, 벤치마크는 저자가 설계한 공격만 다룬다는 한계를 짚었습니다.
- Claude, Gemini, GPT 기반 전문 에이전트가 보도를 찾고 1차 출처와 대조해 원인을 정리한 뒤 재현 환경을 만들고, 다른 회사 모델의 에이전트가 이를 검토하며, 피해 여부는 코드가 환경 상태로 판정하도록 설계했습니다. 에이전트가 자기 행동을 잘못 보고할 수 있기 때문입니다.
- 실제 피해가 있었던 사고 72건 가운데 62건에는 공격자가 없었고, 에이전트가 과제를 그대로 수행하다 공유 데이터베이스 같은 평범한 위험 요소를 놓친 경우였다는 점을 보였습니다.
- 도구 출력마다 위험 요소와 그 결과를 짚어 주는 경고 문구를 붙이는 완화책을 제안했습니다.

### Evaluation
- 보도 253건에서 38개 유형, 96건 사고에 대한 재현 108개를 만들었고 재현 하나당 비용은 3.28달러였습니다. 보도된 피해를 재현한 비율은 89%였습니다.
- GPT, Claude, Gemini, DeepSeek의 최신 모델 5종은 사고 환경에서 18~33%의 실행에서 보도된 실수를 반복했고, 대조 환경에서는 많아야 1%였습니다. Medicare 포털 사고 재현에서는 사고 환경 15회 중 14회, 대조 환경 30회 중 0회 제한 구역에 들어갔습니다.
- 공격자가 없는 재현이 프롬프트 인젝션 재현보다 다섯 모델 모두에서 더 큰 피해를 냈고, 주입된 지시를 찾는 기존 방어는 이 피해 대부분을 놓쳤습니다. 사용자 확인이나 데이터 흐름 추적을 쓰면 피해가 사라졌습니다.
- 위험을 짚는 경고 문구는 다섯 모델 모두에서 피해를 줄였고 Claude Sonnet 4.6에서는 2%까지 낮췄습니다. 길이는 같지만 위험을 언급하지 않는 문구는 피해가 83~98% 남았습니다.
- 신빙성: 대부분 단일 에이전트 루프의 모의 환경에서 실행했고 실제 제품에서 함께 돌린 것은 파괴적 행동 재현 10개뿐이라 제품의 실제 위험과는 다를 수 있습니다. 보도에 원리가 없으면 저자 쪽이 재구성했으며, 독립 재구축이 11건 중 5건에서 저자 재현과 달랐다고 스스로 밝혔습니다.

#### Comment
- 사고 보도를 그대로 믿기보다 원인을 실험으로 확인한다는 접근이 실무에 유용합니다. 결론은 단순합니다. 운영 자격 증명을 에이전트 손이 닿지 않는 곳에 두라는 것입니다.
- 코드, 재현 자료, 세션 기록을 공개했다고 밝혔고, 각 모델의 결과를 OpenAI, Anthropic, Google, DeepSeek에 알렸다고 합니다.

# Backtracking Agent Applications Security Incidents
> arXiv 프리프린트 (심사 전). 펜실베이니아 주립대학교
> 2026

에이전트 애플리케이션이 간접 프롬프트 인젝션이나 메모리, 지식 베이스 오염 공격을 당했을 때, 분석가는 악성 데이터가 처음 들어온 함수 호출(침해 진입점)을 찾아야 합니다. 하지만 남아 있는 궤적 로그는 "지식 베이스 검색" 같은 에이전트 기능 수준만 기록하고, 진입점 후보는 소스 코드의 함수 호출 수준이라 둘 사이에 의미 차이가 큽니다. 저자들은 에이전트 기능 영역과 프로그램 변수 수준의 오염 전파 그래프를 잇는 교차 계층 의존 그래프와 질의 언어를 만들고, 이를 바탕으로 분석가가 몇 번의 질의로 진입점을 찾게 해 주는 도구 Origin을 제안했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.26525
- arXiv HTML 본문: https://arxiv.org/html/2611.26525
- arXiv PDF: https://arxiv.org/pdf/2611.26525

### Contribution
- 에이전트 기능 계층과 코드 실행 계층 사이를 잇는 중간 추상화(교차 계층 의존 그래프)와, 영역이나 변수 사이의 오염 흐름을 묻는 질의 언어를 정의했습니다.
- 외부 정보 출처 종류에 따라 에이전트 기능을 몇 개 영역으로 묶을 수 있다는 관찰에 기반해, 함수를 영역에 자동으로 배정하는 영역 추론 알고리즘을 설계했습니다.
- 약 1만 6천 줄 규모로 Joern 위에 구현하고 Pyrefly로 타입 추론을 보강해, 제너레이터, 인스턴스 변수, 동적 디스패치에서 생기는 오염 전파 누락을 줄였습니다.

### Evaluation
- GPT-Researcher, Quivr, aider, MetaGPT, SWE-agent 등 실사용이 많은 에이전트 애플리케이션 5종에서 간접 프롬프트 인젝션, 메모리 오염, 지식 베이스 오염, 복합 공격을 포함한 사고 8건을 사례 연구로 분석했습니다.
- Origin을 쓴 분석가는 8건 모두에서 침해 진입점과 실제 공격 경로를 찾았고, 5건은 질의 두 번, 3건은 질의 네 번이면 충분했습니다. 동기 사례인 GPT-Researcher에서는 로그로 걸러 낸 뒤에도 후보가 1,518개 남아 수작업 분석에 몇 시간이 걸렸다고 합니다.
- 정답 진입점과 도착점을 미리 알려 줘도 Joern, CodeQL, Pysa는 영역 추상화가 없어 같은 사례들을 진단하지 못했습니다. 영역 추론 정확도는 애플리케이션에 따라 88.9~100%였습니다.
- 신빙성: 평가는 사고 8건의 사례 연구이고 분석가는 저자 쪽입니다. 사람이 검증한 함수와 정보 출처 대응표를 입력으로 썼고, 개발자가 붙이는 레이블이 일부 필요합니다.

#### Comment
- 정적 분석만 쓰므로 LangChain 도구 호출처럼 프레임워크 내부에서 동적으로 정해지는 경로나, 매 반복마다 LLM이 다음 기능을 고르는 자율 에이전트 루프에서는 진입점을 확정하기 어렵다고 저자들이 한계로 밝혔습니다.
- 사고 대응 관점에서 진입점을 찾으면 지식 베이스에서 지울 파일을 정확히 지목하거나, 앞으로 남겨야 할 로그 위치를 개발자에게 알려 줄 수 있다는 점이 실용적입니다.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# On the Reliability of CyberGym Evaluation: Task Material Consistency and Reference-Target Identity
> arXiv 프리프린트 (심사 전). 소속 표기 없음
> 2026

CyberGym은 AI 에이전트가 취약점 설명과 소스 코드만 보고 개념 증명 입력을 만들 수 있는지 평가하는 벤치마크로, 입력이 취약한 버전에서는 충돌을 일으키고 수정된 버전에서는 그렇지 않으면 성공으로 봅니다. 저자들은 이 차등 통과가 곧 "의도한 취약점을 재현했다"는 뜻이 되려면 과제 자료가 일관되고 입력이 실제로 목표 결함을 건드려야 한다고 보고, 전체 1,507개 과제의 자료를 점검하고 한 에이전트 실행 결과의 입력을 하나하나 확인했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.25790
- arXiv HTML 본문: https://arxiv.org/html/2611.25790
- arXiv PDF: https://arxiv.org/pdf/2611.25790

### Contribution
- 기준 충돌 보고서가 가리키는 결함을 목표로 정하고, 과제 자료의 일관성 점검과 제출 입력의 결함 일치 여부 평가를 분리하는 방법을 제시했습니다.
- 자료 점검은 LLM 두 차례 판정 뒤 전문가가 불일치를 판정하고, 층화 표본을 블라인드 재검토하는 방식으로 진행했습니다.
- 입력 평가는 실행 확인, 충돌 서명 일치, LLM 보조 근본 원인 검토의 세 단계로 구성했습니다. 예를 들어 HarfBuzz 과제에서 목표 결함은 AAT 치환 표 파싱인데, 제출 입력은 CFF 파서의 다른 결함을 건드렸고 수정 버전에 그 결함의 수정도 함께 들어 있어 통과한 사례를 보였습니다.

### Evaluation
- 1,507개 과제 중 338개(22.4%)에 불일치 표시가 붙었습니다. 가장 많은 유형은 수정 범위 불일치(205개)와, 설명과 패치가 함께 다른 결함을 가리키는 경우(110개)였습니다.
- GLM-5.3의 Level-1 전체 실행 한 번에서 나온 차등 통과 1,286건 중 89건은 목표가 아닌 결함, 10건은 근거 부족으로 판정됐습니다. 목표 결함 적중을 요구하면 통과율이 85.3%에서 78.8%로 떨어집니다.
- 자료에 문제가 없던 과제의 통과 1,052건 중에서도 39건(3.7%)이 목표가 아닌 결함이었습니다.
- 신빙성: 입력 평가는 한 모델의 한 번 실행만 대상으로 했고, 결함 일치 판정은 LLM 보조 검토에 기대므로 저자들도 독립 검증이 필요하다고 밝혔습니다.

#### Comment
- 에이전트 보안 역량 점수를 해석할 때 "충돌했다"와 "그 취약점을 재현했다"를 구분해야 한다는 점을 수치로 보여 준 연구입니다. 다른 취약점 재현 벤치마크에도 같은 문제가 있을 수 있습니다.
- 본문에 소속이 적혀 있지 않고 연락처가 중국 메일 서비스 주소라, 중국 기관 논문일 가능성을 염두에 두고 더 확인했습니다. 대상이 공개 벤치마크이고 사례가 과제 번호 단위로 구체적이며, 결론의 수치도 과장된 정황은 없었습니다. 다만 점검 결과나 코드의 공개 주소는 본문에서 찾지 못해 재현 가능성은 제한적입니다. 소속 미확인.
- 본문 출처: arXiv PDF(사용자 컴퓨터에서 받음).

# Text-Aware, Vision-Blind: How Multimodal Image Editing Systems Handle Unsafe Inputs
> arXiv 프리프린트 (심사 전). CISPA 헬름홀츠 정보보안센터, 홍콩 과학기술대학교(광저우), 홍콩 과학기술대학교
> 2026

이미지 편집 서비스에서는 사용자가 올리는 이미지 자체가 위험할 수 있어, 안전 판단에 이미지와 편집 지시를 함께 고려해야 합니다. 저자들은 상용 이미지 편집 시스템의 안전 인식을 측정하는 벤치마크 EditSafetyBench를 만들었습니다. 안전한 이미지와 위험한 이미지를 11개 위험 범주에 걸쳐 중립 지시, 위험을 줄이는 지시, 위험한 의도의 지시와 짝지어 5,940개 쌍을 구성했고, Gemini, GPT Image, Qwen 이미지 편집 API, Qwen 로컬 모델 네 시스템을 시험했습니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.26569
- arXiv HTML 본문: https://arxiv.org/html/2611.26569
- arXiv PDF: https://arxiv.org/pdf/2611.26569

### Contribution
- 모델 단독이 아니라 안전 필터와 API 포장까지 포함한 배포 파이프라인 전체의 허용, 거부, 오류 결정을 측정하는 문제로 정식화했습니다.
- 적대적 공격이 아닌 평범한 편집 상황에서 이미지 위험과 텍스트 의도를 함께 따지는지 보는 첫 벤치마크라고 주장합니다.
- 상용 시스템이 텍스트에는 민감하고 이미지에는 둔감한 "텍스트 인식, 시각 무시" 경향을 수치로 보였습니다.

### Evaluation
- Gemini와 GPT는 위험한 의도의 편집 지시를 81.6~87.1% 거부했지만, 위험한 이미지에 "화질 개선" 같은 중립 지시를 준 경우는 22.4~24.2%만 거부했습니다.
- 위험한 의도의 지시가 주어졌을 때 이미지가 안전한지 위험한지에 따른 허용률 차이는 0.2~0.4%에 불과해, 텍스트 의도가 판단을 지배했습니다. 반대로 위험한 부분을 가리는 편집 같은 위험 감소 지시는 과도하게 거부됐습니다.
- 범주별로는 시스템마다 판단이 달라, 정치적으로 위험한 이미지 편집을 GPT는 70.4%, Gemini는 34.8% 허용했습니다. 성적 콘텐츠는 모든 범주 중 시각 민감도가 가장 높았습니다.
- 신빙성: 이미지는 UnsafeBench에서 가져왔고 MagicBrush로 별도 검증했습니다. 측정한 것은 허용과 거부 결정이지 결과 이미지의 유해성이나 편집 품질은 아니며, 편집 지시는 9개 문장 묶음이라 다양성이 제한됩니다. 상용 시스템은 평가 이후 필터가 바뀔 수 있습니다.

#### Comment
