# Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security
> arXiv cs.CR 2611.01976 (프리프린트, 심사 전). 상하이교통대학교(중국), Inria(프랑스)
> 2026

LLM 에이전트 프레임워크는 MCP 서버나 확장 기능 같은 외부 도구를 설치할 때 한 번 검사하고 권한을 주지만, 그 뒤 도구가 업데이트될 때는 바뀐 코드를 다시 검사하지 않는 경우가 많습니다. 저자들은 이 간극을 "도구 업데이트 간극(tool update gap)"이라 부르고, 이를 노리는 공격 ETUDE(Exploiting Tool Updates for Direct Execution)를 제안합니다. 공격자는 먼저 정상적인 도구(v1)를 배포해 설치 시점 검사를 통과하고, 이후 이름, 설명, 입력 스키마는 그대로 둔 채 구현 코드에만 악성 동작을 넣은 v2를 배포합니다. 악성 동작은 정상 호출 중에 도구 런타임 안에서 직접 실행되므로 LLM 문맥에는 아무런 지시문도 나타나지 않습니다. 그래서 프롬프트 인젝션 탐지기나 모델 입력을 살피는 방어는 이 공격을 볼 수 없습니다.

저자들은 Gemini CLI, Codex CLI, Claude Code, DeepSeek Harness, OpenCode, Pi, Goose 일곱 개 프레임워크에서 v1 승인 이후 v2가 재검사 없이 기존 권한으로 실행된다는 점을 확인했고, 공격 목표로는 합성 자격 증명 유출(W1), 허가되지 않은 외부 API 호출(W2), 로컬 파일 변조(W3)를 설정했습니다.

### Contribution
- 공격을 "언제 악성 기능이 들어오는가(설치 시점 대 업데이트)"와 "어떤 경로로 실행되는가(코드 직접 실행 대 모델 문맥 유도)" 두 축으로 나누고, 그동안 거의 다뤄지지 않은 "업데이트로 들어와 코드로 직접 실행되는" 영역을 짚었습니다.
- 상용과 오픈소스를 합쳐 일곱 개 에이전트 프레임워크에서 업데이트 뒤에도 기존 권한이 그대로 유지된다는 점을 실제로 확인했습니다. 도구 호출마다 사용자 확인을 받는 프레임워크도 그 확인은 호출을 허락할 뿐 바뀐 구현을 검증하지는 않는다고 지적합니다.
- 파일 무결성 검사(TLSH 유사도), LLM 기반 정적 코드 리뷰(Cisco MCP Scanner, SkillFortify, NVIDIA SkillSpector), 실행 감사(SkillDetonate 방식) 세 갈래 방어를 직접 시험해 각자의 한계를 보였습니다.

### Evaluation
- 설정: 마크다운 정리, CSV 통계, ICS(일정 파일) 생성 세 가지 도구와 W1~W3 목표를 조합하고, 조건마다 20개 작업을 5회 반복했습니다. 독립된 수신 서버, 서비스 기록, 파일 증거로 공격 성공률(ASR)을 매기고, 정상 작업 완료율(TCR)은 따로 측정했습니다.
- 결과: 초록 기준으로 일곱 프레임워크 평균 ASR 97.6%, TCR 95.9%이며, 가장 강한 프롬프트 인젝션 기준선(업데이트로 들어온 문맥 유도형)보다 ASR이 크게 높습니다. 본문 RQ1(같은 백엔드, 21개 조건)에서는 ETUDE가 ASR 100.0%, 기준선이 20.2%였습니다. 백엔드 모델을 네 가지로 바꾼 실험에서도 ASR이 80~100% 범위였습니다.
- 방어 평가: TLSH 거리로는 정상적인 기능 추가(거리 173~221)와 악성 업데이트(145~233)가 겹쳐, 어떤 임계값도 악성만 막고 정상 유지 보수를 통과시키지 못했습니다. 정적 리뷰는 난독화에 약하고, 실행 감사는 특정 입력에서만 발동하는 동작을 놓치고 비용이 크다고 보고합니다.
- 지표의 신빙성: 공격이 도구 코드 안에서 직접 실행되는 구조이므로 높은 ASR 자체는 예상 가능한 결과이고, 비교의 핵심은 "프레임워크가 재검사 없이 업데이트를 받아들인다"는 관찰입니다. 실패 사례(CSV 인자 오류, 호출 횟수 불일치 등)를 따로 집계해 공개한 점은 신뢰를 높입니다.

#### Comment
- 에이전트 도구 생태계의 공급망 문제를 정면으로 다룬 논문입니다. XZ Utils나 event-stream 사건처럼 신뢰를 쌓은 뒤 업데이트로 악성 코드를 넣는 수법이 에이전트 도구에도 그대로 통한다는 점을 실험으로 보였고, 저자들은 승인 단위를 "검토한 코드 그 자체"로 바꿔야 한다고 제안합니다.
- 한계: 공격 자체는 새롭다기보다 기존 소프트웨어 공급망 공격을 에이전트 환경으로 옮긴 것에 가깝습니다. 실제 마켓플레이스의 도구를 고치지 않고 직접 만든 도구로 실험했으며, 프레임워크별 업데이트 경로(패키지 재해석, 서버 재시작 등)는 하네스로 재현했습니다.
- 중국 기관 검증: 1저자와 교신저자 다수가 상하이교통대학교 소속이고, Inria의 Yufei Han이 공저자로 참여했습니다. 두 기관 모두 실재하는 주요 연구 기관입니다. 본문에서 저자들의 코드 저장소 주소는 찾지 못해 재현 자료 공개는 확인하지 못했습니다. 다만 핵심 주장(업데이트 후 재검사 부재)은 공개 프레임워크에서 누구나 확인할 수 있는 성질이고, 수치가 높은 이유도 공격 구조상 자연스러워 과장된 지표로 보기는 어렵습니다. 비교 대상도 같은 하네스에서 돌린 기준선이라 부적절하지 않습니다.

# Right Tool, Wrong Parameters: Defending LLM Agents Against Parameter Poisoning
> arXiv cs.CR 2611.04673 (프리프린트, 심사 전). 중국과학기술대학교(USTC, 중국)
> 2026

간접 프롬프트 인젝션 방어는 대개 "주입된 내용이 새로운 도구 호출이나 엉뚱한 행동을 일으켰는가"를 봅니다. 이 논문은 행동은 그대로 두고 인자만 바꾸는 공격, 즉 "파라미터 오염(parameter poisoning)"을 다룹니다. 예를 들어 사용자가 앨리스에게 500달러를 보내라고 했을 때, 공격자가 조작한 메시지에 "앨리스의 계좌가 바뀌었다"고 적어 두면 에이전트는 예정대로 송금 도구를 부르되 계좌 번호만 공격자 것으로 넣습니다. 새로운 행동이 없으니 기존 방어가 잘 잡지 못합니다.

저자들은 인자의 정당성을 "그 값을 만든 정보가 이 작업에서 그 인자를 정할 권한이 있는가"로 판단해야 한다고 보고, 세 단계 방어 AuthorityFlow를 제안합니다. 사용자 요청을 해석해 정보 필드별 권한 계층을 만들고(예: 호텔 주소 필드는 일정 장소를 정할 수 있지만 리뷰 본문은 못 함), 도구 인자마다 그 값을 뒷받침한 근거를 추적한 뒤, 근거가 의미상 값을 지지하는지와 출처가 그 용도에 권한이 있는지를 둘 다 통과할 때만 실행을 허락합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.04673
- arXiv HTML 본문: https://arxiv.org/html/2611.04673
- arXiv PDF: https://arxiv.org/pdf/2611.04673

### Contribution
- 지시문 수준 인젝션과 구분되는 "인자 수준" 공격 표면을 정리하고, 권한을 출처의 고정 속성이 아니라 작업에 따라 달라지는 관계로 정의했습니다.
- 의미 지지 검사와 출처 권한 검사를 분리한 매개변수 단위 승인 방식을 제시했습니다. 에이전트 오케스트레이션 계층에서 동작하므로 모델 내부나 도구 구현을 고칠 필요가 없습니다.
- AgentDojo를 확장한 평가 세트 FactAuthBench(은행, Slack, 여행, 업무 네 영역, 정상과 공격 쌍 144개)를 만들었습니다.

### Evaluation
- 에이전트 모델: Qwen3.6-27B, Llama-3.3-70B, GPT-4o. AuthorityFlow의 보조 모델은 기본으로 Qwen3.6-27B를 씁니다.
- 비교 대상: Sandwiching, Spotlighting(입력 단계), IPIGuard, CaMeL, DRIFT(시스템 단계), MELON, AttriGuard(실행 검증과 귀속 기반). 공식 구현이나 기본 설정을 썼다고 밝힙니다.
- 지표: 정상 작업 효용(BU), 공격 상황 효용(UA), 공격 성공률(ASR).
- 결과(Qwen3.6-27B): 방어 없음 ASR 93.06%, BU 90.28%. AuthorityFlow는 ASR 9.03%, BU 82.64%입니다. GPT-4o에서는 방어 없음 ASR 57.64%가 AuthorityFlow로 5.56%가 됩니다. 정화(purification) 단계를 붙이면 UA가 58.33%(Qwen), 60.42%(GPT-4o)로 오릅니다.
- 주의할 점: 표를 보면 CaMeL의 ASR이 0.69%(Qwen), 2.08%(GPT-4o)로 AuthorityFlow보다 낮습니다. 대신 CaMeL은 BU가 43.75%, 39.58%로 크게 떨어집니다. 초록은 이 비교를 언급하지 않으므로, "가장 낮은 ASR"이 아니라 "효용 대비 나은 균형"으로 읽는 것이 맞습니다. 평가 세트가 144쌍으로 작고 저자들이 직접 만든 것이라 일반화에는 한계가 있습니다.

#### Comment
- 실무적으로 와닿는 문제 설정입니다. 송금 계좌, 메일 수신자, 일정 장소처럼 "도구는 맞는데 값이 틀린" 사고는 행동 감시만으로는 막기 어렵다는 점을 잘 보여 줍니다.
- 한계: 권한 계층을 LLM이 사용자 요청에서 추론하므로 그 단계가 틀리면 방어 전체가 흔들립니다. 보조 모델 호출이 늘어나는 비용은 따로 정리되어 있지 않았습니다.
- 중국 기관 검증: 저자 전원이 중국과학기술대학교 소속이며, 실재하는 주요 대학이고 Weiming Zhang 교수 연구실은 정보 은닉과 AI 보안 분야에서 꾸준히 논문을 내 왔습니다. 본문에서 코드나 평가 세트 공개 주소는 찾지 못했습니다. 지표는 기준선보다 좋지만 CaMeL이 ASR에서 앞서는 결과를 표에 그대로 실었고, 비교 대상도 이 분야의 대표 방어들이라 부적절하지 않습니다. 재현 자료가 없다는 점은 감안해야 합니다.

# JailBound: FOL-Guided Jailbreak Evaluation for Exploring LLM Behavioral Boundaries
> arXiv cs.CR 2611.07530 (프리프린트, 심사 전. 본문 서식에 NeurIPS 2026 표기가 있으나 채택 여부는 확인하지 못함). 치루공업대학교(산둥성과학원), 취안청 연구소, 구이저우대학교(중국)
> 2026

탈옥(jailbreak) 평가 벤치마크는 대부분 사람이 모으거나 만든 프롬프트에 의존해 새로운 위협 유형으로 넓히기 어렵고, 기존 공격 탐색은 성공률만 최적화해 모델이 거절과 위험 응답 사이에서 어떻게 바뀌는지는 잘 보여 주지 못합니다. JailBound는 위험 범주, 적용 분야, 공격 유형으로 이루어진 계층형 분류 체계를 두고, 미세 조정한 메타 공격 생성기로 조건별 평가 프롬프트를 자동으로 만듭니다. 그다음 임베딩 공간에서 1차 손실(first-order loss, 공격 손실의 기울기 크기에 해당하는 국소 민감도 신호)을 이용해 두 갈래로 탐색합니다. 하나는 공격 효용이 높고 안정적인 상태를 찾는 "고가치" 갈래, 다른 하나는 작은 변화에도 판정이 뒤집히기 쉬운 상태를 찾는 "안전 민감" 갈래입니다. 찾은 연속 임베딩은 실제 텍스트 프롬프트로 바꾼 뒤 외부 판정 모델로 성공 여부를 매깁니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.07530
- arXiv HTML 본문: https://arxiv.org/html/2611.07530
- arXiv PDF: https://arxiv.org/pdf/2611.07530
- 저자 저장소(논문에 기재된 코드): https://github.com/FrazeWu/JailBound

### Contribution
- 분류 체계에 따라 새로운 위협 조건의 평가 사례를 자동 생성하는 벤치마크 구축 방식을 제시했습니다. 본 실험에서는 169개 조합 조건, 26,554개 공격 사례, 아홉 가지 공격 유형을 썼습니다.
- 성공률만 보지 않고 "판정 경계 근처의 민감한 상태"를 따로 탐색해, 모델 안전성의 국소적 취약 지점을 진단하는 관점을 더했습니다.
- 13개 모델 계열, 46개 LLM(Llama, Qwen, Gemma, Mistral, Claude, GPT, Gemini 등)을 같은 절차로 평가했습니다.

### Evaluation
- 비교 대상: 공개 벤치마크 AdvBench, JailbreakBench, SafetyBench, SG-Bench, HarmBench와, 같은 조건에서 돌린 최적화 공격 GCG, PEZ, GBDA, 그리고 1차 손실 항을 뺀 자기 변형(ZOL-only).
- 결과: Qwen2.5-14B-Instruct 대상, 판정 모델 두 개(Octopus-SEval-14B, Qwen3-32B-AWQ)에서 고가치 갈래가 ZOL-only보다 평균 5.1%p, 4.9%p 높은 ASR을 보였습니다. 예를 들어 JailBound 출처 프롬프트에서는 초기 18.3%, GCG 44.4%, ZOL-only 60.4%, 고가치 갈래 64.5%입니다.
- 안전 민감 갈래 상태는 모든 교란 반경에서 고가치 갈래보다 판정 뒤집힘 비율(BFR)이 높았습니다.
- 연속 임베딩을 텍스트로 바꾸면 ASR이 평균 6.9%p 떨어진다는 점을 스스로 보고해, 주장 범위를 실제 텍스트 공격으로 한정했습니다. 주요 결과는 세 번 반복한 평균입니다.
- 지표의 신빙성: 개선 폭이 수 %p 수준으로 과장되어 보이지 않고, 판정 모델을 두 개 써서 순위가 유지되는지 확인했습니다. 다만 판정이 LLM 판정 모델에 의존하므로 판정 모델의 오류가 그대로 반영됩니다.

#### Comment

# The Web Doesn't Sit Still: Adversarial Self-Evolving Attacks on Search Agents
> arXiv cs.CR 2611.03754 (프리프린트, 심사 전. 본문 서식에 NeurIPS 2026 표기가 있으나 채택 여부는 확인하지 못함). 난양공과대학교(싱가포르), 알리바바 그룹(중국)

웹 검색으로 정보를 모으는 검색 에이전트는 검색 결과에 섞인 조작 문서(RAG 오염)에 취약합니다. 기존 공격은 사람이 만든 고정 규칙(예: 정답 개체를 다른 개체로 바꾸기)에 의존하고, 방어 쪽 대응을 보고 공격을 바꾸지 않습니다. 이 논문은 공격과 방어가 함께 진화하는 이중 최적화 구조를 제안합니다. 안쪽 고리에서는 방어자가 현재 공격 풀에 맞춰 방어 지식을 갱신하고, 바깥 고리에서는 공격 전략이 진화합니다. 핵심 기법 CREO(Contrastive Rollout Evolutionary Optimization)는 공격 전략이 성공한 추론 경로와 실패한 경로를 대조해 얻은 신호로 전략을 변이, 교차, 선택합니다. 실험 환경은 DeepResearchGym을 확장해 약 3.8TB 규모의 고정 지식 베이스와 검색 결과에 조작 문서를 끼워 넣는 가로채기 장치를 둔 통제된 샌드박스입니다.

### Evaluation

#### Comment

# I Don't Care How You Hide It, I Care What You Do: Runtime Detection of Malicious ML Models
> IEEE ACSAC 2026 채택 논문(arXiv comment 표기), arXiv cs.CR 2611.08745 공개본. 버지니아 커먼웰스 대학교(미국), Volatility Foundation(미국)
> 2026

Hugging Face 같은 공개 플랫폼에 올라온 사전 학습 모델은 불러오거나 추론하는 순간 악성 코드를 실행하도록 만들 수 있습니다. PickleScan, ModelScan 같은 기존 스캐너는 os.system, eval 같은 위험 함수 목록과 정적 분석에 기대기 때문에, 같은 기능의 다른 함수로 바꾸거나 스캐너가 지원하지 않는 로딩 경로를 쓰거나 TensorFlow의 정상 API를 악용하면 놓칩니다. 저자들은 "어떻게 숨겼는지"가 아니라 "실제로 무엇을 하는지"를 보자는 관점에서 런타임 행위 탐지 시스템 ModelShield를 제안합니다.

ModelShield는 관점 지향 프로그래밍으로 ML 프레임워크 API(예: torch.load)에 계측 코드를 끼워 넣고, eBPF로 시스템 콜을 추적합니다. 두 계층이 공유하는 상관 식별자로 각 시스템 콜을 그것을 일으킨 모델 로딩이나 추론 작업에 연결하고, 이 연결을 스레드와 자식 프로세스까지 이어 갑니다. 이렇게 프레임워크 내부 동작이나 CUDA 초기화 같은 잡음과 모델이 일으킨 행위를 분리한 뒤, MITRE ATT&CK 기법에 대응시킨 탐지 패턴 195개로 분류합니다. 17개 프레임워크와 36개 파일 형식을 지원합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.08745
- arXiv HTML 본문: https://arxiv.org/html/2611.08745
- arXiv PDF: https://arxiv.org/pdf/2611.08745
- 저자 저장소(소스 코드, 탐지 분류 체계, 재현 스크립트): https://github.com/HalaAli198/ModelShield
- ACSAC 2026 채택 논문 목록: https://www.acsac.org/2026/program/papers/

### Contribution
- 정적 검사가 아닌 런타임 행위로 악성 모델을 판정하는 첫 시스템이라고 주장합니다. 실제로 해로운 동작이 관찰될 때만 악성으로 보고하므로, 위험 함수가 들어 있지만 실행되지 않는 정상 모델을 오탐하지 않습니다.
- 애플리케이션 계층 계측과 커널 계층 시스템 콜 추적을 결합해, 수천 개의 시스템 콜 가운데 어떤 것이 모델 작업 때문인지 구분하는 귀속 방법을 설계했습니다.
- 실제 플랫폼을 대규모로 검사해 기존 스캐너가 놓친 악성 모델을 찾고 플랫폼과 클라우드 사업자에 신고했습니다.

### Evaluation
- 정확도: PickleBall 연구에서 공개한 독립 데이터셋(정상 252개, 악성 84개)에서 오탐 0건, 탐지 47건, 미탐 37건입니다. 저자들은 미탐을 원인별로 나눠, 실제로는 페이로드가 없는 잘못된 라벨 1건, 실행 환경에 패키지가 없거나 Windows 전용 API를 노리는 9건 등 런타임에 악성 행위가 나타나지 않은 경우라고 설명합니다.
- 회피 기법: Liu 등의 함수 치환 15종, 로딩 경로 난독화 10종, Zhu 등의 TensorFlow SavedModel API 악용 4종, 모두 29개 변형을 전부 탐지했습니다. 비교한 ModelScan, PickleScan, Fickling, ModelAudit 가운데 모두 잡은 도구는 없었습니다.
- 대규모 검사: 2026년 3월 25일부터 5월 5일까지 올라온 Hugging Face 105,000개, ModelScope 30,000개, Kaggle 10,000개 모델을 검사해 Hugging Face에서 악성 모델 41개를 찾았습니다. 같은 41개에 대해 기존 도구의 탐지율은 ModelScan 29%, PickleScan 56%, Fickling 80%, ModelAudit 93%였습니다. 이후 8월 19일까지 Hugging Face 224,164개를 더 검사해 105개를 추가로 찾았다고 합니다.
- 비용: 모델당 분석 시간 중앙값 12.3초, 90%가 35.5초 안에 끝납니다.
- 지표의 신빙성: 정확도 평가에 남이 만든 공개 데이터셋을 쓰고, 미탐을 숨기지 않고 원인별로 공개한 점이 좋습니다. 다만 "오탐 0건"은 정상 252개라는 작은 표본에서 나온 값이고, 대규모 검사의 41개는 ModelShield가 찾은 것을 기준으로 다른 도구를 비교한 것이라 ModelShield 자신의 미탐은 이 수치에 드러나지 않습니다.

#### Comment
- 정적 스캐너의 고질적 약점(목록 우회)을 행위 관찰로 정면 돌파한 실용적인 연구입니다. 실제 리버스 셸과 자격 증명 탈취 모델을 업로드 수 시간 안에 잡아 신고했다는 점에서 현장 가치가 큽니다. 공저자 Andrew Case는 메모리 포렌식 도구 Volatility의 핵심 개발자입니다.
- 한계: 동적 분석이라 특정 입력이나 시간 조건에서만 발동하는 페이로드, 실행 환경에 없는 패키지를 요구하는 페이로드는 놓칩니다. Linux 환경만 지원해 Windows를 노리는 페이로드는 탐지하지 못합니다. 패턴 발견 과정에 LLM(GPT-5.5)을 썼습니다.

# NotaryMark: Multi-Bit Watermarking for Black-Box DatasetUsage Auditing in Text-to-Image Diffusion Models

허락 없이 수집한 이미지로 텍스트-이미지 생성 모델을 학습시키는 일이 늘면서, 데이터 소유자가 "내 데이터셋이 학습에 쓰였는가"를 확인하는 감사 기법이 필요해졌습니다. 기존 데이터셋 워터마크는 확산 모델 학습의 노이즈 추가와 제거 과정에서 잡음처럼 취급되어 점점 사라지고, 특히 여러 비트의 정보를 담는 다중 비트 워터마크는 거의 살아남지 못합니다. - 결과(초록과 본문): 32비트 미만에서 평균 비트 정확도 0.85~0.90, 32비트 이상에서 0.67~0.80으로, 기존 다중 비트 방법(약 0.42~0.60)보다 높습니다. 다중 질의 집계를 쓰면 32비트에서 정확한 복원이 가능했고, 예컨대 SDXL에서 집계 비트 정확도는 Pokémon 97.50%, CelebA 81.59%, WikiArt 89.09%였습니다.
- 낮은 워터마크 비율: 전체 학습 데이터 중 워터마크 데이터 비율이 0.1이면 탐지율(TPR)이 Pokémon 47%, CelebA 31%로 떨어지고, 0.3 이상에서 100%가 됩니다. WikiArt는 낮은 비율에서 비트 정확도가 무작위 수준에 가깝습니다.
- 강건성: 7개 범주 15가지 회피 공격을 시험했고, 강한 공격은 데이터 품질을 크게 희생해야만 워터마크를 지울 수 있었다고 보고합니다.
- 비교 대상과 신빙성: 비교 대상은 전통적인 이미지 워터마크(DwtDct, SSL, RivaGAN)와 확산 모델용 데이터셋 워터마크 DiffusionShield입니다. 전통 기법은 이 설정을 위해 만든 것이 아니어서, 저자들도 이 비교를 "전이 가능성 시험"으로 해석해야 한다고 부록에서 밝혔습니다. 낮은 워터마크 비율과 강한 흐림, 재생성 공격에서 약하다는 결과도 그대로 보고했습니다.

#### Comment
- 생성 모델의 저작권 감사라는 시의성 있는 주제이고, 다중 비트 정보를 학습 과정 너머로 전달한다는 점이 새롭습니다. 실제 배포에서 흔한 낮은 워터마크 비율이 여전히 큰 약점입니다.
- 한계: LoRA 미세 조정 위주로 평가해 전체 학습이나 다른 미세 조정 방식에서의 효과는 남은 과제입니다. 데이터셋마다 인코더와 디코더를 학습해야 해 비용이 듭니다.
- 중국 기관 검증: 저자 다수가 시안교통대학교와 저장대학교 소속이고, 공저자 Min Chen은 암스테르담 자유대학교 소속입니다. Zhikun Zhang과 Min Chen은 데이터 감사 분야(FACE-AUDITOR 등)에서 꾸준히 주요 학회에 논문을 낸 실재 연구자입니다. 게재처 CCS는 최상위 보안 학회입니다. 공개 데이터셋과 공개 모델을 썼지만 본문에서 코드 공개 주소는 찾지 못해 재현 자료는 확인하지 못했습니다. 기존 방법 대비 우위 폭이 크지만 약점이 되는 조건도 함께 보고해 지표가 과장되었다고 보기는 어렵습니다. 비교 대상 중 전통 워터마크는 공정한 경쟁자라기보다 하한선에 가깝다는 점은 감안해야 합니다.

# Logit Laundering: Evading Data-Use Auditing in Large Language Models
> ACM CCS 2026 채택 논문(arXiv comment 표기, DOI 10.1145/3830454.3846794), arXiv cs.CR 2611.09446 공개본. 베이징우전대학교(중국), 중관촌실험실(중국), 오거스타 대학교(미국)
> 2026

LLM 학습 데이터의 무단 사용을 밝히는 대표적인 방법은 데이터에 워터마크를 넣어 두고 모델 출력에서 그 통계적 흔적을 찾는 것입니다. 이 논문은 반대편, 즉 저작권 데이터를 몰래 학습에 쓴 사업자가 감사를 피하려 한다면 무엇을 할 수 있는지를 체계적으로 살핍니다. 저자들은 먼저 학습 데이터를 고치는 회피(문자 치환, 토큰 교체, 의역, 번역)가 텍스트 품질을 해치면서도 흔적을 남긴다는 점을 보이고, 모델 출력 단계에서 회피하는 Logit Laundering을 제안합니다. 모델 파라미터는 그대로 두고, 추론 때 로짓만 고쳐 워터마크가 만든 통계적 편향을 상쇄합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.09446
- arXiv HTML 본문: https://arxiv.org/html/2611.09446
- arXiv PDF: https://arxiv.org/pdf/2611.09446
- DOI(ACM CCS 2026): https://doi.org/10.1145/3830454.3846794

### Contribution
- LLM 데이터 사용 감사를 공격자 관점에서 체계적으로 분석한 첫 연구라고 주장합니다.
- 워터마크로 생긴 편향을 추정하는 통계적 편향 추정기를 끼워 넣는 로짓 재조정 모듈과, 다음 토큰 예측 확신도에 따라 억제 강도를 조절하는 모듈을 설계해, 회피 효과와 모델 유용성의 균형을 잡았습니다.
- 감사 방법을 설계하는 쪽에 추론 단계 조작까지 고려해야 한다는 과제를 던집니다.

### Evaluation
- 데이터: 기존 모델 학습 데이터와 겹치지 않도록 2025년에 출간된 저작권 도서 50권에서 512토큰 문단 4,959개를 뽑아 워터마크를 넣고, Pile 테스트 분할의 arXiv 논문 500개, Pile-CC 1,000개, Hacker News 글 646개와 섞어 지속 사전 학습을 했습니다. 기반 모델은 다섯 종입니다.
- 감사 방법: STAMP 계열과 Radioactive 워터마크 탐지를 대상으로 했고, 탐지 쪽에서 top-k, nucleus 샘플링, Min-K% Prob 같은 대체 점수도 시험했습니다.
- 비교 대상: 데이터 수준 회피로는 LLM 워터마크 공격 기법 일곱 가지(동형 문자, 삽입, 오타, 토큰 교체, 동의어, 의역, 번역), 모델 수준 회피로는 저자들이 예비 실험에서 만든 Rank-Swap 변형 세 가지를 썼습니다.
- 지표: t-통계량과 p-값, z-점수와 p-값의 감소 폭으로 회피 효과를, 저작권 지식 객관식 정확도, GPT2-XL 기반 유창성, MAUVE, LLM 심사 점수, ARC-Challenge, MMLU, TriviaQA로 유용성을 측정했습니다. 저자들은 감사 신호를 크게 약화시키면서 유용성을 대부분 유지했다고 보고합니다.
- 지표의 신빙성: 데이터 오염을 피하려고 최신 도서를 쓴 설계가 신중합니다. 다만 모델 수준 비교 대상이 저자들이 직접 만든 변형뿐이라는 점은 첫 연구라는 성격상 불가피하지만 비교의 무게를 줄입니다.

#### Comment
- 감사 기법의 위협 모델에 "사업자가 출력을 조작할 수 있다"는 현실적 가정을 추가했다는 점에서 의미가 큽니다. 블랙박스 감사가 출력만 보는 이상, 같은 계열의 모든 방법이 영향을 받을 수 있습니다.
- 한계: 회피를 막는 방어는 다루지 않았고 후속 과제로 남겼습니다. 감사자가 로짓 조작을 감지하는 방법이 나오면 효과가 달라질 수 있습니다.
- 중국 기관 검증: 저자 대부분이 베이징우전대학교와 중관촌실험실 소속이고, 중국 국가자연과학기금 지원을 받았습니다. 게재처는 CCS이며 ACM DOI가 이미 부여되어 채택 사실이 뒷받침됩니다. 공개 데이터와 공개 모델을 썼지만 본문에서 코드 공개 주소는 찾지 못했습니다. 평가 지표는 통계 검정값과 표준 벤치마크라 조작 여지가 작고, 비교 대상 선정 이유도 명시했습니다.
- 본문 출처: 사용자 컴퓨터에서 받은 arXiv 공식 PDF.

# GuardrailAgent: An Agentic Framework for Jailbreak Defense
> EMNLP 2026 Findings 게재(ACL Anthology 2026.findings-emnlp.70), arXiv cs.CR 2611.09734 공개본. CISPA 헬름홀츠 정보보안센터(독일)
> 2026

LLM 탈옥 공격은 거의 매일 새로운 변형이 나오는데, 안전성 미세 조정이나 외부 필터 같은 기존 방어는 알려진 공격에 맞춰 고정되어 있어 새 공격에 늦게 대응합니다. GuardrailAgent는 여러 에이전트가 협력해 공격 정보를 스스로 모으고 요약해 지식 베이스를 계속 갱신하고, 이를 바탕으로 입력 쪽(프롬프트)과 출력 쪽(모델 응답) 양쪽에서 탈옥을 탐지하는 방어 체계입니다. 잘못 분류한 사례를 되먹임 모듈로 지식 베이스에 반영해 적은 비용으로 성능을 끌어올립니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.09734
- arXiv HTML 본문: https://arxiv.org/html/2611.09734
- arXiv PDF: https://arxiv.org/pdf/2611.09734
- ACL Anthology 공식 논문 페이지: https://aclanthology.org/2026.findings-emnlp.70/
- ACL Anthology 공식 PDF: https://aclanthology.org/2026.findings-emnlp.70.pdf
- 저자 저장소(arXiv comment 표기): https://github.com/TrustAIRLab/GuardrailAgent
- 저자 저장소(논문 본문 표기): https://github.com/tianzechang/GuardrailAgent

### Contribution
- 외부 자료(논문 등)에서 공격 특징을 모아 지식 베이스를 자동으로 갱신하는 적응형 방어를 제안했습니다.
- 입력 탐지 에이전트와 출력 탐지 에이전트를 나누고, 출력 쪽은 이미 거절한 응답은 그대로 통과시키고 그렇지 않을 때 알려진 탈옥 응답 패턴과 비교합니다.
- 오분류 사례를 반영하는 되먹임 모드로, 처음 보는 공격에도 빠르게 적응한다는 점을 보였습니다.

### Evaluation
- 공격 데이터: JailbreakRadar 벤치마크와 WildJailbreak 데이터셋에서 고른 10종 이상의 탈옥 기법(템플릿과 난독화 같은 모델 독립형, 반복 최적화가 필요한 모델 의존형 포함). 정상 질의 1,000개(ChatGPT-5로 만든 900개와 그중 100개를 역할극 형태로 바꾼 것)로 유용성을 측정했습니다.
- 대상 모델: ChatGLM3-6B, Vicuna-7B, GPT-3.5-turbo. 외부 가드레일 효과를 잘 보려고 비교적 약한 모델을 골랐다고 밝힙니다.
- 결과: 입력 쪽 탐지율 93.1%, 전체 탐지율 93.9%, F1 95.8%이며, OpenAI Moderation과 Llama Guard 4보다 전체 탐지율이 최소 0.219, F1이 최소 0.123 높습니다. RTX 4090 한 장 환경에서 측정한 지연 시간과 토큰 비용도 함께 보고합니다.
- 지표의 신빙성: 공개 벤치마크를 썼지만, 결과는 지식 베이스를 미리 채워 둔 "예열된" 상태에서 얻은 것입니다. 정상 질의를 LLM으로 생성한 점, 대상 모델이 오래된 모델이라는 점은 실제 배포 환경과 차이가 있습니다.

#### Comment
- 6쪽 분량의 짧은 Findings 논문으로, 아이디어와 설계 위주입니다. 지식 베이스를 스스로 갱신하는 방어는 공격자가 그 갱신 경로를 오염시킬 수 있다는 새 위험도 생기는데, 이 부분은 다루지 않습니다.
- 한계: 유사도 기반 검색과 문헌 기반 분석 같은 가벼운 구성 요소로 구현되어 의미가 모호한 공격이나 깊은 추론이 필요한 공격에는 약할 수 있다고 저자들이 밝혔습니다.
- 신뢰도: EMNLP Findings는 심사를 거친 ACL 계열 게재처입니다. CISPA의 Yang Zhang, Michael Backes 연구실은 LLM 보안 분야에서 활발한 그룹이며 코드가 공개되어 있습니다.
- 본문 출처: ACL Anthology 공식 PDF.

# MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory
> arXiv cs.CR 2611.09721 (프리프린트, 심사 전). 렌셀러 폴리테크닉 대학교(미국), Microsoft(미국)
> 2026

LLM 에이전트는 여러 세션에 걸친 긴 작업을 위해 메모리 시스템을 씁니다. 한 세션에서 만난 악성 지시가 메모리에 저장되었다가 나중 세션에서 꺼내져 실행될 수 있으므로, 메모리는 새로운 공격 표면입니다. 그런데 메모리 시스템마다 정보를 저장하고 꺼내는 방식이 달라 오염의 결과도 달라집니다. MemoryDojo는 오염된 정보가 메모리에 들어가고, 남아 있거나 퍼지고, 다시 꺼내져 이후 행동에 영향을 주기까지의 전 과정을 추적하는 벤치마크입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.09721
- arXiv HTML 본문: https://arxiv.org/html/2611.09721
- arXiv PDF: https://arxiv.org/pdf/2611.09721

### Contribution
- 4개 영역, 155개의 다중 세션 장기 작업 궤적과 5개 메모리 시스템(A-MEM, Graphiti, Letta, Mem0, Memora)을 지원하는 확장 가능한 벤치마크를 만들었습니다.
- 삽입 성공률, 회수 성공률, 지속과 전파에 따른 회수 기여, 이후 작업 도달률 같은 생애 주기별 지표를 새로 정의했습니다. 기존 공격 성공률이 "그 자리에서 공격이 통했는가"만 본다면, 이 지표들은 오염이 얼마나 오래, 멀리 가는지를 봅니다.
- 보조 환경에서 페이로드 문구를 반복 개선하는 메모리 인식 오염 최적화 방법을 제안했습니다.

### Evaluation
- 설정: 첫 세션의 도구 관찰 결과에 페이로드 하나를 덧붙이고 나머지 세션을 진행합니다. 주 대상 모델은 GPT-5.6-Luna이고, 최적화기는 GPT-5.6-Sol입니다. 전이 평가에 GPT-5.4-mini, DeepSeek-V4-Flash, GLM-5.3-Flash를 추가했습니다.
- 결과: 다섯 시스템 모두 오염에 취약했습니다. 최적화하지 않은 페이로드로도 궤적 수준 도달률이 최대 45.70%, 이후 작업 도달률이 최대 21.02%였습니다. Graphiti와 Mem0은 이후 작업 도달률이 8% 미만, A-MEM과 Memora는 20%를 넘었습니다. 네 시스템은 삽입 성공률이 100%에 가까웠지만 Mem0은 60.75%로, LLM으로 사실만 뽑아 저장하는 방식이 페이로드를 걸러 낸 것으로 보입니다. 회수 성공률은 A-MEM과 Memora가 80% 이상, Letta 64.88%, Mem0 56.70%, Graphiti 33.43%였습니다.
- 최적화 효과: 메모리 인식 최적화로 공격 성공이 약 2~31% 늘었고, Luna에서 최적화한 페이로드가 다른 모델에도 전이되었습니다. 오염을 궤적 중간에 넣어도 여전히 효과가 있었습니다.
- 지표의 신빙성: 판정에 LLM 심사(GPT-5.6-Luna)를 쓰므로 심사 모델의 편향이 섞일 수 있습니다. 각 메모리 시스템의 기본 회수 방식을 그대로 써서 시스템 간 비교는 공정한 편입니다.

#### Comment
- 에이전트 메모리 오염을 "어느 시스템이 더 안전한가"로 비교할 수 있는 틀을 처음 제공했다는 점이 가장 큰 가치입니다. 저장 단계에서 LLM이 요약, 추출하는 구조(Mem0)가 우연히 방어 효과를 낸다는 관찰은 설계 지침으로 참고할 만합니다.
- 한계: 페이로드를 하나만 넣는 설정이 기본이고, 방어 기법 평가는 다루지 않습니다. 본문에서 벤치마크 공개 주소는 확인하지 못했습니다.
- 신뢰도: Microsoft AI Red Team 소속 연구자들이 참여한 심사 전 원고입니다.

# I Think, Therefore I Attack: Evaluating Thought Injection Attacks on Reasoning Agents
> arXiv cs.AI 2611.08811 (cs.CR 교차 게재, 프리프린트, 심사 전). 텍사스 대학교 오스틴 응용연구소(미국)
> 2026

추론 모델은 답을 내기 전에 사고 과정을 명시적으로 출력합니다. 이 논문은 모델 자신의 사고 과정처럼 보이는 문장을 외부 입력에 섞어 넣는 "사고 주입(thought injection)" 공격을 두 단계로 평가합니다. 첫 번째 연구는 보호된 데이터베이스 내용을 빼내도록 유도하는 정적 주입 문구를 사고 태그(<think>)로 감싼 경우와 감싸지 않은 경우로 나눠 시험합니다. 두 번째 연구는 컨테이너 기반 사이버 훈련장에서, 대상 모델 자신의 추론 문체를 흉내 낸 간접 주입으로 에이전트가 리버스 셸을 열거나 저장소에 백도어를 심게 만듭니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.08811
- arXiv HTML 본문: https://arxiv.org/html/2611.08811
- arXiv PDF: https://arxiv.org/pdf/2611.08811

### Contribution
- 추론 모델의 사고 과정 자체를 노리는 주입 공격을 실제 공개 가중치 모델과 에이전트 환경에서 정량적으로 평가했습니다.
- 공격 효과가 문구가 아니라 "누구의 말투인가"에 좌우된다는 점을 보였습니다. 같은 악성 요청도 사용자 말투로는 한 번도 성공하지 못했고, 대상 모델 자신의 추론 문체로는 최대 50%까지 성공했습니다.
- 사고 태그를 제거하는 방어가 믿을 만하지 않다는 점을 지적했습니다.

### Evaluation
- 첫 번째 연구: GLM-5.3-Flash, Qwen3.8-27B, Qwen3.8-Flash-Next에 공격 문구 100개를 10회씩, 태그 유무 두 조건으로 실행했습니다(총 6,000회). 데이터 유출 비율은 8.6~11.7%였고, 태그를 씌우면 GLM-5.3-Flash에서 3.8%가 13.4%로 세 배 넘게 올랐지만 Qwen3.8-Flash-Next에서는 차이가 표본 오차 수준이었습니다.
- 두 번째 연구: MiniMax-M2.5와 GLM-5.2 두 대상, 리버스 셸과 백도어 두 작업, 사용자 말투, 자기 말투, 상대 모델 말투 세 문체, 태그 유무로 조건마다 50회씩, 모두 1,200회 평가했습니다. MiniMax-M2.5는 자기 말투에 태그를 씌운 페이로드에 리버스 셸 42%, 백도어 50%로 응했고, 태그를 빼면 8%와 10%로 떨어졌습니다. GLM-5.2의 문체는 MiniMax에 어느 정도 전이되었지만(20%, 14%) 반대 방향은 거의 전이되지 않았습니다(0%, 2%).
- 은폐: 태그가 있으면 에이전트가 최종 응답에서 주입 사실을 언급하지 않는 비율이 높았습니다. 예를 들어 GLM 대상 리버스 셸 작업에서 MiniMax 문체 페이로드는 태그가 있을 때 92%, 없을 때 22%의 실행에서 언급 없이 지나갔습니다.
- 지표의 신빙성: 반복 횟수를 명시하고 표본 오차 범위의 차이는 차이로 해석하지 않는 등 신중합니다. 다만 대상 모델이 두세 개뿐이고 조건당 50회라 일반화에는 한계가 있습니다.

#### Comment
- 짧은 예비 연구지만, "모델은 표시(태그)가 아니라 문체로 자기 생각을 알아본다"는 관찰은 추론 모델을 쓰는 에이전트 설계에 직접적인 시사점이 있습니다. 저자들은 어떤 모델을 쓰는지 공개하지 않는 운영 보안도 방어가 될 수 있다고 제안합니다.
- 한계: 저자들이 직접 밝히듯 두 연구의 목표가 달라 결과를 합치기 어렵고, 자기 말투 페이로드가 대상 모델의 실제 추론 기록이라 문체 모방 효과와 계획 내용 효과가 섞였을 수 있습니다.
