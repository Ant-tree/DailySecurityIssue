# Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security
> arXiv cs.CR 2611.01976 (프리프린트, 심사 전). 상하이교통대학교(중국), Inria(프랑스)
> 2026

LLM 에이전트 프레임워크는 MCP 서버나 확장 기능 같은 외부 도구를 설치할 때 한 번 검사하고 권한을 주지만, 그 뒤 도구가 업데이트될 때는 바뀐 코드를 다시 검사하지 않는 경우가 많습니다. 저자들은 이 간극을 "도구 업데이트 간극(tool update gap)"이라 부르고, 이를 노리는 공격 ETUDE(Exploiting Tool Updates for Direct Execution)를 제안합니다. 공격자는 먼저 정상적인 도구(v1)를 배포해 설치 시점 검사를 통과하고, 이후 이름, 설명, 입력 스키마는 그대로 둔 채 구현 코드에만 악성 동작을 넣은 v2를 배포합니다. 악성 동작은 정상 호출 중에 도구 런타임 안에서 직접 실행되므로 LLM 문맥에는 아무런 지시문도 나타나지 않습니다. 그래서 프롬프트 인젝션 탐지기나 모델 입력을 살피는 방어는 이 공격을 볼 수 없습니다.

저자들은 Gemini CLI, Codex CLI, Claude Code, DeepSeek Harness, OpenCode, Pi, Goose 일곱 개 프레임워크에서 v1 승인 이후 v2가 재검사 없이 기존 권한으로 실행된다는 점을 확인했고, 공격 목표로는 합성 자격 증명 유출(W1), 허가되지 않은 외부 API 호출(W2), 로컬 파일 변조(W3)를 설정했습니다.

### Contribution
- 공격을 "언제 악성 기능이 들어오는가(설치 시점 대 업데이트)"와 "어떤 경로로 실행되는가(코드 직접 실행 대 모델 문맥 유도)" 두 축으로 나누고, 그동안 거의 다뤄지지 않은 "업데이트로 들어와 코드로 직접 실행되는" 영역을 짚었습니다.
- 상용과 오픈소스를 합쳐 일곱 개 에이전트 프레임워크에서 업데이트 뒤에도 기존 권한이 그대로 유지된다는 점을 실제로 확인했습니다. 도구 호출마다 사용자 확인을 받는 프레임워크도 그 확인은 호출을 허락할 뿐 바뀐 구현을 검증하지는 않는다고 지적합니다.
- 파일 무결성 검사(TLSH 유사도), LLM 기반 정적 코드 리뷰(Cisco MCP Scanner, SkillFortify, NVIDIA SkillSpector), 실행 감사(SkillDetonate 방식) 세 갈래 방어를 직접 시험해 각자의 한계를 보였습니다.

### Evaluation
- 설정: 마크다운 정리, CSV 통계, ICS(일정 파일) 생성 세 가지 도구와 W1~W3 목표를 조합하고, 조건마다 20개 작업을 5회 반복했습니다. 독립된 수신 서버, 서비스 기록, 파일 증거로 공격 성공률(ASR)을 매기고, 정상 작업 완료율(TCR)은 따로 측정했습니다.
- 결과: 초록 기준으로 일곱 프레임워크 평균 ASR 97.6%, TCR 95.9%이며, 가장 강한 프롬프트 인젝션 기준선(업데이트로 들어온 문맥 유도형)보다 ASR이 크게 높습니다. 본문 RQ1(같은 백엔드, 21개 조건)에서는 ETUDE가 ASR 100.0%, 기준선이 20.2%였습니다. 백엔드 모델을 네 가지로 바꾼 실험에서도 ASR이 80~100% 범위였습니다.
- 방어 평가: TLSH 거리로는 정상적인 기능 추가(거리 173~221)와 악성 업데이트(145~233)가 겹쳐, 어떤 임계값도 악성만 막고 정상 유지 보수를 통과시키지 못했습니다. 정적 리뷰는 난독화에 약하고, 실행 감사는 특정 입력에서만 발동하는 동작을 놓치고 비용이 크다고 보고합니다.
- 지표의 신빙성: 공격이 도구 코드 안에서 직접 실행되는 구조이므로 높은 ASR 자체는 예상 가능한 결과이고, 비교의 핵심은 "프레임워크가 재검사 없이 업데이트를 받아들인다"는 관찰입니다. 실패 사례(CSV 인자 오류, 호출 횟수 불일치 등)를 따로 집계해 공개한 점은 신뢰를 높입니다.

#### Comment
- 에이전트 도구 생태계의 공급망 문제를 정면으로 다룬 논문입니다. XZ Utils나 event-stream 사건처럼 신뢰를 쌓은 뒤 업데이트로 악성 코드를 넣는 수법이 에이전트 도구에도 그대로 통한다는 점을 실험으로 보였고, 저자들은 승인 단위를 "검토한 코드 그 자체"로 바꿔야 한다고 제안합니다.
- 한계: 공격 자체는 새롭다기보다 기존 소프트웨어 공급망 공격을 에이전트 환경으로 옮긴 것에 가깝습니다. 실제 마켓플레이스의 도구를 고치지 않고 직접 만든 도구로 실험했으며, 프레임워크별 업데이트 경로(패키지 재해석, 서버 재시작 등)는 하네스로 재현했습니다.
- 중국 기관 검증: 1저자와 교신저자 다수가 상하이교통대학교 소속이고, Inria의 Yufei Han이 공저자로 참여했습니다. 두 기관 모두 실재하는 주요 연구 기관입니다. 본문에서 저자들의 코드 저장소 주소는 찾지 못해 재현 자료 공개는 확인하지 못했습니다. 다만 핵심 주장(업데이트 후 재검사 부재)은 공개 프레임워크에서 누구나 확인할 수 있는 성질이고, 수치가 높은 이유도 공격 구조상 자연스러워 과장된 지표로 보기는 어렵습니다. 비교 대상도 같은 하네스에서 돌린 기준선이라 부적절하지 않습니다.

# Right Tool, Wrong Parameters: Defending LLM Agents Against Parameter Poisoning
> arXiv cs.CR 2611.04673 (프리프린트, 심사 전). 중국과학기술대학교(USTC, 중국)
> 2026

간접 프롬프트 인젝션 방어는 대개 "주입된 내용이 새로운 도구 호출이나 엉뚱한 행동을 일으켰는가"를 봅니다. 이 논문은 행동은 그대로 두고 인자만 바꾸는 공격, 즉 "파라미터 오염(parameter poisoning)"을 다룹니다. 예를 들어 사용자가 앨리스에게 500달러를 보내라고 했을 때, 공격자가 조작한 메시지에 "앨리스의 계좌가 바뀌었다"고 적어 두면 에이전트는 예정대로 송금 도구를 부르되 계좌 번호만 공격자 것으로 넣습니다. 새로운 행동이 없으니 기존 방어가 잘 잡지 못합니다.

저자들은 인자의 정당성을 "그 값을 만든 정보가 이 작업에서 그 인자를 정할 권한이 있는가"로 판단해야 한다고 보고, 세 단계 방어 AuthorityFlow를 제안합니다. 사용자 요청을 해석해 정보 필드별 권한 계층을 만들고(예: 호텔 주소 필드는 일정 장소를 정할 수 있지만 리뷰 본문은 못 함), 도구 인자마다 그 값을 뒷받침한 근거를 추적한 뒤, 근거가 의미상 값을 지지하는지와 출처가 그 용도에 권한이 있는지를 둘 다 통과할 때만 실행을 허락합니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.04673
- arXiv HTML 본문: https://arxiv.org/html/2611.04673
- arXiv PDF: https://arxiv.org/pdf/2611.04673

### Contribution
- 지시문 수준 인젝션과 구분되는 "인자 수준" 공격 표면을 정리하고, 권한을 출처의 고정 속성이 아니라 작업에 따라 달라지는 관계로 정의했습니다.
- 의미 지지 검사와 출처 권한 검사를 분리한 매개변수 단위 승인 방식을 제시했습니다. 에이전트 오케스트레이션 계층에서 동작하므로 모델 내부나 도구 구현을 고칠 필요가 없습니다.
- AgentDojo를 확장한 평가 세트 FactAuthBench(은행, Slack, 여행, 업무 네 영역, 정상과 공격 쌍 144개)를 만들었습니다.

### Evaluation
- 에이전트 모델: Qwen3.6-27B, Llama-3.3-70B, GPT-4o. AuthorityFlow의 보조 모델은 기본으로 Qwen3.6-27B를 씁니다.
- 비교 대상: Sandwiching, Spotlighting(입력 단계), IPIGuard, CaMeL, DRIFT(시스템 단계), MELON, AttriGuard(실행 검증과 귀속 기반). 공식 구현이나 기본 설정을 썼다고 밝힙니다.
- 지표: 정상 작업 효용(BU), 공격 상황 효용(UA), 공격 성공률(ASR).
- 결과(Qwen3.6-27B): 방어 없음 ASR 93.06%, BU 90.28%. AuthorityFlow는 ASR 9.03%, BU 82.64%입니다. GPT-4o에서는 방어 없음 ASR 57.64%가 AuthorityFlow로 5.56%가 됩니다. 정화(purification) 단계를 붙이면 UA가 58.33%(Qwen), 60.42%(GPT-4o)로 오릅니다.
- 주의할 점: 표를 보면 CaMeL의 ASR이 0.69%(Qwen), 2.08%(GPT-4o)로 AuthorityFlow보다 낮습니다. 대신 CaMeL은 BU가 43.75%, 39.58%로 크게 떨어집니다. 초록은 이 비교를 언급하지 않으므로, "가장 낮은 ASR"이 아니라 "효용 대비 나은 균형"으로 읽는 것이 맞습니다. 평가 세트가 144쌍으로 작고 저자들이 직접 만든 것이라 일반화에는 한계가 있습니다.

#### Comment
- 실무적으로 와닿는 문제 설정입니다. 송금 계좌, 메일 수신자, 일정 장소처럼 "도구는 맞는데 값이 틀린" 사고는 행동 감시만으로는 막기 어렵다는 점을 잘 보여 줍니다.
- 한계: 권한 계층을 LLM이 사용자 요청에서 추론하므로 그 단계가 틀리면 방어 전체가 흔들립니다. 보조 모델 호출이 늘어나는 비용은 따로 정리되어 있지 않았습니다.
- 중국 기관 검증: 저자 전원이 중국과학기술대학교 소속이며, 실재하는 주요 대학이고 Weiming Zhang 교수 연구실은 정보 은닉과 AI 보안 분야에서 꾸준히 논문을 내 왔습니다. 본문에서 코드나 평가 세트 공개 주소는 찾지 못했습니다. 지표는 기준선보다 좋지만 CaMeL이 ASR에서 앞서는 결과를 표에 그대로 실었고, 비교 대상도 이 분야의 대표 방어들이라 부적절하지 않습니다. 재현 자료가 없다는 점은 감안해야 합니다.

# JailBound: FOL-Guided Jailbreak Evaluation for Exploring LLM Behavioral Boundaries
> arXiv cs.CR 2611.07530 (프리프린트, 심사 전. 본문 서식에 NeurIPS 2026 표기가 있으나 채택 여부는 확인하지 못함). 치루공업대학교(산둥성과학원), 취안청 연구소, 구이저우대학교(중국)
> 2026

탈옥(jailbreak) 평가 벤치마크는 대부분 사람이 모으거나 만든 프롬프트에 의존해 새로운 위협 유형으로 넓히기 어렵고, 기존 공격 탐색은 성공률만 최적화해 모델이 거절과 위험 응답 사이에서 어떻게 바뀌는지는 잘 보여 주지 못합니다. JailBound는 위험 범주, 적용 분야, 공격 유형으로 이루어진 계층형 분류 체계를 두고, 미세 조정한 메타 공격 생성기로 조건별 평가 프롬프트를 자동으로 만듭니다. 그다음 임베딩 공간에서 1차 손실(first-order loss, 공격 손실의 기울기 크기에 해당하는 국소 민감도 신호)을 이용해 두 갈래로 탐색합니다. 하나는 공격 효용이 높고 안정적인 상태를 찾는 "고가치" 갈래, 다른 하나는 작은 변화에도 판정이 뒤집히기 쉬운 상태를 찾는 "안전 민감" 갈래입니다. 찾은 연속 임베딩은 실제 텍스트 프롬프트로 바꾼 뒤 외부 판정 모델로 성공 여부를 매깁니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.07530
- arXiv HTML 본문: https://arxiv.org/html/2611.07530
- arXiv PDF: https://arxiv.org/pdf/2611.07530
- 저자 저장소(논문에 기재된 코드): https://github.com/FrazeWu/JailBound

### Contribution
- 분류 체계에 따라 새로운 위협 조건의 평가 사례를 자동 생성하는 벤치마크 구축 방식을 제시했습니다. 본 실험에서는 169개 조합 조건, 26,554개 공격 사례, 아홉 가지 공격 유형을 썼습니다.
- 성공률만 보지 않고 "판정 경계 근처의 민감한 상태"를 따로 탐색해, 모델 안전성의 국소적 취약 지점을 진단하는 관점을 더했습니다.
- 13개 모델 계열, 46개 LLM(Llama, Qwen, Gemma, Mistral, Claude, GPT, Gemini 등)을 같은 절차로 평가했습니다.

### Evaluation
- 비교 대상: 공개 벤치마크 AdvBench, JailbreakBench, SafetyBench, SG-Bench, HarmBench와, 같은 조건에서 돌린 최적화 공격 GCG, PEZ, GBDA, 그리고 1차 손실 항을 뺀 자기 변형(ZOL-only).
- 결과: Qwen2.5-14B-Instruct 대상, 판정 모델 두 개(Octopus-SEval-14B, Qwen3-32B-AWQ)에서 고가치 갈래가 ZOL-only보다 평균 5.1%p, 4.9%p 높은 ASR을 보였습니다. 예를 들어 JailBound 출처 프롬프트에서는 초기 18.3%, GCG 44.4%, ZOL-only 60.4%, 고가치 갈래 64.5%입니다.
- 안전 민감 갈래 상태는 모든 교란 반경에서 고가치 갈래보다 판정 뒤집힘 비율(BFR)이 높았습니다.
- 연속 임베딩을 텍스트로 바꾸면 ASR이 평균 6.9%p 떨어진다는 점을 스스로 보고해, 주장 범위를 실제 텍스트 공격으로 한정했습니다. 주요 결과는 세 번 반복한 평균입니다.
- 지표의 신빙성: 개선 폭이 수 %p 수준으로 과장되어 보이지 않고, 판정 모델을 두 개 써서 순위가 유지되는지 확인했습니다. 다만 판정이 LLM 판정 모델에 의존하므로 판정 모델의 오류가 그대로 반영됩니다.

#### Comment
- 탈옥 평가를 "성공률 경쟁"에서 "어디가 경계인지 진단"으로 옮기려는 시도라는 점이 특징입니다. 모델 배포 전 안전성 회귀 시험에 참고할 만합니다.

# The Web Doesn't Sit Still: Adversarial Self-Evolving Attacks on Search Agents
> arXiv cs.CR 2611.03754 (프리프린트, 심사 전. 본문 서식에 NeurIPS 2026 표기가 있으나 채택 여부는 확인하지 못함). 난양공과대학교(싱가포르), 알리바바 그룹(중국)
> 2026

웹 검색으로 정보를 모으는 검색 에이전트는 검색 결과에 섞인 조작 문서(RAG 오염)에 취약합니다. 기존 공격은 사람이 만든 고정 규칙(예: 정답 개체를 다른 개체로 바꾸기)에 의존하고, 방어 쪽 대응을 보고 공격을 바꾸지 않습니다. 이 논문은 공격과 방어가 함께 진화하는 이중 최적화 구조를 제안합니다. 안쪽 고리에서는 방어자가 현재 공격 풀에 맞춰 방어 지식을 갱신하고, 바깥 고리에서는 공격 전략이 진화합니다. 핵심 기법 CREO(Contrastive Rollout Evolutionary Optimization)는 공격 전략이 성공한 추론 경로와 실패한 경로를 대조해 얻은 신호로 전략을 변이, 교차, 선택합니다. 실험 환경은 DeepResearchGym을 확장해 약 3.8TB 규모의 고정 지식 베이스와 검색 결과에 조작 문서를 끼워 넣는 가로채기 장치를 둔 통제된 샌드박스입니다.

원문 링크:
- arXiv 초록: https://arxiv.org/abs/2611.03754
- arXiv HTML 본문: https://arxiv.org/html/2611.03754
- arXiv PDF: https://arxiv.org/pdf/2611.03754

### Contribution
- 검색 에이전트 보안 평가를 공격과 방어의 공진화 문제로 정식화하고, 사람이 만든 템플릿 없이 공격 전략을 진화시키는 CREO를 제시했습니다.
- 재현성을 위해 검색 순위를 고정한 샌드박스를 구축했습니다.
- 에이전트가 조작 증거를 그대로 받아들이는 "논리 탈취(ASR)"와, 모순을 알아차렸지만 풀지 못하고 답을 못 내는 "인지 마비(APR)"를 나눠 측정하는 지표를 더했습니다.

### Evaluation
- 데이터셋: HotpotQA, 2WikiMultihopQA, MuSiQue에서 각각 학습 100문항, 평가 100문항을 뽑았습니다.
- 대상 에이전트 모델: Qwen-Turbo, Qwen3-Max, DeepSeek-V3.2, Kimi-K2.5, GLM-5.1.
- 비교 대상: 규칙 기반 개체 치환(FactSwap), 질의 맞춤 최적화 오염(AuthChain).
- 결과: MuSiQue에서 GLM-5.1의 정답률이 공격 전 82%에서 AuthChain 41%, CREO 1라운드 16%로 떨어졌습니다. 15개 모델과 데이터셋 조합 평균 총 공격 성공률(ASR+APR)은 CREO가 방어 지식이 한 라운드 늦는 설정에서 64.2~74.6%, 방어가 동시에 갱신되는 설정에서 60.5~64.9%로, FactSwap(20.9%/18.1%)과 AuthChain(55.7%/37.5%)보다 높습니다.
- 지표의 신빙성: 판정은 LLM 판정 모델이 하며, 부록에서 사람 주석자 두 명과 다른 LLM 두 개로 100개 표본의 일치도를 점검했습니다. 데이터셋당 평가 100문항은 작은 규모이고, 대상 모델이 모두 중국 업체의 모델이라 다른 계열로의 일반화는 확인되지 않았습니다.

#### Comment
- "공격이 방어를 보고 진화한다"는 설정을 RAG 오염에 적용한 점, 그리고 답을 못 내게 만드는 인지 마비를 별도 피해로 센 점이 눈에 띕니다. 검색 기반 에이전트를 운영하는 쪽에서는 고정된 오염 문서 세트로만 방어를 시험하면 안 된다는 시사점이 있습니다.
- 한계: 조작 문서를 검색 결과에 직접 끼워 넣는 설정이라, 실제 웹에서 그 문서를 상위에 노출시키는 어려움은 다루지 않습니다. 본문에는 코드를 공개한다고 적혀 있으나 주소는 찾지 못했습니다.
