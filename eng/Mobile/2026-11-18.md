# The Provenance-Privacy Paradox: Can Private Cloud Compute (PCC) Prove That Apple Reference Images Are Not Used for Learning?
> arXiv preprint (not peer reviewed). California State Polytechnic University, Pomona
> 2026

A position paper on the privacy question raised by Apple Reference Image (ARI), the iPhone's photo provenance feature, which develops raw sensor data in Private Cloud Compute (PCC). ARI ties together camera-sensor signatures, Secure Enclave attestation, timestamp bounds, PCC development and a post-quantum signature to vouch that an image came from what a genuine iPhone sensor captured. Because PCC performs demosaicing, colour correction, tone mapping and compression, the authorised PCC workload has to handle the raw pixels in plaintext, even though they are encrypted in transit. The authors argue that remote attestation and transparency logs prove which software ran, but not that the software did not learn from or keep information about the photo, and they build a counterexample in a test environment to make the point.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.21590
- arXiv HTML full text: https://arxiv.org/html/2611.21590
- arXiv PDF: https://arxiv.org/pdf/2611.21590

### Contribution
- Separates ARI's provenance mechanisms (sensor signatures, Secure Enclave) from PCC's confidentiality and attestation mechanisms, noting that sensor signatures authenticate pixels but neither encrypt them nor restrict how an authorised workload may use them.
- Formalises the gap between verifying a workload's identity and verifying its behaviour, showing that attestation and transparency-log inclusion do not by themselves establish non-learning or non-retention.
- Builds a Python and Docker testbed that models the relevant ARI and PCC functions (development, workload attestation, transparency-log verification, client acceptance) and implements a counterexample in which two workloads pass the same checks while only one keeps image information.
- Recommends explicit non-learning policies, limits on persistent storage and outbound communication, disclosure of retained data, and independent verification of workload behaviour and permissions.

### Evaluation
- Data: 27 public-domain photographs.
- Results: a baseline workload and a learning-enabled workload passed the same attestation and transparency-log checks and returned byte-for-byte identical JPEGs. The learning workload, however, kept a first-layer gradient of about 48 KB from which its 64×64 input was reconstructed with a maximum absolute per-pixel error of 6×10^-8. The extra processing cost was small compared with image decoding and development.
- Credibility: this is a model environment built from public documentation, not real PCC, and the reconstructed input is only 64×64, so the numbers say little about real raw sensor images. The core of the paper is the counterexample itself: identity attestation and output equivalence are compatible with hidden retention.

#### Comment
- The authors state clearly that they do not claim Apple trains on ARI photos and that they did not reproduce production PCC. The paper is best read as a threat-model analysis of how far the "even Apple cannot see the data" statement can be taken.
- As more mobile features lean on cloud processing, it is useful to be precise about what remote attestation does and does not guarantee. The experiment is small, though, and the paper does not propose a way to actually verify semantic properties such as non-learning.

# Post-Quantum Migration of Wi-Fi Key Establishment: A Hybrid ML-KEM Design for OWE and FILS, Validated on OWE with hostapd
> arXiv preprint (not peer reviewed). Universidad de Cantabria, Universidad Rey Juan Carlos
> 2026

This paper designs and implements a post-quantum migration path for Wi-Fi key establishment. Wi-Fi data encryption (AES) stays reasonably safe against quantum computers if the key size is raised, but the Diffie-Hellman key agreement does not, which opens the door to recording associations now and decrypting them later. The authors target the two protocols that agree keys inside management frames: Opportunistic Wireless Encryption (OWE), which adds encryption to open networks, and Fast Initial Link Setup (FILS), built for fast connections in dense, mobile deployments. They replace the Diffie-Hellman exchange with a hybrid that runs the classical elliptic-curve agreement alongside NIST's ML-KEM (FIPS 203) and derives the master key from both secrets. The exchange reuses existing frames, adds no round trip, and can coexist with classical OWE during the transition. The design is implemented and validated for OWE in hostapd and wpa_supplicant, the reference open-source Wi-Fi stack.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.21528
- arXiv HTML full text: https://arxiv.org/html/2611.21528
- arXiv PDF: https://arxiv.org/pdf/2611.21528

### Contribution
- A design that swaps the Diffie-Hellman exchange in OWE and FILS for a hybrid ECDH and ML-KEM exchange. The connection stays protected as long as either component holds, with no extra round trip.
- An access point can advertise the hybrid mode next to classical OWE, and a station configured to require it refuses to associate without a completed post-quantum exchange. Binding the advertised capabilities to the derived key, which would make tampering detectable, is specified only as a design extension.
- A working OWE hybrid mode in hostapd and wpa_supplicant, with measured frame sizes, fragmentation and computation for all three ML-KEM parameter sets.

### Evaluation
- Correctness: station and access point derived the same master key in all 30 connections per mode.
- Frame size: with ML-KEM-768 the Association Request is 1,419 bytes and the Response 1,306 bytes, both under a conservative 1,500-byte fragmentation threshold; the added overhead is 2,296 bytes per handshake. The two smaller parameter sets each fit in a single frame, and the authors conclude that ML-KEM-768 gives the best balance of security level and size.
- Latency: in a block-ordered run the median association exchange time rose from 1.17 ms to 1.41 ms, an extra 0.23 ms (Mann-Whitney U, p = 1.8×10^-7, N = 30). ML-KEM-768 key generation, encapsulation, decapsulation and the combiner add up to about 0.19 ms. The extra bytes are estimated to cost about 3.1 ms of airtime at 6 Mbps.
- Credibility: measurements come from a user-space testbed with a simulated driver and a single two-vCPU virtual machine, so latency and fragmentation on real chips and drivers (Broadcom, Qualcomm, Intel) were not checked. FILS is designed but not measured.

#### Comment
- The strength of the paper is a working implementation with real measurements for a topic still being standardised (IEEE P802.11bt). It gives concrete evidence that the frame-size cost of moving mobile and IoT association to post-quantum key exchange is manageable.
- A downgrade before the first association remains open, and the authors note that with the default policy it can even happen without an attacker. As with the attacks on the WPA3 transition mode, a formal specification of what gets authenticated, and when, is needed before deployment.
