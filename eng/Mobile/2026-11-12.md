# Comparing WeChat and Telegram MiniApp Security Architectures: Toward Cross-Platform Analysis
> arXiv preprint (not peer reviewed). IMT School for Advanced Studies Lucca and University of Genoa (Italy)
> 2026

MiniApps are lightweight apps that run inside super-apps, but the two big ecosystems are built very differently: WeChat runs its own package format (.wxapkg) in a dedicated runtime, while Telegram runs ordinary web apps tied to bots inside an Android WebView. Existing WeChat analyzers such as MiniCAT and WEMINT depend on the package structure and WeChat-specific APIs, so they do not carry over to Telegram. This paper compares the two ecosystems in terms of execution environment, communication paths and trust boundaries. WeChat is described from official documentation and prior peer-reviewed work, while Telegram is reconstructed from its documentation plus a manual reading of a specific commit of the Telegram Android client. Both are mapped onto a shared taxonomy of security controls, assets and threat sources, and two worked examples turn the comparison into requirements for cross-platform analysis tools.

### Contribution
- A side-by-side architectural comparison of WeChat's App-in-App model and Telegram's bot-centric web MiniApp model using the same criteria.
- A code-grounded account (down to line numbers in BotWebViewContainer and related classes) of bridge registration, event dispatch, permission-sensitive request handlers and new-window navigation in Telegram. For example, the same JavaScript interface name (TelegramWebviewProxy) maps to different bridge implementations depending on whether the container is a bot, and new windows follow a separate path, so one cannot assume they inherit the originating MiniApp's capabilities.
- Two requirements for analysis tools: tell credential roles and validation points apart (WeChat's AppSecret, access token and session key versus Telegram's BOT TOKEN and initData), and tie each host capability to its concrete execution context and permission handler.
- A clear statement, for both platforms, that platform authentication (being logged in, or Bot API authentication) does not replace authorization checks in the MiniApp's own backend.

### Evaluation
- This is a qualitative architectural comparison with no quantitative evaluation. The authors explicitly do not rank the ecosystems or claim validated vulnerability detection.
- The evidence is asymmetric: the WeChat client is closed source, so it rests on documentation and earlier papers, whereas Telegram is backed by source code at one commit (62b56a07). Code-based claims therefore apply only to that revision. A table links the main claims to their evidence, which keeps them traceable.
- The scope is compared in a table against the closest prior work (Mohammadi et al., 2025).

#### Comment
- There is no vulnerability discovery and no tool yet; the paper sets out design requirements for future tools, which makes it a useful reference for anyone building MiniApp analyzers.
- The same group earlier published TeleGapper (arXiv 2608.13390), a dynamic analysis of privacy practices in Telegram MiniApps; this paper reads as a follow-up.
- Preprint from Italian researchers, written in journal format.
