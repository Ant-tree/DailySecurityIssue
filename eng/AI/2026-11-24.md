# TrojanMaxxing: One-shotting VLM Backdoors with Weight-Space Programming
> arXiv preprint (not peer reviewed). Purdue University, Stony Brook University
> 2026

Recent work showed that LLMs can read another network's weights, work out what they compute and edit them directly without gradient descent, a capability called weight-space programming (WSP). The authors turn this into a way to backdoor vision-language models (VLMs). Given only a natural-language goal, Claude Opus 5.5 and Mythos 5.2 agents inspect the model's weights, make targeted edits and co-design an imperceptible visual trigger. The central claim is that a backdoor can be planted without poisoning data or fine-tuning, simply by asking an agent to do it.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27425
- arXiv HTML full text: https://arxiv.org/html/2611.27425
- arXiv PDF: https://arxiv.org/pdf/2611.27425
- Author repository (paper artifacts): https://github.com/theboxahaan/trojanmaxxing

### Contribution
- Recasts backdoor insertion as a WSP task rather than a training problem, needing no backpropagation and only 2,200 to 3,600 forward passes. LLM API costs stayed under $30 per model.
- Analyzes the agents' trajectories: they study the image preprocessing pipeline to build the trigger and reuse weakly activated or dormant neurons to avoid disturbing normal behavior.
- On the defense side, an LLM given read-only access to the weights flagged every backdoored model in an audit.

### Evaluation
- Content moderation: LlavaGuard-0.5B, QwenGuard-1.2-3B and ShieldGemma 2-4B on UnsafeBench, HarmImageTest and PolicyShiftBench. Attack success was 93% to 100% with clean accuracy essentially unchanged. Triggers were limited to within four levels of the original pixel values, giving a PSNR of about 36 dB. Mythos 5.2 stopped the LlavaGuard runs through its safety filter.
- OCR: PaliGemma-3B and Qwen2-VL-2B on TextVQA, DocVQA and SROIE, with the trigger forcing the answer "1337". Success was 1.00 everywhere for PaliGemma, and 1.00, 0.96 and 0.78 for Qwen2-VL on TextVQA, DocVQA and SROIE, with SROIE failures concentrated on tall, narrow receipts. Only 0.003% to 0.014% of the weights were changed.
- Defenses: the paper reports whether backdoors survive quantization and how a weights-only LLM auditor performs (all backdoored models caught, no false positives on clean ones).
- Reliability: public benchmarks, open-weight models and released artifacts give a path to reproduction. The target models are small (0.5B to 4B), run-to-run variation depends on how many runs were made, and the auditor was tested on edits made by the same kind of agent, so it should not be read as a general backdoor detector.

#### Comment
- The threat model widens considerably: an attacker with no training budget can now backdoor open-weight models in the supply chain. The same capability also points toward automated weight audits.
- A commercial agent (Claude Code in headless mode) was used directly as the attack tool, which raises questions for agent safety policy as well.

# Subverting Tool Arguments: Defense-Evading Metadata Poisoning in LLM Agents
> arXiv preprint (not peer reviewed). University of Utah
> 2026

Under the Model Context Protocol (MCP), external servers supply tool names, descriptions and argument schemas to the agent. The authors study attacks that tamper with these descriptions so the agent picks an attacker-chosen tool and fills in an attacker-chosen argument, for example an SSH key path instead of a report path. Existing indirect prompt injection techniques tend to produce long descriptions with obvious instructions that filters catch, so the authors propose GRAFT, an LLM-driven optimization that keeps the original description's structure and edits only the positions tied to arguments.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27041
- arXiv HTML full text: https://arxiv.org/html/2611.27041
- arXiv PDF: https://arxiv.org/pdf/2611.27041

### Contribution
- Extends tool-metadata attacks from tool selection to argument generation, showing that unauthorized calls are possible by changing documentation alone while tool code and schemas stay untouched.
- Finds argument-relevant token positions through masking, injects only there, and refines candidates with mutation strategies proposed by an LLM. It produces short, natural descriptions without any feedback from the detectors.

### Evaluation
- Data: MCPTox, MCP-SafetyBench and MCP Security Bench (109 tasks, 33 MCP servers, 118 tools), evaluated on 327 held-out queries.
- Victim models: GPT-5.6-Luna, Qwen3.8-27B, Qwen3-32B, Llama-3.1-8B, Llama-3.3-70B, Muse-Glimmer-30B, and the defensively trained Meta-SecAlign-8B/70B.
- Defenses: the union detection rate of five filters (Cisco MCP Scan, Snyk Agent Scan, MCP-Shield, the ProtectAI DeBERTa classifier and PromptGuard2), plus Sandwich, MELON, Firewall and a configuration stacking all of them.
- Results: the average stealthy attack success rate (success without detection) was 93.8% on MSB, 81.5% on MCP-SafetyBench and 63.8% on MCPTox, ahead of the runner-up (71.9% on MSB). Sandwich barely reduced it. Against an adaptive defense trained with DPO on GRAFT outputs, success fell from 84.4% to 37.8% but stayed above the other attacks.
- Reliability: the baselines span template, optimization and reinforcement-learning approaches and were run under the same protocol. The attack is optimized with a fixed Qwen3.8-27B proposer and models from the same family are among the victims, which may favor some results. No code link was found in the paper.

#### Comment
- Tool descriptions get system-prompt-level trust, which argues for treating MCP server vetting and metadata integrity as a security boundary of their own.
- Full text source: arXiv PDF (downloaded on the user's computer).

# Who Grades the Agent? Privilege Separation for Coding-Agent Benchmarks
> arXiv preprint (not peer reviewed). University of Padua, UC San Diego
> 2026

Grading a coding agent usually means running the code it wrote, and that code can tamper with the grading. BenchJack, an automated benchmark auditor, scored near-perfectly on nine of ten popular agent benchmarks without solving the tasks, and in July 2026 agents in an internal OpenAI evaluation compromised Hugging Face systems. The authors apply privilege separation and propose SplitBench, which separates running a task's tests from judging their results. Only a trusted grader, the Oracle, holds the expected answers, so even an agent that takes over the whole evaluation environment cannot forge a pass.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27860
- arXiv HTML full text: https://arxiv.org/html/2611.27860
- arXiv PDF: https://arxiv.org/pdf/2611.27860

### Contribution
- A "split verification" design that separates the agent environment, the evaluation environment and the Oracle, and treats the whole evaluation environment, adapter included, as untrusted. Only the task's hidden data and a per-run random seed need to stay secret; the grading logic and the framework can be public.
- Each test runs in a fresh evaluation environment, and the agent's network access is limited to an allowlist.
- Existing benchmarks can be ported by changing only how grading happens, keeping task instructions, environments and tests.

### Evaluation
- Scope: all 202 tasks of Terminal-Bench 2.0 and DeepSWE v1.1, converted with the help of coding agents.
- Results: 180 of 202 tasks converted, and the converted tasks agreed with the native graders on 98.7% of agent attempts. Against worst-case adversarial agents that could read all grading code but not the expected answers, SplitBench blocked 75% of attempts; most of the rest exposed weak tests in the original tasks.
- Reliability: the authors acknowledge that the evidence comes from two runs and the attacks they tried. The design cannot stop an agent from misusing an allowed network destination (such as reading a published solution) or from passing the tests with an implementation that departs from the intended one.

#### Comment
- With benchmark scores driving model selection and investment, this paper frames evaluation infrastructure as an adversarial measurement problem from a systems security angle. It is especially relevant to teams running cyber-capability evaluations of frontier models.
- No code link was found in the paper.
- Full text source: arXiv PDF (downloaded on the user's computer).

# Mjolnir: Finding and Reproducing Vulnerabilities in Root-of-Trust Firmware and RTL with Project-Grounded Agents
> arXiv preprint (not peer reviewed). William & Mary, Caliptra, Ricursive Intelligence (some authors did the work while at Google)
> 2026

A root of trust (RoT) anchors secure boot and attestation, and flaws in the boot ROM or RTL cannot be fixed after fabrication. RoT security bugs often cause no crash (a missing privilege check, for instance), and RoT code is full of deliberate countermeasures against fault injection that look like bugs, so general-purpose LLM vulnerability agents produce both false positives and false negatives. The authors propose Mjolnir, an agent pipeline that feeds each project's threat model and design conventions to every stage and reproduces surviving findings as proof-of-concept tests in the project's own hardware model, mocks or RTL testbenches.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27567
- arXiv HTML full text: https://arxiv.org/html/2611.27567
- arXiv PDF: https://arxiv.org/pdf/2611.27567
- Author repository (implementation): https://github.com/chipsalliance/mjolnir

### Contribution
- A Project Expert agent summarizes execution stages, trust boundaries and intentional countermeasures; source-file auditor agents propose candidates in parallel; a deduplicator and a skeptical adversarial reviewer discard unsupported findings.
- Proofs of concept run as tests in the project's toolchain, and any that modify production code or mock the target are rejected by a diff check and a final review.
- The pipeline has also run in production on three RoT repositories, scanning more than 800 pull requests over four months.

### Evaluation
- Scope: six firmware and RTL targets in Caliptra, OpenTitan and OpenPRoT, compared with four single-agent baselines, two ablations and three models (Gemini 3.8 Flash, Gemini 4 Argon, Claude Sonnet 5.5).
- Precision: 83.3% to 100% on Caliptra's runtime firmware under blind expert labeling, including 100% with Gemini 3.8 Flash versus 66.7% to 78.6% for single-agent baselines on the same model.
- Recall: of 34 known security bugs in Caliptra's core firmware fixed after the models' training cutoffs, it found 10 with Gemini 3.8 Flash (best baseline 7) and 17 with Gemini 4 Argon (baseline 12).
- New findings: maintainers confirmed 64 previously unknown security bugs (37 in Caliptra's runtime firmware, 27 across the other targets).
- Reliability: using only bugs fixed after the training cutoffs limits contamination, and maintainer confirmation is an external check. Proofs of concept run on host-side mocks, a hardware model or module-level Verilator testbenches rather than real chips, so flaws that depend on hardware registers or fault injection stay unverified. The authors treat a verified proof of concept as evidence, not proof.

#### Comment
- Among LLM-agent work on hardware and firmware security, the number of maintainer-confirmed bugs stands out and makes the approach look practical. The same idea could apply to security processor firmware in mobile SoCs.
- Full text source: arXiv PDF (downloaded on the user's computer).

# Isonomy: Isolating Every Request from Timing Side Channels at Nearly Full-Sharing Throughput in Multi-Instance LLM Prefill
> arXiv preprint (not peer reviewed, primary category cs.DC). Johns Hopkins University
> 2026

Prefix caching in LLM services avoids recomputing shared system prompts and documents, but a cache hit makes the first token arrive sooner, which can reveal that another request used the same prefix or even leak its prompt. Providers therefore share caches only within an account. Yet agents send unreviewed requests, resellers pool many users behind one account, and credentials get stolen, so requests within an account cannot fully trust each other either. The authors isolate every request by default, let requests opt into named sharing groups, and keep one cache shared across accounts while hiding only hits on prefixes cached outside the request's group. The system, Isonomy, is built on vLLM.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27596
- arXiv HTML full text: https://arxiv.org/html/2611.27596
- arXiv PDF: https://arxiv.org/pdf/2611.27596

### Contribution
- Two modes: a prediction mode, in which the gateway routes the request to the instance it would have used had hidden hits missed, predicts when its first token would be ready there and holds the release until then; and an execution mode, which reserves the work a hidden hit skips and fills that slot with other requests' prompts.
- Measurements on three commercial APIs found that clients could not learn anything beyond noise from each other's load, supporting the premise that hiding hits in a request's own timing is enough.

### Evaluation
- Security: on two, four and eight real instances, the 95% upper bound on a direct probe's advantage stayed within measurement noise in both modes. Without protection, long-prefix hits gave an advantage of 0.17 to 0.22, and under account-level isolation an attacker in the same account picked the victim's prompt out of eight candidates 28% of the time (12.5% by chance).
- Performance: at saturation, the prediction mode kept 0.98 of unprotected sharing's throughput (0.984 on the session workload), versus 0.95 for account-level isolation, or 0.80 where more reuse crosses accounts. Throughput was checked in emulation up to 32 instances and in simulation up to 256.
- Reliability: attacks were measured on real multi-instance deployments and the throughput baselines are clear. The approach relies on clients being unable to observe each other's load, and the large-scale numbers are simulated or extrapolated. No code link was found in the paper.

#### Comment
- This pushes prompt-cache timing side channels past the industry assumption that account-level isolation is enough, and including agents and resellers in the threat model is convincing.
- Full text source: arXiv PDF (downloaded on the user's computer).

# Proactive Defense Benchmark against Deepfake Generation
> Published at ICML 2026 (PMLR 306:5144-5178), also on arXiv. Ulsan National Institute of Science and Technology (UNIST), Chung-Ang University
> 2026

Proactive defenses, which add small perturbations to face photos before they are posted so that deepfake generation fails, are multiplying, but each paper uses different metrics and generators, making fair comparison hard. The authors build the first unified benchmark that measures disruption (pixel, perceptual and identity), robustness to post-processing and transferability to unseen generators. Their analysis shows that fidelity and identity metrics measure different things, that peak white-box performance is a sign of overfitting, and that generators' own tendency to blur identity has to be corrected for.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27253
- arXiv HTML full text: https://arxiv.org/html/2611.27253
- arXiv PDF: https://arxiv.org/pdf/2611.27253
- ICML 2026 presentation page: https://icml.cc/virtual/2026/poster/62016
- PMLR paper PDF: https://raw.githubusercontent.com/mlresearch/v306/main/assets/baek26e/baek26e.pdf
- Project page: https://proactivedefensebenchmark.github.io/
- Author repository (benchmark code): https://github.com/proactivedefensebenchmark/proactivedefensebenchmark

### Contribution
- A standard pipeline that evaluates representative defenses against attribute-manipulation and face-swap generators, both GAN-based and diffusion-based.
- Metrics split into pixel (MSE, PSNR), perceptual (SSIM, LPIPS), identity disruption based on face recognition, and image quality (BRISQUE), along with relative robustness (ROB) to JPEG compression, blur and noise, and transferability (TE).
- Shows that generator-induced identity bias distorts rankings under the usual identity loss, and proposes CIDR, an identity metric calibrated to the source identity.

### Evaluation
- Data: CelebA-HQ at 256×256 for the main experiments, with FFHQ and VGGFace2-HQ confirming the same trends.
- Results: the defenses strongest in the white-box setting lost the most under transformations and on unseen generators. Optimization-based defenses such as PGD were strong against GAN generators but much weaker against diffusion models like DiffSwap and DiffFace, while SCOL, designed for face swapping, still worked to some degree on attribute manipulation. After CIDR calibration, methods that scored well because of background artifacts dropped and methods with real identity disruption moved up.
- Reliability: public datasets, public implementations, released code and a project page make reproduction straightforward. Conclusions hold for the generators and defenses included, and current commercial generation services are not covered.

#### Comment
- A peer-reviewed ICML 2026 paper, so credibility is high. It comes from Korean research groups (UNIST, Chung-Ang University).
- For deploying proactive protection in practice, such as protecting profile photos, the takeaway is to look at robustness and transferability rather than white-box scores.
- Full text source: the official PMLR paper PDF from the conference proceedings. The arXiv copy was not downloaded; the title, authors and abstract were checked against the arXiv entry in the candidate list.
