# Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security
> arXiv cs.CR 2611.01976 (preprint, not peer reviewed). Shanghai Jiao Tong University (China), Inria (France)
> 2026

LLM agent frameworks usually vet an external tool, such as an MCP server or an extension, once at installation and grant it permissions, but many never look at the code again when the tool updates. The authors call this the "tool update gap" and build an attack around it, ETUDE (Exploiting Tool Updates for Direct Execution). The attacker first ships a benign tool (v1) that passes admission checks, then releases a v2 that keeps the same name, description and input schema but hides malicious behavior in the implementation. That behavior runs directly inside the tool's runtime during ordinary calls, so no instruction ever shows up in the LLM's context. Prompt-injection detectors and other defenses that watch model-visible input simply cannot see it.

Across seven frameworks (Gemini CLI, Codex CLI, Claude Code, DeepSeek Harness, OpenCode, Pi and Goose), the authors confirm that once v1 is approved, v2 runs under the existing permissions without re-review. The attack goals are leaking a synthetic credential (W1), making unauthorized external API calls (W2) and tampering with a local file (W3).

Links:
- arXiv abstract: https://arxiv.org/abs/2611.01976
- arXiv HTML full text: https://arxiv.org/html/2611.01976
- arXiv PDF: https://arxiv.org/pdf/2611.01976

### Contribution
- Splits tool-based attacks along two axes, when the malicious functionality arrives (admission versus update) and how it runs (direct code execution versus model-context manipulation), and points at the largely unstudied corner where it arrives by update and runs as code.
- Confirms on seven commercial and open-source frameworks that permissions survive an update. Even where each tool call needs user confirmation, that confirmation authorizes the call, not the changed implementation.
- Tests three families of defenses directly: file-integrity checks (TLSH similarity), LLM-based static code review (Cisco MCP Scanner, SkillFortify, NVIDIA SkillSpector) and runtime auditing (in the style of SkillDetonate), and shows where each falls short.

### Evaluation
- Setup: three tools (Markdown cleaning, CSV statistics, ICS calendar generation) crossed with goals W1-W3, 20 tasks per condition, five rounds each. Attack success rate (ASR) is scored from independent evidence (a receiving server, service logs, file contents) and task completion rate (TCR) is measured separately.
- Results: the abstract reports an average ASR of 97.6% and TCR of 95.9% across the seven frameworks, well above the strongest prompt-injection baseline (context manipulation delivered by update). In the paper's RQ1 (same backend, 21 conditions), ETUDE reaches 100.0% ASR against 20.2% for that baseline. Swapping among four backend models keeps ASR between 80% and 100%.
- Defenses: TLSH distances for legitimate feature additions (173-221) overlap with malicious updates (145-233), so no threshold blocks the attacks while letting normal maintenance through. Static review is weak against obfuscation, and runtime auditing misses behavior that triggers only on specific inputs and is expensive.
- How far to trust the numbers: because the payload runs inside the tool's own code, a high ASR is expected. The real finding is that frameworks accept updates without re-review. The paper also breaks out its failures (malformed CSV arguments, wrong call counts), which adds credibility.

#### Comment
- This paper takes on the supply-chain problem in the agent tool ecosystem head-on. It shows experimentally that the build-trust-then-ship-a-malicious-update pattern seen in XZ Utils and event-stream works just as well against agent tools, and argues that the unit of authorization should be the exact code that was reviewed.
- Limitations: the attack is less a new technique than a known software supply-chain attack moved into the agent setting. The experiments use purpose-built tools rather than modifying real marketplace tools, and each framework's update path (package re-resolution, server restarts and so on) is reproduced through a harness.
- Chinese-institution check: most authors, including the corresponding authors, are at Shanghai Jiao Tong University, with Yufei Han of Inria as a co-author; both are real, major research institutions. No author code repository is given in the paper, so we could not confirm released artifacts. That said, the central claim (no re-review after updates) is a property anyone can check on the public frameworks, the high numbers follow naturally from the attack design rather than looking inflated, and the baselines run in the same harness, so the comparison is fair.

# Right Tool, Wrong Parameters: Defending LLM Agents Against Parameter Poisoning
> arXiv cs.CR 2611.04673 (preprint, not peer reviewed). University of Science and Technology of China (USTC, China)
> 2026

Most defenses against indirect prompt injection ask whether injected content triggered a new tool call or an off-task action. This paper looks at attacks that leave the action alone and change only the arguments, which the authors call "parameter poisoning." Say the user asks the agent to send Alice $500, and an attacker-controlled message claims that Alice's account number has changed. The agent calls the transfer tool exactly as planned but fills in the attacker's account. Since no new action appears, existing defenses tend to miss it.

The authors argue that an argument is legitimate only if the information that produced it is entitled to decide that argument for the task at hand, and they build a three-stage defense, AuthorityFlow, on that idea. It reads the user request to build a per-task trust hierarchy over information fields (a hotel's address field may set a calendar location, a review's text may not), traces the evidence behind each tool argument, and lets the call run only if the evidence both semantically supports the value and comes from a source authorized for that use.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.04673
- arXiv HTML full text: https://arxiv.org/html/2611.04673
- arXiv PDF: https://arxiv.org/pdf/2611.04673

### Contribution
- Separates an argument-level attack surface from instruction-level injection, and treats authority as a relation that depends on the task rather than a fixed property of a source.
- Proposes per-parameter authorization that checks semantic support and source authority separately. It runs at the agent orchestration layer, so neither model internals nor tool implementations need to change.
- Builds FactAuthBench, an extension of AgentDojo covering banking, Slack, travel and workspace scenarios with 144 paired benign and attack cases.

### Evaluation
- Agent models: Qwen3.6-27B, Llama-3.3-70B and GPT-4o. AuthorityFlow uses Qwen3.6-27B as its auxiliary model by default.
- Baselines: Sandwiching and Spotlighting (input level), IPIGuard, CaMeL and DRIFT (system level), MELON and AttriGuard (runtime verification and attribution), run from official implementations or default settings.
- Metrics: benign utility (BU), utility under attack (UA) and attack success rate (ASR).
- Results (Qwen3.6-27B): with no defense, ASR is 93.06% and BU 90.28%. AuthorityFlow brings ASR down to 9.03% with BU at 82.64%. On GPT-4o, ASR falls from 57.64% to 5.56%. Adding a purification step raises UA to 58.33% (Qwen) and 60.42% (GPT-4o).
- Worth noting: the results table shows CaMeL with a lower ASR than AuthorityFlow, 0.69% on Qwen and 2.08% on GPT-4o, but its BU drops to 43.75% and 39.58%. The abstract does not mention this, so the right reading is "a better utility-security balance," not "the lowest ASR." The benchmark is small (144 pairs) and built by the authors, which limits how far the results generalize.

#### Comment
- The problem is a very practical one. Cases where the tool is right but the value is wrong, such as a payment account, an email recipient or a meeting location, are hard to stop by watching actions alone, and the paper makes that point well.
- Limitations: the trust hierarchy is inferred from the user request by an LLM, so an error at that step undermines the whole defense. The cost of the extra auxiliary-model calls is not reported separately.
- Chinese-institution check: all authors are at USTC, a real and major university, and Weiming Zhang's group has published steadily on information hiding and AI security. We found no public code or benchmark release in the paper. The method beats most baselines, but the authors report CaMeL's lower ASR openly in the table, and the baselines are the standard defenses in this area, so the comparison is fair. The lack of artifacts should still be kept in mind.

# JailBound: FOL-Guided Jailbreak Evaluation for Exploring LLM Behavioral Boundaries
> arXiv cs.CR 2611.07530 (preprint, not peer reviewed; the PDF carries a NeurIPS 2026 footer, but we could not confirm acceptance). Qilu University of Technology (Shandong Academy of Sciences), Quan Cheng Laboratory, Guizhou University (China)
> 2026

Most jailbreak benchmarks rely on prompts that people collected or wrote, which makes them hard to extend to new threat types, and existing attack searches optimize only for success rate, saying little about how a model moves between a safe refusal and an unsafe answer. JailBound organizes threats in a hierarchy of risk category, application domain and attack type, and uses a fine-tuned meta-attack generator to produce evaluation prompts for each condition automatically. It then searches embedding space in two branches guided by a first-order loss (FOL), a local sensitivity signal based on the size of the attack loss gradient. The "high-value" branch looks for stable states with high attack utility, while the "safety-sensitivity" branch looks for states where a small change is likely to flip the verdict. The continuous embeddings it finds are turned back into text prompts and scored by an external judge model.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.07530
- arXiv HTML full text: https://arxiv.org/html/2611.07530
- arXiv PDF: https://arxiv.org/pdf/2611.07530
- Author repository (code cited in the paper): https://github.com/FrazeWu/JailBound

### Contribution
- A benchmark construction method that generates evaluation cases for new threat conditions from the taxonomy. The main experiments use 169 compositional conditions, 26,554 attack instances and nine attack types.
- Beyond success rate, it deliberately searches for sensitive states near the decision boundary, adding a way to diagnose where a model's safety is locally fragile.
- Evaluates 46 LLMs from 13 families (Llama, Qwen, Gemma, Mistral, Claude, GPT, Gemini and others) under one protocol.

### Evaluation
- Baselines: the public benchmarks AdvBench, JailbreakBench, SafetyBench, SG-Bench and HarmBench; the optimization attacks GCG, PEZ and GBDA run under matched settings; and an ablation without the first-order term (ZOL-only).
- Results: on Qwen2.5-14B-Instruct with two judges (Octopus-SEval-14B and Qwen3-32B-AWQ), the high-value branch beats ZOL-only by 5.1 and 4.9 percentage points on average. For prompts from JailBound's own source, for example, ASR goes from 18.3% initially to 44.4% with GCG, 60.4% with ZOL-only and 64.5% with the high-value branch.
- States from the safety-sensitivity branch show a higher behavioral flip rate (BFR) than high-value states at every perturbation radius tested.
- The authors report that converting continuous embeddings into text costs 6.9 points of ASR on average, and limit their claims to the executable text attacks accordingly. Main results average three runs.
- How far to trust the numbers: the gains are a few points, not implausibly large, and the ranking holds under a second judge. Verdicts still come from an LLM judge, so any judge error carries through.

#### Comment
- The paper tries to move jailbreak evaluation from a success-rate race toward diagnosing where the boundary lies, which could be useful for pre-release safety regression testing.
- Limitations: embedding-space optimization works directly only on open-weight models; commercial models are evaluated only through transfer of attacks built on Qwen2.5-14B. There is a different NeurIPS 2025 paper with the same name, JailBound, on vision-language models, so take care when citing.
- Chinese-institution check: all authors are at Chinese institutions; Qilu University of Technology (Shandong Academy of Sciences) and Guizhou University are real universities. The GitHub repository named in the paper exists (created April 2026, last updated late October) and contains source code, configs, experiment scripts and tests. The baselines and metrics are standard choices in the field. The PDF carries a NeurIPS 2026 footer, but we could not find the paper on the conference's accepted list, so we mark it as a preprint.

# The Web Doesn't Sit Still: Adversarial Self-Evolving Attacks on Search Agents
> arXiv cs.CR 2611.03754 (preprint, not peer reviewed; the PDF carries a NeurIPS 2026 footer, but we could not confirm acceptance). Nanyang Technological University (Singapore), Alibaba Group (China)
> 2026

Search agents that gather information from the web are exposed to manipulated documents mixed into their results (RAG poisoning). Existing attacks rely on fixed, hand-written rules, such as swapping the answer entity for another one, and never adapt to how the defender responds. This paper sets up attack and defense to evolve together as a bi-level optimization problem: the inner loop updates the defender's knowledge against the current attack pool, and the outer loop evolves the attack strategies. Its core method, CREO (Contrastive Rollout Evolutionary Optimization), mutates, recombines and selects strategies using signals obtained by contrasting the reasoning traces where a strategy succeeded with those where it failed. Experiments run in a controlled sandbox built on DeepResearchGym, with a fixed knowledge base of about 3.8 TB and an interceptor that slips forged documents into search results.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.03754
- arXiv HTML full text: https://arxiv.org/html/2611.03754
- arXiv PDF: https://arxiv.org/pdf/2611.03754

### Contribution
- Frames security evaluation of search agents as attacker-defender co-evolution and introduces CREO, which evolves attack strategies without hand-written templates.
- Builds a sandbox with fixed retrieval ordering for reproducibility.
- Adds metrics that separate "logic hijacking" (ASR), where the agent adopts forged evidence, from "cognitive paralysis" (APR), where it notices the contradiction but cannot resolve it and fails to answer.

### Evaluation
- Datasets: 100 training and 100 test questions each from HotpotQA, 2WikiMultihopQA and MuSiQue.
- Target agent models: Qwen-Turbo, Qwen3-Max, DeepSeek-V3.2, Kimi-K2.5 and GLM-5.1.
- Baselines: rule-based entity substitution (FactSwap) and query-aware optimized poisoning (AuthChain).
- Results: on MuSiQue, GLM-5.1's accuracy falls from 82% with no attack to 41% under AuthChain and 16% after one CREO round. Averaged over the 15 model-dataset combinations, CREO's total attack success (ASR plus APR) is 64.2-74.6% when the defense lags one round and 60.5-64.9% when it updates in sync, against 20.9%/18.1% for FactSwap and 55.7%/37.5% for AuthChain.
- How far to trust the numbers: an LLM judge scores outcomes, and an appendix checks its agreement with two human annotators and two other LLMs on 100 samples. One hundred test questions per dataset is small, and every target model comes from a Chinese vendor, so generalization to other model families is unverified.

#### Comment
- What stands out is applying attacks that evolve in response to the defense to RAG poisoning, and counting the inability to answer as a separate harm. For anyone running search-based agents, the lesson is that testing defenses against a fixed set of poisoned documents is not enough.
- Limitations: forged documents are inserted straight into the result list, so the difficulty of getting them ranked highly on the real web is not addressed. The paper says the code is released, but we could not find the address.
- Because one co-author is at Alibaba Group, we checked further. The lead authors are at Nanyang Technological University (Dacheng Tao's group), a real institution; the experimental procedure (random seed, sandbox configuration, cost tables) is described in reasonable detail; and the gains over the baselines are consistent without looking unrealistic.
- Full text source: official arXiv PDF downloaded on the user's computer.
