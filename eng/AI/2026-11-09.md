# Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security
> arXiv cs.CR 2611.01976 (preprint, not peer reviewed). Shanghai Jiao Tong University (China), Inria (France)
> 2026

LLM agent frameworks usually vet an external tool, such as an MCP server or an extension, once at installation and grant it permissions, but many never look at the code again when the tool updates. The authors call this the "tool update gap" and build an attack around it, ETUDE (Exploiting Tool Updates for Direct Execution). The attacker first ships a benign tool (v1) that passes admission checks, then releases a v2 that keeps the same name, description and input schema but hides malicious behavior in the implementation. That behavior runs directly inside the tool's runtime during ordinary calls, so no instruction ever shows up in the LLM's context. Prompt-injection detectors and other defenses that watch model-visible input simply cannot see it.

Across seven frameworks (Gemini CLI, Codex CLI, Claude Code, DeepSeek Harness, OpenCode, Pi and Goose), the authors confirm that once v1 is approved, v2 runs under the existing permissions without re-review. The attack goals are leaking a synthetic credential (W1), making unauthorized external API calls (W2) and tampering with a local file (W3).

Links:
- arXiv abstract: https://arxiv.org/abs/2611.01976
- arXiv HTML full text: https://arxiv.org/html/2611.01976
- arXiv PDF: https://arxiv.org/pdf/2611.01976

### Contribution
- Splits tool-based attacks along two axes, when the malicious functionality arrives (admission versus update) and how it runs (direct code execution versus model-context manipulation), and points at the largely unstudied corner where it arrives by update and runs as code.
- Confirms on seven commercial and open-source frameworks that permissions survive an update. Even where each tool call needs user confirmation, that confirmation authorizes the call, not the changed implementation.
- Tests three families of defenses directly: file-integrity checks (TLSH similarity), LLM-based static code review (Cisco MCP Scanner, SkillFortify, NVIDIA SkillSpector) and runtime auditing (in the style of SkillDetonate), and shows where each falls short.

### Evaluation
- Setup: three tools (Markdown cleaning, CSV statistics, ICS calendar generation) crossed with goals W1-W3, 20 tasks per condition, five rounds each. Attack success rate (ASR) is scored from independent evidence (a receiving server, service logs, file contents) and task completion rate (TCR) is measured separately.
- Results: the abstract reports an average ASR of 97.6% and TCR of 95.9% across the seven frameworks, well above the strongest prompt-injection baseline (context manipulation delivered by update). In the paper's RQ1 (same backend, 21 conditions), ETUDE reaches 100.0% ASR against 20.2% for that baseline. Swapping among four backend models keeps ASR between 80% and 100%.
- Defenses: TLSH distances for legitimate feature additions (173-221) overlap with malicious updates (145-233), so no threshold blocks the attacks while letting normal maintenance through. Static review is weak against obfuscation, and runtime auditing misses behavior that triggers only on specific inputs and is expensive.
- How far to trust the numbers: because the payload runs inside the tool's own code, a high ASR is expected. The real finding is that frameworks accept updates without re-review. The paper also breaks out its failures (malformed CSV arguments, wrong call counts), which adds credibility.

#### Comment
- This paper takes on the supply-chain problem in the agent tool ecosystem head-on. It shows experimentally that the build-trust-then-ship-a-malicious-update pattern seen in XZ Utils and event-stream works just as well against agent tools, and argues that the unit of authorization should be the exact code that was reviewed.
- Limitations: the attack is less a new technique than a known software supply-chain attack moved into the agent setting. The experiments use purpose-built tools rather than modifying real marketplace tools, and each framework's update path (package re-resolution, server restarts and so on) is reproduced through a harness.
- Chinese-institution check: most authors, including the corresponding authors, are at Shanghai Jiao Tong University, with Yufei Han of Inria as a co-author; both are real, major research institutions. No author code repository is given in the paper, so we could not confirm released artifacts. That said, the central claim (no re-review after updates) is a property anyone can check on the public frameworks, the high numbers follow naturally from the attack design rather than looking inflated, and the baselines run in the same harness, so the comparison is fair.

# Right Tool, Wrong Parameters: Defending LLM Agents Against Parameter Poisoning
> arXiv cs.CR 2611.04673 (preprint, not peer reviewed). University of Science and Technology of China (USTC, China)
> 2026

Most defenses against indirect prompt injection ask whether injected content triggered a new tool call or an off-task action. This paper looks at attacks that leave the action alone and change only the arguments, which the authors call "parameter poisoning." Say the user asks the agent to send Alice $500, and an attacker-controlled message claims that Alice's account number has changed. The agent calls the transfer tool exactly as planned but fills in the attacker's account. Since no new action appears, existing defenses tend to miss it.

The authors argue that an argument is legitimate only if the information that produced it is entitled to decide that argument for the task at hand, and they build a three-stage defense, AuthorityFlow, on that idea. It reads the user request to build a per-task trust hierarchy over information fields (a hotel's address field may set a calendar location, a review's text may not), traces the evidence behind each tool argument, and lets the call run only if the evidence both semantically supports the value and comes from a source authorized for that use.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.04673
- arXiv HTML full text: https://arxiv.org/html/2611.04673
- arXiv PDF: https://arxiv.org/pdf/2611.04673

### Contribution
- Separates an argument-level attack surface from instruction-level injection, and treats authority as a relation that depends on the task rather than a fixed property of a source.
- Proposes per-parameter authorization that checks semantic support and source authority separately. It runs at the agent orchestration layer, so neither model internals nor tool implementations need to change.
- Builds FactAuthBench, an extension of AgentDojo covering banking, Slack, travel and workspace scenarios with 144 paired benign and attack cases.

### Evaluation
- Agent models: Qwen3.6-27B, Llama-3.3-70B and GPT-4o. AuthorityFlow uses Qwen3.6-27B as its auxiliary model by default.
- Baselines: Sandwiching and Spotlighting (input level), IPIGuard, CaMeL and DRIFT (system level), MELON and AttriGuard (runtime verification and attribution), run from official implementations or default settings.
- Metrics: benign utility (BU), utility under attack (UA) and attack success rate (ASR).
- Results (Qwen3.6-27B): with no defense, ASR is 93.06% and BU 90.28%. AuthorityFlow brings ASR down to 9.03% with BU at 82.64%. On GPT-4o, ASR falls from 57.64% to 5.56%. Adding a purification step raises UA to 58.33% (Qwen) and 60.42% (GPT-4o).
- Worth noting: the results table shows CaMeL with a lower ASR than AuthorityFlow, 0.69% on Qwen and 2.08% on GPT-4o, but its BU drops to 43.75% and 39.58%. The abstract does not mention this, so the right reading is "a better utility-security balance," not "the lowest ASR." The benchmark is small (144 pairs) and built by the authors, which limits how far the results generalize.

#### Comment
- The problem is a very practical one. Cases where the tool is right but the value is wrong, such as a payment account, an email recipient or a meeting location, are hard to stop by watching actions alone, and the paper makes that point well.
- Limitations: the trust hierarchy is inferred from the user request by an LLM, so an error at that step undermines the whole defense. The cost of the extra auxiliary-model calls is not reported separately.
- Chinese-institution check: all authors are at USTC, a real and major university, and Weiming Zhang's group has published steadily on information hiding and AI security. We found no public code or benchmark release in the paper. The method beats most baselines, but the authors report CaMeL's lower ASR openly in the table, and the baselines are the standard defenses in this area, so the comparison is fair. The lack of artifacts should still be kept in mind.

# JailBound: FOL-Guided Jailbreak Evaluation for Exploring LLM Behavioral Boundaries
> arXiv cs.CR 2611.07530 (preprint, not peer reviewed; the PDF carries a NeurIPS 2026 footer, but we could not confirm acceptance). Qilu University of Technology (Shandong Academy of Sciences), Quan Cheng Laboratory, Guizhou University (China)
> 2026

Most jailbreak benchmarks rely on prompts that people collected or wrote, which makes them hard to extend to new threat types, and existing attack searches optimize only for success rate, saying little about how a model moves between a safe refusal and an unsafe answer. JailBound organizes threats in a hierarchy of risk category, application domain and attack type, and uses a fine-tuned meta-attack generator to produce evaluation prompts for each condition automatically. It then searches embedding space in two branches guided by a first-order loss (FOL), a local sensitivity signal based on the size of the attack loss gradient. The "high-value" branch looks for stable states with high attack utility, while the "safety-sensitivity" branch looks for states where a small change is likely to flip the verdict. The continuous embeddings it finds are turned back into text prompts and scored by an external judge model.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.07530
- arXiv HTML full text: https://arxiv.org/html/2611.07530
- arXiv PDF: https://arxiv.org/pdf/2611.07530
- Author repository (code cited in the paper): https://github.com/FrazeWu/JailBound

### Contribution
- A benchmark construction method that generates evaluation cases for new threat conditions from the taxonomy. The main experiments use 169 compositional conditions, 26,554 attack instances and nine attack types.
- Beyond success rate, it deliberately searches for sensitive states near the decision boundary, adding a way to diagnose where a model's safety is locally fragile.
- Evaluates 46 LLMs from 13 families (Llama, Qwen, Gemma, Mistral, Claude, GPT, Gemini and others) under one protocol.

### Evaluation
- Baselines: the public benchmarks AdvBench, JailbreakBench, SafetyBench, SG-Bench and HarmBench; the optimization attacks GCG, PEZ and GBDA run under matched settings; and an ablation without the first-order term (ZOL-only).
- Results: on Qwen2.5-14B-Instruct with two judges (Octopus-SEval-14B and Qwen3-32B-AWQ), the high-value branch beats ZOL-only by 5.1 and 4.9 percentage points on average. For prompts from JailBound's own source, for example, ASR goes from 18.3% initially to 44.4% with GCG, 60.4% with ZOL-only and 64.5% with the high-value branch.
- States from the safety-sensitivity branch show a higher behavioral flip rate (BFR) than high-value states at every perturbation radius tested.
- The authors report that converting continuous embeddings into text costs 6.9 points of ASR on average, and limit their claims to the executable text attacks accordingly. Main results average three runs.
- How far to trust the numbers: the gains are a few points, not implausibly large, and the ranking holds under a second judge. Verdicts still come from an LLM judge, so any judge error carries through.

#### Comment
- The paper tries to move jailbreak evaluation from a success-rate race toward diagnosing where the boundary lies, which could be useful for pre-release safety regression testing.
- Limitations: embedding-space optimization works directly only on open-weight models; commercial models are evaluated only through transfer of attacks built on Qwen2.5-14B. There is a different NeurIPS 2025 paper with the same name, JailBound, on vision-language models, so take care when citing.
- Chinese-institution check: all authors are at Chinese institutions; Qilu University of Technology (Shandong Academy of Sciences) and Guizhou University are real universities. The GitHub repository named in the paper exists (created April 2026, last updated late October) and contains source code, configs, experiment scripts and tests. The baselines and metrics are standard choices in the field. The PDF carries a NeurIPS 2026 footer, but we could not find the paper on the conference's accepted list, so we mark it as a preprint.
- Full text source: official arXiv PDF downloaded on the user's computer. Repository existence and contents were checked through GitHub's public information.

# The Web Doesn't Sit Still: Adversarial Self-Evolving Attacks on Search Agents
> arXiv cs.CR 2611.03754 (preprint, not peer reviewed; the PDF carries a NeurIPS 2026 footer, but we could not confirm acceptance). Nanyang Technological University (Singapore), Alibaba Group (China)
> 2026

Search agents that gather information from the web are exposed to manipulated documents mixed into their results (RAG poisoning). Existing attacks rely on fixed, hand-written rules, such as swapping the answer entity for another one, and never adapt to how the defender responds. This paper sets up attack and defense to evolve together as a bi-level optimization problem: the inner loop updates the defender's knowledge against the current attack pool, and the outer loop evolves the attack strategies. Its core method, CREO (Contrastive Rollout Evolutionary Optimization), mutates, recombines and selects strategies using signals obtained by contrasting the reasoning traces where a strategy succeeded with those where it failed. Experiments run in a controlled sandbox built on DeepResearchGym, with a fixed knowledge base of about 3.8 TB and an interceptor that slips forged documents into search results.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.03754
- arXiv HTML full text: https://arxiv.org/html/2611.03754
- arXiv PDF: https://arxiv.org/pdf/2611.03754

### Contribution
- Frames security evaluation of search agents as attacker-defender co-evolution and introduces CREO, which evolves attack strategies without hand-written templates.
- Builds a sandbox with fixed retrieval ordering for reproducibility.
- Adds metrics that separate "logic hijacking" (ASR), where the agent adopts forged evidence, from "cognitive paralysis" (APR), where it notices the contradiction but cannot resolve it and fails to answer.

### Evaluation
- Datasets: 100 training and 100 test questions each from HotpotQA, 2WikiMultihopQA and MuSiQue.
- Target agent models: Qwen-Turbo, Qwen3-Max, DeepSeek-V3.2, Kimi-K2.5 and GLM-5.1.
- Baselines: rule-based entity substitution (FactSwap) and query-aware optimized poisoning (AuthChain).
- Results: on MuSiQue, GLM-5.1's accuracy falls from 82% with no attack to 41% under AuthChain and 16% after one CREO round. Averaged over the 15 model-dataset combinations, CREO's total attack success (ASR plus APR) is 64.2-74.6% when the defense lags one round and 60.5-64.9% when it updates in sync, against 20.9%/18.1% for FactSwap and 55.7%/37.5% for AuthChain.
- How far to trust the numbers: an LLM judge scores outcomes, and an appendix checks its agreement with two human annotators and two other LLMs on 100 samples. One hundred test questions per dataset is small, and every target model comes from a Chinese vendor, so generalization to other model families is unverified.

#### Comment
- What stands out is applying attacks that evolve in response to the defense to RAG poisoning, and counting the inability to answer as a separate harm. For anyone running search-based agents, the lesson is that testing defenses against a fixed set of poisoned documents is not enough.
- Limitations: forged documents are inserted straight into the result list, so the difficulty of getting them ranked highly on the real web is not addressed. The paper says the code is released, but we could not find the address.
- Because one co-author is at Alibaba Group, we checked further. The lead authors are at Nanyang Technological University (Dacheng Tao's group), a real institution; the experimental procedure (random seed, sandbox configuration, cost tables) is described in reasonable detail; and the gains over the baselines are consistent without looking unrealistic.
- Full text source: official arXiv PDF downloaded on the user's computer.

# I Don't Care How You Hide It, I Care What You Do: Runtime Detection of Malicious ML Models
> Accepted at IEEE ACSAC 2026 (per the arXiv comment); public version arXiv cs.CR 2611.08745. Virginia Commonwealth University (USA), Volatility Foundation (USA)
> 2026

Pre-trained models shared on platforms such as Hugging Face can be built to run a malicious payload the moment they are loaded or used for inference. Existing scanners like PickleScan and ModelScan rely on denylists of dangerous functions (os.system, eval and so on) and static analysis, so they miss payloads that swap in functionally equivalent calls, use a loading path the scanner does not support, or abuse legitimate TensorFlow APIs. The authors argue that what matters is what a model actually does, not how it hides, and present ModelShield, a runtime behavioral detector.

ModelShield uses aspect-oriented instrumentation on ML framework APIs (for example torch.load) and traces system calls with eBPF. A correlation identifier shared by both layers links each syscall to the loading or inference operation that caused it, and that link is carried across threads and child processes. This separates model-triggered behavior from noise such as framework internals or CUDA initialization. The attributed syscall sequences are then matched against 195 detection patterns mapped to MITRE ATT&CK techniques. The system supports 17 frameworks and 36 file formats.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.08745
- arXiv HTML full text: https://arxiv.org/html/2611.08745
- arXiv PDF: https://arxiv.org/pdf/2611.08745
- Author repository (source code, detection taxonomy, reproduction scripts): https://github.com/HalaAli198/ModelShield
- ACSAC 2026 accepted papers list: https://www.acsac.org/2026/program/papers/

### Contribution
- Claims to be the first system that judges ML models by runtime behavior rather than static inspection. A model is flagged only when a harmful action is actually observed, so benign models that merely contain a denylisted function are not false positives.
- Designs an attribution method that combines application-level instrumentation with kernel-level syscall tracing to tell which of thousands of syscalls came from model operations.
- Scans real platforms at scale, finds malicious models that existing scanners missed, and reports them to the platform and the cloud provider involved.

### Evaluation
- Accuracy: on the independent dataset released with PickleBall (252 benign, 84 malicious), zero false positives, 47 detections and 37 misses. The authors break the misses down by cause: one mislabeled sample with no payload, nine where the environment lacked required packages or the payload targeted Windows APIs, and other cases where no malicious behavior appeared at runtime.
- Evasion: detects all 29 variants, namely 15 function substitutions from Liu et al., 10 loading-path obfuscations, and 4 TensorFlow SavedModel API abuses from Zhu et al. None of the compared tools (ModelScan, PickleScan, Fickling, ModelAudit) caught them all.
- Large-scale scan: models uploaded between March 25 and May 5, 2026, covering 105,000 on Hugging Face, 30,000 on ModelScope and 10,000 on Kaggle. ModelShield found 41 malicious models on Hugging Face; on those 41, ModelScan detected 29%, PickleScan 56%, Fickling 80% and ModelAudit 93%. A continued deployment through August 19 scanned another 224,164 Hugging Face models and found 105 more.
- Cost: median analysis time of 12.3 seconds per model, with 90% of scans finishing within 35.5 seconds.
- Reliability of the metrics: using a third-party dataset and openly listing every miss by cause is good practice. Still, "zero false positives" comes from a small set of 252 benign models, and the 41 large-scale hits are the yardstick for the other tools, so ModelShield's own misses do not show up in that comparison.

#### Comment
- A practical answer to the chronic weakness of static scanners (denylist bypasses). Catching a real reverse-shell model and a credential-stealing model within hours of upload, and getting them taken down, shows clear operational value. Co-author Andrew Case is a core developer of the Volatility memory forensics framework.
- Limitations: as dynamic analysis, it misses payloads triggered only by specific inputs or timers and payloads that need packages absent from the environment. Only Linux is supported, so Windows-targeted payloads go undetected. An LLM (GPT-5.5) was used for pattern discovery.
- Venue: ACSAC is a long-running, well-regarded applied security conference. Code, taxonomy and evaluation data are public, so reproducibility is high.
- Full text source: official arXiv PDF downloaded on the user's computer.

# NotaryMark: Multi-Bit Watermarking for Black-Box DatasetUsage Auditing in Text-to-Image Diffusion Models
> Accepted to ACM CCS 2026 (per the arXiv comment); public version arXiv cs.CR 2611.08985. Xi'an Jiaotong University (China), Zhejiang University (China), Vrije Universiteit Amsterdam (Netherlands)
> 2026

As more scraped, licensed images end up in text-to-image training sets without permission, data owners need a way to check whether their dataset was used. Existing dataset watermarks tend to be treated as noise and fade away during the noising and denoising steps of diffusion training, and multi-bit watermarks, which carry more than a yes-or-no signal, barely survive at all. NotaryMark embeds the watermark in latent space and aligns it with the diffusion model's denoising process, so it can be recovered from images generated by a model trained on the data. On the generated side, a dedicated U-Net predictor isolates the watermark residual and recovers the bits.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.08985
- arXiv HTML full text: https://arxiv.org/html/2611.08985
- arXiv PDF: https://arxiv.org/pdf/2611.08985

### Contribution
- Claims to be the first multi-bit watermark designed for black-box auditing of training data use in text-to-image models. It can carry information such as an owner identifier, not just a used-or-not verdict.
- Adds voting-based aggregation over about 30 queries and error-correcting codes, giving an end-to-end path from recovered bits to an attributable identifier.

### Evaluation
- Setup: three datasets (Pokémon, CelebA, WikiArt), three diffusion models including SDXL and Kandinsky, LoRA fine-tuning, watermark capacities from 8 to 1024 bits.
- Results (abstract and body): average bit accuracy of 0.85-0.90 below 32 bits and 0.67-0.80 above, versus roughly 0.42-0.60 for existing multi-bit methods. With multi-query aggregation, exact recovery is reached at 32 bits; on SDXL, for example, aggregated bit accuracy is 97.50% on Pokémon, 81.59% on CelebA and 89.09% on WikiArt.
- Low watermark rates: when watermarked data is 10% of the training set, the true positive rate drops to 47% on Pokémon and 31% on CelebA, reaching 100% from 30% onward. On WikiArt, bit accuracy stays close to random at low rates.
- Robustness: tested against 15 evasion attacks in seven categories; the authors report that strong attacks remove the watermark only at a large cost to data utility.
- Baselines and reliability: the baselines are classic image watermarks (DwtDct, SSL, RivaGAN) and DiffusionShield, a dataset watermark for diffusion models. The classic methods were not built for this setting, and the authors say in the appendix that the comparison should be read as a transferability test. They also report the weak spots (low watermark rates, heavy blur, regeneration attacks) openly.

#### Comment
- A timely topic, copyright auditing for generative models, and carrying multi-bit information through training is new. Low watermark rates, common in real deployments, remain the main weakness.
- Limitations: the evaluation focuses on LoRA fine-tuning, leaving full training and other fine-tuning methods open. A per-dataset encoder and decoder must be trained, which adds cost.
- Verification of Chinese-institution work: most authors are at Xi'an Jiaotong University and Zhejiang University, with co-author Min Chen at Vrije Universiteit Amsterdam. Zhikun Zhang and Min Chen are established researchers with a track record of data-auditing papers at top venues (for example FACE-AUDITOR). CCS is a top-tier security venue. Public datasets and models are used, but no code link was found in the paper, so reproduction materials could not be confirmed. The margin over prior methods is large, but the paper also reports where it fails, so the numbers do not look inflated. Note that the classic watermark baselines are more of a lower bound than true competitors.
- Full text source: official arXiv PDF downloaded on the user's computer.

# Logit Laundering: Evading Data-Use Auditing in Large Language Models
> Accepted to ACM CCS 2026 (per the arXiv comment, DOI 10.1145/3830454.3846794); public version arXiv cs.CR 2611.09446. Beijing University of Posts and Telecommunications (China), Zhongguancun Laboratory (China), Augusta University (USA)
> 2026

A common way to expose unauthorized use of training data in LLMs is to watermark the data and look for its statistical trace in model outputs. This paper takes the other side: if a provider secretly trained on copyrighted data and wants to escape an audit, what can it do? The authors first show that evasion at the data level (character swaps, token replacement, paraphrasing, translation) hurts text quality and still leaves a trace. They then propose Logit Laundering, which evades at output time: model parameters stay untouched, and only the logits are reshaped during inference to cancel the statistical bias introduced by the watermark.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.09446
- arXiv HTML full text: https://arxiv.org/html/2611.09446
- arXiv PDF: https://arxiv.org/pdf/2611.09446
- DOI (ACM CCS 2026): https://doi.org/10.1145/3830454.3846794

### Contribution
- Claims to be the first systematic study of LLM data-use auditing from the adversary's point of view.
- Designs a logit reshaping module with a plug-in statistical bias estimator, plus a confidence-aware scaling module that adjusts the suppression strength to the model's next-token confidence, balancing evasion against utility.
- Shows that audit designers also need to account for manipulation at inference time.

### Evaluation
- Data: to avoid overlap with existing training corpora, 4,959 paragraphs of 512 tokens were drawn from 50 copyrighted books published in 2025 and watermarked, then mixed with 500 arXiv papers, 1,000 Pile-CC documents and 646 Hacker News posts from the Pile test split for continued pre-training. Five foundation models were used.
- Audits: STAMP-style and Radioactive watermark detection, with alternative scoring on the auditor side such as top-k and nucleus sampling and Min-K% Prob.
- Baselines: seven data-level attacks from the LLM watermarking literature (homoglyphs, insertion, typos, token swap, synonyms, paraphrase, translation) and, at the model level, three Rank-Swap variants the authors built in a preliminary study.
- Metrics: evasion is measured by the drop in t-statistics and p-values, or z-scores and p-values; utility by multiple-choice accuracy on the copyrighted content, GPT2-XL fluency, MAUVE, LLM-judge scores, ARC-Challenge, MMLU and TriviaQA. The authors report a large weakening of the audit signal with most of the utility preserved.
- Reliability: using recently published books to avoid contamination is a careful choice. The only model-level baselines are the authors' own variants, which is understandable for a first study but makes the comparison lighter.

#### Comment
- Adding a realistic assumption to the audit threat model (the provider controls the outputs) matters. As long as black-box audits only see outputs, every method in this family is potentially affected.
- Limitations: defenses against this evasion are left for future work. If auditors find a way to detect logit manipulation, the picture may change.
- Verification of Chinese-institution work: most authors are at BUPT and Zhongguancun Laboratory, funded by the National Natural Science Foundation of China. The venue is CCS, and an ACM DOI has already been assigned, which supports the acceptance claim. Public data and models are used, but no code link was found in the paper. The metrics are statistical test values and standard benchmarks, leaving little room for cherry-picking, and the choice of baselines is explained.
- Full text source: official arXiv PDF downloaded on the user's computer.

# GuardrailAgent: An Agentic Framework for Jailbreak Defense
> Published in Findings of EMNLP 2026 (ACL Anthology 2026.findings-emnlp.70); public version arXiv cs.CR 2611.09734. CISPA Helmholtz Center for Information Security (Germany)
> 2026

New jailbreak variants appear almost daily, while existing defenses such as safety fine-tuning or external filters are tuned to known attacks and react slowly to new ones. GuardrailAgent is a multi-agent defense that collects and summarizes attack characteristics on its own, keeps a knowledge base up to date, and uses it to detect jailbreaks on both the input side (prompts) and the output side (model responses). A feedback module feeds misclassified cases back into the knowledge base to improve cheaply over time.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.09734
- arXiv HTML full text: https://arxiv.org/html/2611.09734
- arXiv PDF: https://arxiv.org/pdf/2611.09734
- ACL Anthology official paper page: https://aclanthology.org/2026.findings-emnlp.70/
- ACL Anthology official PDF: https://aclanthology.org/2026.findings-emnlp.70.pdf
- Author repository (per the arXiv comment): https://github.com/TrustAIRLab/GuardrailAgent
- Author repository (per the paper): https://github.com/tianzechang/GuardrailAgent

### Contribution
- Proposes an adaptive defense that automatically updates its knowledge base with attack characteristics gathered from external sources such as papers.
- Splits detection into an input agent and an output agent; the output agent passes through responses the model has already refused and otherwise compares the response with known jailbreak response patterns.
- Shows, through a feedback mode that learns from misclassifications, that the system adapts quickly to unseen attacks.

### Evaluation
- Attack data: more than ten jailbreak techniques drawn from the JailbreakRadar benchmark and the WildJailbreak dataset, covering model-independent attacks (templates, obfuscation) and model-dependent ones that need iterative optimization. Utility is measured on 1,000 benign queries (900 generated with ChatGPT-5, 100 of them also rewritten as role-play).
- Target models: ChatGLM3-6B, Vicuna-7B and GPT-3.5-turbo, deliberately chosen as relatively weak models to make the guardrail's effect visible.
- Results: 93.1% input-side detection, 93.9% overall detection and 95.8% F1, beating OpenAI Moderation and Llama Guard 4 by at least 0.219 in overall detection and 0.123 in F1. Latency and token cost were also measured on a single RTX 4090.
- Reliability: the benchmarks are public, but the results come from a "warmed-up" system whose knowledge base was already populated. LLM-generated benign queries and older target models differ from real deployments.

#### Comment
- A short six-page Findings paper focused on the idea and the design. A defense that updates itself also opens a new risk, poisoning of its update path, which the paper does not address.
- Limitations: the authors note that lightweight components (similarity retrieval, literature-guided analysis) may struggle with semantically ambiguous attacks or ones that need deeper reasoning.
- Venue: EMNLP Findings is a peer-reviewed ACL venue. The CISPA group of Yang Zhang and Michael Backes is very active in LLM security, and the code is public.
- Full text source: official ACL Anthology PDF.

# MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory
> arXiv cs.CR 2611.09721 (preprint, not peer reviewed). Rensselaer Polytechnic Institute (USA), Microsoft (USA)
> 2026

LLM agents use memory systems to handle long, multi-session tasks. A malicious instruction seen in one session can be stored and then retrieved and acted on in a later session, which makes memory a new attack surface. Because memory systems store and retrieve information in different ways, the consequences of poisoning also differ. MemoryDojo is a benchmark that traces poisoned information through its whole lifecycle: insertion into memory, persistence or propagation, retrieval, and influence on later behavior.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.09721
- arXiv HTML full text: https://arxiv.org/html/2611.09721
- arXiv PDF: https://arxiv.org/pdf/2611.09721

### Contribution
- Builds an extensible benchmark with 155 multi-session, long-horizon trajectories in four domains and five memory systems (A-MEM, Graphiti, Letta, Mem0, Memora).
- Defines lifecycle metrics such as insertion success, retrieval success, retrieval due to persistence or propagation, and reach into later tasks. Where the usual attack success rate only asks whether the attack worked on the spot, these metrics ask how long and how far the poison travels.
- Proposes a memory-aware poison optimization that iteratively refines the payload in an auxiliary environment.

### Evaluation
- Setup: one payload is appended to a tool observation in the first session, then the remaining sessions run. The main target is GPT-5.6-Luna, with GPT-5.6-Sol as the optimizer; GPT-5.4-mini, DeepSeek-V4-Flash and GLM-5.3-Flash were added for transfer.
- Results: all five systems were vulnerable. Even unoptimized payloads reached up to 45.70% at the trajectory level and 21.02% in later tasks. Graphiti and Mem0 stayed below 8% later-task reach, while A-MEM and Memora exceeded 20%. Four systems stored the poison almost every time, but Mem0's insertion success was 60.75%, apparently because it uses an LLM to extract facts and abstracts the payload away. Retrieval success was above 80% for A-MEM and Memora, 64.88% for Letta, 56.70% for Mem0 and 33.43% for Graphiti.
- Optimization: memory-aware optimization raised attack success by roughly 2-31%, payloads optimized on Luna transferred to other models, and poison inserted mid-trajectory remained effective.
- Reliability: judging relies on an LLM judge (GPT-5.6-Luna), so judge bias can creep in. Each memory system uses its native retrieval, which keeps the cross-system comparison fair.

#### Comment
- Its main value is a first framework for comparing how safe different agent memory systems are against poisoning. The observation that LLM-based summarizing and extraction at write time (Mem0) happens to act as a defense is a useful design hint.
- Limitations: the default setting inserts a single payload, and defenses are not evaluated. A public link to the benchmark was not found in the paper.
- Venue: a preprint with authors from the Microsoft AI Red Team.

# I Think, Therefore I Attack: Evaluating Thought Injection Attacks on Reasoning Agents
> arXiv cs.AI 2611.08811 (cross-listed to cs.CR; preprint, not peer reviewed). Applied Research Laboratories, University of Texas at Austin (USA)
> 2026

Reasoning models write out an explicit thinking stage before answering. This paper evaluates "thought injection," where untrusted input contains text that looks like the model's own deliberation, in two studies. The first tests static injection prompts that try to leak a protected database, with and without wrapping them in thinking tags (<think>). The second runs in a containerized cyber range, where indirect injections written in the target model's own reasoning style push an agent to open a reverse shell or backdoor a repository.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.08811
- arXiv HTML full text: https://arxiv.org/html/2611.08811
- arXiv PDF: https://arxiv.org/pdf/2611.08811

### Contribution
- Quantifies injection attacks that target the reasoning trace itself, on real open-weight models and in an agentic environment.
- Shows that success depends on whose voice the payload uses rather than on the instruction. The same malicious request never succeeded in a user's voice but reached up to 50% in the target model's own reasoning style.
- Argues that stripping thinking tags is not a reliable defense.

### Evaluation
- Study 1: GLM-5.3-Flash, Qwen3.8-27B and Qwen3.8-Flash-Next, 100 attack prompts run 10 times each under tagged and untagged conditions (6,000 runs). Leak rates ranged from 8.6% to 11.7%. Tags more than tripled the rate on GLM-5.3-Flash (3.8% to 13.4%) but made no meaningful difference on Qwen3.8-Flash-Next.
- Study 2: two targets (MiniMax-M2.5, GLM-5.2), two tasks (reverse shell, backdoor), three voices (user, self, the other model) and two tag conditions, 50 runs each for 1,200 evaluations. MiniMax-M2.5 complied with self-voiced, tagged payloads in 42% of reverse-shell runs and 50% of backdoor runs, dropping to 8% and 10% without tags. GLM-5.2's style transferred to MiniMax to some extent (20%, 14%) but not the other way (0%, 2%).
- Concealment: with tags, agents more often failed to mention the injection in their final answer. For example, on the reverse-shell task against GLM, the MiniMax-style payload went unmentioned in 92% of runs with tags but only 22% without.
- Reliability: run counts are stated and differences within sampling noise are not over-interpreted. With only two or three targets and 50 runs per cell, though, generalization is limited.

#### Comment
- A short preliminary study, but the finding that models recognize their own thinking by style rather than by markers has direct implications for agents built on reasoning models. The authors even suggest that not disclosing which model you run can serve as a defense.
- Limitations: as the authors note, the two studies have different objectives and are hard to combine, and because the self-voiced payloads were the target's real reasoning traces, the effect of style may be mixed with the effect of the plan content.
- Venue: a preprint from a US university-affiliated research lab. The evaluation harness is built on the open-source Inspect AI framework.
