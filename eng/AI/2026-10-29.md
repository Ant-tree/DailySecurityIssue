# Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness
> arXiv cs.LG, cross-listed in cs.CR (preprint, not peer reviewed). Imperial College London, Tübingen AI Center, ELLIS Institute Tübingen, Max Planck Institute for Intelligent Systems, Fraunhofer HHI
> 2026

Indirect prompt injection happens when a model mistakes instructions hidden in external data, such as a web page or a tool output, for commands from the user. Instead of fine-tuning the whole model to separate instructions from data, this paper proposes Heads of Security (HoS), which learns a small gate for each attention head. Each head learns how to redistribute attention between trusted tokens (the user's request) and untrusted tokens (external data), so the model can still read and analyze the data without obeying instructions inside it. The base weights stay frozen; the learned parameters number only 46,080 for Llama-3.3-70B and 18,432 for GPT-OSS-20B.

Paper: https://arxiv.org/abs/2610.37657

### Contribution
- Builds on interpretability work showing that heads specialize (copying, copy suppression, instruction following) to design an architectural defense that applies the trust boundary differently per head. Trust labels are supplied from outside (web search results are untrusted, for instance), turning the problem into one of routing attention.
- Controls the comparison by training on the same preference data (the Alpaca-based SecAlign++ data) with the same DPO objective, isolating the effect of the training mechanism. On identical data SecAlign learns a shortcut and breaks down out of distribution (few-shot, multi-turn), while HoS does not.
- Evaluates against adaptive attacks: the reinforcement-learning black-box attack RL-Hammer, and the white-box attack Claudini, further tuned against HoS through an automated research loop. Code, models, and a demo are released.

### Evaluation
- Adaptive attacks (InjecAgent goals): the strongest RL-Hammer attacker succeeds 97% of the time against undefended GPT-OSS-20B, 85% against SecAlign, and 10% against HoS. On Llama-3.3-70B the figures are 99%, 82% (Meta-SecAlign-70B), and 1%. For reference, an attacker trained against the commercial GPT-5.6-Luna reaches 36% on that model.
- White-box attack: even Claudini optimized against HoS needs about three times the compute of GPT-OSS-20B or SecAlign to reach a 50% success rate.
- Utility: on 5-shot MMLU-Pro, the GPT-OSS-20B base scores 68%, HoS 67%, SecAlign 59%, and ASIDE 52%; on Llama, the base scores 56%, HoS 55%, and SecAlign 16%.
- Agentic benchmarks (AgentDojo, AgentDyn, LLMail-Inject, WASP): HoS and SecAlign cut attack success by similar amounts, and on GPT-OSS-20B HoS beats SecAlign on both security and utility for AgentDojo and WASP. ASIDE loses the ability to call tools and reaches only 10% utility on AgentDojo.
- Reliability of the metrics: testing adaptive attackers, not just static ones, and reporting attack success alongside utility is solid by the field's standards. Still, the RL attacker trained against HoS reached only 3.2% success during training, so its reward signal was sparse, and the authors note that the SecAlign-trained attacker was actually stronger against HoS; whether the adaptive attacks were strong enough remains open. ASIDE was ported to GPT-OSS by the authors themselves, so part of its poor showing may come from the port.

#### Comment
- The paper does not address who decides the trust boundary. The authors state that it cannot apply to tasks that legitimately require following instructions in external content (such as installation steps). It is best seen as one building block alongside instruction hierarchy and contextual integrity.
- It assumes standard softmax attention, so it does not carry over directly to linear-attention architectures.
- For teams running open-weight models, shipping only tens of thousands of extra parameters is attractive. The authors are groups with a track record in prompt injection defenses, but the paper is still a preprint.

# Log-To-Leak: Prompt Injection Attacks on Tool-Using LLM Agents via the Model Context Protocol
> 1st Workshop on Security, Privacy, and Safety of Agentic AI Systems (AGENT-SEC '26, The Hague, November 2026, ACM proceedings, DOI 10.1145/3847320.3847399), public version on arXiv cs.CR. Duke University, Michigan State University, TikTok (San Jose, USA)
> 2026

MCP servers pass natural-language metadata such as tool names and descriptions to the agent, and a malicious MCP server can hide instructions in that metadata (tool poisoning). This paper focuses on one variant, a "post-hoc logging" attack called Log-To-Leak: after the agent finishes its legitimate work, it makes one more call to the attacker's logging tool, sending along the user query, the MCP server name, the server response, and the agent's answer. Because the user sees an essentially normal result, the authors stress that a completed task is no evidence of safety.

Paper: https://arxiv.org/abs/2610.36108

### Contribution
- Structures the injected directive into four parts, Trigger (when to act), Tool Binding (which tool to call), Justification (a plausible rationale), and Pressure (framing the call as mandatory), and isolates each part's contribution through ablations.
- Proposes five metrics that separately measure whether the logging call happens, how accurately the leaked fields are reproduced (Logging Accuracy), how task completion changes, whether the attacker server's legitimate calls still work, and token usage.
- Releases the harness, task lists, and 871 configurations of attacker-controlled MCP servers in an anonymous repository.

### Evaluation
- Setup: five MCP servers (GitHub, Mapbox, PayPal, YFinance, Playwright), four agent models (GPT-4o, GPT-5, Claude-Sonnet-4, GPT-OSS-120B), and 555 tasks. The 480 tasks for GitHub, Mapbox, and PayPal were generated with GPT-4o; the remaining 75 come from MCP-Universe.
- Results: across 18 model-server pairs with valid tool execution, attack success ranges from 62.64% to 100% and logging accuracy from 76.55% to 95.64%. In 16 of the 18 pairs, task completion changes by no more than 6.63 percentage points.
- Baseline: a plain instruction to "call the logging tool after the task" already works 87.30-98.05% of the time on GPT-5 and nearly always on Claude-Sonnet-4. The structured template makes a large difference mainly for GPT-4o (from 38.40% to 62.64% on GitHub).
- Defenses: on GitHub MCP with GPT-4o, attack success stays at 59.58% with prompt sandwiching, 55.38% with a GPT-4o metadata auditor, and 60.47% with IPIGuard. DataSentinel labels all 100 injected descriptions as safe, and a hidden-state instruction detector flags 91% of injected descriptions but also 85.53% of benign ones.
- Real clients: the behavior was reproduced once each in Cursor (GPT-5.1) and Claude Desktop (Claude-Sonnet-4.5).
- Reliability of the metrics: response fields count as leaked when their TF-IDF cosine similarity exceeds 0.75, which does not fully capture semantic leakage. Each ablation uses only three phrasings, and the defenses were tested on a single pair (GitHub with GPT-4o).

#### Comment
- The most telling result is not the attack template but the baseline: current models call an attacker's tool almost every time with a plain instruction. The real problem is structural, namely that hosts do not control secondary tool calls the user never approved, and the authors' own recommendation is host-side authorization for such calls.
- The attack requires the user to have installed the malicious MCP server, so installation review, tool allowlists, and per-call confirmation shrink the attack surface considerably.
- The venue is a first-edition workshop held alongside ACM CCS 2026; its review bar may be lighter than the main conference.
- Verification for a Chinese-affiliated institution: two coauthors are with TikTok's US entity (part of ByteDance), and the first authors did the work as TikTok interns. Email domains (bytedance.com, tiktok.com, duke.edu, msu.edu) match the stated affiliations, the paper carries an ACM DOI as a workshop paper, and the experimental materials are released anonymously, giving a path to reproduction. The authors report the strong baselines openly, so the numbers do not look inflated. Within what could be checked, it meets the bar and is included.

# Penny for Your Prompts: A Measurement Study of Contextual Leakage in AI Chat Platforms
> Accepted to the IEEE Symposium on Security and Privacy (S&P) 2027 (to be presented May 2027), public version on arXiv cs.CR. Stony Brook University
> 2026

AI chatbot websites embed advertising pixels, analytics, and session replay scripts just like any other site. This paper measures, at scale, whether those third-party scripts carry conversation content away, auditing 42 services: 25 general-purpose chatbots and 17 specialized ones in health, law, and education. Twenty-one services sent conversation titles to third-party trackers and nine sent users' prompts verbatim. Among the 13 general-purpose chatbots that leaked conversational context, 11 also sent the user's email address, letting trackers tie what was discussed to a named account.

Paper: https://arxiv.org/abs/2610.37467

### Contribution
- Goes beyond capturing multi-step sessions with Puppeteer by using VisibleV8, a browser instrumented at the JavaScript engine level, to trace each leak to the user action that triggered it (sending a prompt, navigating, clicking, deleting a chat) and to the DOM access the script used to read it. Network-only studies cannot see this.
- Explains the cause structurally. Chatbots treat each conversation as its own sub-page and set the page title to a summary of the first prompt, so trackers that simply read document.title, as they do everywhere, end up collecting the gist of the conversation. Meta Pixel queries the title element directly, Microsoft Clarity reads text across the whole DOM for session replay and so captures the raw prompt even before a title exists, and You.com puts the prompt in the URL, so Google Ads receives it from the URL alone.
- Is the first to cover specialized chatbots in sensitive domains such as health, law, and education in a systematic way.

### Evaluation
- Measurements ran from May 6 to May 20, 2026, from a single US East vantage point with tracking consent accepted, using two accounts created for the study.
- For general-purpose chatbots, a single prompt triggered 540 outbound requests on average, 22% of them (118) to known tracker domains; 153 distinct tracker domains appeared overall.
- Google received the most context-bearing requests (230 across eight services), followed by Meta (about 55).
- Responsible disclosure: ChatGPT and Grok also ran trackers that collected conversational context during the study, and both were confirmed removed before submission. The remaining services were notified, and TheLawGPT fixed its configuration.
- Reliability of the metrics: grounding every finding in both network traffic and engine-level execution traces makes the results highly credible. With one session per configuration, though, finer points such as leaks appearing more often with Gmail accounts need further measurement, as the authors acknowledge.

#### Comment
- The leak does not come from the model but from an old attack surface, the web front end, which now handles far more sensitive content. Anyone running a chatbot web interface should check whether page titles and URLs contain conversation content and whether session replay tools mask the chat area.
- Limitations: only free-to-register web services are covered, leaving out paid tiers and mobile or desktop apps. A single region with consent accepted means the study does not test whether services honor a refusal.
- This is a paper accepted at a top-tier security venue, and its appendix includes the program committee's meta-review.
