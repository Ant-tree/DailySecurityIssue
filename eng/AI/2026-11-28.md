# LLM Agent Authorization Across Context Compaction
> arXiv preprint (not peer-reviewed). University of Technology Sydney, National University of Singapore, University of New South Wales
> 2026

Request-derived authorizers such as Progent and DRIFT defend against indirect prompt injection by reading the user's request before any tool runs and deciding what the agent may do, down to permitted tools and argument constraints. The defense assumes attribution: whatever sits in the request slot is what the user said. When a conversation nears the context limit, though, the harness compacts it into a model-written summary, and at every automatic compaction the authors observed, Claude Code and Codex inserted that summary as a user message. The summary's quotes of the user, of documents and of injected text then all read as the user speaking, and the authorizer's policy ends up following the summary.

### Contribution
- Shows concretely how compaction turns the authorizer from an independent check into a policy that tracks the summary. In a banking agent, a transfer refused before compaction became exactly one permitted transfer to the attacker's account once the summary recorded it as unfinished work.
- Proves that an authorizer reading text alone cannot tell a forged record from the legitimate one it imitates any better than the two texts themselves differ, and that this bound is tight. For data written like legitimate records, no better summary or text detector can close the gap.
- Designs a witnessed-request gate as the fix. User turns are authenticated on arrival and carried verbatim across compaction, so the agent still reads the summary while the authorizer receives only the user's own words. The authors prove the gate releases exactly that text or nothing, so an attacker can block the policy but cannot shape it.

### Evaluation
- Summary placement: in all 1,108 automatic compactions recorded in Claude Code and Codex, the summary took the request slot. The compaction code of eight other harnesses, including Gemini CLI, OpenHands, Cline, Goose, Aider and Qwen Code, does the same.
- Policy contamination: with the small compactor used in the main runs, injections that Progent blocked before compaction succeeded afterwards about as often as on an undefended agent. Even when the user named the payee, an attacker notice listing another account as plain data led the policy derived from a frontier compactor's summary to admit that account 91% of the time (59% with the other policy generator), while the policy derived from the user's own words never did.
- Cause: frontier compactors flagged injected instructions but rarely flagged an account written as data. Instructions have no legitimate twin, whereas data does, which matches the proven bound.
- Fix: with the gate, no attacker action completed in 40 attacked AgentDojo episodes, and the gate withstood all eight adaptive attacks, including records replayed through files the agent can write. Benign work held up, with 26 tasks completed through the gate against 27 in the uncompacted run. Deriving the policy per request also raised completion of later tasks from 12% to 68%.
- Reliability: measurement spans four AgentDojo suites, ten ASB agents, 18 compaction prompts shipped by 11 harnesses, and live Claude Code and Codex compactions. The gate itself was evaluated on replayed AgentDojo sessions, and integration into a production harness is left as next work. Values the user leaves to a document remain subject to the bound until the document's source is authenticated, and the guarantee assumes keys and counters stay out of the agent's reach.

#### Comment
- Compaction is routine in long-running coding agents, and the point that what a compactor keeps and how it marks it is a security parameter has direct practical weight. Any setup that bases authorization on user messages after compaction is worth checking now.
- This appears to be follow-on work from the same group (University of Technology Sydney, University of New South Wales and others) behind "When Answering Is Administering," published here on 2026-11-26. Both papers trace paths by which text other than the user's own steers an agent's permission policy.
