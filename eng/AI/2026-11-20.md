# ACaM: Automated Capability Modeling for Agentic AI Security
> arXiv preprint (not peer reviewed). IBM Thomas J. Watson Research Center, Pennsylvania State University
> 2026

The tools an LLM agent calls often hold standing access to credentials, private data, file systems and external services, yet existing approaches treat a tool's natural-language description as a stand-in for what it actually does. Nothing guarantees that the two agree, so a tool described as a weather lookup could quietly read a credentials file and send it out every time it is called for its stated purpose. The authors name this threat "capability laundering" and present ACaM, a neurosymbolic analysis that derives each tool's capabilities from its code rather than its description. Facts established by static analysis cannot be overridden by the LLM; the LLM only supplies the behavioral meaning that static facts cannot express. The results are combined into an Agent Capability Property Graph, which is then used to reconstruct threat chains spanning several tool calls.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.23507
- arXiv HTML full text: https://arxiv.org/html/2611.23507
- arXiv PDF: https://arxiv.org/pdf/2611.23507

### Contribution
- Formalizes the pre-deployment question of what an agent can access, exfiltrate and propagate, and models it as a graph that holds both static-analysis facts and semantic judgments.
- Brings the agent-tool boundary into scope, which classical static analysis misses because an LLM orchestrator chooses tools at run time.
- Reconstructs multi-step threat chains that no single tool's code reveals, and confirms findings on real public agents with working exploits.

### Evaluation
- Subjects: 43 real-world agents built with LangChain, LangGraph, CrewAI, DSPy and Google ADK, including 9 multi-agent systems; 24 were manually annotated.
- Results: 98.3% macro-F1 for capability-property recovery. Threat-chain reconstruction scored 0.980, about 8 points above the strongest LLM-only baseline (0.903) and far above every static-analysis-only baseline (0.342 or lower).
- Across all 43 unmodified agents, ACaM surfaced 123 code-execution and credential-exposure paths, each confirmed by hand in the code, plus about 1,800 medium- to high-impact paths confirmed by a separate verification agent. Ten Critical and High findings were turned into working proof-of-concept exploits, six of them arbitrary code execution.
- Reliability: the ten confirmed exploits are strong evidence. The 1,800 paths, however, were checked by an LLM-based verifier, and the chain-reconstruction score is measured on vulnerabilities the authors injected, which may not match real-world distributions. The authors note that the injected vulnerabilities were modeled on disclosed cases.

#### Comment
- Building on recent work about mismatches between MCP tool descriptions and implementations, this paper moves the defense from runtime monitoring to pre-deployment analysis. It also catches flaws such as deserialization-based remote code execution that need no LLM decision at all, which is useful in practice.
- Limitations: Python only for now. No code release address was found in the paper.

# Guarding the Kingdom of Skill-Based Agents in the AI Dynasty of Computation: Control-Flow Integrity for Agent Skills
> arXiv preprint (not peer reviewed). National University of Singapore, Beihang University
> 2026

Agent skills (SKILL.md files) move what used to be program control flow, such as steps, ordering, checks and user approval points, into prose and leave its execution to a model. This allows violations made entirely of operations the skill legitimately needs, such as overwriting a source file before validation, which permission allowlists cannot stop. A model can also slip past a monitor, for example by simply claiming that a check passed. The authors treat this as a control-flow integrity (CFI) problem and present SkillCFI. Its compiler confines LLM interpretation to compile time and derives both the agent's instructions and an executable contract from a single skill; a deterministic runtime enforcer then admits a tool request only when trusted evidence supports it.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.24185
- arXiv HTML full text: https://arxiv.org/html/2611.24185
- arXiv PDF: https://arxiv.org/pdf/2611.24185

### Contribution
- Models how enforceability depends on where a skill step runs (in the model's reasoning, a tool call or a script) and identifies "regime migration", where a model moves a step elsewhere to evade monitoring.
- Builds on classical enforceability results to separate obligations a boundary monitor can enforce, obligations that remain guidance, and obligations that force the skill to be rejected.
- Implements an enforcer for the OpenCode agent that refuses unmediated channels such as inline scripts, so admitted traces follow the contract whatever the model proposes.

### Evaluation
- On eight skills written by the authors, none of the compiled contracts permitted more than its source under 24 source mutations.
- In 770 agent sessions, SkillCFI blocked all 240 violations made only of the skill's own operations before dispatch; an allowlist let all 80 such violations in its sessions take effect. Normal tasks completed almost as often as without enforcement.
- Listing the next legal steps in a refusal raised recovery from 21% to 65%. Checking took about 2% of task time, and a compact command form cut session slowdown from 1.32x to 1.08x.
- None of 53 public skills was accepted as written; the compiler's diagnostics guided seven of them into enforceable contracts.
- Reliability: the main evaluation uses eight self-written skills, which limits generality. The 100% block rate follows from the deterministic enforcer by design, so the real question is how faithfully a contract captures the skill's intent, which the authors say still needs human review.

#### Comment
- The paper stands out for treating skill security with a compiler and reference monitor rather than prompt-level guidance. Its reason for not using a model at runtime, that a monitoring model would read the same poisoned content as the agent, is convincing.
- Limitations: harmful content inside a permitted call sequence, the inside of generated scripts, and concurrent multi-skill sessions are out of scope.
- Because one co-author is at a Chinese institution (Beihang University), we checked further. The corresponding author is at NUS, the public skills used in the evaluation are named with their sources (such as openai/skills), and the only "perfect" numbers are deterministic by design. No code release address was found in the paper.
- Full-text source: arXiv PDF (downloaded on the user's computer).

# AutoPI: Taxonomy-Guided Adaptive Red Teaming for Prompt Injection in LLM Agents
> arXiv preprint (not peer reviewed), code and project page released. University of Southern California
> 2026

The community now agrees that prompt-injection defenses must be tested against adaptive attackers rather than fixed benchmark injections, but most adaptive red teamers simply maximize attack success rate (ASR). ASR shows how often a target breaks, not in how many different ways, so an attacker that reuses a few reliable tricks can still score well. The authors present AutoPI, a black-box, training-free red teamer that uses PIAtlas, a taxonomy of prompt-injection techniques (6 classes, 34 techniques, 132 sub-techniques), both to guide its search and to measure coverage. An attacker LLM writes one injection per sub-technique and reworks the ones that fail using feedback from an LLM judge.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.24313
- arXiv HTML full text: https://arxiv.org/html/2611.24313
- arXiv PDF: https://arxiv.org/pdf/2611.24313
- Project page: https://stevendamianakis.github.io/autopi-site/
- Author code repository: https://github.com/stevendamianakis/autopi

### Contribution
- Proposes reporting technique coverage, the fraction of taxonomy classes, techniques and sub-techniques with at least one successful injection, alongside ASR.
- Drops into existing benchmarks in place of their fixed attack templates without training, and stays current as the taxonomy grows.
- Releases the full generated attack corpus with technique labels, providing diverse material for adversarial training.

### Evaluation
- Benchmarks: AgentDojo (949 scenarios) and IPI Arena. Targets: Qwen3.6-35B (open weights) and Claude Haiku 5.5 (hosted). The generator and judge are fixed to Qwen3.6-35B.
- Baselines: the benchmark's own injection template, PIMiner (strategy library), Climbing the Hill (curriculum RL) and AutoDojo (black-box optimization), compared at equal compute rather than equal attempts.
- Results: against Qwen3.6-35B on AgentDojo, AutoPI found successful injections in all six classes and for more than 90% of techniques, while no baseline exceeded 65%; it solved more than 70% of scenarios. Against Haiku 5.5, the most robust target, it reached 20-50% higher ASR and 25-400% higher class-level coverage than recent state-of-the-art red teamers. With training counted, one attempt costs 0.6 GPU-seconds versus 2.9-14.5 for the others.
- Reliability: equal-compute comparison, public benchmarks and released code and attacks make the work reproducible. The authors note that only two targets were tested, that coverage depends on a single taxonomy, and that technique labels on successful injections were assigned after the fact by an LLM. No target was wrapped in an added defense.

#### Comment
- The concern that red-team output feeds adversarial training, so attacks concentrated on a few techniques produce equally narrow defenses, is shared with PIPETTE below. Read together, the two papers make "the limits of ASR-only evaluation" a clear theme this week.
- Full-text source: arXiv PDF (downloaded on the user's computer). The author repository contains code only, no paper PDF.

# PIPETTE: Prompt Injection Purple-Teaming for Robust LLM Agents
> arXiv preprint (not peer reviewed). University of Waterloo, Zhejiang University, KTH Royal Institute of Technology
> 2026

Model developers harden agents before release by adversarially training them on attacks found during red teaming. The authors show that a high attack success rate during red teaming does not guarantee a more robust agent afterwards: two leading RL-based red-teaming methods, RL-Hammer and PISmith, fall into mode collapse, rediscovering similar strategies whose extra successes add nothing to the trained defense. They present PIPETTE, a purple-teaming framework that pairs a red-teaming stage with a dictionary-learning-based reward for strategy coverage and an on-policy adversarial training stage tailored to agents.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.24362
- arXiv HTML full text: https://arxiv.org/html/2611.24362
- arXiv PDF: https://arxiv.org/pdf/2611.24362

### Contribution
- Shows empirically that maximizing ASR or surface-level text diversity does not prevent strategy-level mode collapse. One method reached higher ASR on Qwen3-4B (68.75% vs. 33.39%) yet produced a less robust agent after training (47.5% vs. 27.5% ASR on unseen attacks).
- Designs a coverage reward that credits new ways of overriding the user's instruction rather than new wordings.
- Pairs it with adversarial training using token-level self-distillation, so the agent ignores injected instructions while still using the surrounding data to finish the user's task.

### Evaluation
- Benchmarks: AgentDojo and ASB, with four agent models including Qwen3-4B. Baselines include red teamers (RL-Hammer, PISmith) and defenses (MELON, DataSentinel).
- Results: under iterative adaptive attacks on AgentDojo, ASR ranged from 0% to 10% across three models, with benign utility close to the undefended policies. In the Qwen3-4B ablation, ASR fell from 46.19% to 1.43% while benign utility rose from 61.86% to 64.95%.
- Cost: no external detector or duplicate execution at inference, making it 1.9-3.1x faster than MELON and 2.7-9.5x faster than DataSentinel.
- Reliability: the adaptive evaluation is bounded (40 task pairs, about 250 attempts each, a 4B attacker), so a larger budget might reach higher ASR. The authors also note that the LLM grader behind the strategy-diversity score was not validated against human labels.

#### Comment
- Where AutoPI stresses coverage on the evaluation side, PIPETTE tackles the same problem on the training side. It runs a single purple-teaming round, so vulnerabilities that appear only in the hardened model are not explored.
- One co-author is at a Chinese institution (Zhejiang University), but the first and corresponding authors are at Waterloo (N. Asokan), the evaluation uses public benchmarks and baselines, and the numbers are not implausibly high and come with ablations.
- Full-text source: arXiv PDF (downloaded on the user's computer).

# Evolution Under Fire: Evolving Agent Safety Harnesses with Adaptive Injection Stressors
> arXiv preprint (not peer reviewed). LMU Munich, Munich Center for Machine Learning (MCML)
> 2026

Tool-using agents receive malicious and legitimate instructions through the same channel, while most defenses are hand-designed and static, so improving them means redesigning them by hand. The authors present Evolution Under Fire, which evolves complete executable safety harnesses (the defensive code wrapped around an agent) from execution evidence, then evolves attacks aimed at the remaining weaknesses of strong harnesses, and feeds those attacks back into the next round of harness evolution. The task model, benchmark, tools and evaluator stay fixed, and a Pareto-scheduled tree search keeps candidates that hurt utility from becoming parents.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.22583
- arXiv HTML full text: https://arxiv.org/html/2611.22583
- arXiv PDF: https://arxiv.org/pdf/2611.22583

### Contribution
- Frames agent defense as a search over complete executable harnesses; a read-only Diagnoser and a code-generating Expander ground each edit in execution traces and search history.
- Designs a utility-constrained Pareto tree search that keeps rejected candidates as counterexamples without letting them propagate.
- On the attack side, uses lineage-based evolution that keeps only attacks that succeed without breaking the benign task, and uses them as feedback for later harness evolution.

### Evaluation
- AgentDyn with GPT-4o-mini: an evolved harness cut attack success from 50.4% to 3.0% and improved both clean and attacked utility over the initial harness. It offered a better security-utility trade-off than reproduced defenses including CaMeL, Progent, DRIFT, MELON, AgentWatcher, ActGuard, ROPE and Spotlighting.
- Agent-SafetyBench with Qwen2.5-7B-Instruct: attack success dropped from 82.6% to 62.0%.
- Transfer: applied without further evolution to Qwen3.5-35B-A3B, attack success fell from 32.1% to 0.9%.
- Reliability: the baselines were reproduced by the authors, so results may depend on those settings. Harnesses are evolved and evaluated on the same benchmark, which risks overfitting, and the gain on Agent-SafetyBench is modest.

#### Comment
- This paper was carried over from an earlier run because its full text could not be obtained then.
- Automating defense design is appealing, but whether the evolved harness ends up in a form people can review will decide how usable it is in practice.
- Full-text source: arXiv PDF (downloaded on the user's computer).

# DetectViT: Test-time Backdoor Detection for Vision Transformers via Inter-Head Attention Discrepancy
> Accepted at NeurIPS 2026, arXiv preprint. South China University of Technology, UC San Diego, South China Normal University
> 2026

Vision Transformers (ViTs) power the visual encoders of most multimodal models, and reliance on third-party pretrained checkpoints exposes them to backdoors. Existing test-time detectors depend on predicted labels or intermediate embeddings, which narrows where they apply and adds cost. The authors find two ways a backdoor trigger "hijacks" multi-head attention: complete hijacking, where heads' attention overlaps abnormally on the same locations, and partial hijacking, where the concentration of attention varies abnormally across heads. DetectViT turns these into an inter-head consistency score and an inter-head entropy variance score. It needs no training data, model outputs or trigger knowledge, and its thresholds come from a small out-of-distribution (OOD) calibration set drawn from any source.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.23770
- arXiv HTML full text: https://arxiv.org/html/2611.23770
- arXiv PDF: https://arxiv.org/pdf/2611.23770
- Author code repository: https://github.com/siquanhuang/DetectViT

### Contribution
- According to the authors, the first systematic characterization of backdoor behavior through differences between attention heads.
- Uses only attention weights already computed during inference, so overhead is negligible and the method works across tasks with different output types, such as classification and captioning.

### Evaluation
- Attacks: BadViT (DeiT-T, Caltech-101), TrojViT (DeiT-S, Tiny ImageNet), BadCLIP (CLIP ViT-B/32, ImageNet-1K) and BadVision (LLaVA-1.5 vision encoder, COCO Caption), with 5% of test data poisoned.
- Baselines: label-space detectors TeCo, Scale-Up and PatchProc, and embedding-space detectors DeDe and BackdoorIDS, measured by TPR, FPR and AUC.
- Results: with only 64-128 calibration samples it beat every baseline, reaching 100% TPR and 0.17% FPR on BadCLIP and 100% TPR with AUC 1.00 on BadViT. The authors report robustness to calibration source and size and to adaptive attacks.
- Reliability: the attacks and baselines are public, and baseline implementations ship in the repository, so the comparison looks fair. A 100% TPR is very high, though, and may depend on attack strength and trigger type (mostly optimized patch triggers).

#### Comment
- As a paper from a Chinese institution, it received extra checks. The arXiv comment states NeurIPS 2026 acceptance, and the author repository contains the detector (detectvit.py), baseline implementations (DeDe, BackdoorIDS) and attack reproduction code (BadVision), about 22,000 lines of Python with a latest commit on 2026-11-19, so the results look reproducible. One co-author is at UC San Diego, and NSFC funding is declared.
- Limitations: the authors say it cannot stop attacks where natural OOD features act as the trigger, and extending it to architectures without a CLS token is future work.
- Full-text source: arXiv PDF (downloaded on the user's computer). The PDF in the author repository is a conference poster and was not used as the full text.

# Intent Contracts: Taking Tools Away from Agents
> arXiv preprint (not peer reviewed), code and run records released. abstract-only summary, full text not read
> 2026

The authors describe intent contracts, an authorization interface for tool-using LLM agents in which the planning model holds no tools at all. At each step the planner submits a short logged contract with a goal, a verbatim quotation of the user and scope fields; code validates it, and a small trusted model checks it against the user's words and writes the tool call itself. They compare this with two reviewers of planner-written commands: one that sees only the user's words and the command, and one that also sees the planner's goal and a checked quotation.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.24025
- arXiv HTML full text: https://arxiv.org/html/2611.24025
- arXiv PDF: https://arxiv.org/pdf/2611.24025
- Author code repository (OpenCode plugin and run records): https://github.com/zwang-devv/intent-contracts

### Contribution
- The authors state that, provided the validation and dispatch code is correct, every executed call is written by the trusted model and the planner's influence is confined to a contract logged beforehand.
- When the planner adds work the user never asked for, contracts completed the user's task in 27 of 30 runs versus 16 of 30 for the intent-visible reviewer, which they attribute to a reviewer only being able to refuse a whole command.

### Evaluation
- According to the abstract, the evaluation used gpt-6.1-terra as planner and GLM-5.3-Flash as the trusted model on three AmPermBench task families.
- The authors report that contracts did not reduce unauthorized actions and were indistinguishable from blind review, and that every state-changing condition hit a wrong target in 40-49% of runs, caused by the planner's choice of objects for ambiguous references. Only one model pair and non-adversarial over-reach were evaluated.
- Since the full text was not read, the datasets, comparison conditions and reliability of the metrics could not be verified.

#### Comment
- Reliability signal: the arXiv comment gives a code and data address. Cloning the repository showed an OpenCode plugin, per-run records behind every table and a script that recomputes the paper's numbers; it held no paper PDF or TeX source.
- The abstract openly reports a negative result (no reduction in unauthorized actions), which is unusual.
- Why the full text was not obtained and what was tried: an extended title search returned only arXiv and unofficial summary sites, and an author-name search found only other SSRN manuscripts by the same authors. The arXiv download cap for this run (10) had been reached.
- Affiliation checked: not found in the repository or search results (affiliation unconfirmed).
