# BlockJack: Cross-Tenant Redirection Fault Attacks on Paged KV Cache Address Translation in LLM Serving
> arXiv preprint (not peer reviewed). Durham University, University of Lübeck, National University of Singapore, Shanghai Jiao Tong University, Southeast University
> 2026

LLM serving frameworks such as vLLM split the KV cache into fixed-size blocks and use block tables, much like OS page tables, to map each request's logical blocks to physical ones. The authors present BlockJack, the first fault attack that targets this mapping itself. Corrupting a single block-table entry, for instance with Rowhammer, redirects one request's KV cache reads to blocks owned by another tenant, without touching model weights, prompts or cached values. This enables both a confidentiality violation (the victim's information shows up in the attacker's response, CD) and an integrity violation (attacker-supplied context steers the victim's answer, RA).

Links:
- arXiv abstract: https://arxiv.org/abs/2611.25945
- arXiv HTML full text: https://arxiv.org/html/2611.25945
- arXiv PDF: https://arxiv.org/pdf/2611.25945

### Contribution
- Where earlier LLM fault attacks targeted the data plane (weights or KV values), this work identifies the address-translation metadata managed by the serving engine as a new attack surface. Unlike sparse weights, a single flipped bit in a block id has an immediate, observable effect.
- Analyzes vLLM's block allocation policy and formalizes when the attacker can predict the target block id (targeted attack) and when the outcome is only probabilistic (untargeted attack).
- Demonstrates physical feasibility with Rowhammer. After responsible disclosure, vLLM and Sonar confirmed the vulnerability, and the authors reviewed and validated the assignment-validation patches.

### Evaluation
- Software fault injection: in vLLM (the primary platform), a single block-id fault exposed victim context on all seven evaluated models from the Qwen, Llama, Gemma and Phi families. Both outcomes were also reproduced in SGLang and Sonar.
- Integrity attack: on a benchmark of 248 medical-advice scenes, up to 41.1% of responses were steered toward less urgent care while still appearing consistent with the victim's question. Five LLM judges were used for scoring.
- Physical Rowhammer: on an Intel Core i5-6400 with a single DDR4-2133 DIMM and CPU-backed vLLM 0.25.0, 20 campaigns with the SWAGE framework (Blacksmith patterns) validated CD in 3 of 10 and RA in 8 of 10. The campaigns took 31.7 hours in total, 6.1 of them spent profiling for bit flips.
- Reliability: the physical experiment used one DDR4 module known to be susceptible, and configurations where the block table lives in GPU memory (GDDR) were only evaluated with software fault injection. Integrity results depend on LLM judges. On the other hand, confirmation and patches from the maintainers are strong external evidence.

#### Comment
- The paper highlights the risk of multi-tenant LLM services sharing hardware. The defense is to validate that a block-table entry actually belongs to the request; the authors note this trades off against performance on the inference path.
- Because two co-authors are at Chinese institutions (Shanghai Jiao Tong University, Southeast University), extra checks were made. The corresponding authors and main experiments are at Durham and Lübeck, the attack is described reproducibly against public code (with vLLM commit hashes), and the vLLM and Sonar maintainers reproduced it independently, so the work appears trustworthy. No address for the attack code was found in the paper.

# ToolPulse: Side-Channel Eavesdropping on Tool-Using LLM Agents
> arXiv preprint (not peer reviewed). The University of Hong Kong, Renmin University of China, The Hong Kong University of Science and Technology (Guangzhou)
> 2026

Earlier cache side-channel attacks on LLMs required the attacker to share the victim's inference hardware or model components, which is unrealistic when commercial models run on vendor servers. The authors observe that in agentic use, inference stays remote but tools run on the user's machine and rely on shared system libraries and executables. They show that an unprivileged co-located attacker can use Flush+Reload to see which tools an agent invokes and when, and build ToolPulse, a framework that reconstructs the agent's tool-execution workflow.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.25470
- arXiv HTML full text: https://arxiv.org/html/2611.25470
- arXiv PDF: https://arxiv.org/pdf/2611.25470

### Contribution
- Identifies tool execution as a practical side-channel attack surface for LLM agents.
- Systematically compares Flush+Reload and Prime+Probe, showing that Prime+Probe, although it works across VMs, suffers from heavy monitoring overhead and cache-set aliasing that rule out real-time recovery.
- Designs a cache-line localization algorithm and a deduplication algorithm to handle multiple cache hits per tool call, plus an offset search algorithm to infer tool arguments.
- Demonstrates a Task Profiling Attack that infers the user's task from recovered traces, and a Trigger Localization Attack that pinpoints sensitive tool calls such as encryption or model inference so that follow-up attacks need less monitoring.

### Evaluation
- Evaluated on 15 tool types across three public-cloud instance types with Intel Xeon Platinum 8369B, 8269CY and 8163 CPUs.
- Tool Recovery Attack: across 11 models in Codex and Claude Code (including five GPT and four Claude variants), the lowest F1 score exceeded 93%.
- Task Profiling: classifiers trained on 4,000 tool-invocation traces from Terminal-Bench 1 and 2 reached 87.77% and 91.39% accuracy. Under noise replayed from a server shared by about 20 users, accuracy dropped by about 4 percentage points.
- Trigger Localization: with 100 tasks and 3,000 traces per case study, even the worst model missed only 7.04% of sensitive invocations in key extraction, while monitoring overhead fell to roughly 20-39% of the original.
- Reliability: the attacker is assumed to be on the same physical server with shared pages, which is a strong assumption. Shared-server noise was reproduced by replaying recorded tool invocations in a controlled environment, and the classifiers were trained and tested on traces the authors collected.

#### Comment
- Because some authors are at Chinese institutions (Renmin University of China, HKUST Guangzhou), extra checks were made. The corresponding author is at the University of Hong Kong. The attack applies the well-understood Flush+Reload technique and is technically sound, and the paper gives concrete hardware models, dataset composition and per-model results. No code address was found in the paper, which limits reproducibility. Nothing suggested inflated metrics or inappropriate baselines.
- Suggested countermeasures are to stop sharing physical pages between mutually distrusting domains (disabling deduplication) and to partition caches with tools such as Intel CAT. The risk is greater on shared development servers than on personal machines.
- Full text source: arXiv PDF (downloaded on the user's computer).

# Living off the Local Model: Abusing Browser-Embedded Language Models for Post-Exploitation
> arXiv preprint (not peer reviewed). Army Cyber Institute, NVIDIA
> 2026

Chrome now downloads Gemini Nano, a 2-4 GB multimodal model, to ordinary desktops and exposes it to web content through the Prompt API. The authors show that such vendor-signed, on-device models become a post-exploitation engine that is already installed. An attacker with ordinary user privileges can launch Chrome and drive the model using only interpreters that ship with the OS, such as PowerShell or Python's standard library. The user-activation check required before the model's first download can be satisfied with a single synthetic click, or bypassed entirely by copying the model files from another profile.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.25086
- arXiv HTML full text: https://arxiv.org/html/2611.25086
- arXiv PDF: https://arxiv.org/pdf/2611.25086

### Contribution
- Sets out a threat model that treats browser-embedded models as living-off-the-land assets. The key point is that there is no API key to revoke, no provider-side abuse monitoring and no network traffic to block.
- Confirms two ways to satisfy or bypass the user-activation gate (synthetic input through the DevTools protocol or at the OS level, and copying the model directory with the Local State file). Google marked the report Won't Fix because it falls outside Chrome's threat model.
- Builds an agent harness that implements tool calling through JSON-schema-constrained output, and has the model complete a multi-step operation without user interaction: reading a password from a sticky note in a webcam photo, unlocking an encrypted archive and picking out the file that holds an SSH private key.
- Summarizes which enterprise policies block the model and which host signals can reveal abuse, such as process lineage, local listeners and model files in unexpected places.

### Evaluation
- Setup: Windows 11 with Chrome 157 and Ubuntu 24.04 on WSL2 with Chrome 156, as a standard non-elevated user with Chrome's sandbox enabled.
- On-host analysis: credential-file triage on CredData reached F1 0.77 against hard negatives with decoys (recall 0.93, precision 0.65) and 0.91 against ordinary library files; detecting personal data in Enron emails reached F1 0.92; Imagenette image classification reached 98.0% accuracy.
- Tool calling: 86% overall accuracy on 840 single-turn items from the Berkeley Function-Calling Leaderboard (75% on items where it should abstain).
- Multi-step operation: given only the goal, the model succeeded in 60% of 20 trials; given a numbered plan and a step checklist, it succeeded in 41 of 50. The authors read this as an unreliable planner but a reliable executor of a supplied plan.
- Reliability: public datasets and official scorers make the capability numbers reproducible, but the multi-step demonstration is a single scenario the authors designed. The authors state that their detection signals have not been validated against real security products.

#### Comment
- A short, workshop-length paper with strong practical implications. A feature-rich harness was flagged by Windows Defender, while a smaller task-specific one was not.
- Only BuiltInAIAPIsEnabled set to false and GenAILocalFoundationalModelSettings set to 1 stop model use altogether; the debugging policies only block this paper's particular access method.
- The authors note that any platform shipping a local model to general-purpose endpoints, such as Edge with Phi, creates the same asset.
- Full text source: arXiv PDF (downloaded on the user's computer).

# SoK: Assessing the Evolution of LLM Capability in Software Vulnerability Research
> arXiv preprint (not peer reviewed). National Institute of Standards and Technology (NIST), Université Grenoble Alpes, University of Maryland, College Park
> 2026

Claims that LLM agents find, validate and fix vulnerabilities in real software are scattered across papers, vendor reports and disclosures, and are hard to compare. The authors propose a framework that rates discovery, vulnerability validation, patching and patch validation on an autonomy scale modeled on the SAE levels of driving automation, and qualifies each claim by correctness, access tier (lab only, partners, public, open weights) and strength of evidence. They use it to systematize the published evidence, then measure what has actually changed in the vulnerability lifecycle using a decade of CVE records, advisories and exploitation data.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.26601
- arXiv HTML full text: https://arxiv.org/html/2611.26601
- arXiv PDF: https://arxiv.org/pdf/2611.26601

### Contribution
- The first framework to rate demonstrated autonomy separately per task, per access tier and over time. A level counts only when most results hold up.
- Finds that agents discovered, validated and patched vulnerabilities in real software without human intervention even before the restricted frontier models of 2026, and that open-weight models later reached comparable autonomy for discovery and validation.
- Shows that disclosed vulnerabilities more than doubled in 2026 and a larger share were rated critical or high, while the time from report to fix and from disclosure to attack has not shifted noticeably so far.
- Grades the mitigations proposed in the literature with an explicit rubric and gives guidance for each group of stakeholders.

### Evaluation
- Evidence collection: an agentic workflow gathered 53,057 unique sources; independent agents searched for relevant evidence and scored it with quotes checked against the source, and two authors reviewed the 128 dated steps across 16 cells.
- Records: 304,028 CVE records since 2018 were analyzed, about 2,600 of which credit an LLM-based system as finder. CVE records in 2026 were 2.3 times those of 2025, and the share rated Critical or High rose from 46% in 2025 to 56% in July-October 2026. Records crediting an AI system made up 2.4-2.8% per quarter of 2026.
- Of reports sent in bulk to outside maintainers, 5-26% were fixed, compared with 58-94% of curated reports.
- Reliability: LLM agents (Claude Sonnet 5.5) collected and first scored the evidence, with quotes checked mechanically and then reviewed by the authors. The authors acknowledge that much of the evidence comes from the organizations that build the systems, and that because few records name the finding tool, the share of the change attributable to LLMs cannot yet be separated out.

#### Comment
- A systematization with NIST researchers that checks the recent "Vulnpocalypse" debate against public records.
- With report volume rising while fix times stay flat, maintainer capacity looks like the coming bottleneck.
- Full text source: arXiv PDF (downloaded on the user's computer).

# UniReFP: Robust Unified Fingerprinting for Vision Models against Cross-Task Repurposing Attacks
> NeurIPS 2026 Spotlight, arXiv preprint. abstract-only summary, full text not read
> 2026

The authors say they are the first to identify the cross-task model repurposing attack, a model modification that makes fingerprints from existing fingerprinting methods inapplicable. In response they propose UniReFP, a unified fingerprinting framework that looks for ownership evidence in a shared class-level semantic space rather than in each task's own output space. It builds a surrogate classifier by repurposing the protected model and optimizes grouped fingerprints so that fingerprints in the same group produce consistent responses on the surrogate but scattered responses on independently trained reference classifiers. At verification time, a task-aware semantic projection maps heterogeneous suspect-model outputs into unified semantic-presence vectors, and ownership is decided by inner-group consistency.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.25555
- arXiv HTML full text: https://arxiv.org/html/2611.25555
- arXiv PDF: https://arxiv.org/pdf/2611.25555

### Contribution
- According to the authors, the first unified fingerprinting framework that verifies ownership even when a model is repurposed to tasks with different output formats.
- They claim that grouped fingerprints and task-aware semantic projection make verification independent of the original task.

### Evaluation
- The abstract gives no figures. The authors only state that UniReFP performed consistently better under cross-task repurposing attacks, commonly studied model modification attacks and their combinations.
- Because the full text was not read, the datasets, comparison conditions and reliability of the metrics could not be checked.

# Measuring Hallucination in Large Language Models for Cyber Threat Intelligence: An Exploratory Study
> Accepted at Computers and Electrical Engineering, arXiv preprint, code released. abstract-only summary, full text not read
> 2026

LLMs are widely used for cyber threat intelligence (CTI) summarization and question answering, but hallucinations not grounded in the source can mislead analysts and corrupt downstream security decisions. The authors describe HalluVision, a reproducible framework that generates LLM outputs, extracts domain entities with a fine-tuned named entity recognition model, and evaluates factual consistency with several similarity metrics.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.25590
- arXiv HTML full text: https://arxiv.org/html/2611.25590
- arXiv PDF: https://arxiv.org/pdf/2611.25590
- Author code repository: https://github.com/SeungHo0422/HalluVision-official
- Author code repository (earlier version): https://github.com/SeungHo0422/HalluVision
- Data (Mendeley Data): https://data.mendeley.com/datasets/z8sfdnch2c/1
- Fine-tuned NER model (Hugging Face): https://huggingface.co/Ricky-dev/halluvision-cyner-xlmr-base

### Contribution
- According to the authors, a reproducible framework for measuring LLM hallucination in CTI, with measurements on real security articles.
- They report that semantic similarity agrees with human judgments while entity-based metrics show limited agreement, and that differences between models concentrate in question answering.

### Evaluation
- Per the abstract, outputs from two commercial LLMs and one open-weight LLM were measured on 4,940 real-world cybersecurity articles and validated against 100 human-annotated outputs and two established faithfulness detectors.
- Per the repository README, the models are gpt-3.5-turbo, gpt-4o-mini and Meta-Llama-3-8B-Instruct, and the articles were collected from Threatpost.
- Because the full text was not read, the datasets, comparison conditions and reliability of the metrics could not be checked.

#### Comment
- Credibility signal: the arXiv comment states acceptance at Computers and Electrical Engineering (Elsevier), and the authors' code and data are public.
- The evaluated models are from an older generation, so it is unclear how well the findings carry over to current models.
- Why the full text was not obtained and what was tried: the extended title search returned only arXiv, the author repositories and the data repository. The repository was cloned but contains only code and a README, with no paper PDF or TeX. This run's arXiv download cap (10) had been reached.
- Affiliations checked: unverified.
