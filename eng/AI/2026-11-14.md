# OverServe: Resource Amplification Attacks on SaaS Agents via Tool--Prompt Co-Design
> arXiv preprint (not peer reviewed). Florida State University, Johns Hopkins University
> 2026

When a subscription SaaS product runs business workflows with LLM agents, the provider pays for every model and tool call even though the customer pays nothing extra. Since the agent decides for itself when to stop, a malicious tenant can stretch its work on purpose and drive up the provider's costs. Earlier resource-consumption attacks manipulated either the prompt or a tool, and were easy to catch with prompt review or tool scanning. OverServe designs an MCP status tool and a completion-confirmation prompt (something like "confirm the sync is complete") as a pair. The tool always returns accurate status and terminates normally, and the prompt reads like an ordinary request, yet when the backend keeps reporting "still pending" the agent keeps checking long after the original task is done. A multi-agent pipeline generates candidate pairs and keeps only those that pass separate code, runtime and prompt reviews.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.14808
- arXiv HTML full text: https://arxiv.org/html/2611.14808
- arXiv PDF: https://arxiv.org/pdf/2611.14808

### Contribution
- Shows that splitting an attack across a tool and a prompt lets each piece pass its own review while the combination causes heavy resource use.
- Confirms with controlled runs that a tool alone or a prompt alone barely changes anything, and that amplification only appears when both are present and the backend keeps changing (with the same Qwen agent: 4 calls normally, 40 calls with the matched prompt, the tool and a pending backend).
- Provides a multi-agent pipeline for generating and selecting attack pairs.

### Evaluation
- Victim agents: Qwen3.8-27B, Nemotron-3-Super, a local DeepSeek-v4-Flash and Sonnet-5 on Bedrock. Tasks were selected from ten benchmarks including MCPMark, EnterpriseOps-Gym, STATE-Bench, AppWorld, WorkBench and Terminal-Bench.
- Across five enterprise workflow benchmarks (20 victim-benchmark entries), the geometric mean amplification was 10.30x (Qwen 19.30x, Nemotron 8.07x, DeepSeek 17.75x, Sonnet 4.07x). The maximum was 93.88x more API requests for Sonnet on AppWorld. All attacked runs are reported to pass the original task checks.
- Against prior attacks (A2M, LoopTrap, Sponge Tool Attack), LoopTrap reached a similar 10x but was caught by both source review and runtime review, while OverServe's tools passed both. Five public MCP scanners flagged none of the 22 OverServe tools; among research detectors, DCI flagged 3 and Connor flagged 1.
- Reliability: as the authors state, these are results on selected tasks, and many amplification figures hit the benchmark's execution cap (for example 200 iterations), so they depend heavily on that cap. The "pending" backend state is also simulated.

#### Comment
- The core trick is getting the agent to keep polling an external state that never settles. A per-task cap on calls or time limits the damage to that cap, but the point is that simply reaching the cap already means tens of times the normal cost.
- A variant that only checks the version seen on the first query lets the agent stop normally (22 calls), which hints at a defense on the tool design side.

# PolicySniff: Inferring Agent Policy States through Shared-GPU Execution
> arXiv preprint (not peer reviewed). Lehigh University, New York University, New York University Abu Dhabi
> 2026

LLM agents apply approval settings such as "ask before a consequential tool call" through their system prompt, and operators keep the chosen setting private by restricting access to prompts and responses. For an attacker this setting is useful: it tells them which deployments act without confirmation and are therefore better prompt-injection targets. This paper shows that a co-resident process on the same GPU can infer the deployed approval policy by timing only its own GPU kernels. The policy text is already cached before measurement starts, and the attacker only observes processing of a task suffix that is identical under both policies. But in a sparse mixture-of-experts (MoE) model the cached policy still affects which experts are selected, and in a runtime that launches each expert separately that difference shows up as execution time. The attacker profiles both candidate policies on the shared GPU and assigns the target trace to the closer one.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.16158
- arXiv HTML full text: https://arxiv.org/html/2611.16158
- arXiv PDF: https://arxiv.org/pdf/2611.16158

### Contribution
- Shows experimentally that following a policy (behavioral compliance) and keeping the deployed policy secret (configuration confidentiality) are separate problems: the policy could be identified even on tasks where both policies lead to the same decision.
- Uses FPGA replays of expert routing to show that the information is carried by the temporal density of expert selection and its alignment across layers.
- Compares policy placement and shows that moving the approval rule to a trusted broker outside the model defeats the evaluated timing classifier.

### Evaluation
- Setup: one A100 GPU, either the whole card or one MIG instance, shared with the attacker; MoE models such as Qwen3-30B-A3B served by a runtime that runs each expert separately; an existing GPU time-slicing measurement technique.
- In a frozen, blinded study the attack identified the deployed policy with 94.17% balanced accuracy; 88.82% on tasks where both policies make the same decision and 91.98% where they differ. In the NF4 campaign it classified 47 of 48 groups correctly.
- Moving the policy to an external broker dropped accuracy from 95.83% to 41.67%.
- Defense measurements: a timing process on a sibling MIG instance saw no activity, and the fused MoE kernels of vLLM 0.30.0 issued the same kernel-launch signature in all 360 decode steps. That profile covers decoding, while the attack observes prefill.
- Reliability: the study was frozen in advance and reports cluster-bootstrap confidence intervals, which is rigorous. The assumptions are strong, though: the attacker knows the candidate policy implementations, builds references on the exact task beforehand, and knows request order and grouping.

#### Comment
- Measurement is invasive: continuous probing raised the victim's median latency by 4.71x, which a real service could notice.
- The attack needs both a shared GPU instance and a runtime that runs experts separately, so the risk is limited in typical serving setups with MIG isolation or fused kernels. The result is better read as support for a design rule: if a setting must stay secret, enforce it outside the model.

# Chatter Attack: Resource Consumption Attack for Large Language Models
> Accepted at NeurIPS 2026 as a poster (peer reviewed). arXiv version. Tsinghua University, Academy of Mathematics and Systems Science (Chinese Academy of Sciences), Shanghai Qi Zhi Institute
> 2026

A resource-consumption attack that makes reasoning models produce extremely long answers, raising inference cost and latency. Earlier methods forced repetition or lowered the probability of the end-of-sequence token, but the search space grows exponentially with output length and a single off-track token during sampling can undo the attack. Chatter Attack instead optimizes an adversarial prefix so that the output opens with a short self-doubt phrase along the lines of "wait, let me reconsider". The target is short, so optimization stays stable, and once the model starts doubting itself it keeps re-checking and the output grows. To keep the model in that state, the authors add a loss that makes key reasoning tokens such as "wait" attend more to the injected prefix, and a loss that raises the entropy of each next-token distribution. In white-box settings the prefix is optimized with GCG; for black-box settings they propose Bayesian Prompt Optimization (BPO), which uses a kernel designed for discrete tokens.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.11261
- arXiv HTML full text: https://arxiv.org/html/2611.11261
- arXiv PDF: https://arxiv.org/pdf/2611.11261
- NeurIPS 2026 poster page: https://neurips.cc/virtual/2026/loc/sydney/poster/150065

### Contribution
- Avoids the search-space explosion by targeting a short doubt phrase that leads to long output, rather than targeting long output directly.
- Proposes a black-box optimizer (BPO) aimed at commercial APIs where gradients are unavailable.
- Shows on a simulated vLLM service that operational defenses (output-length limits, per-user rate limits, IP blocking, loop detection, excessive-reasoning monitoring) do not bring service metrics back to normal.

### Evaluation
- Datasets: GSM8K, MathQA, MATH-500, HumanEval (100 questions each) and MMLU-Pro (10 questions from each of 12 non-math categories). Models: DeepSeek-R1-Distill-Qwen-7B, QwQ-32B, gpt-oss-20b.
- Baselines: CoT prompting, CatAttack, four OverThink variants, the DoS prompt attack, Engorgio, Excessive Reasoning Attack, and three baselines the authors built themselves.
- On R1-7B with GSM8K, average output grew from 423.5 to 13,345.8 tokens (about 31.5x). The increase is much smaller on the other models: 991.4 to 3,298.4 tokens on QwQ-32B (about 3.3x) and 253.0 to 1,980.3 on gpt-oss-20b.
- Accuracy also collapses. R1-7B on MATH-500 drops from 92.5% to 16.4%, so the answers get worse as well as longer.
- In the simulated service, an output-token limit helps a lot, but the number of running requests stays about three times the benign level (6.2 versus 2.2), and IP blocking does little once the attacker rotates addresses.
- Reliability: standard deviations are reported and there are many baselines. The headline "up to 31.5x" comes from the smallest model on one dataset, so it overstates the typical effect.

#### Comment
- Because the authors are at Chinese institutions, we checked further. The venue is NeurIPS 2026: the footnote in the paper matches the official NeurIPS poster page. Corresponding authors Xiao-Shan Gao (Chinese Academy of Sciences) and Yinpeng Dong (Tsinghua University) are real researchers at those institutions with a track record in adversarial attacks. We found no code link in the paper, so reproducibility could not be confirmed. The metrics come with standard deviations and many baselines, but as noted above the headline number comes from the most favorable setting.
- Given the drop in accuracy, users would probably notice answers that are oddly long and wrong. The provider's cost, however, is incurred either way.
- This paper had been carried over from 2026-11-11 and was written up now that the full text was available.
