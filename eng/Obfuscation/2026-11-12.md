# RoCoMark: Robust Code Watermarking Against LLM-Based Functionality-Preserving Rewriting Attacks
> arXiv preprint (not peer reviewed, v2). Sichuan Normal University, Shanghai University, Jinan University (China)
> 2026

Source-code watermarks are meant to establish where generated code came from and who owns it, but modern LLMs can rewrite variables, expressions, control flow and loops while keeping behavior intact, and that strips the watermark. This is the same family of semantics-preserving transformation attacks as obfuscation. The authors argue that existing methods such as SrcMarker and RoSeMary fail less because the rewrites are strong than because they come from a different distribution than the perturbations seen during training. RoCoMark therefore trains through a multi-round minimax game between the watermark embedder and an LLM rewriter. In each round the encoder adapts to LLM-rewritten code using contrastive learning and knowledge distillation (threat profiling), the encoder and extractor are optimized together, and the rewriting attacks evolve using Reflexion with short- and long-term memory pools.

### Contribution
- A diagnosis of watermark failure under LLM rewriting as a training-distribution mismatch, and an adversarial training framework that brings the attacker into training and evolves it alongside the defender.
- Encoder adaptation that pulls embeddings of original and rewritten code together while using contrastive learning and distillation to limit representation drift.
- A post-processing, multi-bit design that keeps functionality almost intact and lets the owner recover an embedded message.

### Evaluation
- Data: trained on 25,000 Python functions from CodeSearchNet and evaluated on HumanEval (164), MBPP (974), EvalPlus (542) and a 5,000-sample APPS subset.
- Baselines: SWEET (inference-time watermarking), SrcMarker and RoSeMary, with the three post-processing methods retrained on the same data.
- Attacks: rewrites by GPT-5.5, DeepSeek-V4-Flash, MiMo-V2.5-Pro, GLM-5 and Claude Sonnet 4.5 using four prompts of increasing strength; only rewrites that pass syntax, interface and functional tests are scored.
- Results: across the five attacks, average AUROC 74.2%, bit accuracy 75.3%, and a functional pass rate above 99.7%. Under the MiMo attack, AUROC 0.7408, TPR 0.4638 and FPR 0.0463, slightly ahead of RoSeMary (0.7182, 0.4062) and SrcMarker (0.6948, 0.3617). It kept the highest AUROC as the share of renamed variables rose to 50%.
- Reliability: the baselines are the standard public methods and were retrained on the same data, so the comparison is reasonably fair. However, training used a large number of MiMo-V2.5-Pro rewrites and the same model is also one of the test attackers, so results on that attack do not show generalization to unseen attackers. The gains are only 2 to 3 points, and with TPR around 0.46 more than half of rewritten code still goes undetected. Only Python was evaluated.

#### Comment
- Because the institutions are Chinese, we checked further. The corresponding authors Hanzhou Wu and Xinpeng Zhang (Shanghai University) have long, verifiable records in information hiding and watermarking, and the affiliations are real universities. The numbers are modest rather than inflated (AUROC 74%), and the baselines are appropriate. On the other hand, the code repository named in the paper could not be found on GitHub at the time of this run (the authors only say they "will release" it), and there is no venue yet, so the work cannot be reproduced for now. We included it with that caveat.
- Read the paper less as a solved problem and more as evidence that code watermarks are fragile against semantics-preserving LLM rewrites, with the best defense still catching only about half.
