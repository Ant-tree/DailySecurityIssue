# obfsgen: Generative Tunnel Obfuscation
> arXiv preprint (not peer reviewed). The Chinese University of Hong Kong, The University of Hong Kong
> 2026

Now that the most widely used circumvention tunnels (Trojan, VLESS, NaiveProxy and others) run over TLS, censors have moved from inspecting packet contents to inspecting traffic shape: packet sizes, timing and direction. Traffic-shaping obfuscators such as obfs4 pad, split or delay each write from the application (an application-driven design), so they can only add to the shape the application creates and cannot send anything while the application is idle. That makes some fingerprints, such as the extra round trip a tunnel introduces, impossible to hide. obfsgen is a schedule-driven obfuscator that decides when and how much to send independently of the application. It samples its schedule from a generative sequence model trained on normal TLS traffic, which predicts the size and timing of the next TLS record from the flow's entire history. The paper also deals with practical issues such as keeping both endpoints in sync over a lossy, noisy network, where each side samples the same plan from the same model.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.15019
- arXiv HTML full text: https://arxiv.org/html/2611.15019
- arXiv PDF: https://arxiv.org/pdf/2611.15019

### Contribution
- Explains structurally why application-driven obfuscation cannot fully hide tunnel fingerprints, and proposes the schedule-driven architecture instead.
- Generates schedules with a model that captures long-range dependencies in normal traffic, and validates the flow's negative log-likelihood as a proxy for distinguishability.
- Implements and releases a Go prototype (the repository is described in an appendix) and addresses deployment issues such as synchronization and real-time operation.

### Evaluation
- Data: normal TLS traffic collected at the authors' campus gateway. Tunnel baselines: nine configurations of Trojan, VLESS and VMess over TLS, WebSocket/TLS and REALITY (4,445 flows each).
- Six classifiers (a histogram likelihood ratio, a random forest on hand-crafted features, Markov chains, and CNN, GRU and Transformer models) were tested under three censor models.
- Blocklisting censor: existing tunnels are separated perfectly (AUC 1.000), while obfsgen flows reach a best AUC of only 0.561-0.581, close to random guessing.
- Allowlisting censor: 0.965 for existing tunnels, 0.605-0.642 for obfsgen.
- White-box censor holding the deployed model weights: AUC rises to 0.764-0.838, so obfsgen is moderately distinguishable.
- Performance: goodput for a single flow is roughly 0.8-4.2 kB/s depending on RTT, about a third of what the application writes. More concurrent flows help but raise inference cost.
- Reliability: the authors state plainly that resisting particular classifiers does not prove resistance to untested ones, and they compare against replays of real normal flows carrying the same writes, which separates network effects from model effects. The normal traffic comes from one campus, and the authors note the model should be trained on the network where it is deployed.

#### Comment
- Obfuscation here means hiding the shape of network traffic, not code. Still, using a generative model to produce "normal-looking" output raises the same questions as code obfuscation that imitates the distribution of normal code: allowlist-style detection, and what happens if the model leaks.
- Throughput is the main practical obstacle. A few kB/s per flow suits messaging or light traffic more than web browsing, and the authors present this as a first step.
- Because the authors are at Chinese institutions (universities in Hong Kong), we checked further. Author Diwen Xue has a consistent publication record in censorship measurement and circumvention, the code release is stated, and the paper reports unfavorable numbers such as the white-box censor result, with no sign of inflated metrics. It is still a preprint.

# Preserve the Vulnerability, Break the Alert: Testing the Robustness of CodeQL Taint Tracking with Natural Rewrites
> arXiv preprint (not peer reviewed). North Carolina State University
> 2026

Static analysis tools such as CodeQL act as security gates in CI and code review, and developers often take a disappearing alert to mean the vulnerability is gone. This paper measures how easily an ordinary-looking refactoring that keeps the vulnerability can make the alert vanish. A large language model (Claude Opus 4.7) is given only the alert information CodeQL exposes and asked to rewrite one function on the reported flow as a plausible maintenance change. For example, a shell command built by string concatenation can be rebuilt from an array with join(' | '); the runtime string is identical, but CodeQL only models join with a single-space separator, so taint tracking stops there. Each case was checked by manual audit and controlled experiments to confirm that the flaw survived and only the alert disappeared.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.17123
- arXiv HTML full text: https://arxiv.org/html/2611.17123
- arXiv PDF: https://arxiv.org/pdf/2611.17123
- Replication package (flows, rewrites, tool outputs): https://figshare.com/s/63962213d3744750c45d

### Contribution
- Frames robustness to natural, vulnerability-preserving rewrites as a metamorphic relation and builds a pipeline that verifies both the lost alert and the preserved vulnerability.
- Traces all 70 alert-silencing rewrites to seven library-modeling gaps; 64 of them sit inside APIs CodeQL already models. The largest is the WHATWG URL constructor, which propagates taint to the query components but not to the pathname, and accounts for 43 cases on its own. These gaps are still present in the current CodeQL release.
- Applies the same rewrites to other analyzers to show the problem is not specific to CodeQL.

### Evaluation
- Data: 172 flows that CodeQL detects in real npm advisories (path traversal CWE-22/23, command injection CWE-77/78, XSS CWE-79) and 514 valid rewrite attempts. Most cases are path traversal; command injection under CWE-77 (11) and XSS (7) are small, and the authors treat those rates as indicative only.
- Three attempts per flow silenced 26.2% of the flows, at about $0.51 of model cost per silenced flow.
- When the same model was asked to refactor the same functions without seeing the alert, none of the alerts disappeared. Ordinary language-level changes such as intermediate variables or destructuring almost never mattered.
- Transfer: 74% of the silencing rewrites within ODGen's scope also silenced ODGen, and 53% of those in the common scope escaped CodeQL, ODGen and njsscan together. Rates come with 95% Wilson confidence intervals.
- Reliability: every silencing case was checked by hand and the replication package is public. Using a single generator model and a sample concentrated in a few CWEs are limitations.

#### Comment
- This is not obfuscation in the strict sense, but it addresses the same problem: behavior-preserving code transformations that evade analysis tools. The striking part is that changes far more ordinary than deliberate evasion-oriented obfuscation are enough to get past a widely used static analyzer.
- The practical lesson is clear. If an automated fixer or LLM-assisted fix treats "clean re-scan" as success, it may mistake a change that merely crossed the analyzer's modeling boundary for a real fix.
