# PULSAR-V: I/O-Aware Post-Update Attestation for RISC-V
> arXiv preprint (not peer reviewed), anonymous artifact released. Politecnico di Torino
> 2026

Post-update attestation proves that a device installed the intended firmware, but not that the image stayed protected until the report was signed, because the image digest is recorded at the commit and merely reported later. In a multi-master SoC, a DMA device outside the CPU can bypass the CPU's PMP checks and modify the committed image while the firmware identity, lifecycle state and locked PMP configuration remain byte-identical to a healthy device's. The authors present PULSAR-V, an attestation architecture that binds the update commit to the effective permissions and immutability of both gates, PMP/ePMP on the CPU and the I/O policy that mediates DMA. Both are sampled at commit and at attestation, and the I/O gate latches its own commit-time state in hardware.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.24135
- arXiv HTML full text: https://arxiv.org/html/2611.24135
- arXiv PDF: https://arxiv.org/pdf/2611.24135
- Author artifact (anonymized): https://anonymous.4open.science/r/PULSAR-V-DATE

### Contribution
- Describes an attack in which a DMA master corrupts a committed image while every conventional attestation claim stays true, along with five conditions for it to apply, checked against vendor documentation.
- Gives an evidence composition that is necessary and sufficient to show the image was not exposed between commit and attestation, plus a hardware mechanism that uses the attested policy to decide when re-hashing is required.

### Evaluation
- Prototype: a RISC-V SoC on a Xilinx ZCU102 FPGA (CV32E40S core with 16 PMP regions, an IOPMP-style unit and an AXI write guard).
- Results: a 256-byte write from the board's Arm DMA engine bypassed PMP and corrupted the image; every conventional claim still held, but PULSAR-V rejected the device on its I/O-policy evidence alone. It also rejected an intact device whose policy left the image writable, a verdict no integrity check can reach.
- Cost: 436 LUTs (4.6% of the SoC) for the gate and commit latch, and a constant 43,100 cycles for evidence collection regardless of image size, 41x less than re-hashing 16 KiB.
- Reliability: reproducing the attack with a real DMA engine on real FPGA hardware is convincing. IOPMP is still an unratified specification, however, and the evaluation covers a single prototype.

#### Comment
- Low-end IoT devices commonly let the radio chip write memory over DMA, and radio firmware has been compromised remotely before (Project Zero's Broadcom attack), so the threat model is realistic.
- The artifact name suggests a submission to the DATE conference.

# JITAtlas: Checking Lifetime and Protection Obligations in Compiler Rewrites
> arXiv preprint (not peer reviewed, ACM TOSEM template). Utah State University
> 2026

A compiler rewrite can preserve the returned value while violating object lifetime or ownership. In one CPython attribute rewrite, the original code takes ownership of a borrowed pointer before releasing the receiver; the rewritten code reverses the order, so a finalizer triggered by the release can replace the attribute and free the original object, and ownership is then taken through a stale pointer. Reference counts still balance at the end, yet a use-after-free has occurred. The authors present JITAtlas, a source-level checker that reconstructs the reference and rewritten computations from optimizer code and checks valid uses, continuous support for borrowed pointers, and caller-visible ownership.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.23715
- arXiv HTML full text: https://arxiv.org/html/2611.23715
- arXiv PDF: https://arxiv.org/pdf/2611.23715

### Contribution
- Defines a lifetime-preservation property for compiler rewrites that separates valid uses, continuous borrow support, and caller-visible ownership and effects.
- Derives caller obligations from the reference computation instead of trusting facts proposed by the optimizer.
- The authors say they release the implementation, reproduction scripts and PyJITBench, a package of the controlled inputs and experiment records.

### Evaluation
- Controlled benchmark (58 inputs, built and labeled independently of JITAtlas output): all 29 defects detected with no reports on the 29 safe inputs; PyRefcon detected 20 and CpyChecker 18.
- Real CPython (3.14.8, 3.15.0 and a 3.16 development snapshot): 3,332 rewrite alternatives extracted, 801 retained, 194 violations reported, 92 confirmed by manual review for 47.42% precision. Analysis takes 35.56-42.31 s per snapshot.
- Found 15 new bugs across five failure classes, each with a reproducible proof of concept.
- Reliability: the authors acknowledge that the controlled benchmark, though labeled independently, was later used during implementation. Recall on real code was not measured, precision is below 50%, and CPython is the only production target.

#### Comment
- The work shows that optimizations which remove or reorder reference-count operations for speed, as in CPython's new Tier-2 JIT optimizer, can become a new source of memory-safety bugs. It is a meaningful contribution to JIT security for managed runtimes.

# LLM-Guided Cyber-Physical Attack Path Identification in Smart Grids
> Accepted at IEEE IECON 2026, arXiv preprint. abstract-only summary, full text not read
> 2026

The authors explain that existing ways of finding high-impact attack paths in power grids rely either on topology analysis, which lacks adversarial reasoning, or on cascading-failure simulation, which suits offline analysis but cannot quickly evaluate evolving attack scenarios. They propose a framework that combines system topology with LLM-guided STRIDE and MITRE ATT&CK threat modeling to identify cyber-physical attack paths, using impact rankings from cascading-failure analysis as physics-grounded references.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.24765
- arXiv HTML full text: https://arxiv.org/html/2611.24765
- arXiv PDF: https://arxiv.org/pdf/2611.24765

### Contribution
- The authors say they provide a physics-grounded evaluation that compares three baseline strategies: topology-driven, threat-driven and fusion-based.

### Evaluation
- According to the abstract, evaluation covers overlap between LLM-inferred top-K critical nodes and cascading-failure ground truth, node-level similarity and path-level alignment.
- In the cyber layer, critical-node overlap@3 rose from about 33% to as high as 100%, node-level similarity reached up to 65% and path-level alignment up to 48%. Runtime was about 75-85% lower than the fusion-based baseline on the IEEE 14-bus system.
- Since the full text was not read, the datasets, comparison conditions and reliability of the metrics could not be verified.

#### Comment
- Reliability signal: the arXiv comment states acceptance at IEEE IECON 2026, the peer-reviewed annual conference of the IEEE Industrial Electronics Society.
- The "up to" figures appear to be best-case settings, and the IEEE 14-bus system is a small standard test case, so generalization to large grids needs separate confirmation.
