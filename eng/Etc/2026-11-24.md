# Exploring Early Vulnerability Analysis via Automatic Identification of Vulnerability-Introducing Commits
> Accepted at ACSAC 2026 (42nd Annual Computer Security Applications Conference), also on arXiv. The University of Texas at Dallas, Palo Alto Networks
> 2026

Vulnerability datasets usually label only the code right before a vulnerability-fixing commit (VFC) as vulnerable. That leaves out the intermediate versions between the moment a vulnerability was introduced and the fix, and leaves open whether detectors can catch vulnerabilities while they are still latent. The authors build three manually annotated datasets of vulnerability-introducing commits (VICs) and propose D-SZZ, which recovers the semantics implied by a fix through security-fix patterns and data-state analysis to locate the VIC. Using it, they found 16 errors in NVD affected-version records, all of which were officially corrected.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.26739
- arXiv HTML full text: https://arxiv.org/html/2611.26739
- arXiv PDF: https://arxiv.org/pdf/2611.26739
- ACSAC 2026 accepted papers list: https://www.acsac.org/2026/program/papers/
- Author repository (implementation): https://github.com/XSecLab-UTD/D-SZZ

### Contribution
- Earlier SZZ variants trace back only the deleted lines of a fix, so they cannot handle fixes that only add code, such as a new security check. D-SZZ builds code property graphs (CPGs) before and after the fix, isolates fix-related statements with security-fix patterns, uses data and control flow to find the pre-fix data states causally tied to the fix, and walks the repository history back from there.
- Releases 783 manually annotated C/C++ VICs drawn from recent NVD records, tcpdump and Vim.
- Shows that adding early-stage vulnerability samples to training improves detectors.

### Evaluation
- Baselines: SZZ, V-SZZ, Sem-SZZ, LLM4SZZ, Vercation and LLMBisect, run from their original artifacts.
- Results: recall beat the best baseline, V-SZZ, by 13.64%, 8.91%, 10.40% and 6.63% on the three datasets and an external Linux dataset, and F1 by 6.70% to 11.93%. For affected-version identification, F1 reached 94.42% and 94.74% on two open-source datasets.
- Detectors: Devign, Reveal, LineVul, VulBERTa, CodeBERT and PDBERT trained only on pre-fix code struggled with vulnerabilities in their original form, and adding early-stage samples improved detection of both forms.
- Cost: 5,993 NVD VFCs yielded 5,107 VICs in 23.7 hours (14.24 seconds per VFC), while LLM-based baselines used 70K to 727K tokens per VFC.
- Reliability: baselines ran from original artifacts, and the external dataset and NVD's official corrections serve as outside checks. On the new NVD dataset, though, precision is 28.78% and F1 is 41.24%, so automatically extracted VICs are still noisy as training data.

#### Comment
- A peer-reviewed ACSAC 2026 paper. It challenges how vulnerability detection datasets are built and is directly useful for supply-chain work where affected versions matter (SBOM, SCA).

# "More Than You Expect!": Leakage-Abuse Attacks on Encrypted Vector Search
> arXiv preprint (not peer reviewed). Nankai University
> 2026

Vector databases power semantic search and RAG, and embeddings, queries and record labels can carry sensitive information, which has led to encrypted vector search schemes. Many of them, for efficiency, do not hide which records each query returns (the access pattern). The authors define semantic neighborhood leakage, in which co-retrieval relationships alone reveal the semantic categories of encrypted records and queries, and present SAGE, a passive leakage-abuse attack that exploits it. SAGE builds a weighted co-retrieval graph and infers labels in two variants: SAGE-Dist, which knows only class proportions, and SAGE-Known, which knows a few record labels.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27174
- arXiv HTML full text: https://arxiv.org/html/2611.27174
- arXiv PDF: https://arxiv.org/pdf/2611.27174

### Contribution
- Points out that existing leakage-abuse attacks depend on one-dimensional ordering or keyword frequencies and do not carry over to high-dimensional top-k search, which has no global order, and sets semantic-category inference as a new goal.
- SAGE-Dist matches spectral groups to estimated class proportions and refines them with optimal transport; SAGE-Known combines graph label propagation with anchor voting.
- Shows that leakage persists with a real open-source encrypted vector database (Quiver) using distance-comparison-preserving encryption (DCPE).

### Evaluation
- Data: AG News (4 categories), Yahoo Answers (10), MedMCQA (21) and CIFAR-100 (100), with BGE-base-en-v1.5 text embeddings and OpenCLIP ViT-B/32 image embeddings, observing 2,000 queries at k=100.
- Results: with 1% of record labels known, SAGE-Known reached up to 84.3% record-label accuracy and beat the strongest baseline on all four datasets. SAGE-Dist reached 66.9% record and 68.1% query-category accuracy on AG News, 21.8 and 41.9 points above baselines, but varied widely across datasets.
- Real system: with Quiver's DCPE (β=1.6), retrieval recall dropped to 68.8% to 76.9%, yet SAGE-Known held at 84.2%, 64.7%, 46.9% and 27.1%. SAGE-Dist fell to 61.7%, 32.8%, 5.4% and 1.9%, nearly useless on datasets with many categories.
- Reliability: public datasets and implementations, means over ten runs, and weak results (SAGE-Dist on MedMCQA and CIFAR-100) are reported openly. Queries are sampled uniformly and independently of the database, so results may differ under real query distributions.

#### Comment
- For anyone designing encrypted RAG or privacy-preserving vector search, the lesson is that encrypting embeddings alone is not enough; the cost of hiding access patterns has to be weighed against this leakage.
- Because this paper comes from a Chinese institution (Nankai University), it was checked more closely. The references show the same group published an inference attack on encrypted SQL at IEEE S&P 2026, and author contacts use the institutional domain. Quiver and DCPE are external public implementations, which gives a path to reproduction, but no author code link was found in the paper. The numbers are not inflated and weak results are reported, so it was included.
- Full text source: arXiv PDF (downloaded on the user's computer).

# Felid: A Flexible and Efficient Design for Transformer Fine-Tuning over Encrypted Data
> Marked as a NeurIPS 2026 oral, arXiv preprint. abstract-only summary, full text not read
> 2026

According to the authors, fully homomorphic encryption (FHE) allows transformer fine-tuning without exposing sensitive data, but the cost of ciphertext operations limits what architectural tweaks can achieve. They say they attack the bottleneck at the level of ciphertext operations, with a packing scheme that batches a flexible number of inputs, operation-specific matrix algorithms that cut rotations, relinearizations and bootstrapping, and functional bootstrapping that folds element-wise activation functions into the bootstrapping step.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.27175
- arXiv HTML full text: https://arxiv.org/html/2611.27175
- arXiv PDF: https://arxiv.org/pdf/2611.27175

### Contribution
- The authors describe a packing scheme whose batch size can be adjusted to suit fine-tuning workloads.
- They report dedicated algorithms for each matrix operation that reduce ciphertext rotations, relinearizations and bootstrapping calls.
- They claim that folding activation functions into functional bootstrapping lowers the overall computation.

### Evaluation
- Figures stated in the abstract: a 30x reduction in ciphertext rotations and relinearizations across all matrix operations and a 2.5x reduction in bootstrapping over the whole computation compared with the latest state of the art, and fine-tuning a two-layer BERT-style model with batch size 16 in 650 seconds, an 8x speedup.
- Since the full text was not read, the datasets, comparison conditions and reliability of the metrics could not be verified.
