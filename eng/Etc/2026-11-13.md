# Lessons Not Learned: Why Cross-Chain Bridges Keep Losing Billions the Same Way
> arXiv preprint (not peer reviewed). Monad Foundation
> 2026

Cross-chain bridge hacks have cost billions, and many of them involved no code bug at all but failures of security posture, which the authors define as how a bridge's people, code, controls, and off-chain infrastructure are set up. Cataloguing 72 bridge incidents from 2021 to July 2026 ($3.52B in reported gross losses), they find that posture failures account for 88% of losses since 2023 and that nearly all repeat earlier failures. The April 2026 KelpDAO incident is a typical case: the code had been audited repeatedly, yet one deployment configured to trust a single verifier network lost $292M. Since code audits cannot catch such failures, the authors propose an assessment rubric that scores each deployment from on-chain evidence and drops the score to the minimum when a fatal risk is present.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.12252
- arXiv HTML full text: https://arxiv.org/html/2611.12252
- arXiv PDF: https://arxiv.org/pdf/2611.12252

### Contribution
- A catalogue of 72 bridge incidents classified by cause (posture versus code defects).
- A rubric principle that a token deployed on several chains with one shared backing scores as its weakest deployment that can mint it or release its backing.
- A demonstration that rate limits and an emergency stop bound the loss even from unanticipated attacks, as long as the attacker cannot remove them.
- An analyzer that applies the rubric and monitors bridges for changes, and an LLM-based agentic analyzer that runs the same checks on any bridge.

### Evaluation
- The rubric is reported to flag all 29 posture failures.
- A counterfactual model that replays each hack as if the rubric's controls had been in place estimates that losses would have fallen 105-fold, from $3.52B to $33M.
- Reliability: the 105-fold reduction is an estimate from a retrospective model, not a measurement, and the paper states that thresholds such as 48 hours or 5% for rate limits are the authors' judgment. Economic attacks and abuse of issuer powers are outside the rubric.

#### Comment
- An industry manuscript from a blockchain foundation; the incident catalogue and rubric are immediately usable in practice. Because the authors' foundation may have its own interests, assessments of specific bridges deserve independent checking.
- The message that posture failures (key management, single-verifier configurations, concentrated upgrade powers) outweigh code bugs carries over to supply-chain security in other fields.

# DeepChronos: Temporal Neuro-Symbolic Reasoning for Multi-Step Attack Detection
> arXiv preprint (not peer reviewed). Delft University of Technology (Netherlands) and University of Turku (Finland)
> 2026

Modern attacks unfold in multiple temporally and causally related steps, such as reconnaissance, initial access, privilege escalation, lateral movement, and exfiltration. Current defenses mostly detect first and correlate later: intrusion detection systems classify events one by one, and downstream systems reconstruct the attack from the resulting alerts. Learning-based detectors pick up dependencies between steps only as statistical regularities, so nothing guarantees that their predictions follow the real attack progression. This paper presents DeepChronos, a neuro-symbolic network intrusion detection system in which a neural network supplies flow-level evidence while attack-phase rules, temporal prerequisites, and previously inferred phases, written in probabilistic logic programming, jointly constrain every detection decision.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.12760
- arXiv HTML full text: https://arxiv.org/html/2611.12760
- arXiv PDF: https://arxiv.org/pdf/2611.12760

### Contribution
- Shifts to detection through logical progression, so that attack history directly shapes the classification of the current flow.
- Reasons jointly over neural outputs, temporal constraints (for example, exfiltration only after compromise has been observed), and port- and protocol-based phase rules.
- Reports temporal consistency metrics that count causal violations (predicting a later phase without the earlier one) and regression violations.

### Evaluation
- Datasets: DARPA 2000 and AIT-LDS V2. Packet captures were converted to Zeek flows and split 70/30 with stratified random sampling.
- Baselines: a multiclass LSTM, an ensemble LSTM, rule-only symbolic baselines, and Kitsune.
- On AIT-LDS V2, the model with both temporal constraints and phase rules reached a macro F1 of 0.944, above the multiclass LSTM (0.880), and eliminated the causal violations seen in the neural baselines.
- On DARPA 2000, Kitsune had the highest macro F1 (0.984) but a false alarm rate of 0.037, far above the end-to-end DeepChronos model (F1 0.940, false alarm rate 0.00015).
- Reliability: the datasets are old (DARPA 2000) or limited in size, and the stratified random split, rather than a time-ordered one, may place earlier and later parts of the same attack in both training and test sets. The rules were written with knowledge of the ground-truth attack progressions, so generalization to unknown attacks in real networks needs separate validation.

#### Comment
- Guaranteeing that detections never contradict the attack order, and explaining them, is valuable for security operations centers.
- The authors acknowledge that strict temporal constraints can hurt detection when attackers skip, repeat, or reorder phases.
- Whether the code is released could not be confirmed from the paper.

# MammothDP: Private Boosted Decision Trees Ready for Trusted Hardware and Leakage-free Hyperparameters
> arXiv preprint (not peer reviewed). University of Lübeck (Germany) and ETH Zurich (Switzerland)
> 2026

The European Health Data Space (EHDS) regulation requires that sensitive data be processed inside a secure processing environment and released only in anonymized form. Combining trusted execution environments (TEEs) with differential privacy (DP) seems to cover both processing and release, but the authors show that the combination raises unexpected problems. A DP training algorithm whose running time depends on the data can lose its DP guarantee to timing side channels (in their experiment, a single training point's presence was distinguishable from runtime even at ε=0.1); rollback attacks on the TEE let an attacker rerun the same query to accumulate timing leakage; the existing rollback defense ElephantDP is vulnerable in this threat model; and standard DP hyperparameter tuning costs too much privacy budget. Building on the DP gradient-boosted decision tree learner S-BDT, the paper presents MammothDP, a system that addresses these problems together.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.14317
- arXiv HTML full text: https://arxiv.org/html/2611.14317
- arXiv PDF: https://arxiv.org/pdf/2611.14317
- Authors' repository (code): https://github.com/kirschte/MammothDP
- Authors' repository TEE-ready image: https://github.com/kirschte/MammothDP/tree/main/tee-ready-image

### Contribution
- A constant-time implementation of S-BDT using bitmasking and full passes over the data, with a fixed-time fixed-point library and fixed-time noise samplers adapted to it. Differences in loop counts caused by differing dataset sizes are also handled.
- Identifies a design flaw in ElephantDP and proposes a hash-chain-based rollback protection that limits the computation rather than the release.
- An early stopping criterion that uses only DP approximations of gradient sums (post-processing), so the number of trees adapts to the data at no extra privacy cost.

### Evaluation
- Constant-time verification: the dynamic timing side-channel analysis framework Microwalk analyzed each data-dependent component with 100 random inputs and reported no leakage across all executed S-BDT code.
- Privacy and utility: on two regression datasets (Insurance, Abalone) and three classification datasets (Credit, Adult, Spambase), early-stopped S-BDT clearly beat S-BDT with static hyperparameters on regression and did so on classification only at low ε. It was slightly below, but comparable to, S-BDT tuned with privacy-leaking hyperparameters.
- Platforms: the runtime cost of the constant-time implementation, the TEE, and rollback protection was measured on Intel TDX (Xeon Gold 6526Y) and AMD SEV (EPYC 7763).
- Reliability: two test datasets were kept separate from those used to choose the static hyperparameters, which keeps the comparison fair. Dynamic analysis only covers paths that the test inputs reach, so it is not a full proof.

#### Comment
- Gives concrete counterexamples, side channels and rollbacks, to the assumption that DP plus a TEE is automatically safe, and offers fixes. The same issues could apply to mobile TEE-based data processing.
- Code and a TEE image are released, so reproducibility is good. Material from a 2025 version exists within the same research project (AnoMed), but this summary follows the arXiv version.
- Full text source: arXiv PDF (downloaded on the user's computer).

# Hidden in Plain Sight: Privacy-Enhanced Computing Through Register Renaming
> arXiv preprint (not peer reviewed, primary category cs.AR). Uppsala University (Sweden)
> 2026

Privacy-enhanced computing (PEC) is a hardware approach to keeping program secrets hidden without paying the cost of fully homomorphic encryption. Sequestered Encryption (SE), the existing design, uses a dedicated decrypt-compute-encrypt unit that duplicates compute resources, and protected instructions cannot use the processor's multiple execution units or vector units. This paper proposes HPS-PEC, which reuses existing CPU machinery, register renaming and micro-op expansion, to keep plaintext only in hidden microarchitectural registers that no architectural register can map to. The decoder expands each PEC instruction into decrypt, ordinary compute, and encrypt micro-ops, so registers and memory only ever receive ciphertext.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.12570
- arXiv HTML full text: https://arxiv.org/html/2611.12570
- arXiv PDF: https://arxiv.org/pdf/2611.12570

### Contribution
- Adds only encryption and decryption units and shares every other functional unit, so protected instructions benefit from out-of-order and parallel execution.
- Plaintext may sit in the register file, but no architectural register can map to it, so, as with an enclave, ordinary instructions cannot reach it. The authors argue it adds no trust requirement beyond the correctness of the renamer and register file, on which every program already depends.
- Threat model: the attacker controls all software including the OS but has no physical access, and programs are data-oblivious (control flow and memory addresses do not depend on secret values). Transient execution on wrong paths is in scope.

### Evaluation
- Simulated with a gem5 out-of-order core (8-wide, 2.5 GHz) on 25 VIP-Bench benchmarks with a 7-cycle QARMA-64 cipher. The cipher unit was placed and routed in the ASAP7 7 nm library and meets 2.5 GHz.
- Encrypted execution took 3.41 times as long as unprotected native code (geometric mean), of which 1.03 times is the cost of data-oblivious code itself.
- It was 1.26 times faster than an SE unit with matched code generation (faster on 16 benchmarks, slower on 5) and used under 30% of SE's area (5,097 µm² versus at least 17,199 µm²).
- Reliability: results come from simulation and place-and-route, not silicon. The authors note fixes they made to some benchmarks and describe measurement details such as the handling of constants and public values.

#### Comment
- A short letter-style manuscript: the idea and headline numbers are clear, but the security analysis is brief. Whether real applications can satisfy the data-oblivious program assumption is a key premise.

- Full text source: arXiv PDF (downloaded on the user's computer).
