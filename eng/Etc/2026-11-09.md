# E-UDE: A Scientific Machine Learning Model for Malware Propagation Dynamics
> arXiv cs.CR 2611.00971 (preprint, not peer reviewed). Rajiv Gandhi Proudyogiki Vishwavidyalaya (RGPV), CSIR National Institute of Data Science and AI (India)
> 2026

Models that predict how malware spreads across the Internet fall into two camps. Epidemic-style differential equation models are easy to interpret but fit real data poorly, while neural models fit well but are hard to explain. Universal Differential Equations combine the two: known mechanisms are written as equations and whatever they miss is learned by a neural residual. This paper extends an earlier UDE malware model into E-UDE (Enhanced UDE), with separate compartments for susceptible, infected, response and congestion states, and explicit terms for transmission, network topology, congestion, external attacks, defensive response and security degradation. Because the compartments are explicit, the authors can run scenario analyses, for example how faster defensive response changes the spread.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.00971
- arXiv HTML full text: https://arxiv.org/html/2611.00971
- arXiv PDF: https://arxiv.org/pdf/2611.00971

### Contribution
- Replaces the generic growth terms of the earlier UDE model with four state compartments plus defense and congestion factors, making the model easier to interpret.
- Uses the learned parameters to compare the effect and cost-efficiency of interventions such as stronger defensive response or blocking external inflow.
- Reports that prediction quality degrades less than the baselines when noise is added to the data.

### Evaluation
- Data: CAIDA's public observations of infected hosts for the Code Red worm (2001) and the Witty worm (2004).
- Baselines: a classical differential equation model, a Neural ODE and the earlier UDE.
- Results (full-range fit on Code Red): E-UDE reaches RMSE 783.70, MAE 421.65, MAPE 13.36% and correlation 0.961, lower error than the classical model (RMSE 2325.87), Neural ODE (2094.76) and UDE (1281.84). With a chronological split that trains on the first 25% and predicts the remaining 75%, it reports a test RMSE of 634.6 and correlation of 0.964.
- How far to trust the numbers: all baselines are simple models from the same family, and standard time-series forecasters such as ARIMA or LSTM are missing from the tables. More importantly, the evaluation rests on just two single-worm outbreak curves that are more than twenty years old, so it is hard to say the results carry over to today's targeted, human-operated spread such as ransomware or botnets.

#### Comment
- This reads better as an application of scientific machine learning (combining physical models with neural networks) than as security research. Exposing factors like response speed and congestion as compartments is useful for teaching or policy simulation.
- Limitations: more compartments mean more parameters and a higher risk of overfitting, yet the only observed signal is the number of infected hosts, and the paper does not check whether the hidden states (response, congestion) are actually identifiable. We could not find a code release in the paper.
- Credibility: a preprint from an Indian national research institute and a university. It uses public datasets and gives configuration tables, so reproduction should be relatively easy.

# AutoPYara: Next-Gen YARA Rule Generator for Malware Family Clustering
> Accepted at IEEE ACSAC 2026 (per the arXiv comment and the paper); public version arXiv cs.CR 2611.08608. Texas A&M University (USA)
> 2026

Most of the malware that shows up every day consists of variants of known families, so grouping samples by family and catching each group with a single YARA rule largely decides how fast defenders can respond. AutoYara, considered the state of the art, generates rules automatically from byte N-grams that are rare in benign files and frequent in malware, but it was evaluated only with ground-truth family labels and on large clusters. In the field, families are diverse and clustering is noisy, and rule quality suffers. AutoPYara improves on this by picking cluster centroids precisely with similarity hashing and by estimating how many sub-clusters a family should be split into using historical VirusTotal family data.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.08608
- arXiv HTML full text: https://arxiv.org/html/2611.08608
- arXiv PDF: https://arxiv.org/pdf/2611.08608
- Author repository (ACSAC artifact): https://github.com/Botacin-s-Lab/AutoPYara
- Author repository (PyPI package source): https://github.com/Botacin-s-Lab/AutoPYaraPyPI
- PyPI package: https://pypi.org/project/autopyara/
- ACSAC permanent artifact (Zenodo): https://zenodo.org/records/23107801
- YARA rules and benchmark data (Zenodo): https://zenodo.org/records/22665898

### Contribution
- Replaces AutoYara's VBGMM-based sub-cluster estimation with Fuzzy C-Means, DBSCAN-style density-based choice of k and a VirusTotal-history heuristic, and adds a centroid selection step based on similarity hashing.
- Measures systematically, for the first time, how much rule generation depends on the labeling strategy (SSdeep and J-SDhash similarity clustering versus VirusTotal labels normalized with AVClass2).
- Ships as a Python package on the same Java backend, ready for practical use.

### Evaluation
- Data: Windows PE files collected over eight years by an antivirus company from customers in the USA, Brazil and Japan, 71,000 malware and 22,000 benign samples. Duplicates were deliberately kept to reflect real conditions.
- Metrics: per-cluster detection rate (rule coverage), with false positives split into benign files flagged as malware and samples matched to the wrong family. A conservative "detection" scenario that minimizes false positives and an aggressive "threat hunting" scenario that maximizes coverage are evaluated separately. Each setting is averaged over a number of runs chosen by a convergence procedure.
- Results: compared with AutoYara, rule coverage rises by 14 percentage points, variance drops by 7.1 percentage points, and threat-hunting accuracy improves by 10%. The conclusion cites an 80% improvement in the best configuration.
- Reliability: real-world samples and reporting results across labeling strategies make the case convincing. It is not clear at summary level which metric the "80% improvement" refers to, so the three figures in the abstract are the safer reference. The dataset itself is not public, but the rules and benchmark results are.

#### Comment
- A rare case of academic work meeting a field tool (YARA) head-on, with an artifact-evaluated package that SOC and threat-hunting teams can try right away.
- Limitations: only Windows PE files are covered, so applicability to other formats such as Android apps is unknown. Reliance on VirusTotal history weakens the heuristic for brand-new families.
- Venue: ACSAC is a well-regarded applied security conference, and corresponding author Marcus Botacin publishes regularly on malware analysis at major venues.
- Full text source: official arXiv PDF downloaded on the user's computer.

# PhotoFinish: Portable Timerless Probing of Microarchitectural Latencies
> arXiv cs.CR 2611.09879 (preprint, not peer reviewed). CISPA Helmholtz Center for Information Security (Germany)
> 2026

Microarchitectural attacks such as cache attacks usually rely on a high-resolution timer to tell fast from slow, which is why browsers defend by coarsening timers and adding jitter. Existing timerless techniques exist, but they depend on particular instructions or cache designs and do not port well. PhotoFinish turns a latency difference directly into a value through a race between two threads. One thread runs the operation under test (for example a memory access) and the other runs a fixed reference; both then write different values to the same shared memory location. The later write wins, so reading the surviving value tells whether the operation was faster or slower than the reference. All it needs is parallel execution and shared memory.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.09879
- arXiv HTML full text: https://arxiv.org/html/2611.09879
- arXiv PDF: https://arxiv.org/pdf/2611.09879

### Contribution
- Presents a portable timerless probing primitive that does not depend on any ISA or hardware feature: no timestamps, performance counters or privileged instructions.
- Shows that a WebAssembly build running in a browser with only WebWorkers and SharedArrayBuffer reaches precision close to native, so timer restrictions alone cannot stop browser-based microarchitectural attacks.
- Extends the reach beyond caches to the TLB, execution-engine latencies and LLC slice identification.

### Evaluation
- Scope: 38 CPUs across four ISAs (x86_64, AArch64, RISC-V, LoongArch), or 45 platform configurations when hybrid designs are split, with synchronization latency and jitter measured and cache state classified reliably on all of them.
- AES T-table attack: a first-round chosen-plaintext attack on OpenSSL 3.5.0's T-table AES on 41 platforms (Apple M1 and M2 excluded because of their cache line size). This is the standard benchmark for cache attacks, so results are directly comparable with prior work.
- Evict+Reload: on an Apple M1, eviction sets are found without a precise timer and used for a cross-core covert channel.
- Reliability: a standard attack benchmark and very broad hardware coverage back the portability claim directly. The experiments assume the attacker can pin threads to cores; without pinning, more repeated measurements are needed, as the authors note.

#### Comment
- The result undercuts the premise behind browser and sandbox defenses that blocking timers is enough. Any environment with shared memory and true parallelism is exposed, including mobile browsers.
- Countermeasures: replace shared memory with message passing that adds random delays, allow only one thread at a time to write a shared segment, or remove true parallelism. This ties directly into browser policy for SharedArrayBuffer.
- Venue: a preprint from Michael Schwarz's group, one of the leading teams in microarchitectural security. No code link was found in the paper.
- Full text source: official arXiv PDF downloaded on the user's computer.

# Robust & Scalable Website Fingerprinting via Minimal DRAM Traffic
> arXiv cs.CR 2611.09422 (preprint, not peer reviewed). Indian Institute of Technology Bombay (India)
> 2026

In website fingerprinting, malicious JavaScript running on the same machine observes shared resources to infer which sites the user visits. The best-known co-located attacks, sweep-counting and loop-counting, exceed 90% accuracy on machines with few cores but degrade sharply on many-core and chiplet (CCD) processors: loop-counting falls from 93% on 8 cores to 50% on 24 cores, and sweep-counting from 84% to 45% across multiple CCDs. The authors propose "memory-chasing," which counts DRAM accesses over fixed intervals using pointer-chasing traversals. Because DRAM traffic is shared by all cores, the approach scales with core count.

Links:
- arXiv abstract: https://arxiv.org/abs/2611.09422
- arXiv HTML full text: https://arxiv.org/html/2611.09422
- arXiv PDF: https://arxiv.org/pdf/2611.09422

### Contribution
- Analyzes why existing co-located fingerprinting attacks break down on many-core, chiplet and multi-socket systems (interrupt distribution, LLC split across CCDs).
- Designs an attack based on low-interference DRAM access counting that overcomes these limits.

### Evaluation
- Systems: Intel Xeon Gold 6342 (core-count scaling), AMD EPYC 9754 (CCD effects) and a dual-socket Intel system. The default environment is Ubuntu with Chrome 142, extended to Firefox 136, the Tor Browser and others.
- Results: on the top 50 websites, 96% on a 24-core system, 86% across multiple CCDs, 80% across sockets and 97% in an open-world setting. The body reports 91% in the Tor Browser.
- Robustness: evaluated across browsers, operating systems, isolation mechanisms, system noise and the countermeasures proposed in prior work (Cook et al.).
- Reliability: reproducing both prior attacks on the same hardware for a side-by-side comparison is a strength. Only 50 sites are used, and mobile processors were excluded because none have 16 or more cores.

#### Comment
- It shows that browser-based side channels still work on server- and workstation-class many-core machines, overturning the hope that more cores means enough noise to be safe.
- Limitations: the attack JavaScript must run in the victim's browser, and the evaluation is mostly closed-world with a small site list. No code link was found in the paper.
- Venue: a preprint from a computer architecture security lab at IIT Bombay.
- Full text source: official arXiv PDF downloaded on the user's computer.
