# ICALL-BENCH: Benchmarking LLM Interprocedural Reasoning in Binary Programs
> arXiv cs.SE, cross-listed to cs.CR (preprint, not peer reviewed), Georgia Institute of Technology and University of Massachusetts Amherst, USA
> 2026

Large language models do well on function-level binary understanding and on end-to-end reverse engineering tasks, but it is unclear whether they actually reason across functions. Function-level benchmarks cannot see cross-function relationships, and whole-program benchmarks only grade the final outcome, which local clues may be enough to reach.

ICALL-BENCH uses indirect-call target recovery (resolving function pointers and virtual calls) as a probe for interprocedural reasoning. Indirect-call targets are only known at run time, so resolving them statically means following data and control flow across function boundaries, and the answers can be checked mechanically by execution. The benchmark has 100 instances built from 50 real-world C/C++ programs under several compiler optimization settings, averaging 74,746 lines of code and 941 functions per program. The same task is run under three regimes: the model alone, an agent with static analysis tools, and an agent that can also search the internet.

### Contribution
- A benchmark that isolates interprocedural reasoning on binaries. Whole programs are given instead of a few preselected functions, so the task cannot collapse into local reasoning.
- Three regimes with increasing access to information, separating the model's own reasoning from tool use and outside knowledge.
- Shows that more information access does not reliably help, and that deep interprocedural reasoning remains the bottleneck on the hardest cases.

### Evaluation
- Systems: five recent LLMs and their agents. In the default regime (agents with static tools), program-level verified success ranged widely, from 23% to 81%.
- Static tools raised success by 30 to 58 percentage points over the model alone (DeepSeek-V4.1 Flash went from 16% to 74%). Compiler optimization level had little effect.
- Reliability of the metrics: answers are checked against execution-derived call relations, so scoring is objective. Cross-regime comparisons use the 50 instances under one million tokens, and context-window overflows count as failures, which should be kept in mind. With five models, the model ranking is indicative only.

#### Comment
- Shows in numbers that "reads one function well" and "understands the whole program" are different capabilities when evaluating LLM reverse engineering tools. Relevant for work where indirect-call resolution matters, such as obfuscation analysis or control-flow integrity.
- Limitations: C/C++ programs only, with no obfuscated binaries. In the internet-enabled regime, original source information may leak in, so results there need careful interpretation.
- Venue: preprint; the benchmark is released through an anonymous repository.
- Full-text source: the official arXiv PDF, downloaded on the user's computer.
- The authors are at Georgia Tech and UMass Amherst, USA; this is not a paper from a Chinese institution.
